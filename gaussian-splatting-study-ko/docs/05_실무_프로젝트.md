# 5장. 실제 촬영부터 배포 자산까지

## 1. 실무 파이프라인

```text
요구사항 정의
→ 촬영 계획
→ 사진/영상 획득
→ 프레임 선별
→ SfM/COLMAP
→ 3DGS 학습
→ 검증·정리
→ PLY/SPZ/glTF 등으로 변환
→ 웹·XR·엔진 배포
→ 성능과 품질 모니터링
```

## 2. 촬영 체크리스트

- 대상의 각 지점이 최소 3개 이상의 시점에서 보이도록 60~80% 중첩을 확보합니다.
- 한 바퀴만 돌지 말고 낮은·중간·높은 고도의 경로를 추가합니다.
- 모션 블러를 줄이고 초점, 노출, 화이트밸런스를 가능한 한 고정합니다.
- 걷는 사람, 흔들리는 나무, 화면, 반사체처럼 시간에 따라 바뀌는 요소를 줄입니다.
- 유리와 거울은 별도 마스킹 또는 후처리 대상으로 기록합니다.
- 장면 규모가 필요하면 기준 길이, GPS, LiDAR 또는 알려진 카메라 baseline을 확보합니다.
- 개인정보와 촬영 허가를 확인합니다.

## 3. Nerfstudio로 가장 쉬운 실무 입문

Nerfstudio는 COLMAP 전처리, Splatfacto 학습, 웹 viewer, PLY 내보내기를 한 도구 체계로 제공합니다. GPU 환경에서 공식 설치 문서를 먼저 따르세요.

### 이미지 전처리

```powershell
ns-process-data images --data D:\capture\images --output-dir D:\capture\processed
```

명령 구성:

- `ns`: Nerfstudio의 접두사
- `process-data`: 원본을 카메라 자세와 Nerfstudio 형식으로 변환
- `images`: 입력이 이미지 폴더임을 지정하는 subcommand
- `--data`: 입력 경로를 받는 long option
- `--output-dir`: 처리 결과를 저장할 output directory

### 영상 전처리

```powershell
ns-process-data video --data D:\capture\scene.mp4 --output-dir D:\capture\processed
```

영상에서는 서로 거의 같은 프레임을 과도하게 쓰지 않도록 추출 프레임 수를 조절합니다. 많다고 항상 좋은 것이 아니며 blur와 중복 프레임은 SfM 시간과 오매칭을 늘립니다.

### 학습

```powershell
ns-train splatfacto --data D:\capture\processed
```

- `train`: 파라미터 최적화 실행
- `splatfacto`: Nerfstudio의 3DGS 계열 method 이름
- `--data`: 처리된 카메라·이미지 데이터 경로

Nerfstudio 문서에 따르면 기본 `splatfacto`는 품질·속도·크기의 균형형이고, `splatfacto-big`은 Gaussian을 더 사용해 메모리와 시간을 늘리는 대신 품질을 노립니다.

### PLY 내보내기

```powershell
ns-export gaussian-splat --load-config D:\outputs\config.yml --output-dir D:\exports\scene
```

- `export`: 학습 결과를 외부 자산으로 변환
- `gaussian-splat`: 내보낼 자산 유형
- `--load-config`: 어떤 학습 체크포인트를 읽을지 알려 주는 설정 파일
- `PLY`: Polygon File Format의 약자지만 3DGS에서는 Gaussian 속성을 담는 point-like container로 자주 사용

## 4. 원 공식 구현 경로

Graphdeco 구현은 연구 재현과 원 알고리즘 이해에 적합합니다.

```powershell
git clone https://github.com/graphdeco-inria/gaussian-splatting.git --recursive
python train.py -s D:\capture\colmap_scene -m D:\outputs\scene --eval
python render.py -m D:\outputs\scene
python metrics.py -m D:\outputs\scene
```

약어와 옵션:

- `git`: distributed version control system 명령
- `clone`: 원격 저장소 복제
- `--recursive`: Git submodule까지 재귀적으로 함께 받음
- `-s`: `--source_path`의 짧은 옵션
- `-m`: `--model_path`의 짧은 옵션
- `--eval`: train/test 분할을 사용해 평가 가능하게 함
- `render.py`: 저장한 모델에서 평가 시점 이미지 생성
- `metrics.py`: 렌더 결과의 PSNR, SSIM, LPIPS 등을 계산

원 구현의 라이선스는 일반적인 permissive open-source 라이선스가 아닙니다. 상용 이용 전 저장소의 `LICENSE.md`를 반드시 검토하세요.

## 5. COLMAP을 직접 사용할 때

COLMAP은 크게 feature extraction → feature matching → mapping 순서입니다.

```powershell
colmap feature_extractor --database_path database.db --image_path images
colmap exhaustive_matcher --database_path database.db
colmap mapper --database_path database.db --image_path images --output_path sparse
```

- feature: 이미지의 구별 가능한 국소 특징
- descriptor: feature 주변 모양을 수치 벡터로 표현한 기술자
- matcher: 서로 다른 이미지의 같은 지점을 찾는 모듈
- exhaustive: 가능한 이미지 쌍을 폭넓게 비교
- mapper: 대응점으로 카메라 pose와 3D 점을 복원
- `db`: database의 약자, 여기서는 SQLite 파일 확장자

수백 장 이하의 일반 장면은 exhaustive matcher가 단순하고 강력합니다. 긴 동영상이나 대규모 데이터는 sequential/vocab-tree 방식이 더 효율적일 수 있습니다.

## 6. 검수 기준

### 기하 검수

- 카메라 trajectory가 갑자기 튀지 않는가?
- sparse point cloud가 실제 형태와 비슷한가?
- 잘못 등록된 이미지가 없는가?
- 바닥·벽·얇은 구조가 끊기지 않는가?

### 영상 검수

- train view만이 아니라 보류한 test view에서도 선명한가?
- 카메라 이동 중 popping, floaters, 색 깜빡임이 없는가?
- 입력 사진과 크게 다른 경로에서도 구조가 유지되는가?

### 제품 검수

- 목표 기기의 FPS와 frame time을 만족하는가?
- 첫 로딩 시간, 전송 크기, 최대 GPU 메모리가 허용 범위인가?
- 브라우저/모바일/VR에서 색 공간과 alpha가 일치하는가?
- 자산 포맷과 viewer 버전을 함께 기록했는가?

## 7. 적용 분야

- 부동산·관광: 현장 원격 투어
- 문화유산: 사진 기반 시각 기록
- 영화·VFX: 빠른 location capture와 배경 자산
- 게임·XR: 사실적 환경과 volumetric content
- 디지털 트윈: 공장·건설·도시의 시각화 레이어
- 로보틱스: dense mapping, localization, simulation
- 자율주행: 동적 도로 장면 재구성과 sensor simulation
- 전자상거래: 상품의 자유 시점 표현

단, 치수 측정, 충돌, 물리 해석이 핵심이면 mesh/CAD/LiDAR 표현을 함께 유지해야 합니다.
