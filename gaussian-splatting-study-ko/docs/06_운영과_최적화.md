# 6장. 운영, 품질, 속도와 비용

## 1. 먼저 측정할 네 축

| 축 | 대표 지표 | 질문 |
|---|---|---|
| 화질 | PSNR, SSIM, LPIPS, 사용자 평가 | 새 시점이 자연스러운가? |
| 속도 | FPS, frame time, 학습 시간 | 목표 기기에서 실시간인가? |
| 메모리 | Gaussian 수, VRAM, 파일 크기 | 장면을 로드할 수 있는가? |
| 안정성 | 등록률, 재현성, 실패 장면 | 반복 실행해도 결과가 일정한가? |

- `PSNR`: Peak Signal-to-Noise Ratio, 픽셀 오차 기반이며 높을수록 좋음
- `SSIM`: Structural Similarity Index Measure, 구조 유사도이며 높을수록 좋음
- `LPIPS`: Learned Perceptual Image Patch Similarity, 지각적 차이이며 낮을수록 좋음
- `FPS`: Frames Per Second, 초당 프레임 수
- `VRAM`: Video Random Access Memory, GPU 메모리

숫자 하나만 최적화하지 마세요. PSNR이 높아도 이동 중 popping이 심하거나 파일이 너무 크면 제품 품질은 낮습니다.

## 2. 데이터 단계 최적화가 가장 싸다

1. blur와 중복 프레임 제거
2. 노출이 크게 다른 프레임 분리 또는 보정
3. 동적 물체 mask 적용
4. SfM 등록 실패 이미지 제거
5. test view를 촬영 경로 구간 단위로 보류

잘못된 입력을 더 오래 학습하는 것은 해결책이 아닙니다.

## 3. 학습 메모리 줄이기

- 입력 해상도를 낮춰 먼저 pipeline을 검증합니다.
- Gaussian densification 종료 시점을 앞당깁니다.
- opacity가 낮거나 projected radius가 작은 Gaussian을 prune합니다.
- SH degree를 낮춰 색 계수 수를 줄입니다.
- 이미지 cache를 GPU 대신 CPU에 두는 옵션을 검토합니다.
- 작은 장면 crop으로 hyperparameter를 정한 뒤 전체 장면을 학습합니다.

## 4. 렌더링 최적화

- 화면에 없거나 near/far plane 밖인 Gaussian을 culling합니다.
- projected radius가 너무 작은 Gaussian을 제거합니다.
- tile 단위로 관련 Gaussian만 처리합니다.
- transmittance가 거의 0인 픽셀은 early termination합니다.
- 거리에 따라 LOD(Level of Detail)를 바꿉니다.
- 큰 장면은 공간 계층과 streaming을 사용합니다.

gsplat 공식 대규모 예시는 `radius_clip`으로 화면상 반경이 작은 Gaussian을 건너뛰는 방법을 제공합니다.

## 5. 압축 전략

| 방법 | 줄이는 것 | 위험 |
|---|---|---|
| pruning | Gaussian 개수 | 얇은 구조 손실 |
| quantization | 위치·scale·SH 비트 수 | banding·색 오차 |
| codebook | 반복 속성 공유 | 세부 외관 감소 |
| lower SH degree | 색 계수 | view-dependent 효과 감소 |
| spatial hierarchy | 필요한 구역만 로드 | 전환 popping |
| SPZ/glTF compression | 전송·저장 크기 | viewer 호환성 |

압축 전후에 정지 화면뿐 아니라 카메라 경로 동영상으로 검수해야 합니다.

## 6. 배포 포맷과 표준화

PLY는 연구 생태계에서 널리 쓰이지만 Gaussian 속성의 이름과 배치가 구현마다 다를 수 있습니다. `.splat`, `.ksplat`, `.spz`도 각 생태계의 장단점이 있습니다.

2026년 Khronos는 glTF 2.0의 `KHR_gaussian_splatting` release candidate를 발표했습니다. 기본 ellipsoid kernel과 위치·회전·scale·opacity·SH 계열 속성을 표준 자산 컨테이너에 담고, SPZ와 같은 압축 extension이 결합되는 방향입니다. 아직 release candidate이므로 최종 규격과 viewer 지원 상태를 배포 시점에 다시 확인해야 합니다.

## 7. 재현성 기록

장면별 manifest에 다음을 남깁니다.

```yaml
scene_id: factory_room_a
capture_date: 2026-08-09
camera: example-camera
image_count_raw: 1200
image_count_used: 420
sfm_tool: COLMAP
trainer: nerfstudio-splatfacto
trainer_commit: replace-with-commit-sha
steps: 30000
export_format: ply
coordinate_convention: documented-separately
```

- `manifest`: 자산을 만든 입력과 설정의 목록
- `SHA`: Secure Hash Algorithm 기반 Git commit 식별값
- coordinate convention: 축 방향, handedness, 단위, 행렬 방향의 약속

## 8. 장애 대응 순서

```text
입력 파일 확인
→ 카메라 등록 결과 확인
→ 초기 point cloud 확인
→ 작은 해상도·짧은 step으로 재현
→ NaN/VRAM/gradient 로그 확인
→ 파라미터 하나씩 변경
→ 렌더 경로로 회귀 비교
```

여러 설정을 동시에 바꾸면 원인을 알 수 없습니다. 장면, 코드 commit, seed, 환경, 명령 전체를 함께 기록합니다.
