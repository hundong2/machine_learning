# YOLO26 단안 깊이 추정: 공식 문서 한글 해설

기준 문서: [Ultralytics Monocular Depth Estimation](https://docs.ultralytics.com/tasks/depth/)

번역·해설 기준일: 2026-08-04

## 1. 단안 깊이 추정이란?

단안 깊이 추정은 **한 장의 RGB 이미지**를 입력받아 모든 픽셀에 카메라로부터의 예상 거리를 부여합니다. 출력은 입력 이미지와 정렬된 `(H, W)` 형태의 조밀한 실수 배열이며, YOLO26 Depth 결과의 단위는 미터입니다.

```text
RGB 이미지 (H, W, 3) ── YOLO26 Depth ──> 깊이 맵 (H, W), 단위: m
```

활용 분야는 3D 장면 재구성, 로봇 내비게이션, AR/VR, 장애물 인지, 촬영 장면의 공간 구조 분석 등입니다.

단, 한 대의 일반 카메라만으로 절대 거리를 알아내는 문제는 본질적으로 모호합니다. 똑같이 보이는 작은 물체가 가까이 있을 수도 있고 큰 물체가 멀리 있을 수도 있습니다. 모델은 대규모 학습 데이터에서 배운 시각적 단서를 사용해 이 모호성을 통계적으로 해결합니다. 따라서 출력값은 센서 측정값이 아니라 **모델의 추정값**이며, 안전이 중요한 시스템에서는 거리 센서와 검증 절차가 필요합니다.

## 2. 모델 선택

모델 이름은 `yolo26{크기}-depth.pt` 형식입니다.

| 모델 | 파라미터(M) | NYU δ1 | NYU AbsRel | NYU RMSE(m) | 선택 기준 |
|---|---:|---:|---:|---:|---|
| `yolo26n-depth.pt` | 6.4 | 0.882 | 0.109 | 0.414 | 가장 가볍고 빠른 입문용 |
| `yolo26s-depth.pt` | 13.2 | 0.896 | 0.104 | 0.399 | 속도와 정확도 균형 |
| `yolo26m-depth.pt` | 23.3 | 0.921 | 0.089 | 0.364 | 더 높은 정확도 |
| `yolo26l-depth.pt` | 27.7 | 0.930 | 0.083 | 0.351 | 고성능 GPU 권장 |
| `yolo26x-depth.pt` | 57.0 | 0.933 | 0.080 | 0.344 | 최고 정확도 중심 |

표의 공식 수치는 NYU Depth V2 Eigen 테스트 분할에서 TTA와 log-least-squares 정렬을 사용한 결과입니다. 서로 다른 평가 절차의 수치를 직접 비교하면 안 됩니다. 입문 실습에서는 다운로드와 추론이 가장 가벼운 `n` 모델이 적절합니다.

## 3. 왜 log-depth head를 사용하는가?

YOLO26 Depth의 헤드는 대략 `exp(logit)` 형태로 양의 깊이를 출력합니다. 고정된 `sigmoid × max_depth` 방식처럼 10 m 등의 상한을 구조에 박아 넣지 않으므로, 실내의 짧은 거리와 도로의 긴 거리를 같은 모델로 다루기 쉽습니다.

핵심은 다음 두 부분을 분리하는 것입니다.

- 상대 구조: 어떤 표면이 더 가깝거나 먼지 나타내는 깊이의 형태
- 절대 스케일: 그 구조가 실제로 몇 미터인지 정하는 보정값

공식 문서의 제어 실험에서는 실내·실외 혼합 데이터에서 10 m 상한 헤드보다 비제한 log 헤드의 δ1이 크게 높았습니다. 이는 10 m보다 먼 픽셀을 상한형 헤드가 표현할 수 없기 때문입니다.

## 4. 추론과 결과 객체

```python
from ultralytics import YOLO

model = YOLO("yolo26n-depth.pt")
result = model("https://ultralytics.com/images/bus.jpg", imgsz=768)[0]
depth = result.depth.data.cpu().numpy()  # (H, W), float32, meters
```

깊이 작업의 주요 필드는 다음과 같습니다.

| 필드 | 형태 | 의미 |
|---|---|---|
| `result.depth` | `DepthMap` | 한 이미지의 깊이 결과 |
| `result.depth.data` | `torch.Tensor (H, W)` | 픽셀별 미터 단위 깊이 |
| `result.boxes` | 없음 | 객체 검출 작업이 아니므로 박스 없음 |
| `result.masks` | 없음 | 인스턴스 분할 작업이 아니므로 마스크 없음 |

이미지를 리사이즈해 추론하더라도 반환된 깊이 맵은 입력 이미지 해상도에 맞춰 정렬됩니다.

## 5. 깊이 맵을 읽는 두 가지 방식

원시 깊이 맵은 계산에는 좋지만 한 채널 실수 배열이라 사람이 보기 어렵습니다. `colorize_depth`로 색을 입힐 수 있습니다.

```python
from ultralytics.utils.plotting import colorize_depth

# 상대 깊이: 역깊이를 백분위 범위로 정규화, 가까운 곳이 따뜻한 색
relative = colorize_depth(depth, cmap="spectral", mode="disparity")

# 절대 깊이: 0~20 m를 고정 범위로 선형 정규화, 먼 곳이 따뜻한 색
metric = colorize_depth(
    depth, vmin=0.0, vmax=20.0, cmap="inferno", mode="metric"
)
```

- `disparity`: `1/depth`를 사용합니다. 장면 내 앞뒤 구조를 눈으로 비교하기 좋고 가까운 곳이 따뜻하게 표시됩니다.
- `metric`: 미터 값을 선형 정규화합니다. `vmin`, `vmax`를 고정하면 서로 다른 프레임에서도 같은 색이 같은 거리를 뜻합니다.
- 0 이하인 깊이는 유효하지 않은 픽셀로 보고 검은색으로 표시됩니다.

## 6. 학습과 미세조정

작은 예제 데이터셋에서 학습 흐름을 확인하는 공식 예시는 다음과 같습니다.

```python
from ultralytics import YOLO

model = YOLO("yolo26n-depth.pt")
model.train(data="depth8.yaml", epochs=100, imgsz=640)
```

사용자 도메인에 사전학습 모델을 미세조정할 때는 AdamW와 낮은 학습률을 권장합니다.

```python
model = YOLO("yolo26s-depth.pt")
model.train(
    data="path/to/dataset.yaml",
    epochs=20,
    imgsz=640,
    optimizer="AdamW",
    lr0=1e-4,
    warmup_bias_lr=1e-4,
)
```

사전학습 모델에 처음부터 학습할 때의 SGD 기본 학습률을 그대로 쓰면 이미 배운 표현을 빠르게 훼손할 수 있습니다. `mosaic`, `mixup`, `cutmix`, `copy_paste`는 여러 이미지를 섞어 RGB-깊이 정렬을 깨뜨리므로 깊이 작업에서 지원되지 않습니다.

## 7. 사용자 데이터셋 형식

RGB 파일과 깊이 파일의 상대 경로 및 기본 이름이 일치해야 합니다.

```text
dataset/
├── images/
│   ├── train/scene_001.jpg
│   └── val/scene_101.jpg
└── depth/
    ├── train/scene_001.npy
    └── val/scene_101.npy
```

`scene_001.npy`는 이미지와 같은 높이·너비의 `float32` 배열이며 값의 단위는 미터입니다. 로더는 이미지 경로의 마지막 `images`를 `depth`로 바꾸고 확장자를 `.npy`로 바꿔 짝을 찾습니다.

예시 YAML:

```yaml
path: /absolute/path/to/dataset
train: images/train
val: images/val
max_depth: 20.0
```

`max_depth`는 모델 출력의 상한이 아니라 검증 지표에 포함할 GT 깊이의 범위를 정합니다. 0, NaN, 무한대 등의 무효 깊이는 손실과 지표에서 제외해야 합니다.

## 8. 스케일 보정과 미세조정의 차이

상대적 앞뒤 구조는 좋은데 전체적으로 미터 값만 일정하게 어긋난다면 네트워크를 다시 학습하기보다 보정을 사용합니다.

```python
model = YOLO("yolo26s-depth.pt")
model.calibrate(data="path/to/dataset.yaml")
model.save("yolo26s-depth-calibrated.pt")
```

보정은 라벨이 있는 분할에서 예측과 GT 사이의 두 파라미터 log-affine 변환을 닫힌 형식으로 맞춥니다. 가중치를 바꾸지 않으므로 상대 구조를 훼손하지 않습니다. 반대로 물체 경계나 장면 구조 자체가 틀리면 미세조정이 필요합니다. 공식 문서는 안정적인 보정을 위해 약 100장 이상의 라벨 이미지를 안내합니다.

## 9. 검증 지표

| 지표 | 직관 | 방향 |
|---|---|---|
| δ1 / δ2 / δ3 | 예측/정답 비율이 각각 1.25, 1.25², 1.25³ 안인 픽셀 비율 | 높을수록 좋음 |
| AbsRel | `mean(abs(pred-gt) / gt)` | 낮을수록 좋음 |
| RMSE | 미터 단위 제곱근 평균 제곱 오차 | 낮을수록 좋음 |
| SILog | 전역 스케일 변화에 덜 민감한 로그 깊이 오차 | 낮을수록 좋음 |

```python
metrics = model.val(data="nyu-depth.yaml", imgsz=768)
print(metrics.delta1, metrics.abs_rel, metrics.rmse, metrics.silog)
```

공식 구현은 각 예측을 GT에 중앙값 정렬한 뒤 모든 유효 픽셀을 모아 통계를 냅니다. 논문이 이미지별 지표를 먼저 평균하면 같은 예측에서도 값이 조금 다를 수 있습니다.

## 10. 모델 내보내기

```python
model = YOLO("yolo26n-depth.pt")
model.export(format="onnx", imgsz=768)
```

공식 문서는 TorchScript, ONNX, OpenVINO, TensorRT, CoreML, TensorFlow 계열, NCNN 등 여러 형식을 지원합니다. 대상 하드웨어에 맞는 런타임과 양자화 정확도를 별도로 검증하세요.

## 11. 꼭 기억할 한계

- 텍스처가 적은 벽, 반사·투명 표면, 극단적인 조명, 학습 분포 밖의 장면에서 오차가 커질 수 있습니다.
- 색상 맵은 시각화일 뿐이며 픽셀의 실제 값은 `depth_raw.npy`에서 확인해야 합니다.
- 모델의 전역 보정값은 특정 카메라의 초점거리와 촬영 환경에 최적이 아닐 수 있습니다.
- 충돌 회피나 사람 안전처럼 실패 비용이 큰 용도에서는 LiDAR/스테레오/ToF 센서와 결합하고 현장 검증을 수행해야 합니다.
