# [2026-09-22] 오늘 학습: 순차적 중요도 샘플링·신뢰 하한 & PDIS·sequential DR·안전한 정책 개선

> **오늘의 핵심 문장:** 여러 턴 에이전트의 새 정책을 과거 로그로 평가할 때는 행동 확률비를 시간축으로 올바르게 누적하고, 평균 개선치가 아니라 **불확실성을 뺀 개선량의 하한**이 양수일 때만 다음 배포 단계로 나아가야 한다.

지난 시간에는 한 상황에서 한 행동을 고르는 **contextual bandit(문맥이 주어진 단일 선택 문제)**에서, 과거·목표 **정책(policy, 현재까지 본 정보에 따라 다음 행동 확률을 정하는 규칙)**의 확률비로 평균을 보정하는 **IPS**, 가중치가 실질적으로 몇 표본에 퍼졌는지 보는 **유효표본크기(ESS)**, 확률비와 보상 예측을 결합하는 **이중 강건 추정(DR)**을 배웠다. 하지만 실제 LLM/VLM 에이전트는 검색하고, 도구를 호출하고, 결과를 읽고, 다음 행동을 고르는 과정을 여러 번 반복한다. 첫 행동은 둘째 상태를 바꾸고, 둘째 행동은 셋째 상태를 바꾼다. 오늘은 한 줄짜리 로그의 확률비를 **여러 단계의 궤적(trajectory, 시작부터 종료까지의 상태·행동·보상 기록)**으로 확장하고, 누적 확률비의 폭발을 **per-decision IS(PDIS, 보상 시점까지만 비율을 누적하는 방법)**와 **sequential DR(시간별 가치 예측 오차를 보정하는 DR)**로 완화한 뒤, **오프정책 신뢰 하한(lower confidence bound, LCB)**으로 안전한 정책 개선 여부를 판단한다.

## 1. 지식의 씨앗: 이 개념들은 왜 탄생했을까?

### 1.1 왜 마지막 성공률만 비교하면 안 될까?

고객 지원 에이전트가 다음 순서로 일한다고 하자.

~~~text
사용자 요청
  → 계정 조회
  → 환불 규정 검색
  → 환불 도구 호출
  → 결과 확인
  → 사용자에게 최종 답변
~~~

새 에이전트의 최종 성공률을 가장 정확히 알려면 실제 사용자에게 배포해 보면 된다. 그러나 환불, 의료, 보안, 파일 삭제처럼 실패 비용이 큰 작업은 “먼저 배포하고 나중에 측정”하기 어렵다. 그래서 과거 정책이 남긴 궤적을 이용해 새 정책의 가치를 미리 추정하는 **오프정책 평가(off-policy evaluation, OPE)**가 필요해졌다.

여기서 단일 행동 IPS를 그대로 쓰면 새로운 문제가 생긴다. 새 정책과 과거 정책의 비율은 한 번만 곱하는 것이 아니라 매 단계 곱해야 한다.

$$
\rho_{1:t}
=\prod_{j=1}^{t}
\frac{\pi(a_j\mid h_j)}
{b(a_j\mid h_j)}.
$$

각 비율이 조금씩만 $1$에서 벗어나도 긴 궤적에서는 곱이 매우 작거나 매우 커진다. 한 개의 희귀한 성공 궤적이 전체 평균을 지배할 수 있고, 로그가 많아 보여도 실제 정보량은 거의 없을 수 있다. 이것이 **순차적 중요도 샘플링**과 시간별 ESS 진단이 탄생한 이유다.

### 1.2 왜 per-decision으로 보상을 나눌까?

택시 기사의 하루 수입을 평가한다고 하자. 하루가 끝난 뒤 총수입만 보고 전체 경로 확률비를 곱할 수도 있다. 하지만 첫 번째 승차에서 받은 요금은 그 뒤의 다섯 번째 경로 선택에 영향을 받지 않는다. 미래 선택의 확률비까지 첫 보상에 곱하면 불필요한 잡음을 추가한다.

**per-decision importance sampling(PDIS)**은 시점 $t$의 보상 $r_t$에 그 보상이 생기기까지의 비율 $\rho_{1:t}$만 곱한다. 미래 행동은 아직 $r_t$를 만들지 않았으므로 제외한다. 인과 순서를 이용해 쓸데없는 분산을 걷어 내는 것이다.

단, 최종 성공 보상만 있고 중간 보상이 모두 $0$이라면 이 장점이 거의 사라진다. 마지막 보상에는 결국 전체 궤적 비율 $\rho_{1:H}$가 붙기 때문이다. 따라서 에이전트 평가에서는 “검색 성공”, “도구 인수 검증 통과”, “상태 변경 확인” 같은 **검증 가능한 중간 결과**를 기록하는 일이 중요하다. 다만 원래 목표가 최종 성공률이라면 임의의 중간 보너스를 반환값에 더하는 순간 평가 대상 자체가 바뀐다. 원래 효용이 시간별 보상의 합으로 자연스럽게 분해되거나, 할인합을 궤적별로 그대로 보존하는 **reward redistribution(같은 총보상을 여러 시점에 재배치하는 방법)**일 때만 PDIS의 분산 이점을 같은 수치 목표에 적용할 수 있다. 정책의 순위만 보존하는 **reward shaping(학습 안내를 위해 보상 모양을 바꾸는 방법)**은 최적화에는 쓸 수 있어도 원래 성공률의 LCB·최소 개선폭과 같은 단위로 해석할 수 없으므로 별도 목표로 보고해야 한다.

### 1.3 왜 점추정치 대신 신뢰 하한을 볼까?

새 정책의 추정 성공률이 $72\%$, 기존 정책이 $70\%$라고 하자. 이 $2$%p 차이가 수천 개의 고른 표본에서 나온 것인지, 가중치가 큰 궤적 두 개에서 나온 것인지에 따라 의미가 완전히 다르다.

안전한 정책 개선의 질문은 다음과 같다.

> “새 정책이 더 좋아 보이는가?”가 아니라
>
> “통계적 불확실성을 보수적으로 빼고도 최소한 기존 정책보다 나쁘지 않은가?”

이를 위해 개선량

$$
\Delta=V(\pi)-V(\pi_0)
$$

의 한쪽 신뢰구간 하한을 계산한다. $\pi_0$는 현재 운영 정책, $\pi$는 후보 정책이다. 하한이 $0$보다 충분히 크면 제한적 온라인 실험으로 진행하고, 하한이 음수라면 평균 추정치가 양수여도 증거 부족으로 보류한다.

### 1.4 역사적 흐름

중요도 샘플링은 한 분포에서 얻은 표본으로 다른 분포의 기댓값을 계산하는 통계 기법이다. 강화학습에서는 이를 여러 시점의 정책 비율로 확장해 과거 정책의 궤적으로 새 정책을 평가했다. 그러나 궤적 길이에 따라 분산이 폭발하는 문제가 드러나면서 다음 계열이 발전했다.

1. **trajectory IS:** 전체 반환값에 전체 궤적 비율을 곱한다.
2. **per-decision IS:** 각 보상에 그때까지의 누적 비율만 곱한다.
3. **weighted·clipped IS:** 극단 가중치의 영향을 줄이는 대신 편향을 받아들인다.
4. **sequential DR:** 목표 정책의 가치 모델을 기준선으로 두고, 실제 관측의 시간차 오차만 확률비로 보정한다.
5. **high-confidence OPE:** 추정 평균이 아니라 보수적 하한으로 배포 결정을 내린다.

오늘의 핵심은 이 방법들이 서로를 대체하는 마법 공식이 아니라, **지원집합·분산·모델 오차·배포 위험을 서로 다른 각도에서 다루는 도구 모음**이라는 점이다.

## 2. 친절한 용어 사전

| 기호·용어 | 초보자를 위한 뜻 | 오늘의 역할 |
| --- | --- | --- |
| 정책(policy) | 현재까지 본 정보에 따라 다음 행동의 확률을 정하는 규칙 | $b$와 $\pi$를 구분하는 출발점이다. |
| 에피소드(episode) | 하나의 과제가 시작해 성공·실패·중단으로 끝날 때까지의 한 실행 | 통계적으로 한 표본이 되는 기본 단위다. |
| $H$ | 한 에피소드가 가질 수 있는 최대 단계 수 | 다중 턴 작업의 시간 길이. |
| $h_t$ | $t$번째 행동 직전까지의 모든 관측·행동 기록 | LLM에서는 프롬프트, 대화, 화면, 도구 결과를 모두 포함한 역사다. |
| prefix | 전체 궤적 중 시작부터 특정 시점까지의 앞부분 | $\rho_{1:t}$가 보정하는 범위다. |
| $s_t$ | 현재 의사결정에 필요한 상태 요약 | Markov 가정이 맞다면 $h_t$ 대신 $s_t$만으로 다음을 예측할 수 있다. |
| Markov 가정 | 현재 상태를 알면 더 오래된 과거가 다음 결과 예측에 추가 정보를 주지 않는다는 가정 | 긴 역사 $h_t$를 상태 $s_t$로 요약할 수 있는 조건이다. |
| $a_t$ | $t$번째 행동 | 도구 호출, 클릭, 검색 질의, 답변 토큰 묶음 등이 될 수 있다. |
| $r_t$ | $a_t$ 뒤에 관측한 즉시 보상 | 단계 성공, 비용, 안전 위반 또는 최종 과제 성공을 수치화한다. |
| $\gamma\in[0,1]$ | 미래 보상을 얼마나 할인할지 정하는 수 | $\gamma=1$이면 모든 시점의 보상을 같은 비중으로 본다. |
| $G=\sum_{t=1}^{H}\gamma^{t-1}r_t$ | 한 궤적의 할인 누적 보상 | 반환값(return)이라고 부른다. |
| $b(a_t\mid h_t)$ | 실제 로그를 만든 과거 정책의 행동 확률 | 행동 정책 또는 로깅 정책. |
| propensity | 로그에서 실제 행동이 선택될 확률 | 여기서는 $b(a_t\mid h_t)$와 같은 뜻으로 쓴다. |
| $\pi(a_t\mid h_t)$ | 평가하려는 새 정책의 같은 행동 확률 | 목표 정책. |
| $w_t=\pi/b$ | 한 시점의 정책 확률비 | 그 행동을 목표 정책 관점에서 재가중한다. |
| $\rho_{1:t}=\prod_{j=1}^{t}w_j$ | 시작부터 $t$까지의 누적 확률비 | 해당 시점까지의 상태 분포 차이까지 보정한다. |
| trajectory IS | 전체 반환값 $G$에 $\rho_{1:H}$를 곱하는 방법 | 불편일 수 있지만 긴 궤적에서 분산이 매우 커진다. |
| PDIS | $r_t$에 $\rho_{1:t}$만 곱하는 방법 | 미래 행동 비율이 과거 보상에 주는 불필요한 잡음을 제거한다. |
| $Q_t^\pi(h_t,a_t)$ | 지금 행동한 뒤 목표 정책을 계속 따를 때의 기대 반환 | sequential DR의 행동가치 모델이다. |
| $V_t^\pi(h_t)$ | 현재 역사에서 목표 정책을 따를 때의 기대 반환 | $Q$를 목표 정책 행동 확률로 평균낸 값이다. |
| critic·가치 모델 | 앞으로 받을 보상의 기댓값을 예측하는 모델 | $\widehat Q_t,\widehat V_t$를 학습한다. |
| Bellman 방정식 | 현재 가치가 즉시 보상과 다음 상태 가치의 합이라는 재귀 관계 | 올바른 가치 모델의 TD 잔차 평균을 $0$으로 만든다. |
| TD 잔차 $\delta_t$ | 실제 한 단계 결과와 가치 모델의 예측 차이 | DR이 로그로 보정할 부분이다. |
| sequential DR | 가치 모델의 예측에 누적 비율로 가중한 TD 잔차를 더하는 방법 | 로깅 정책 또는 가치 모델 중 하나가 맞을 때의 보호막을 노린다. |
| 점추정치 | 데이터에서 계산한 하나의 숫자 | “개선량은 $0.04$”처럼 중심값만 말한다. |
| 표준오차(SE) | 같은 절차를 반복할 때 점추정치가 흔들리는 전형적 크기 | 신뢰 하한을 계산한다. |
| LCB | lower confidence bound, 신뢰 하한 | 개선량이 보수적으로 보아도 양수인지 판단한다. |
| UCB | upper confidence bound, 신뢰 상한 | 안전 비용이 보수적으로 보아도 허용 한도 아래인지 판단한다. |
| Wald 근사 | 추정량이 큰 표본에서 정규분포처럼 움직인다고 보고 표준오차로 구간을 만드는 방법 | 간단하지만 작은 ESS·두꺼운 꼬리에서는 부정확할 수 있다. |
| bootstrap | 관측 단위를 반복 재표집해 전체 계산 절차의 흔들림을 재현하는 방법 | 복잡한 추정량과 사용자 군집의 불확실성을 계산한다. |
| 교차 적합(cross-fitting) | 일부 에피소드로 보조 모델을 학습하고, 그 모델이 보지 않은 에피소드를 평가하는 일을 폴드별로 반복하는 방법 | 현재 결과를 외운 가치·확률 모델이 평가를 낙관적으로 만드는 일을 줄인다. |
| delta method·영향함수 | 복잡한 추정량을 표본 평균 주위에서 1차로 펼쳐 각 관측의 영향을 계산하는 방법 | WPDIS 같은 비율 추정량의 표준오차를 구한다. |
| 안전한 정책 개선 | 새 정책이 기준 정책보다 나쁘지 않다는 충분한 증거가 있을 때만 배포하는 절차 | 평균 최대화와 배포 게이트를 분리한다. |
| 지원집합(overlap) | $\pi$가 고를 행동을 $b$도 양의 확률로 골랐는가 | 없던 행동의 결과를 로그만으로 알아낼 수 없다는 식별 조건이다. |
| 순차적 무교란성 | 기록된 역사에 조건부로 행동 선택과 잠재적 미래 결과 사이에 숨은 원인이 없다는 가정 | 중요한 상태가 로그에서 빠지면 OPE가 편향될 수 있다. |

오늘은 유한 길이 에피소드가 서로 독립이고 같은 환경의 초기 상태·전이 규칙을 공유한다고 가정한다. 행동 정책은 각 단계의 실제 선택 확률을 기록하며, 목표 정책은 평가 데이터를 본 뒤 임의로 고르지 않고 미리 고정하거나 별도 검증 로그에서 평가한다. 또한 목표 정책이 양의 확률을 주는 모든 도달 가능한 $(h_t,a_t)$에 대해 $b(a_t\mid h_t)>0$이고, 필요한 모멘트가 유한하다고 가정한다. 합과 점확률 표기는 이산 행동을 위한 것이다. 연속 행동에서는 합을 적분으로, 확률비를 “같은 작은 구간에 두 정책이 주는 상대 밀도”인 $d\pi/db$로 바꾼다.

## 3. 수학의 해부학 (증명과 원리)

### 3.1 궤적의 확률은 어떻게 분해될까?

한 에피소드의 궤적을

$$
\tau=(s_1,a_1,r_1,s_2,a_2,r_2,\ldots,s_H,a_H,r_H,s_{H+1})
$$

라고 쓰자. 정책 $\pi$ 아래의 궤적 확률은 초기 상태 분포 $d_1$, 환경 전이 확률 $P$, 정책 확률의 곱으로 분해된다.

$$
p_\pi(\tau)
=d_1(s_1)
\prod_{t=1}^{H}
\pi(a_t\mid h_t)
P(s_{t+1},r_t\mid h_t,a_t).
$$

행동 정책 $b$ 아래에서도 초기 상태와 같은 환경 전이는 동일하다.

$$
p_b(\tau)
=d_1(s_1)
\prod_{t=1}^{H}
b(a_t\mid h_t)
P(s_{t+1},r_t\mid h_t,a_t).
$$

따라서 두 궤적 확률의 비에서는 환경 항이 소거된다.

$$
\frac{p_\pi(\tau)}{p_b(\tau)}
=\prod_{t=1}^{H}
\frac{\pi(a_t\mid h_t)}
{b(a_t\mid h_t)}
=\rho_{1:H}.
$$

이 소거는 “환경을 몰라도 정책 확률만 알면 된다”는 강력한 장점이다. 하지만 두 로그가 서로 다른 사용자 집단·도구 버전·환경 규칙에서 만들어졌다면 환경 항이 같다는 전제가 깨진다.

### 3.2 trajectory importance sampling

목표 정책의 가치는

$$
V(\pi)
=\mathbb E_{\tau\sim p_\pi}[G(\tau)],
\qquad
G(\tau)=\sum_{t=1}^{H}\gamma^{t-1}r_t
$$

이다. $p_\pi/p_b$를 곱해 행동 정책의 기댓값으로 바꾸면

$$
\begin{aligned}
V(\pi)
&=\sum_\tau p_\pi(\tau)G(\tau)\\
&=\sum_\tau p_b(\tau)
\frac{p_\pi(\tau)}{p_b(\tau)}
G(\tau)\\
&=\mathbb E_{\tau\sim p_b}
\left[\rho_{1:H}G(\tau)\right].
\end{aligned}
$$

로그 궤적 $n$개로 만든 추정치는

$$
\widehat V_{\mathrm{TIS}}
=\frac1n\sum_{i=1}^{n}
\rho_{1:H}^{(i)}G_i.
$$

지원집합과 로깅 확률이 맞으면 불편 추정량이지만, 곱셈 구조가 문제다. 로그 공간에서는

$$
\log\rho_{1:t}
=\sum_{j=1}^{t}
\left[
\log\pi(a_j\mid h_j)
-\log b(a_j\mid h_j)
\right]
$$

이므로 작은 로그확률 차이가 시간에 따라 누적된다.

예를 들어 단계별 비율의 제곱 기댓값이 단순화를 위해 서로 독립이고

$$
\mathbb E_b[w_t^2]=c>1
$$

로 같다면

$$
\mathbb E_b[\rho_{1:t}^2]
=\prod_{j=1}^{t}\mathbb E_b[w_j^2]
=c^t.
$$

두 번째 모멘트가 지수적으로 증가할 수 있다는 뜻이다. 실제 시계열에서는 비율들이 독립이 아니지만, “길수록 곱의 꼬리가 위험해진다”는 핵심은 남는다.

### 3.3 per-decision IS는 왜 맞을까?

전체 반환값을 먼저 펼치자.

$$
\widehat V_{\mathrm{TIS}}
=\frac1n\sum_i
\sum_{t=1}^{H}
\gamma^{t-1}\rho_{1:H}^{(i)}r_{i,t}.
$$

$r_t$가 결정된 뒤의 미래 행동 비율을 조건부로 평균내면 각각 기댓값이 $1$이다.

$$
\mathbb E_b
\left[
\prod_{j=t+1}^{H}
\frac{\pi(a_j\mid h_j)}
{b(a_j\mid h_j)}
\middle|
h_{t+1}
\right]
=1.
$$

따라서 시점 $t$ 보상에는 미래 비율이 필요 없다.

$$
\mathbb E_b[\rho_{1:H}r_t]
=\mathbb E_b[\rho_{1:t}r_t].
$$

이를 모든 시점에 적용하면

$$
\boxed{
\widehat V_{\mathrm{PDIS}}
=\frac1n\sum_{i=1}^{n}
\sum_{t=1}^{H}
\gamma^{t-1}
\rho_{1:t}^{(i)}r_{i,t}
}
$$

를 얻는다. 이 조건부 소거에는 미래의 모든 도달 가능한 역사에서 지원집합 조건이 필요하며, 일찍 끝난 에피소드는 이후 보상 $0$인 **absorbing state(종료 뒤 계속 머무는 가상 상태)**에 있다고 약속하면 길이를 맞출 수 있다. 올바른 조건에서는 여전히 불편하지만, 초반 보상에 미래 비율을 곱하지 않아 보통 분산이 작다. “항상 더 작다”는 보편 정리는 아니며 보상·정책·상관 구조에 따라 달라질 수 있다.

### 3.4 두 단계 손계산: 미래 비율을 버리면 무엇이 달라질까?

각 단계에서 행동 $A,B$ 중 하나를 고르고, $B$를 고르면 즉시 보상 $1$, $A$면 $0$을 받는 두 단계 문제를 보자. 이 장난감 예제에서는 두 시점의 행동을 역사와 무관하게 같은 확률로 독립 추출하며, 할인은 $\gamma=1$이다.

$$
b(A)=0.8,\quad b(B)=0.2,
\qquad
\pi(A)=0.2,\quad \pi(B)=0.8.
$$

한 단계 비율은

$$
w(A)=0.25,
\qquad
w(B)=4.
$$

가능한 네 궤적을 모두 적으면 다음과 같다.

| 궤적 | $p_b(\tau)$ | $(r_1,r_2)$ | $\rho_{1:2}$ | TIS 기여 $\rho_{1:2}(r_1+r_2)$ | PDIS 기여 $w_1r_1+\rho_{1:2}r_2$ |
| --- | ---: | ---: | ---: | ---: | ---: |
| $AA$ | $0.64$ | $(0,0)$ | $0.0625$ | $0$ | $0$ |
| $AB$ | $0.16$ | $(0,1)$ | $1$ | $1$ | $1$ |
| $BA$ | $0.16$ | $(1,0)$ | $1$ | $1$ | $4$ |
| $BB$ | $0.04$ | $(1,1)$ | $16$ | $32$ | $20$ |

목표 정책은 각 단계에서 $B$를 확률 $0.8$로 고르므로 참값은

$$
V(\pi)=0.8+0.8=1.6.
$$

두 추정 기여값의 행동 정책 아래 평균도 모두 $1.6$이다. 그러나 한 궤적 기여값의 분산은

$$
\begin{aligned}
\operatorname{Var}_b(Y_{\mathrm{TIS}})
&=38.72,\\
\operatorname{Var}_b(Y_{\mathrm{PDIS}})
&=16.16.
\end{aligned}
$$

이다. $BA$에서 첫 보상은 첫 행동 $B$가 이미 만들었다. TIS는 이후 $A$의 작은 비율까지 곱해 기여를 $1$로 줄이지만, PDIS는 첫 보상에 $w_1=4$만 적용한다. 반대로 $BB$ 같은 희귀 궤적의 영향은 여전히 크다. PDIS는 분산 문제를 완화할 뿐 제거하지 않는다.

### 3.5 시간별 ESS와 가중치 진단

각 시점의 누적 가중치로

$$
\operatorname{ESS}_t
=\frac{\left(\sum_{i=1}^{n}\rho_{1:t}^{(i)}\right)^2}
{\sum_{i=1}^{n}\left(\rho_{1:t}^{(i)}\right)^2}
$$

를 계산할 수 있다. 보통 $t$가 커질수록 목표 정책과 행동 정책의 차이가 누적되어 ESS가 감소한다.

단 하나의 최종 ESS만 보고하면 어느 시점부터 정보가 무너졌는지 알 수 없다. 다음을 함께 그려야 한다.

- $t$별 $\operatorname{ESS}_t/n$
- $t$별 최대 $\rho_{1:t}$
- 상위 $1\%$ 궤적이 추정치에서 차지하는 비율
- 행동 유형·도구·사용자 집단별 지원집합 위반
- 종료된 궤적과 살아 있는 궤적의 비율

자기정규화한 per-decision 추정량은 각 시점에서

$$
\widehat V_{\mathrm{WPDIS}}
=\sum_{t=1}^{H}\gamma^{t-1}
\frac{
\sum_{i=1}^{n}\rho_{1:t}^{(i)}r_{i,t}
}{
\sum_{i=1}^{n}\rho_{1:t}^{(i)}
}
$$

로 쓸 수 있다. 분모가 양수일 때 관측 보상의 가중평균이 되어 흔들림을 줄일 수 있지만, 유한 표본에서 일반적으로 편향되고 지원집합 문제를 해결하지 않는다.

가중치 클리핑

$$
\widetilde\rho_{1:t}
=\min(\rho_{1:t},c)
$$

도 같은 편향–분산 교환을 만든다. 특히 시점별 비율 $w_t$를 자르는 것과 누적 비율 $\rho_{1:t}$를 자르는 것은 서로 다른 추정량이다. 상한 $c$와 잘린 질량을 숨기지 말고 민감도 분석으로 공개해야 한다.

### 3.6 sequential DR: 가치 예측과 시간차 오차를 결합하기

목표 정책의 참된 행동가치와 상태가치는

$$
Q_t^\pi(h_t,a_t)
=\mathbb E_\pi
\left[
\sum_{k=t}^{H}\gamma^{k-t}r_k
\middle|
h_t,a_t
\right],
$$

$$
V_t^\pi(h_t)
=\sum_a\pi(a\mid h_t)Q_t^\pi(h_t,a)
$$

이다. 실제로는 이를 모르므로 다른 데이터 폴드에서 학습한 $\widehat Q_t$를 사용하고

$$
\widehat V_t(h_t)
=\sum_a\pi(a\mid h_t)\widehat Q_t(h_t,a),
\qquad
\widehat V_{H+1}=0
$$

로 둔다. 열린 텍스트 행동 공간에서는 모든 $a$를 합할 수 없으므로 목표 정책 표본을 이용한 Monte Carlo 근사가 필요할 수 있다.

한 단계의 예측 오차인 TD 잔차는

$$
\delta_t
=r_t+\gamma\widehat V_{t+1}(h_{t+1})
-\widehat Q_t(h_t,a_t)
$$

이다. sequential DR 추정량은

$$
\boxed{
\widehat V_{\mathrm{SDR}}
=\frac1n\sum_{i=1}^{n}
\left[
\widehat V_1(h_{i,1})
+\sum_{t=1}^{H}
\gamma^{t-1}
\widehat\rho_{1:t}^{(i)}
\delta_{i,t}
\right]
}
$$

이다. 첫 항은 가치 모델이 예측한 목표 정책의 출발점이고, 합은 실제 로그가 알려 준 시간별 예측 오류를 보정한다. $H=1$이면 지난 시간의 contextual-bandit DR과 같은 구조가 된다.

왜 이중 강건한지 두 경우로 나누어 보자. 보조 모델은 현재 평가 궤적과 독립인 데이터에서 학습했거나 교차 적합했다고 가정한다.

**경우 A: 로깅 확률 모델이 정확하다.**

$\widehat b=b$이면 누적 비율이 각 prefix의 분포를 행동 정책에서 목표 정책으로 바꾼다.

$$
\mathbb E_b
\left[
\rho_{1:t}f(h_t,a_t,r_t,h_{t+1})
\right]
=\mathbb E_\pi[f(h_t,a_t,r_t,h_{t+1})].
$$

따라서 SDR의 기댓값은

$$
\mathbb E[\widehat V_1]
+\sum_{t=1}^{H}\gamma^{t-1}
\mathbb E_\pi
\left[
r_t+\gamma\widehat V_{t+1}-\widehat Q_t
\right].
$$

$\mathbb E_{\pi}[\widehat Q_t\mid h_t]=\widehat V_t(h_t)$를 이용하면 $\widehat V_t$ 항들이 망원경처럼 상쇄되어 $V(\pi)$만 남는다. 가치 모델이 틀려도 확률비가 오류를 교정한다.

**경우 B: 가치 모델이 정확하다.**

$\widehat Q_t=Q_t^\pi$이면 Bellman 방정식으로

$$
\mathbb E
\left[
r_t+\gamma V_{t+1}^\pi(h_{t+1})
-Q_t^\pi(h_t,a_t)
\middle|
h_t,a_t
\right]
=0.
$$

따라서 현재 결과를 보기 전에 정해지고 $(h_t,a_t)$만으로 계산되는 유한한 가중치 $\widehat\rho_{1:t}$라면 각 잔차 항의 조건부 평균은 $0$이고, 출발값 $\mathbb E[V_1^\pi(h_1)]$가 참값을 준다. 가중치나 가치 모델이 같은 궤적의 $r_t,h_{t+1}$를 보고 과적합되지 않도록 별도 데이터 또는 교차 적합이 필요하다.

그러나 두 모델이 모두 틀리거나, 가치 모델이 평가 데이터를 외우거나, 숨은 상태 때문에 순차적 무교란성이 깨지거나, 지원집합이 끊기면 이중 강건성의 보장이 사라진다. “두 모델 중 하나만 대충 괜찮으면 된다”가 아니라 **정확성 조건 중 하나가 성립할 때 일관성 또는 불편성을 얻는 구조**다.

### 3.7 최종 보상만 있을 때의 한계

중간 보상이 모두 $0$이고 마지막에만 $r_H$가 있다면

$$
\widehat V_{\mathrm{PDIS}}
=\frac1n\sum_i
\gamma^{H-1}\rho_{1:H}^{(i)}r_{i,H}.
$$

즉 trajectory IS와 사실상 같은 긴 비율을 사용한다. sequential DR은 잘 맞는 $Q$ 모델이 있으면 도움을 줄 수 있지만, 그 모델이 관측하지 못한 행동으로 외삽한 값은 로그가 검증해 주지 못한다.

에이전트 시스템에서는 보상을 억지로 잘게 쪼개면 보상 해킹이 생길 수 있다. 원래 반환값 $G$를 그대로 평가하려면 재분배한 보상 $\widetilde r_t$가 모든 궤적에서

$$
\sum_{t=1}^{H}\gamma^{t-1}\widetilde r_t=G
$$

를 보존해야 한다. 모든 정책에 공통인 알려진 경계 상수만 차이 난다면 그 상수를 다시 보정할 수 있다. 정책 순서만 보존하는 shaping은 좋은 정책을 찾는 데는 유용하지만 원래 $G$의 수치, 개선량 $\Delta$, 최소 개선폭 $\delta_{\min}$을 보존하지는 않는다. 이런 경우 shaped return은 별도 목표로 명시한다. 원래 목표를 보존하는 재분배 아래에서 좋은 중간 신호는 “모델이 그럴듯하게 말했다”가 아니라 다음처럼 환경이 확인할 수 있는 사건이어야 한다.

- 검색한 문서가 요구한 식별자를 실제로 포함한다.
- 도구 호출 인수의 스키마와 권한 검사가 통과한다.
- 파일을 쓴 뒤 다시 읽어 기대한 해시 또는 내용이 확인된다.
- 결제·환불 상태가 외부 시스템에서 목표 상태로 바뀐다.
- 안전 제약을 위반하지 않고 종료 조건을 만족한다.

### 3.8 개선량의 신뢰 하한

후보 정책 $\pi$와 기준 정책 $\pi_0$를 같은 로그에서 평가하면, 각 궤적의 OPE 기여값을 각각 $D_i(\pi)$와 $D_i(\pi_0)$라 쓰고 **짝지은 차이**

$$
Z_i=D_i(\pi)-D_i(\pi_0)
$$

를 만든다. 개선량 추정치와 표준오차는

$$
\widehat\Delta
=\frac1n\sum_{i=1}^{n}Z_i,
$$

$$
s_Z^2
=\frac1{n-1}
\sum_{i=1}^{n}
\left(Z_i-\widehat\Delta\right)^2,
\qquad
\widehat{\operatorname{SE}}(\widehat\Delta)
=\frac{s_Z}{\sqrt n}
$$

이다. 같은 궤적에서 두 정책의 기여를 빼면 공통 변동이 상쇄되어 두 값을 독립적으로 비교하는 것보다 효율적일 수 있다. 이 단순한 $s_Z/\sqrt n$ 식은 $D_i$가 에피소드별로 더해지는 점수이고, 보조 모델이 고정됐거나 교차 적합됐으며, 에피소드가 독립에 가까울 때 바로 적용된다. WPDIS처럼 모든 표본이 하나의 무작위 분모를 공유하거나, 같은 로그로 보조 모델·클리핑 상한·후보를 적응적으로 골랐다면 delta method·영향함수 또는 선택과 학습을 포함한 전체 파이프라인 bootstrap이 필요하다.

큰 표본·유한 분산·독립성·사전 고정된 후보라는 조건에서 한쪽 $100(1-\alpha)\%$ Wald 하한은

$$
\operatorname{LCB}_{1-\alpha}
=\widehat\Delta
-z_{1-\alpha}
\widehat{\operatorname{SE}}(\widehat\Delta)
$$

이다. 한쪽 $95\%$ 하한은 $z_{0.95}\approx1.645$를 쓴다. 양쪽 $95\%$ 구간의 $1.96$과 구분해야 한다.

예를 들어

$$
\widehat\Delta=0.060,
\qquad
\widehat{\operatorname{SE}}=0.025
$$

이면

$$
\operatorname{LCB}_{0.95}
=0.060-1.645(0.025)
\approx0.0189.
$$

최소 실용 개선폭을 $\delta_{\min}=0.01$로 미리 정했다면 이 근사 하한은 기준을 넘는다. 반대로 평균 개선이 $0.04$여도 표준오차가 $0.03$이면

$$
0.04-1.645(0.03)\approx-0.0094
$$

이므로 “나쁨이 증명됐다”가 아니라 **안전한 개선을 주장할 증거가 부족하다**고 판단한다.

극단 가중치, 작은 ESS, 사용자별 반복 로그, 시간 의존성이 있으면 단순 Wald 구간은 낙관적일 수 있다. 이때는 사용자·세션 단위 cluster bootstrap, 시간 블록 bootstrap, 가중치를 명시적으로 제한한 농도부등식, 또는 별도의 온라인 canary 실험이 필요하다. 어떤 구간도 잘못된 보상 정의·숨은 혼란 변수·환경 변화까지 자동으로 포함하지 않는다.

### 3.9 안전한 정책 개선 규칙

가장 단순한 배포 게이트는

$$
\operatorname{LCB}_{1-\alpha}
\left(
V(\pi)-V(\pi_0)
\right)
\ge\delta_{\min}
$$

일 때만 후보를 통과시키는 것이다. 안전 비용 $C_k$도 있다면 각 비용의 상한을 함께 제한한다.

$$
\operatorname{UCB}_{1-\alpha_k}
\left(
C_k(\pi)-C_k(\pi_0)
\right)
\le\eta_k.
$$

여러 안전 비용과 품질 개선을 동시에 보장하려면 전체 실패확률 $\alpha$를 품질 LCB와 각 비용 UCB에 나누어 배정해야 한다. 후보 $K$개를 같은 로그에서 시험한 뒤 가장 좋아 보이는 하나를 고르면 다중 비교와 선택 편향도 생긴다. 안전하게 하려면 다음 중 하나가 필요하다.

- 탐색용 로그와 최종 게이트용 로그를 분리한다.
- 후보 선택까지 포함한 전체 절차를 bootstrap한다.
- Bonferroni처럼 $\alpha/K$로 보수적으로 보정한다.
- 정책을 미리 등록하고 단 하나의 확인 검정을 수행한다.

기준 정책과 후보를 섞은 보수적 정책도 사용할 수 있다.

$$
\pi_\lambda
=(1-\lambda)\pi_0+\lambda\pi,
\qquad
0\le\lambda\le1.
$$

$\lambda=0$은 기존 정책, $\lambda=1$은 후보 정책이다. 이미 $\pi,\pi_0\ll b$라는 지원집합 조건이 성립한다면 작은 $\lambda$부터 LCB와 안전 비용 UCB를 확인해 확률비의 극단성을 줄이며 점진적으로 개선할 수 있다. 특히 $b=\pi_0$인 지원 영역에서는

$$
\frac{\pi_\lambda(a\mid h)}{b(a\mid h)}
=(1-\lambda)
+\lambda\frac{\pi(a\mid h)}{b(a\mid h)}.
$$

그러나 $b(a\mid h)=0$인데 후보 $\pi(a\mid h)>0$인 행동은 어떤 $\lambda>0$에서도 $\pi_\lambda(a\mid h)>0$이므로 혼합으로 지원집합 위반을 복구할 수 없다. 그 행동을 후보에서 제한하거나 안전한 탐색으로 새 로그를 수집해야 한다. 정책 혼합도 OPE 가정이 맞을 때의 통계적 절차이지, 실제 배포에서의 완전한 안전 보증은 아니다.

### 4.1 다중 턴 LLM/VLM 에이전트를 순차 의사결정으로 보기

LLM 에이전트의 한 시점을 다음처럼 매핑할 수 있다.

| 순차 의사결정 요소 | LLM/VLM 에이전트의 실제 항목 |
| --- | --- |
| 역사 $h_t$ | system prompt(모델의 행동 규칙을 담은 최상위 지시문), 사용자 대화, 이전 사고·행동, 화면 이미지, 도구 결과 |
| 행동 $a_t$ | 검색 질의, 함수 호출, 클릭 좌표, 코드 실행, 사용자에게 보낼 답변 |
| 전이 | 도구·웹사이트·운영체제·사용자가 행동에 반응해 다음 상태를 만든다 |
| 보상 $r_t$ | 실행 성공, 검증 통과, 비용, 지연, 안전 위반, 최종 과제 성공 |
| 종료 | 성공, 실패, 시간 초과, 사용자가 중단, 최대 턴 도달 |
| 정책 확률 | 그 역사에서 실제 행동 문자열 또는 구조화된 호출을 생성할 확률 |

핵심은 상태가 “마지막 사용자 문장”만이 아니라는 점이다. 예를 들어 검색 결과가 로그에서 빠졌다면 같은 대화 텍스트 아래에서도 행동 선택과 성공 결과를 동시에 좌우하는 숨은 변수가 생긴다. 순차적 무교란성은 모델 구조가 아니라 **로깅 스키마**가 지켜 주어야 한다.

### 4.2 행동 확률은 모델의 raw Softmax만이 아니다

**Softmax**는 모델의 원시 점수(logit)를 합이 $1$인 토큰 확률로 바꾸는 함수다. raw Softmax는 후처리 전의 원래 확률을 뜻한다.

도구 호출 $a_t$를 **실제로 생성된 정확한 토큰 경로** $(y_{t,1},\ldots,y_{t,L_t})$ 자체로 정의하고, 후처리가 없다면

$$
P_b(Y_{1:L}=y_{1:L},T=L\mid h_t)
=
\left[
\prod_{\ell=1}^{L}
\widetilde b(y_\ell\mid h_t,y_{<\ell})
\right]
P_b(T=L\mid h_t,y_{\le L})
$$

로 계산한다. $\widetilde b$는 temperature·top-$k/p$·mask 뒤에 실제로 재정규화된 sampler 분포이고, $T=L$은 그 길이에서 EOS·stop 조건으로 종료되는 사건이다. 반면 $a_t$를 “파싱된 동일한 함수 호출”이라는 의미 단위로 정의하고 $F$가 토큰열을 호출로 바꾸는 파서라면

$$
b(a_t\mid h_t)
=\sum_{y:F(y)=a_t}
P_b(Y=y,\text{ stop/accept}\mid h_t)
$$

처럼 같은 호출로 이어지는 모든 직렬화·종료·거절·재시도·후보 선택 경로의 확률을 합해야 한다. 실제 최종 행동 확률에는 다음이 모두 들어갈 수 있다.

- temperature·top-$k$·top-$p$로 바뀐 샘플링 분포
- JSON 문법 또는 함수 스키마 제약
- 금지 도구·권한 정책에 의한 마스킹
- 여러 후보 생성 뒤 reranker(후보 순위기)가 고르는 절차
- 안전 필터의 거절과 재시도
- timeout·파서 오류 뒤 fallback(대체 경로) 정책
- “종료” 행동과 최대 토큰 절단

raw 모델 log-probability만 기록하고 최종 노출 절차를 빠뜨리면 $b$가 틀린다. greedy·beam search는 raw Softmax가 아니라 선택된 경로에 질량이 집중된 정책이고, top-$k/p$는 잘린 토큰에 정확히 확률 $0$을 주어 지원집합을 끊을 수 있다. 또한 토큰 확률의 곱을 행동 단위로 만들고 다시 턴별로 곱하면 너무 작은 수가 컴퓨터에서 $0$처럼 되는 **수치 언더플로**가 생기므로, 구현에서는 로그 비율을 합산하고 진단 시점에만 안전하게 변환한다.

### 4.3 전체 파이프라인

~~~text
1. 평가 목표와 안전 비용을 먼저 고정
   ↓
2. 기준 정책의 실제 행동 확률·상태·도구 결과·종료 이유를 기록
   ↓
3. 사용자/세션/시간 단위로 train·selection·final-gate 로그 분리
   ↓
4. 다른 폴드에서 Q̂, V̂ 보조 모델 학습
   ↓
5. 후보 정책의 동일 행동 확률 계산
   ↓
6. 시점별 ρ, ESS, 최대 가중치, 지원집합 위반 진단
   ↓
7. TIS·PDIS·WPDIS·sequential DR을 함께 계산
   ↓
8. 짝지은 개선량과 cluster-aware LCB/UCB 계산
   ↓
9. 통과 후보만 shadow(결과만 계산하고 사용자에게 적용하지 않음)와 canary(소량 트래픽 시험)
   ↓
10. 온라인 결과가 확인되면 점진적으로 트래픽 확대
~~~

OPE 추정량끼리 크게 다르면 가장 좋은 숫자를 고르지 않는다. 차이는 지원집합 부족, 가치 모델 외삽, 클리핑 편향, 잘못된 propensity, 최종 보상 집중 중 하나를 알려 주는 진단 신호다.

| “후보 100개 중 LCB가 양수인 하나를 고르면 된다.” | 같은 로그를 반복 탐색하면 우연한 승자를 고른다. 선택용·확인용 데이터를 분리하거나 다중 비교를 보정해야 한다. |

| “오프라인 통과는 온라인 실험을 대체한다.” | OPE는 위험한 후보를 거르는 단계다. 제한적 canary와 모니터링이 마지막 확인이다. |

### 4.6 엔지니어의 최소 감사 체크리스트

1. 에피소드 시작·종료·timeout·재시도 규칙을 버전과 함께 고정한다.
2. 상태에는 모델이 실제로 본 텍스트·이미지·도구 결과와 정책 버전을 남긴다.
3. 실제 sampler와 모든 직렬화·종료·필터·재시도·reranking 경로를 기록해 최종 행동의 주변 propensity를 재구성할 수 있게 한다.
4. 목표 정책이 양의 확률을 주지만 행동 정책은 $0$인 영역을 별도 보고한다.
5. $t$별 ESS, 최대 누적 비율, 상위 기여 궤적과 종료 생존률을 시각화한다.
6. 가치 모델과 propensity 모델은 사용자·시간 단위 교차 적합으로 평가 로그와 분리한다.
7. TIS·PDIS·WPDIS·SDR, 여러 클리핑 상한의 민감도를 함께 본다.
8. 평균 품질뿐 아니라 실패 비용·지연·토큰·권한 위반을 별도 제약으로 둔다.
9. 여러 후보를 탐색한 데이터와 최종 배포 게이트 데이터를 분리한다.
10. LCB 통과 뒤에도 shadow → 작은 canary → 점진 확대 순서와 즉시 rollback(이전 버전 복귀) 기준을 둔다.

## 5. 💡 오늘의 AI 트렌드 & 오픈소스 (Must-Read)

### 5.1 MintAct: VLM 에이전트의 핵심 병목이 “모델 하나”에서 “순차 RL 시스템”으로 이동하다

[MintAct 사전논문(arXiv v1, 2026-09-18 UTC)](https://arxiv.org/abs/2609.22083)은 Apple 연구진이 발표한 $2$B·$4$B·$8$B 비전-언어 에이전트 계열이다. 한 모델이 raw screenshot을 보고 UI grounding, Android·desktop·web의 다단계 탐색, 시각 정보에 근거한 구조화 도구 호출을 수행한다. 각 도메인의 행동 집합을 무작정 합치지 않고 **system prompt(도메인별 규칙을 담은 최상위 지시문)**로 구분하며, 모바일·데스크톱·웹 UI 좌표를 공통 $999\times999$ 공간으로 정규화하고 도메인별 학습 비율을 명시적으로 제어한다. 시각 도구 사용은 좌표가 아니라 구조화된 함수 호출을 쓴다.

학습은 고해상도 단일 단계 **SFT(supervised fine-tuning, 정답 행동을 모방하는 지도 미세조정)**, 저해상도 다단계 SFT, 도메인별 **강화학습(RL)** 전문가의 성공 궤적만 골라 다시 학습하는 **RFT(rejection-sampled fine-tuning)**, mobile·desktop 공동 **asynchronous RL(환경 실행과 모델 학습을 병렬로 겹치는 강화학습)** 순서다. desktop은 $200$개 초과, mobile은 $100$개 초과 환경 인스턴스를 병렬로 운영한다. 느린 환경이 섞인 비동기 학습에서는 rollout(환경에서 궤적을 생성하는 과정) 정책이 낡는 **staleness gap**과 inference engine·trainer 수치가 다른 **engine gap**을 분리한다. 전자는 제한된 queue·주기적 parameter sync(학습기 가중치를 생성 서버에 복사)·정책 확률비의 변화를 자르는 **PPO 계열 clipping**으로, 후자는 실제 생성 정책과 trainer 재계산 정책 사이의 token-level truncated importance ratio로 다룬다. 논문 설정의 상한은 $C=2$다.

저자 보고 MintAct-8B는 초기 Qwen3-VL-8B 대비 AndroidWorld $47.6\rightarrow67.0$, OSWorld-Verified $33.9\rightarrow48.9$, Weblica $55.5\rightarrow74.7$, MM-ToolSandBox $3.1\rightarrow24.5$로 올랐다. 공동 RL은 mobile·desktop만 사용했으며, RFT 이후 OSWorld-Verified는 $43.1\rightarrow48.9$로 올랐지만 AndroidWorld는 $68.1\rightarrow67.0$으로 $1.1$점 낮아졌다. “모든 도메인이 동시에 단조 개선됐다”는 결과는 아니다.

**엔지니어 인사이트 (Impact):** 오늘 배운 중요도비와 같은 확률비 아이디어가 실제 asynchronous VLM RL에도 쓰인다. 다만 MintAct가 사용하는 것은 궤적 prefix의 누적비 $\rho_{1:t}$가 아니라, 실제 생성 엔진과 trainer 재계산 분포 사이의 **토큰별** 비율 $\pi_{\mathrm{prox}}/\pi_{\mathrm{roll}}$을 $C=2$로 자른 학습용 가중치다. 따라서 배포 전 정책 가치를 추정하는 PDIS와는 목적·형태가 모두 다르다. 또 최종 joint RL이 네 도메인을 모두 직접 학습한 것은 아니며, 논문 공개 시점 기준 arXiv 페이지에는 모델 가중치·학습 코드·전체 데이터의 공개 링크가 제시되지 않았다. 논문 수치와 재현 가능한 오픈소스 릴리스를 구분해 읽어야 한다.

### 5.2 생산 LLM 에이전트 평가는 “전체 벤치마크 매번 실행”에서 “정보가 큰 항목을 반복 측정”으로 이동하다

[Efficient Benchmarking in Production 사전논문(arXiv v1, 2026-09-18 UTC)](https://arxiv.org/abs/2609.21267)은 수만 명의 월간 사용자를 둔 production analytics agent의 반복 평가 비용을 줄이는 문제를 다룬다. 전체 $519$문항 중 유효 결과가 적어도 $80\%$ 있는 실행만 보존해, $52$일 동안의 $574$회 benchmark run을 시간순으로 $287$개 **calibration run(평가법을 맞추는 과거 실행)**과 $287$개 **held-out run(맞추는 데 쓰지 않은 검증 실행)**으로 나눴다. 무작위 표집, 과거 결과 caching, 난이도 층화 고정 subset, **IRT(item response theory, 문항 난이도와 시스템 능력으로 통과 확률을 설명하는 모형)** 기반 adaptive testing을 비교했다.

저자 보고 **multidimensional 2PL**은 여러 능력 축과 문항별 난이도·구분도를 쓰는 2-parameter logistic IRT 모형이며, 이를 이용한 adaptive testing은 $200$문항, 즉 전체의 $38.5\%$를 실행했을 때 held-out run의 유효 문항 기준 reference pass rate 대비 $1.03$%p **MAE(mean absolute error, 절대 오차 평균)**를 얻었다. 그러나 실제 production workflow에는 더 복잡한 adaptive 방식이 아니라, 실행 전에 문항이 고정되고 병렬화·문항별 성능 하락 진단이 쉬운 **난이도 층화 고정 subset**을 배포했다. 원래 에이전트에서 고른 subset과 **Rasch(능력을 한 축, 문항을 난이도 하나로 나타내는 IRT)·gp-IRT parameter**를 그대로, 서로 다른 agent framework·**실행 harness(모델·도구·채점기를 묶는 실행 껍질)**·tool·model 구성을 가진 다섯 agent family의 $299$개 run에 적용했다. 가중 subset 점수와 IRT의 미관측 문항 복원을 섞는 **gp-IRT 추정**은 이 run들을 합친 **pooled(통합) 기준**으로 $12$개 예산 중 $11$개에서 무작위 표집보다 낮은 MAE를 보였지만, family별 이득은 일정하지 않았다.

이 결과는 “$38.5\%$만 실행하면 어떤 에이전트든 충분하다”는 일반 법칙이 아니다. 데이터는 한 조직·한 내부 benchmark에서 왔고, transfer 검증은 고정 subset에만 적용됐다. 논문도 MAE와 순위 상관은 측정했지만 실제 release threshold에서 놓친 regression(성능 하락)·false alarm(문제가 없는데 막은 경우)·full benchmark와의 의사결정 일치는 직접 평가하지 않았다고 밝힌다. benchmark 문항, 문항별 결과 행렬, 구현도 공개하지 않았다.

**엔지니어 인사이트 (Impact):** 오늘의 LCB와 이 연구의 benchmark subset은 같은 질문의 두 층이다. 먼저 어떤 궤적·문항을 얼마만큼 실행할지 계산 예산을 배분하고, 그다음 그 불완전한 관측으로 얻은 개선량의 불확실성을 배포 게이트에 반영해야 한다. 점수 MAE가 작다는 사실만으로 안전한 release decision이 보장되지는 않는다. 실제 팀에서는 고정 regression subset으로 빠르게 반복하되, 주기적인 full run과 보수적 개선량 하한으로 subset drift와 우연한 승자를 함께 감시하는 구조가 현실적이다.

## 6. 오늘의 메타인지 질문 (스스로 묻고 답하기)

**질문:** 과거 정책으로 모은 $50{,}000$개 에이전트 궤적에서 후보 정책의 sequential DR 평균이 기준보다 $3$%p 높고 한쪽 $95\%$ LCB도 $+0.5$%p라면 바로 전체 배포해도 될까? 최소한 무엇을 추가로 확인해야 하는가?

**모범 답안:** 바로 전체 배포하면 안 된다. 먼저 시점별 ESS와 최대 누적 비율을 확인해 $50{,}000$개가 후반 턴에서 소수 궤적에 의존하지 않는지 본다. 후보가 고르지만 과거 정책은 전혀 고르지 않은 행동이 있는지, 실제 sampler·필터·reranker를 포함한 propensity가 기록됐는지 확인한다. 가치 모델은 사용자·시간 단위 교차 적합을 했는지, 관측 밖 행동에 낙관적으로 외삽하지 않는지 감사한다. 후보를 같은 로그에서 여러 개 시험해 골랐다면 선택 편향을 보정하거나 별도의 final-gate 로그에서 LCB를 다시 계산해야 한다. 품질 개선과 별도로 안전 위반·비용·지연의 UCB가 한도를 넘지 않는지 보고, 환경·사용자 분포 변화와 보상 정의의 타당성도 점검한다. 모든 조건을 통과해도 shadow와 소규모 canary에서 실제 온라인 결과를 확인한 뒤 점진적으로 확대한다.
