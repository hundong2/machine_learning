# [2026-09-30] 오늘 학습: 계층적 랜덤효과·사후예측검사 & 상관 판정자·가중 Conformal 재검량

> **오늘의 핵심 문장:** 같은 기반 모델을 쓰는 판정자 셋의 일치는 독립된 세 표가 아니다. 공유 오류를 계층적으로 모델링하고 실제와 모형이 만든 가상 데이터를 비교한 뒤, 배포 입력의 구성이 바뀌면 그 변화만큼 검량 표본을 다시 가중해야 한다.

지난 시간에는 반복 판정자의 숨은 정답을 잠재계층 모형과 EM으로 추정하고, detector drift를 변화점 검정으로 감시하며, 확정 감사 라벨로 Conformal Risk Control을 수행했다. 그 출발점에는 두 가지 강한 가정이 있었다.

1. 실제 상태 $Y_i$를 알면 판정자들의 오류는 서로 독립이다.
2. 검량 데이터와 앞으로 들어올 요청은 교환가능하다.

현실에서는 둘 다 쉽게 깨진다. 같은 계열 LLM judge들은 같은 사전학습 데이터, 안전 튜닝, 프롬프트, 검색 결과를 공유해 함께 틀린다. 또 배포 뒤 한국어·모바일 화면·희귀 도구 호출의 비중이 바뀌면 검량 데이터의 쉬운 사례가 미래 트래픽을 대표하지 못한다.

오늘은 이 두 문제를 연결한다.

- **상관된 판정자:** 항목 난이도와 judge 계열별 공유 랜덤효과를 넣어 “함께 틀림”을 표현한다.
- **모형 점검:** posterior predictive check로 모형이 실제 합치율·이중 오류·난이도 패턴을 재현하는지 확인한다.
- **입력 분포 변화:** 배포/검량 밀도비로 conformal 점수를 가중해 새 트래픽에 맞춘다.
- **운영 안전:** 가중치 폭주, 조건부 분포 변화, 지연 라벨이 생기면 자동화를 확대하지 않고 재검량 상태로 전환한다.

> **난이도 표지:** 출발점은 로지스틱 함수와 조건부확률이다. 계층모형, 베이지안 사후분포, 사후예측검사, 밀도비, 가중 분위수까지 진행하지만 모든 수식은 “여러 LLM judge로 에이전트 안전 여부를 판정하고 새 배포 트래픽에서 자동 통과 임계값을 정한다”는 하나의 사례에 묶는다.

## 1. 지식의 씨앗: 이 개념들은 왜 탄생했을까?

### 1.1 왜 판정자 수가 곧 증거의 수가 아닐까?

서로 다른 이름의 LLM judge 세 개가 모두 “안전”이라고 답했다고 하자. 겉으로는 세 명이 독립적으로 동의한 것처럼 보인다. 그러나 세 judge가 같은 기반 모델의 미세조정 버전이고 같은 시스템 프롬프트를 사용했다면 다음 오류가 공유될 수 있다.

- 한국어 부정 표현을 같은 방식으로 놓친다.
- 이미지 속 작은 경고 문구를 모두 읽지 못한다.
- 특정 문체를 안전하다고 과신한다.
- 같은 검색 결과의 잘못된 사실을 함께 따른다.
- 프롬프트의 선택지 순서에 비슷하게 끌린다.

동전을 세 번 독립적으로 던진 것과 같은 동전을 사진 복사해 세 장 놓은 것은 다르다. 후자는 표의 개수는 셋이지만 새로운 정보는 거의 하나다. 전날의 Dawid–Skene형 조건부 독립 모형은 이런 공유 원인을 표현하지 못해 사후확률을 지나치게 $0$이나 $1$에 붙일 수 있다.

### 1.2 왜 “어려운 항목”을 별도 변수로 두어야 할까?

판정자 정확도만 추정하면 모든 항목이 같은 난이도라고 암묵적으로 가정한다. 하지만 실제 요청은 다르다.

- 명백한 비밀번호 유출은 거의 모든 judge가 잡는다.
- 완곡한 표현으로 숨긴 권한 상승은 많은 judge가 놓친다.
- 화면이 흐리거나 도구 결과가 길면 모든 judge가 어려워한다.
- 특정 judge 계열만 잘 아는 코드 문법도 있다.

시험에서 학생 실력과 문제 난이도를 분리하듯, 판정에서도 **판정자 능력**과 **항목 난이도**를 분리해야 한다. 그래야 어려운 항목에서 모두 틀린 것을 판정자 전체의 영구적 성능 저하로 오해하지 않는다.

### 1.3 왜 적합도 점수 하나로는 부족할까?

복잡한 계층모형은 거의 언제나 데이터에 어느 정도 맞는다. 로그가능도나 학습 손실이 낮다는 사실만으로 “우리가 걱정하는 패턴”까지 맞는지는 알 수 없다.

예를 들어 전체 정확도는 맞아도 다음은 틀릴 수 있다.

- 같은 계열 judge 둘이 동시에 틀리는 비율
- 희귀 양성에서의 거짓 음성률
- 긴 trajectory에서 후반부 오류가 늘어나는 정도
- 특정 언어에서 만장일치가 과도하게 나타나는 현상

**Posterior predictive check**, 줄여서 PPC는 적합된 모형으로 가상 데이터를 여러 번 만들고, 실제 데이터의 중요한 요약통계와 비교한다. 모형이 현실의 복사기를 자처한다면 현실에서 보인 특징도 복사할 수 있어야 한다는 생각이다.

### 1.4 왜 과거 검량 표본을 그대로 쓸 수 없을까?

검량 표본에 데스크톱 영어 요청이 많고 실제 배포에는 모바일 한국어 요청이 많다면, 단순 평균은 배포 위험을 잘못 나타낸다. 배포에서 자주 나타나는 유형에 더 큰 무게를 주고 드문 유형에는 작은 무게를 주어야 한다.

검량 분포를 $P_{\mathrm{cal}}$, 배포 분포를 $P_{\mathrm{dep}}$라 하자. 입력 $x$의 중요도 가중치는

$$
w(x)
=
\frac{p_{\mathrm{dep}}(x)}
{p_{\mathrm{cal}}(x)}
$$

다. 배포에서 검량보다 세 배 자주 나타나는 입력은 대략 세 배의 대표성을 갖는다. 이것은 9월 18일부터 배운 중요도 가중을 conformal 검량에 적용한 것이다.

### 1.5 무엇까지 고칠 수 있고 무엇은 못 고칠까?

밀도비 가중이 고칠 수 있는 것은 **covariate shift**, 즉 입력 $X$의 비율은 바뀌지만 같은 입력에서 결과가 생기는 규칙은 유지되는 경우다.

$$
P_{\mathrm{dep}}(X)\neq P_{\mathrm{cal}}(X),
\qquad
P_{\mathrm{dep}}(Y\mid X)
=
P_{\mathrm{cal}}(Y\mid X).
$$

반면 모델 버전, 공격 전략, 정책 정의가 바뀌어

$$
P_{\mathrm{dep}}(Y\mid X)
\neq
P_{\mathrm{cal}}(Y\mid X)
$$

가 되면 **concept shift**다. 이때는 오래된 라벨을 재가중하는 것만으로 새 조건부 오류를 만들 수 없다. 새 구간의 확정 라벨이 필요하다.

### 1.6 역사적 흐름

1. **항목반응이론(IRT):** 시험 문항 난이도와 응답자 능력을 분리해 정답 확률을 모델링했다.
2. **일반화 선형 혼합모형(GLMM):** 로지스틱 회귀에 집단별 랜덤효과를 넣어 반복 측정과 군집 상관을 표현했다.
3. **베이지안 계층모형:** 적은 표본의 집단을 전체 평균 쪽으로 부분 풀링하고 모수 불확실성을 사후분포로 보존했다.
4. **Posterior predictive checking:** 적합된 확률모형이 실제 데이터의 중요한 패턴을 생성할 수 있는지 점검하는 모형 비판 도구가 되었다.
5. **중요도 가중:** 한 분포에서 얻은 표본으로 다른 분포의 기댓값을 계산하는 도구로 발전했다.
6. **가중 conformal:** covariate shift 아래에서 새 테스트 입력의 대표성을 반영하도록 conformal 순위와 분위수를 가중했다.
7. **AI 운영:** 상관된 LLM judge와 변하는 배포 트래픽을 동시에 다루기 위해 모형 점검, shift 감지, 재검량, 보류 정책을 한 파이프라인으로 결합한다.

## 2. 친절한 용어 사전

| 기호·용어 | 초보자를 위한 뜻 | 오늘의 역할 |
| --- | --- | --- |
| $i=1,\ldots,n$ | 평가할 항목 번호 | 응답 하나, 도구 호출 하나, 또는 agent trajectory 하나다. |
| $r=1,\ldots,R$ | 판정자 번호 | 사람, LLM judge, 규칙 detector를 뜻한다. |
| $g(r)$ | 판정자 $r$이 속한 계열 | 같은 기반 모델·프롬프트·제공자를 공유하는 judge 묶음이다. |

| $C_{ir}$ | 정답 지시자 $\mathbf 1\{A_{ir}=Y_i\}$ | 판정이 실제 상태와 같으면 $1$이다. |
| $\mathbf 1\{\cdot\}$ | 괄호 안이 참이면 $1$, 거짓이면 $0$인 함수 | 사건을 숫자로 세게 해 준다. |
| $\sigma(z)$ | 로지스틱 함수 $1/(1+e^{-z})$ | 모든 실수를 $0$과 $1$ 사이 확률로 바꾼다. |
| logit | 확률 $p$를 $\log\frac{p}{1-p}$로 바꾸는 함수 | 확률의 여러 원인을 덧셈 형태로 분해한다. |
| $\alpha_r$ | 판정자 $r$의 기본 능력 | 클수록 평균적인 항목을 맞힐 로그오즈가 높다. |
| $\beta_r$ | 실제 계층에 따른 능력 차이 | 양성 탐지와 음성 판별의 비대칭을 표현한다. |
| $d_i$ | 항목 $i$의 난이도 | 클수록 모든 판정자가 맞히기 어렵다. |
| $u_{ig}$ | 항목 $i$에서 계열 $g$가 공유하는 랜덤효과 | 같은 계열 judge들이 함께 잘하거나 함께 틀리는 원인을 담는다. |
| random effect | 집단별 숨은 차이를 공통 분포에서 나온 변수로 보는 효과 | 단순한 무작위 잡음이 아니라 반복되는 군집 구조다. |
| fixed effect | 각 판정자처럼 관심 대상을 개별 모수로 추정하는 효과 | $\alpha_r,\beta_r$가 여기에 해당한다. |
| $\sigma_d^2$ | 항목 난이도의 분산 | 항목 간 난이도가 얼마나 다른지 나타낸다. |
| $\tau_g^2$ | 계열 공유효과의 분산 | 클수록 같은 계열 내부의 상관 오류가 강하다. |
| 계층모형 | 개별 모수를 상위 공통 분포에 연결한 모형 | 적은 표본의 judge 계열을 전체 정보로 안정화한다. |
| partial pooling | 집단별 정보와 전체 평균을 절충하는 추정 | 표본이 적은 집단일수록 평균 쪽으로 더 수축한다. |
| shrinkage | 불안정한 극단값을 상위 평균 쪽으로 당기는 현상 | 작은 집단의 정확도 $0\%$나 $100\%$ 과신을 줄인다. |
| prior | 데이터를 보기 전 모수에 둔 분포 | 가능한 효과 크기를 규제한다. |
| likelihood | 모수가 관측 데이터를 얼마나 그럴듯하게 만드는지 나타내는 함수 | 판정 패턴을 설명한다. |
| posterior | 데이터 관측 뒤 갱신된 모수·잠재변수의 분포 | 하나의 점이 아니라 불확실성 전체를 보존한다. |
| posterior predictive distribution | 사후분포에서 모수를 뽑고 새 데이터를 생성한 분포 | “적합된 모형이라면 어떤 데이터가 나와야 하는가?”를 답한다. |
| replicated data $A^{\mathrm{rep}}$ | 적합된 모형으로 다시 만든 가상 판정 데이터 | 실제 $A^{\mathrm{obs}}$와 비교한다. |
| discrepancy $T$ | 데이터의 중요한 특징을 숫자로 요약한 통계량 | 계열 내 이중 오류율, 만장일치율 등이 된다. |
| posterior predictive $p$-value | 가상 데이터의 $T$가 실제보다 큰 사후확률 | 극단적이면 해당 패턴을 모형이 재현하지 못한다는 신호다. |
| $X$ | 입력 공변량 | 언어, 기기, 도구, 길이, 이미지 종류, 고객군 등이다. |
| covariate shift | $P(X)$만 바뀌고 $P(Y\mid X)$는 유지되는 변화 | 밀도비 가중으로 보정할 수 있는 대상이다. |
| concept shift | $P(Y\mid X)$ 자체가 바뀌는 변화 | 새 라벨 없이 입력 가중만으로 해결할 수 없다. |
| density ratio $w(x)$ | 배포 밀도를 검량 밀도로 나눈 값 | 새 배포에서 각 검량 항목의 대표성을 정한다. |
| support overlap | 배포에서 가능한 입력이 검량에도 양의 확률로 존재하는 조건 | 없으면 해당 영역을 과거 데이터로 보정할 수 없다. |
| nonconformity score $S_i$ | 예측과 실제 라벨의 어긋남 정도 | 클수록 모델 관점에서 이상하거나 어려운 사례다. |
| weighted quantile | 각 값의 가중치를 반영해 구한 분위수 | 배포에서 중요한 검량 점수에 더 큰 표를 준다. |
| $\delta_z$ | 질량 전부가 값 $z$에 놓인 점질량 | 가중 경험분포를 간결하게 쓸 때 사용한다. |
| $N_{\mathrm{eff}}$ | 유효표본크기, 가중치가 실제로 몇 개의 균등 표본과 비슷한지 나타내는 값 | 가중치가 한두 점에 몰리면 급격히 작아진다. |
| clipping | 지나치게 큰 가중치를 상한에서 자르는 기법 | 분산은 낮추지만 정확한 보장에 편향을 넣을 수 있다. |
| cross-fitting | 한 조각에서 가중치 모형을 학습하고 다른 조각을 평가하는 교차 절차 | 같은 데이터 재사용으로 생기는 과적합을 줄인다. |
| recalibration | 새 데이터로 임계값·확률·예측집합을 다시 맞추는 과정 | drift 뒤 자동화를 안전하게 재개하는 절차다. |
| abstention | 자신 없을 때 자동 결정을 보류하는 행동 | 지원집합 밖·낮은 ESS·모형 실패 사례를 사람에게 보낸다. |

## 3. 수학의 해부학 (증명과 원리)

### 3.1 전날 모형의 숨은 독립 가정

전날의 기본 모형은 실제 상태 $Y_i$가 주어지면 판정들이 독립이라고 두었다.

$$
P(A_{i1},\ldots,A_{iR}\mid Y_i)
=
\prod_{r=1}^{R}
P(A_{ir}\mid Y_i).
$$

따라서 같은 방향의 판정이 여러 개 들어오면 각 판정의 우도비를 모두 곱한다. 하지만 공유 원인 $U_i$가 빠져 있다면 실제 결합분포는

$$
P(\mathbf A_i\mid Y_i)
=
\int
\prod_{r=1}^{R}
P(A_{ir}\mid Y_i,U_i=u)
p(u)\,du
$$

가 된다. 일반적으로

$$
\int \prod_r f_r(u)p(u)\,du
\neq
\prod_r\int f_r(u)p(u)\,du.
$$

즉 숨은 공통 원인을 적분해 없앤 뒤에는 판정들이 서로 의존한다. 조건부 독립은 “모든 필요한 공통 원인을 조건에 넣었을 때”만 성립한다.

### 3.2 정답 여부를 이용한 계층적 로지스틱 모형

실제 계층을 부호로 바꿔

$$
z_i=2Y_i-1\in\{-1,+1\}
$$

로 두자. 판정의 정답 여부는

$$
C_{ir}
=
\mathbf 1\{A_{ir}=Y_i\}
$$

다. 판정자 $r$이 항목 $i$를 맞힐 확률을

$$
p_{ir}
=
P(C_{ir}=1\mid Y_i,d_i,u_{i,g(r)})
$$

라 하고 다음처럼 모델링한다.

$$
\boxed{
\operatorname{logit}(p_{ir})
=
\alpha_r+\beta_r z_i-d_i+u_{i,g(r)}
}
$$

각 항의 의미는 다음과 같다.

- $\alpha_r$: 판정자 $r$의 평균적인 정답 능력
- $\beta_r z_i$: 실제 위험과 실제 정상에서의 비대칭
- $-d_i$: 항목이 어려울수록 정답 로그오즈를 낮추는 효과
- $u_{i,g(r)}$: 같은 계열이 항목 $i$에서 공유하는 추가 성공·실패 효과

상위 분포는 예를 들어

$$
d_i\sim\mathcal N(0,\sigma_d^2),
$$

$$
u_{ig}\sim\mathcal N(0,\tau_g^2)
$$

로 둔다. 평균을 $0$으로 고정하는 것은 $\alpha_r$, $d_i$, $u_{ig}$가 같은 상수를 서로 떠넘기는 위치 비식별성을 막는 역할도 한다.

다만 평균을 $0$으로 두는 것만으로 모든 식별성 문제가 끝나지는 않는다. 잠재 정답 $Y_i$를 함께 추정하면 “정상”과 “위험”의 이름을 통째로 뒤집는 label switching이 남을 수 있으므로, 일부 확정 gold label, 방향이 알려진 anchor judge, 또는 부호 제약이 필요하다. 또한 $\sigma_d^2$와 $\tau_g^2$를 분리하려면 항목과 계열이 충분히 많고, 한 항목을 같은 계열의 여러 판정자와 다른 계열 판정자가 함께 평가하는 crossed 설계가 필요하다.

정답 확률을 관측 판정 확률로 쓰면

$$
P(A_{ir}=a\mid Y_i,d_i,u_{i,g(r)})
=
p_{ir}^{\mathbf 1\{a=Y_i\}}
(1-p_{ir})^{\mathbf 1\{a\neq Y_i\}}.
$$

이 식은 $a=Y_i$이면 $p_{ir}$만 남고, 다르면 $1-p_{ir}$만 남는다.

> 이 모형은 교육용 최소 형태다. 실제로는 언어·프롬프트·시간 효과, 판정자별 slope, 다범주 라벨, 비정보적이지 않은 누락을 추가할 수 있다. 복잡성을 늘릴수록 anchor와 표본 설계도 함께 강화해야 한다.

### 3.3 공유 랜덤효과가 상관을 만드는 과정

같은 계열 $g$에 속한 판정자 $r,s$를 생각하자. $Y_i,d_i,u_{ig}$까지 알면

$$
C_{ir}\perp C_{is}
\mid
Y_i,d_i,u_{ig}
$$

라고 둘 수 있다. 그러나 $u_{ig}$를 보지 못해 적분하면

$$
\begin{aligned}
&\operatorname{Cov}
(C_{ir},C_{is}\mid Y_i,d_i)\\
&=
\operatorname{Cov}_{u}
\left[
\sigma(\eta_{ir}+u),
\sigma(\eta_{is}+u)
\right],
\end{aligned}
$$

여기서

$$
\eta_{ir}=\alpha_r+\beta_r z_i-d_i
$$

다. 두 로지스틱 함수는 모두 $u$가 커질수록 증가하므로 이 공분산은 보통 양수다. 같은 항목이 그 계열에 유난히 쉬우면 둘 다 맞히고, 유난히 어려우면 둘 다 틀리는 경향이 생긴다.

직관을 숫자로 보자. 두 판정자의 주변 정답률이 각각 $p=0.9$이고 정답 지시자 사이 상관이 $\rho=0.5$라면

$$
\operatorname{Cov}(C_1,C_2)
=
\rho p(1-p)
=
0.5\times0.9\times0.1
=
0.045.
$$

따라서 둘이 동시에 틀릴 확률은

$$
\begin{aligned}
P(C_1=0,C_2=0)
&=(1-p)^2+\operatorname{Cov}(C_1,C_2)\\
&=0.01+0.045\\
&=0.055.
\end{aligned}
$$

독립이라고 계산한 $1\%$보다 실제는 $5.5\%$다. 같은 오답 두 표를 독립 증거 두 개처럼 세면 위험을 크게 과소평가할 수 있다.

### 3.4 잠재 진실과 랜덤효과의 사후분포

모수 전체를

$$
\Theta
=
(\pi,\boldsymbol\alpha,\boldsymbol\beta,
\sigma_d,\boldsymbol\tau)
$$

라 하자. 잠재 진실 $\mathbf Y$, 난이도 $\mathbf d$, 공유효과 $\mathbf u$까지 포함한 사후분포는

$$
\begin{aligned}
&p(\Theta,\mathbf Y,\mathbf d,\mathbf u
\mid\mathbf A,\mathbf X)\\
&\propto
p(\mathbf A\mid\mathbf Y,\mathbf d,\mathbf u,\Theta,\mathbf X)
p(\mathbf Y\mid\pi,\mathbf X)\\
&\qquad\times
p(\mathbf d\mid\sigma_d)
p(\mathbf u\mid\boldsymbol\tau)
p(\Theta).
\end{aligned}
$$

전날의 단순 EM 갱신처럼 닫힌형식 해가 나오지 않는 경우가 많다. 따라서 다음 중 하나를 사용한다.

- MCMC로 사후분포에서 표본을 뽑는다.
- 변분추론으로 계산하기 쉬운 분포를 근사한다.
- Laplace 근사로 최빈값 주변을 정규분포로 근사한다.
- EM 안에서 랜덤효과 적분을 수치적으로 근사한다.

중요한 것은 계산법의 이름보다 **잠재 라벨과 판정자 성능의 불확실성이 서로 연결되어 있다**는 사실이다. 하나의 soft label과 하나의 정확도만 저장하면 이 연결을 잃는다.

### 3.5 Partial pooling이 작은 집단을 안정화하는 이유

로지스틱 혼합모형 자체에는 아래 정규–정규 켤레식이 정확히 적용되지 않는다. 다만 최빈값 주변의 Laplace 근사나 큰 표본의 국소 정규근사에서 항목–계열 공유효과의 임시 추정값을 $\widehat u_{ig}$라 하고

$$
\widehat u_{ig}\mid u_{ig}
\sim
\mathcal N(u_{ig},s_{ig}^2),
\qquad
u_{ig}\sim\mathcal N(0,\tau_g^2)
$$

라고 근사해 보자. 이 보조 정규모형에서의 사후평균은

$$
\boxed{
\mathbb E[u_{ig}\mid\widehat u_{ig}]
=
\frac{\tau_g^2}{\tau_g^2+s_{ig}^2}
\widehat u_{ig}
}
$$

다. 사후분산은

$$
\operatorname{Var}(u_{ig}\mid\widehat u_{ig})
=
\frac{\tau_g^2s_{ig}^2}{\tau_g^2+s_{ig}^2}.
$$

표본이 적어 $s_{ig}^2$가 크면 곱해지는 계수가 작아져 전체 평균 $0$ 쪽으로 강하게 수축한다. 반대로 충분한 관측으로 $s_{ig}^2$가 작으면 항목–계열 자체의 추정값을 더 믿는다. 이것이 “모두 한 정확도를 쓴다”와 “각 공유효과를 완전히 따로 센다” 사이의 절충이다. 위 식은 수축 직관을 보여 주는 **국소 정규근사**이며, 원래 로지스틱 GLMM의 정확한 켤레 사후분포라고 해석하면 안 된다.

### 3.6 Posterior predictive distribution 만들기

관측 데이터를 $\mathbf A^{\mathrm{obs}}$라 하자. 사후예측 표본 한 개는 두 단계로 만든다.

1. 사후분포에서

$$
(\Theta^{(s)},\mathbf Y^{(s)},\mathbf d^{(s)},\mathbf u^{(s)})
\sim
p(\Theta,\mathbf Y,\mathbf d,\mathbf u
\mid\mathbf A^{\mathrm{obs}})
$$

를 뽑는다.

2. 그 값으로

$$
\mathbf A^{\mathrm{rep},(s)}
\sim
p(\mathbf A\mid
\Theta^{(s)},\mathbf Y^{(s)},\mathbf d^{(s)},\mathbf u^{(s)})
$$

를 생성한다.

기존 항목에서 판정 노이즈만 점검하려면 추정된 $d_i,u_{ig}$를 조건으로 복제한다. 새 항목 일반화까지 점검하려면 새 $X$, 새 잠재 정답 $Y$, 새 난이도와 계열 효과를 생성모형의 상위 분포에서 다시 뽑아야 한다. $X$나 $Y$를 고정해 조건부 예측을 하는 경우에는 그 사실을 명시한다. 두 질문은 다르므로 어떤 predictive check인지 밝혀야 한다.

### 3.7 어떤 통계량으로 현실과 가상 데이터를 비교할까?

좋은 discrepancy $T$는 전체 평균 정확도처럼 이미 모형이 쉽게 맞추는 값보다, 모형의 취약한 가정을 직접 겨냥한다.

| 점검 통계량 $T$ | 발견하려는 문제 |
| --- | --- |
| 같은 계열 두 judge의 동시 오류율 | 공유 오류를 랜덤효과가 충분히 설명하는가? |
| 다른 계열 간 동시 오류율 | 계열 구분 밖의 공통 원인이 남았는가? |
| 항목별 만장일치율의 분포 | 난이도 분산이 너무 작거나 큰가? |
| 양성·음성별 오류율 | $\beta_r$가 계층 비대칭을 설명하는가? |
| 언어·도구·길이 구간별 오류율 | 빠진 공변량이나 interaction이 있는가? |
| judge별 투표 패턴의 빈도 | 특정 불일치 조합을 체계적으로 놓치는가? |

사후예측 $p$-값의 몬테카를로 근사는

$$
\widehat p_{\mathrm{PPC}}
=
\frac{1}{S}
\sum_{s=1}^{S}
\mathbf 1
\left\{
T(\mathbf A^{\mathrm{rep},(s)},\mathbf Y^{(s)})
\ge
T(\mathbf A^{\mathrm{obs}},\mathbf Y^{(s)})
\right\}
$$

다. 오류율처럼 정답이 필요한 통계량은 같은 사후표본의 $\mathbf Y^{(s)}$를 복제 데이터와 관측 데이터 양쪽에 사용한다. 별도 gold holdout이라면 양쪽에 고정된 $\mathbf Y^{\mathrm{gold}}$를 사용하고, 만장일치율처럼 관측 판정만 필요한 통계량은 $T(\mathbf A)$로 단순화한다. 누락률–난이도 관계를 검사하려면 누락 지시자 $M_{ir}$의 생성모형까지 명시적으로 포함해야 한다. 값이 $0$이나 $1$에 지나치게 가까우면 관측 통계량이 모형의 가상 세계에서 드물다는 뜻이다.

그러나 이것은 고전적 귀무가설 검정의 균등한 $p$-값이 아니다. 같은 데이터를 모형 적합과 점검에 함께 쓰므로 보수적일 수 있다. “$0.05$ 아래면 자동 기각”보다 그래프, 여러 사전 지정 통계량, holdout predictive check와 함께 **어떤 구조를 모형이 놓쳤는지** 찾는 도구로 사용한다.

### 3.8 중요도 가중 항등식 유도

검량 분포와 배포 분포에서 조건부 결과 규칙이 같다고 하자.

$$
p_{\mathrm{dep}}(y\mid x)
=
p_{\mathrm{cal}}(y\mid x).
$$

또 배포에서 가능한 모든 $x$에 대해 $p_{\mathrm{cal}}(x)>0$라고 하자. 임의의 함수 $h(X,Y)$에 대해

$$
\begin{aligned}
\mathbb E_{\mathrm{dep}}[h(X,Y)]
&=
\int h(x,y)
p_{\mathrm{dep}}(x)
p(y\mid x)\,dx\,dy\\
&=
\int h(x,y)
\frac{p_{\mathrm{dep}}(x)}
{p_{\mathrm{cal}}(x)}
p_{\mathrm{cal}}(x)
p(y\mid x)\,dx\,dy\\
&=
\mathbb E_{\mathrm{cal}}
\left[
w(X)h(X,Y)
\right].
\end{aligned}
$$

이것이 중요도 가중의 핵심이다. 분자를 바꾸는 마법이 아니라, 배포에서 얼마나 자주 만날지를 검량 표본의 표 수에 반영한다.

### 3.9 가중 split conformal 분위수

검량 항목의 nonconformity score를

$$
S_i=s(X_i,Y_i),
\qquad i=1,\ldots,n
$$

이라 하자. 분류에서는 실제 라벨 확률이 낮을수록 큰 점수를 주는

$$
S_i=1-\widehat p(Y_i\mid X_i)
$$

를 예로 들 수 있다.

여기서 검량 라벨 $Y_i$는 모델 적합과 독립된 split에서 얻은 **성숙한 확정 gold label**이어야 한다. EM 사후확률이나 hard pseudo-label을 대신 넣으면 아래의 유한표본 coverage가 그대로 따라오지 않는다. soft label로 만든 점수는 유용한 휴리스틱일 수 있지만 동일한 보장이라고 부르면 안 된다.

새 입력 $x$에서

$$
W(x)
=
\sum_{j=1}^{n}w(X_j)+w(x)
$$

로 두고 정규화 가중치를

$$
p_i(x)
=
\frac{w(X_i)}{W(x)},
\qquad
p_{n+1}(x)
=
\frac{w(x)}{W(x)}
$$

로 둔다. 다음 가중 경험분포를 만든다.

$$
\mu_x
=
\sum_{i=1}^{n}
p_i(x)\delta_{S_i}
+
p_{n+1}(x)\delta_{+\infty}.
$$

새 테스트 점수는 아직 모르므로 그 질량을 보수적으로 $+\infty$에 둔다. $1-\alpha$ 가중 분위수는

$$
q_{1-\alpha}(x)
=
\inf
\left\{
t:
\mu_x((-\infty,t])
\ge
1-\alpha
\right\}.
$$

예측집합은

$$
\boxed{
\mathcal C(x)
=
\left\{
y:
s(x,y)\le q_{1-\alpha}(x)
\right\}
}
$$

다. 정확한 밀도비, 독립적인 split, covariate shift, support overlap 조건 아래에서 새 배포 표본에 대해

$$
P_{\mathrm{dep}}
\left\{
Y\in\mathcal C(X)
\right\}
\ge
1-\alpha
$$

라는 주변 coverage를 얻는다.

만약 $p_{n+1}(x)>\alpha$이면 유한한 검량 점수의 총질량이 $1-\alpha$에 못 미치므로 $q_{1-\alpha}(x)=+\infty$다. 이때는 전체 라벨 집합을 반환하거나 자동 결정을 보류해야지, 임계값을 임의로 잘라서는 안 된다.

또한 예측집합 coverage와 “자동 통과한 사례의 위험률”은 같은 보장이 아니다. 이진 문제에서 $0$을 안전, $1$을 위험이라고 하고 **오직** $\mathcal C(x)=\{0\}$일 때만 자동 통과시키면

$$
P\left(Y=1,\mathcal C(X)=\{0\}\right)
\le
P\left(Y\notin\mathcal C(X)\right)
\le
\alpha
$$

라는 전체 배포 질량에 대한 상계는 얻는다. 그러나 이것은

$$
P\left(Y=1\mid\mathcal C(X)=\{0\}\right)\le\alpha
$$

를 뜻하지 않으며, subgroup별 위험도 보장도 아니다. 선택된 자동 통과 집단의 조건부 위험을 직접 통제하려면 conformal risk control이나 별도의 selective-risk 설계가 필요하다.

#### 왜 가중 순위가 맞는가?

검량 $n$개와 배포 테스트 한 개의 값을 한데 놓고 “어느 점이 배포에서 온 점인가?”를 생각하자. 합쳐진 값들이 주어졌을 때 각 점이 배포 점일 조건부 확률은 밀도비 $w(X_i)$에 비례한다. 따라서 균등한 순위 대신 이 조건부 확률을 질량으로 사용해야 한다. $+\infty$ 질량은 아직 보지 못한 테스트 점수가 가장 나쁠 가능성을 보수적으로 포함한다.

> 이 보장은 각 언어·각 고객군마다 동시에 $1-\alpha$ coverage를 준다는 뜻이 아니다. 전체 배포 분포에 대한 주변 보장이다. 세그먼트별 보장이 필요하면 충분한 표본과 다중검정 예산을 포함해 별도로 설계해야 한다.

### 3.10 손으로 보는 가중 분위수와 유효표본크기

검량 점수가 오름차순으로

$$
(0.05,0.10,0.20,0.30,0.40,0.80,0.90,1.00,1.10,1.20)
$$

이고 마지막 점수의 배포 가중치만 $10$, 나머지는 모두 $1$이라고 하자. 새 테스트 입력 가중치는 $1$, 목표 coverage는 $80\%$다.

검량 가중치 합은

$$
9\times1+10=19
$$

이고 테스트 질량까지 포함한 합은 $20$이다. 목표 누적질량은

$$
0.8\times20=16.
$$

$1.10$까지의 누적 가중치는 $9$이고, $1.20$을 포함하면 $19$가 된다. 따라서

$$
q_{0.8}=1.20.
$$

모든 가중치가 같았다면 $+\infty$를 포함한 $11$개 질량의 $80\%$ 지점은 아홉 번째 검량 점수 $1.10$이다. 배포에서 중요해진 어려운 사례가 $1.20$에 있으므로 가중 검량이 더 넓고 보수적인 집합을 만든 것이다.

하지만 검량 가중치의 유효표본크기는

$$
\begin{aligned}
N_{\mathrm{eff}}
&=
\frac{\left(\sum_iw_i\right)^2}
{\sum_iw_i^2}\\
&=
\frac{19^2}
{9\times1^2+10^2}\\
&=
\frac{361}{109}\\
&\approx3.31.
\end{aligned}
$$

실제 행은 $10$개지만 가중치 집중도는 균등 표본 약 $3.31$개에 해당한다. 이 값은 Kish 형태의 **집중도 진단값**이지 정확한 독립 표본 수나 coverage 인증서가 아니다. 가중 보정이 가능하다는 사실과 정밀도가 충분하다는 사실은 다르다.

### 3.11 밀도비를 도메인 분류기로 추정하기

실제로 $p_{\mathrm{dep}}(x)$와 $p_{\mathrm{cal}}(x)$를 직접 알기 어렵다. 검량 표본에는 $D=0$, 최근 배포 입력에는 $D=1$이라는 도메인 라벨을 붙이고 분류기

$$
q(x)=P(D=1\mid X=x)
$$

를 학습할 수 있다. 베이즈 정리를 쓰면

$$
\boxed{
w(x)
=
\frac{q(x)}{1-q(x)}
\frac{P(D=0)}{P(D=1)}
}
$$

다. 두 도메인을 같은 수로 샘플링했다면 마지막 사전오즈 항은 $1$이다.

주의할 점은 다음과 같다.

- 배포/검량 구분을 너무 잘하는 분류기는 shift가 크다는 뜻이며 큰 가중치를 만들 수 있다.
- 같은 검량 라벨로 score model, ratio model, threshold를 모두 튜닝하면 과적합한다.
- cross-fitting 또는 별도 split으로 가중치 추정과 conformal 검량을 분리한다.
- $w$를 임의로 clipping하면 분산은 줄지만 정확한 밀도비에서 오는 보장은 일반적으로 그대로 유지되지 않는다.
- 추정 가중치를 쓴 유한표본 보장은 추가 조건이나 보수적 오차 경계가 필요하다. “가중치를 넣었으니 distribution-free”라고 말하면 안 된다.

### 3.12 온라인 재검량은 예측 가능한 블록으로 운영하기

스트리밍 데이터에서 매 요청 뒤 임계값을 즉흥적으로 바꾸면 현재 결과를 보고 규칙을 고르는 선택 편향이 생긴다. 안전한 기본 설계는 블록 단위다.

1. **Freeze:** 구간 $k$에 사용할 score model, judge 구성, 밀도비 모형, 임계값을 미리 고정한다.
2. **Serve:** 해당 구간 요청을 처리하고 입력·판정·버전·propensity를 기록한다.
3. **Mature:** 지연된 확정 라벨이 성숙할 때까지 pending으로 분리한다.
4. **Audit:** 사전 지정한 무작위·층화 감사 표본으로 PPC, ESS, coverage, 위험을 계산한다.
5. **Recalibrate:** 다음 구간 $k+1$에만 새 임계값을 적용한다.

다음 중 하나가 발생하면 자동 확대보다 **HOLD**가 우선이다.

$$
N_{\mathrm{eff}}<N_{\min},
$$

$$
\max_i w_i>w_{\max},
$$

$$
\text{support overlap 실패},
$$

$$
\text{PPC에서 사전 지정 통계량의 극단적 불일치},
$$

$$
P_{\mathrm{dep}}(Y\mid X)
\neq
P_{\mathrm{cal}}(Y\mid X)
\text{가 의심되는 변화점}.
$$

**HOLD**는 서비스 전체 중단만 뜻하지 않는다. 고위험 자동 통과를 멈추고 사람 검토율을 높이며, 새 regime의 확정 라벨을 모으는 안전 상태다.

### 4.2 상관 judge를 설계 단계에서 줄이기

통계모형은 나쁜 측정 설계를 완전히 구하지 못한다. 먼저 판정자의 오류 원인을 다양화해야 한다.

- 서로 다른 기반 모델 계열을 섞는다.
- 동일 프롬프트의 표현만 바꾼 복제본을 독립 판정자로 세지 않는다.
- 검색·OCR·도구 결과를 독립적으로 생성하거나 공유 여부를 기록한다.
- 선택지 순서를 무작위화하고 그 순서를 공변량으로 남긴다.
- 일부 항목은 충분한 절차를 거친 사람 adjudication으로 anchor를 만든다.
- 판정자 버전, 시스템 프롬프트 해시, temperature, provider를 로그에 남긴다.

세 judge의 이름이 다르다는 사실보다 오류를 만드는 경로가 다른지가 중요하다.

### 4.3 항목 난이도는 “모델이 못한 이유”를 분리한다

동일한 judge가 쉬운 영어 텍스트에서는 $95\%$, 흐린 한국어 화면에서는 $65\%$ 정확하다고 하자. 항목 난이도를 빼면 두 구간의 혼합 비율이 바뀔 때 judge 자체가 drift한 것처럼 보인다.

계층모형은 다음 질문을 분리한다.

- 판정자 능력 $\alpha_r$가 변했는가?
- 새 요청의 난이도 $d_i$ 분포가 변했는가?
- 특정 계열 공유효과의 분산 $\tau_g^2$가 커졌는가?
- 양성/음성 비대칭 $\beta_r$가 달라졌는가?

이 분해가 곧 인과적 결론은 아니다. 그러나 “누가 나빠졌는가?”와 “무엇이 어려워졌는가?”를 한 정확도보다 훨씬 잘 구분한다.

### 4.4 PPC는 모델의 단위 테스트다

소프트웨어 단위 테스트가 중요한 동작을 예제로 검증하듯 PPC는 생성모형의 중요한 행동을 통계량으로 검증한다.

예를 들어 실제 같은 계열 이중 오류율이 $18\%$인데 사후예측 표본 대부분이 $5\%$에서 $9\%$라면, 평균 정확도가 맞아도 모형은 공유 오류를 충분히 표현하지 못한다. 다음 조치를 고려한다.

- 계열 정의를 더 세분화한다.
- 언어·도구·시간 interaction을 추가한다.
- 하나의 정규 랜덤효과 대신 heavy-tail 또는 mixture를 검토한다.
- 누락 메커니즘을 별도로 모델링한다.
- 독립 holdout 항목에서 같은 discrepancy를 다시 확인한다.

PPC를 통과했다는 것은 모형이 참이라는 증명이 아니다. 우리가 측정한 실패 모드에서는 아직 큰 불일치를 찾지 못했다는 뜻이다.

### 4.5 가중 conformal은 “새 고객 구성”을 반영한다

AI 서비스에서 $X$는 원문 전체일 수도 있지만, 밀도비를 안정적으로 추정하려면 해석 가능한 배포 특징을 함께 사용한다.

| 공변량 예시 | 왜 필요한가? |
| --- | --- |
| 언어·지역 | 번역 품질과 안전 표현이 달라진다. |
| 텍스트·이미지·비디오 | modality별 오류 구조가 다르다. |
| 모바일·데스크톱 | 화면 밀도와 OCR 난이도가 달라진다. |
| 도구 종류·권한 수준 | 동일 문장도 실행 결과의 위험이 다르다. |
| 입력 길이·trajectory 단계 | 긴 문맥에서 정보 손실이 커질 수 있다. |
| 모델·judge 버전 | 업그레이드가 score 분포를 바꾼다. |

배포에서 한국어 모바일 요청이 증가했다면 그 영역의 검량 항목 가중치가 커진다. 해당 영역의 오류 score가 크면 threshold가 보수적으로 변하고 자동 처리율은 내려간다. 이것은 성능 저하를 숨기는 것이 아니라 새 트래픽에 맞춰 불확실성을 정직하게 키우는 동작이다.

### 4.6 Conformal 보장과 확률 보정은 다르다

확률 보정 calibration은 “$0.8$이라고 말한 사례 중 실제 양성이 약 $80\%$인가?”를 묻는다. Conformal coverage는 “예측집합이 실제 라벨을 정해진 비율 이상 포함하는가?”를 묻는다.

잘 보정된 확률이라도 분포가 바뀌면 calibration이 깨질 수 있다. 반대로 conformal은 base probability가 완벽히 보정되지 않아도 순위 교환가능성으로 coverage를 만들 수 있다. 그러나 weighted conformal 역시 covariate shift와 정확한 가중치라는 가정이 필요하다.

따라서 운영에서는 다음을 따로 본다.

- reliability diagram·ECE·Brier score: 확률 품질
- coverage·set size·abstention rate: conformal 결과
- $N_{\mathrm{eff}}$·최대 가중치·overlap: shift 보정의 안정성
- subgroup risk·지연 라벨·pending 수: 운영 안전

### 4.7 수학과 AI 부품의 1:1 매핑

| 오늘의 수학 | AI 시스템에서의 부품 |

### 4.8 구현 순서

1. **평가 단위를 고정한다.** 응답, tool call, 전체 trajectory 중 무엇이 한 항목인지 정한다.
2. **judge genealogy를 기록한다.** 기반 모델·프롬프트·검색·버전으로 계열 $g(r)$를 만든다.
3. **anchor audit를 설계한다.** 무작위·층화 표본에 독립 adjudication을 수행한다.
4. **계층모형을 적합한다.** 판정자 능력, 항목 난이도, 계열 공유효과를 추정한다.
5. **PPC 목록을 사전 고정한다.** 계열 내 이중 오류, 세그먼트 오류, 만장일치율을 비교한다.
6. **배포 shift를 추정한다.** 검량 대 최근 배포 도메인 분류기로 $w(x)$를 구한다.
7. **overlap과 ESS를 확인한다.** 실패하면 가중 threshold를 강행하지 않고 보류한다.
8. **fresh calibration split으로 분위수를 구한다.** ratio model과 threshold 튜닝의 데이터 재사용을 피한다.
9. **다음 블록에만 적용한다.** 현재 결과를 본 뒤 같은 구간의 규칙을 고치지 않는다.
10. **모든 버전을 저장한다.** 모델, judge, score, ratio estimator, threshold, feature schema를 함께 버전 관리한다.

### 4.9 초보자가 흔히 하는 오해와 주의할 점

1. **“judge가 세 개면 독립 표가 세 개다.”** 같은 기반 모델·프롬프트·검색을 공유하면 오류도 공유한다.
2. **“랜덤효과는 무작위 노이즈를 더한다는 뜻이다.”** 반복되는 집단 차이를 상위 분포로 구조화하는 변수다.
3. **“항목 난이도를 넣으면 진짜 원인을 찾는다.”** 더 나은 분해일 뿐, 공변량 누락이 있으면 인과 해석은 어렵다.
4. **“PPC $p$-값이 $0.5$면 모형이 참이다.”** 선택한 통계량에서 극단적 불일치가 없다는 뜻뿐이다.
5. **“PPC를 많이 돌리면 모든 모형 오류를 찾는다.”** 보지 않은 discrepancy는 찾지 못한다.
6. **“확률이 잘 보정되면 conformal은 필요 없다.”** calibration과 coverage는 다른 목표다.
7. **“weighted conformal은 모든 drift를 고친다.”** $P(Y\mid X)$가 유지되는 covariate shift가 핵심 조건이다.
8. **“도메인 분류 정확도가 높을수록 좋다.”** 두 분포가 너무 잘 구분되면 overlap이 약하고 가중치 분산이 커질 수 있다.
9. **“큰 가중치는 정보가 많다는 뜻이다.”** 오히려 소수 표본이 결과를 지배해 ESS가 작아진다.
10. **“clipping 뒤에도 같은 유한표본 보장이 남는다.”** 분산과 편향의 교환이며 별도 보정 없이는 원래 보장을 그대로 주장할 수 없다.
11. **“전체 coverage가 맞으면 모든 언어가 안전하다.”** 주변 보장은 작은 subgroup 실패를 숨길 수 있다.
12. **“새 모델로 judge만 바꾸면 입력 shift다.”** 같은 $X$에서도 $P_\theta(\widehat Y,S\mid X)$와 조건부 오류분포가 바뀐다. 이것을 환경의 $P(Y\mid X)$가 바뀌었다는 뜻으로 자동 해석하면 안 된다.
13. **“아직 라벨이 없는 사례는 음성이다.”** pending을 음성으로 처리하면 지연이 긴 위험 사건을 체계적으로 지운다.
14. **“온라인이면 매 요청마다 즉시 재학습해야 한다.”** 결과 의존적 적응은 보장을 깨뜨릴 수 있어 예측 가능한 블록 운영이 더 안전하다.

### 5.1 Claude Sonnet 5.5: 토큰 단가보다 “완료된 작업 하나의 비용” 경쟁

Anthropic은 2026년 9월 28일 [Claude Sonnet 5.5](https://www.anthropic.com/claude-sonnet-5-5)를 발표했다. 모델 ID는 **claude-sonnet-5-5**다. 공식 발표는 Sonnet 5보다 출력이 $30\%+$ 빠르고, 입력·출력 토큰 단가는 각각 백만 토큰당 $\$2$, $\$10$로 같지만 같은 작업에 필요한 토큰이 대체로 줄고 일부 워크로드에서는 tool step도 줄어 작업당 비용이 최대 $30\%$ 낮다고 주장한다.

#### 공식 발표의 핵심 수치

| 항목 | Sonnet 5.5 | 비교·조건 |
| --- | ---: | --- |
| Terminal-Bench 4.0 | $70.6\%$ (Max) | Sonnet 5는 $10.3\%$; 발표사 harness와 effort 조건을 함께 봐야 한다. |
| FrontierCode 1.1 Main | $52.1\%$ (Xhigh), $46.2\%$ (Max) | effort가 증가해도 비단조적이며, Max의 추가 review 행동이 timeout·범위 밖 수정으로 감점된 사례가 있었다. |

가장 흥미로운 점은 높은 effort가 항상 더 낫지 않았다는 사실이다. 공식 각주는 Max effort에서 추가 code-review 행동이 timeout이나 범위 밖 수정으로 이어져 FrontierCode 점수가 Xhigh보다 낮아졌다고 설명한다. 추론량을 늘리는 것은 계산 예산을 늘리는 것이지, 작업 목표에 맞는 행동을 자동 보장하는 것이 아니다.

#### 마이그레이션도 하나의 분포 변화다

공식 발표와 [Sonnet 5.5 마이그레이션 가이드](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide)는 adaptive thinking이 기본이고, thinking을 끈 마이그레이션에서는 tool 사이 reasoning을 유지하는 **between_tools** 설정을 검토하라고 안내한다. 또한 Sonnet 5.5는 thinking 설정과 무관하게 forced tool choice인 **any** 또는 특정 **tool**을 지원하지 않아 HTTP $400$을 반환한다. Claude API와 Google Cloud에서는 **auto + strict**를 사용하고, strict tool use가 없는 Bedrock에서는 **auto**로 호출한 뒤 애플리케이션에서 입력을 검증해야 한다. 기존 effort 값도 그대로 믿지 말고 다시 sweep해야 한다. 모델 이름만 바꿔도 다음이 변할 수 있다.

- tool call 횟수와 순서
- 중간 reasoning 길이
- structured output 실패 유형
- 이미지 이해 score 분포
- 안전 classifier의 fallback 빈도

따라서 기존 judge 점수와 임계값을 그대로 옮기면 안 된다. 오늘 수학의 언어로 말하면 모델 교체는 적어도 $P_\theta(\widehat Y,S\mid X)$와 조건부 오류분포를 바꾼다. 이것만으로 환경의 정답 생성규칙 $P(Y\mid X)$가 바뀌었다고 부를 수는 없지만, 기존 score calibration에는 분명한 체제 변화다. 모델 버전과 trajectory 특징을 $X$에 포함하고, 새 버전의 확정 audit label로 PPC와 calibration을 다시 수행해야 한다.

#### 엔지니어 인사이트 (Impact)

첫째, 모델 선택 기준이 “벤치마크 최고점”에서 다음과 같은 다목적 Pareto 문제로 이동하고 있다.

$$
\begin{aligned}
\text{maximize}\quad
&(\text{quality},\text{success rate},\text{reliability}),\\
\text{minimize}\quad
&(\text{latency},\text{cost per completed task},\text{retry rate}).
\end{aligned}
$$

하나의 곱으로 서로 다른 단위를 억지로 합치기보다, 어느 지표도 악화시키지 않고 다른 지표를 개선할 수 없는 Pareto frontier를 찾는다. 일상적 버그 수정·문서 작업은 빠른 모델에, 열린 판단은 더 강한 모델에 보내는 라우팅이 중요해진다.

둘째, 발표 수치는 공급사 자체 측정과 제한된 외부 테스터 결과가 섞여 있다. 모델·effort·harness·도구 예산이 다르면 점수 하나로 원인을 분리할 수 없다. 실제 조직의 요청 분포에서 성공률, 평균이 아니라 꼬리 지연, tool failure, 재시도 비용을 함께 측정해야 한다.

셋째, Sonnet 5.5는 공개 가중치 모델이 아니다. API 공급자 변경과 조용한 서버 측 수정 가능성까지 운영 버전에 포함하고, canary·gold audit·rollback 경로를 유지해야 한다.

### 5.2 JEV-27B: 자유 생성 대신 확률 결정을 한 번에 내는 공개 가중치 System 1

AutoTrust AI는 2026년 9월 27일 [JEV-27B 발표 글](https://huggingface.co/blog/autotrust/autotrustjev-27b-fast-calibrated-decisions-and-ful)과 [모델 카드](https://huggingface.co/autotrust/JEV-27B)를 공개했다. 이 모델은 “피싱인가?”, “어느 팀으로 라우팅할까?”, “위험도를 $0$부터 $5$ 중 어디로 둘까?”처럼 답의 형식이 제한된 문제에 긴 자유문장을 생성하지 않고 확률분포를 직접 반환한다.

지원 형식은 다음 세 가지다.

| 형식 | 출력 |
| --- | --- |
| noul | 거짓·참 두 확률 |
| choice | $2$개에서 $16$개 선택지의 확률 |
| score | $0$부터 $5$까지 여섯 수준의 분포와 기댓값 |

#### 구조와 학습

- 동결된 Qwen3.8-27B 텍스트 백본
- rank-$16$ LoRA 약 $108.8$M 모수
- $24$-slot FP32 decision head 약 $123$K 모수
- 학습되는 부분은 백본 대비 약 $0.4\%$
- 제작팀 보고 B200 한 장에서 약 $9.2$시간

adapter를 켜면 빠른 확률 결정인 System 1, 끄면 원래 생성·추론 경로인 System 2를 같은 vLLM 서버에서 사용한다. 모델 전체를 분류기로 덮어쓰지 않아 adapter-off HumanEval 결과가 base Qwen과 $164$개 모두 byte-identical했다고 보고한다.

[jev-distill-corpus-v3](https://huggingface.co/datasets/SargeDev/jev-distill-corpus-v3)는 총 $740{,}957$행이고 train split은 $655{,}806$행이다. 구성은 TypeSafe Jev 분포를 담은 **yuri_v3 $498{,}010$행**, programmatic ground truth인 **openjev_v2 $94{,}801$행**, 정보가 없는 placeholder 표적인 **yuri_v1 $148{,}154$행**이다. 모델 카드가 적은 세 구성 수의 합은 보고 총량보다 $8$행 많다는 원문 내부 불일치도 있다. yuri_v1의 train $137{,}203$행은 정확히 $[0.5,0.5]$이며 $0.05$배로 downweight됐고 temperature fitting에서도 제외됐다. 공개 체크포인트는 $5{,}000$ step, batch $128$로 약 $640$K 행을 본 상태다. 학습 손실은 모든 활성 slot에서 $\mathrm{KL}(\text{target}\Vert\text{model})$이고, score에는 $0.5$배 ranked probability score를 더했다. 따라서 전체가 교사의 의미 있는 soft probability라는 설명은 틀리다.

#### 수치와 검증 범위

| 평가 | 결과 | 해석 제한 |
| --- | ---: | --- |
| 6개 공개 결정 benchmark 평균 | JEV-27B $84.07$, 교사 $83.85$ | 제작팀이 두 모델을 실행한 자체 결과이며, live leaderboard 채택 여부나 독립 재현과는 구분해야 한다. |
| 같은 53개 도메인의 held-out $25{,}376$개 | 평균 $\mathrm{KL}(\text{teacher}\Vert\text{student})\approx0.017$ | 교사의 출력이 목표라서 실제 정답 정확도와 같지 않다. |
| 자체 test_set_30k ECE(temperature 적용) | $0.0009$ | corpus target에 대한 self-report이며 독립 human-gold·배포 calibration으로 해석하면 안 된다. |
| B200 단일 요청 중앙 지연 | $137$ms | 로컬 $20$회 self-report로 네트워크를 제외했으며, hosted API와 동조건 비교가 아니다. |
| batch $128$ | 결정당 $4.2$ms | 처리량 지표이며 개별 사용자 지연과 다르다. |

별도 저자가 공개한 [decision-models-under-pressure](https://github.com/gazelle93/decision-models-under-pressure) human-gold stress benchmark의 동일 항목을 AutoTrust가 JEV-27B로 다시 실행했을 때, 선택지 $16$개 정확도는 교사 $76.9\%$, JEV-27B $74.0\%$였고 선택지 순서만 바꾸면 JEV-27B의 답이 $7.4\%$ 변했다. 이는 독립 저자의 JEV 실행 결과가 아니라 제작팀의 재실행 수치다. 즉 in-domain KL이 작아도 외부 human-gold 정확도와 순서 강건성이 자동으로 따라오지 않는다.

모델 가중치는 **Apache-2.0**이다. 다만 “공개 가중치·데이터”와 “완전 재현 가능한 연구”는 구분해야 한다. 별도 정식 논문과 전체 학습 파이프라인의 독립 재현이 아직 제시된 것은 아니며, 수치 대부분은 제작팀 보고다.

#### 엔지니어 인사이트 (Impact)

JEV-27B가 보여 주는 설계는 모든 요청을 비싼 자유 생성으로 처리하지 않는 것이다.

1. 제한된 반복 판단은 System 1 확률 head가 빠르게 처리한다.
2. 확신이 낮거나 지원집합 밖이면 System 2 또는 사람에게 올린다.
3. 고위험 행동은 확률이 높아도 별도 정책·승인 게이트를 통과시킨다.

여기서 “확률이 나온다”는 사실만으로 자동화 임계값을 정하면 안 된다. 교사의 오류와 편향도 증류되고, 선택지 순서에 민감하며, 제작팀도 multi-hop·산술·counting·adversarial 입력의 한계를 명시한다. 추가로 다음 제약이 있다.

- yuri_v1의 $[0.5,0.5]$ placeholder는 정보가 없는 표적이며, 데이터 행 수만으로 supervision의 양을 과대평가하게 만든다.
- 기본 serving은 state가 $1{,}024$ token을 넘으면 앞 $60\%$와 뒤 $40\%$만 남기므로, 긴 문맥에서는 중간 근거가 사라질 수 있다. 한도를 올리면 지연·메모리도 다시 측정해야 한다.
- 데이터와 평가는 영어 중심이며 다국어 성능을 체계적으로 검증하지 않았다.
- System 1은 설명을 생성하지 않고, adapter를 끈 System 2는 System 1이 내린 결정을 알지 못해 서로 다른 답을 낼 수 있다.
- confidence-gated escalation은 합리적인 운영 패턴이지만, 공개 결과가 그 전체 파이프라인의 위험률을 검증한 것은 아니다.

오늘의 수학과 직접 연결하면, JEV-27B의 in-domain calibration은 출발점일 뿐이다. 실제 조직의 언어·업무·선택지 수가 학습 분포와 다르면

- 도메인별 reliability와 PPC를 확인하고,
- 검량/배포 밀도비와 $N_{\mathrm{eff}}$를 측정하며,
- weighted conformal threshold로 보류 구간을 만들고,
- 모델 버전 변화로 $P_\theta(\widehat Y,S\mid X)$가 달라졌거나 환경의 concept shift가 의심되면 새 gold label 없이 자동 확대하지 않아야 한다.

두 발표의 공통 메시지는 “더 큰 모델 하나”보다 **작업별 경로 선택과 검량**이 중요해졌다는 점이다. Sonnet 5.5는 완료된 작업당 비용을 줄이는 범용 경로를, JEV-27B는 반복 결정을 전문 head로 분리하는 경로를 보여 준다. 어느 쪽도 실제 배포 분포에서의 독립 audit를 대신하지 않는다.

## 6. 오늘의 메타인지 질문 (스스로 묻고 답하기)

### 질문

같은 기반 모델 계열의 judge $J_1,J_2$와 다른 계열 judge $J_3$가 모두 한 응답을 “안전”이라고 판정했다. 과거 검량에서 각 judge의 주변 정답률은 $90\%$였지만, $J_1,J_2$의 정답 지시자 상관은 $\rho=0.5$였다. 배포 뒤 한국어 모바일 요청이 급증해 일부 검량 항목의 밀도비가 매우 커졌고, 새 agent 모델도 동시에 교체됐다.

1. 왜 $J_1,J_2$의 두 표를 독립적인 $0.9\times0.9$ 증거로 계산하면 안 되는가?
2. 계층모형 적합 뒤 어떤 PPC 통계량을 가장 먼저 확인하겠는가?
3. weighted conformal을 그대로 적용해 자동 통과를 확대해도 되는가?

### 모범 답안

$J_1,J_2$는 공유 오류 원인을 가지므로 $Y$만 조건으로 독립이 아니다. 두 판정자의 오류 확률은 각각 $0.1$이지만, 상관을 반영한 동시 오류 확률은

$$
\begin{aligned}
P(C_1=0,C_2=0)
&=(0.1)^2+\rho(0.9)(0.1)\\
&=0.01+0.5\times0.09\\
&=0.055.
\end{aligned}
$$

독립 가정의 $0.01$보다 $5.5$배 크다. 따라서 같은 “안전” 두 표가 동시에 틀릴 가능성을 과소평가하면 안 된다. $J_3$가 다른 계열이라는 사실은 도움이 되지만, 실제 독립성은 데이터로 점검해야 한다.

다만 이 상관 예시만으로 “세 judge가 안전이라고 했을 때 실제로 위험일 사후확률”까지 계산할 수는 없다. 그 값에는 위험의 사전확률과 각 실제 클래스에서의 민감도·특이도, 세 judge의 클래스 조건부 결합분포도 필요하다.

첫 PPC로는 **같은 계열의 동시 오류율**을 권한다.

$$
T_{\mathrm{within}}
=
\frac{
\sum_i
\mathbf 1\{C_{i1}=0,C_{i2}=0\}
}{
n
}.
$$

관측 $T_{\mathrm{within}}$이 사후예측 분포보다 훨씬 크면 $u_{ig}$의 구조나 계열 정의가 공유 오류를 충분히 설명하지 못한다. 다른 계열 간 동시 오류율과 한국어·모바일 구간별 오류율도 함께 비교해야 한다.

weighted conformal의 자동 확대는 아직 허용하면 안 된다. 이유는 세 가지다.

1. 큰 밀도비로 $N_{\mathrm{eff}}$가 작아졌다면 분위수가 소수 항목에 지배된다.
2. 한국어 모바일 영역이 과거 검량 support 밖이면 가중으로 새 정보를 만들 수 없다.
3. agent 모델 교체는 적어도 $P_\theta(\widehat Y,S\mid X)$와 조건부 오류분포를 바꾸므로 기존 score 검량을 무효화할 수 있다. 이것만으로 환경의 $P(Y\mid X)$가 바뀌었다고 단정할 수는 없지만, covariate-shift 가중치만으로 해결되지 않는다.

따라서 고위험 자동 통과를 **HOLD**하고, 새 모델·새 트래픽의 무작위 또는 층화 audit에서 성숙 gold label을 모은다. 그 뒤 judge 계층모형과 PPC를 다시 적합하고, overlap·최대 가중치·$N_{\mathrm{eff}}$를 확인한 fresh split에서 임계값을 재검량한다.
