## 학습 목표

CLIP은 이미지와 문장을 각각 벡터로 바꾼 뒤, 한 배치 안의 올바른 쌍을 찾는 문제로 두 인코더를 함께 학습한다. 이 글을 마치면 다음을 할 수 있다.

- 이미지 인코더와 텍스트 인코더의 출력 shape를 공동 임베딩 공간까지 추적한다.
- L2 정규화, 학습 가능한 logit scale, 대칭 교차 엔트로피를 단계별로 유도한다.
- 작은 $2 \times 2$ 예를 손으로 계산하고 NumPy 결과와 비교한다.
- 실행 가능한 PyTorch dual encoder와 zero-shot classifier를 구현한다.
- C++과 C#에서 동일한 안정적 softmax loss를 재현한다.
- layout·dtype·tokenization 계약을 프레임워크 사이에서 맞춘다.
- false negative, 중복 caption, 작은 batch, mixed precision, 분산 `all_gather` 실패를 진단한다.
- 이미지·텍스트 인코더를 분리 배포하고 prompt embedding을 캐시하는 기준을 세운다.

## 선수 지식과 기호

batch 크기를 $N$, 공동 임베딩 차원을 $D$라고 하자. 이미지 batch는 $X \in \mathbb{R}^{N \times C \times H \times W}$, token id는 $U \in \mathbb{N}^{N \times L}$이다. $L$은 padding을 포함한 최대 token 길이다.

이미지 인코더 $f_\theta$와 텍스트 인코더 $g_\phi$가 만든 투영 전 특징 차원을 각각 $D_I,D_T$라 하고, 선형 투영 행렬을 $W_I \in \mathbb{R}^{D_I \times D}$, $W_T \in \mathbb{R}^{D_T \times D}$라 하자.

| 기호 | 뜻 | 대표 shape |
| --- | --- | --- |
| $h_i^I$ | $i$번째 이미지의 encoder feature | $(D_I)$ |
| $h_i^T$ | $i$번째 문장의 encoder feature | $(D_T)$ |
| $v_i$ | 정규화된 image embedding | $(D)$ |
| $t_i$ | 정규화된 text embedding | $(D)$ |
| $S$ | cosine similarity matrix | $(N,N)$ |
| $A$ | logit matrix | $(N,N)$ |
| $\tau$ | temperature | scalar, $\tau>0$ |
| $\alpha$ | logit scale | scalar, $\alpha=1/\tau$ |

교재의 `InfoNCE`라는 이름은 널리 쓰이는 설명이지만, 구현 관점에서는 **정규화된 두 embedding 집합에 적용한 양방향 cross entropy**라고 읽으면 가장 정확하다.

## 1. 닫힌 분류기에서 언어로 만든 분류기로

일반적인 $K$-class classifier의 마지막 weight는 $W \in \mathbb{R}^{D \times K}$로 고정된다. 추론할 수 있는 class 집합도 이 $K$개에 묶인다.

CLIP zero-shot 분류는 class 이름을 prompt로 바꾼 뒤 text encoder로 class weight를 즉석에서 만든다. 예를 들어 class가 `고양이`, `개`, `자동차`라면 다음 문장들을 encoding한다.

- `고양이 사진`
- `개 사진`
- `자동차 사진`

정규화한 text embedding을 열 방향으로 쌓으면 $T_{class} \in \mathbb{R}^{K \times D}$가 된다. 이미지 embedding $V \in \mathbb{R}^{N \times D}$와의 logit은 다음과 같다.

$$
A_{zero} = \alpha V T_{class}^{\mathsf{T}}
$$

결과 shape는 $(N,K)$다. 즉 일반 classifier의 학습된 weight 대신 **언어에서 계산한 weight**를 쓴다고 볼 수 있다.

> 원문 교정 1: CLIP 이전의 “모든 비전 AI”가 closed-set이었다는 표현은 지나치다. open-vocabulary·zero-shot 연구는 이전에도 있었다. CLIP의 중요한 기여는 대규모 자연어-이미지 쌍과 단순한 대조 목적을 결합해 여러 데이터셋에서 전이 가능한 zero-shot 분류기를 보인 것이다.

또한 open-vocabulary는 무한하고 무조건 정확한 인식이라는 뜻이 아니다. 추론 시점에는 여전히 사용자가 제시한 $K$개 후보 문장 안에서 고른다. prompt 표현, 언어, 학습 데이터 분포, 세밀한 class 차이에 따라 결과가 크게 달라질 수 있다.

## 2. 두 인코더가 만나는 공동 임베딩 공간

### 2.1 전체 tensor shape 추적

대표적인 image-text batch의 흐름은 다음과 같다.

| 단계 | 이미지 경로 | 텍스트 경로 |
| --- | --- | --- |
| 입력 | $(N,3,H,W)$, `float32` | $(N,L)$, `int64` token id |
| backbone | $(N,D_I)$ | $(N,L,D_T)$ |
| 문장 pooling | 이미 완료 | $(N,D_T)$ |
| projection | $(N,D)$ | $(N,D)$ |
| L2 normalize | $(N,D)$ | $(N,D)$ |
| matrix multiply | $(N,D)@(D,N)$ | 공동 결과 $(N,N)$ |

텍스트 encoder의 한 문장 대표값은 구현마다 다르다. 원래 CLIP 계열은 end-of-text 위치의 hidden state를 사용하는 방식이 흔하다. `mean pooling`, 첫 token, 마지막 padding 위치를 임의로 섞으면 같은 checkpoint라도 다른 embedding이 나온다.

### 2.2 투영과 L2 정규화

투영 전 특징을 공동 차원으로 보낸다.

$$
z_i^I = h_i^I W_I
$$

$$
z_i^T = h_i^T W_T
$$

그다음 각 row를 단위 길이로 만든다.

$$
v_i = \frac{z_i^I}{\lVert z_i^I \rVert_2}
$$

$$
t_i = \frac{z_i^T}{\lVert z_i^T \rVert_2}
$$

따라서 $v_i^{\mathsf{T}}t_j$는 cosine similarity이고 범위는 $[-1,1]$이다. production code에서는 0으로 나누지 않도록 norm에 작은 $\epsilon$을 둔다.

## 3. 유사도 행렬과 대칭 손실 유도

### 3.1 similarity와 logit은 구분한다

모든 image-text 조합의 cosine similarity를 행렬로 쓴다.

$$
S_{ij}=v_i^{\mathsf{T}}t_j
$$

softmax에 들어갈 logit은 scale을 곱한 값이다.

$$
A_{ij}=\alpha S_{ij}=\frac{S_{ij}}{\tau}
$$

$S$와 $A$의 shape는 둘 다 $(N,N)$이지만 값의 범위는 다르다. $S$는 $[-1,1]$이고, $A$는 $\alpha$ 때문에 더 넓어진다.

원래 구현 방식은 양수인 $\alpha$를 보장하기 위해 자유 parameter $s$를 두고 다음처럼 계산한다.

$$
\alpha=\exp(s)
$$

초기 temperature가 $0.07$이면 $s_0=\log(1/0.07)$이다. 수치 폭주를 막기 위해 $\alpha$의 상한을 두는 구현도 사용한다.

> 원문 교정 2: 모델이 temperature $\tau$ 자체를 제한 없이 직접 학습한다고 이해하면 부정확하다. 보통 학습 parameter는 `logit_scale`의 로그 $s$이고, 실제 곱셈값은 $\exp(s)=1/\tau$다.

### 3.2 image-to-text 확률

한 image row $i$에서 $N$개 text 중 올바른 text $i$를 고르는 확률은 다음과 같다.

$$
p_{ij}^{I \to T}
=
\frac{\exp(A_{ij})}
{\sum_{k=1}^{N}\exp(A_{ik})}
$$

row 방향 cross entropy는 다음과 같다.

$$
\mathcal{L}_{I \to T}
=
-\frac{1}{N}
\sum_{i=1}^{N}
\log p_{ii}^{I \to T}
$$

### 3.3 text-to-image 확률

같은 행렬의 column 방향에서는 text $j$가 올바른 image $j$를 고른다.

$$
p_{ij}^{T \to I}
=
\frac{\exp(A_{ij})}
{\sum_{k=1}^{N}\exp(A_{kj})}
$$

$$
\mathcal{L}_{T \to I}
=
-\frac{1}{N}
\sum_{j=1}^{N}
\log p_{jj}^{T \to I}
$$

최종 손실은 두 방향 평균이다.

$$
\mathcal{L}_{CLIP}
=
\frac{1}{2}
\left(
\mathcal{L}_{I \to T}
+
\mathcal{L}_{T \to I}
\right)
$$

두 방향을 모두 쓰는 이유는 image retrieval과 text retrieval의 ranking을 동시에 학습하기 위해서다.

### 3.4 gradient가 실제로 요구하는 것

row loss만 보면 logit에 대한 gradient는 다음과 같다.

$$
\frac{\partial \mathcal{L}_{I \to T}}
{\partial A_{ij}}
=
\frac{1}{N}
\left(
p_{ij}^{I \to T}
-
\mathbf{1}[i=j]
\right)
$$

정답 logit은 확률이 1보다 작은 동안 증가하고, 오답 logit은 현재 softmax 확률에 비례해 감소한다.

> 원문 교정 3: 모든 대각선 밖 similarity를 반드시 $-1$로 보내는 목적은 아니다. cross entropy는 정답 logit이 같은 row와 column의 경쟁자보다 충분히 크기를 요구한다. 이미 쉬운 negative는 gradient가 작으며, 의미가 비슷한 caption을 무조건 반대 방향 벡터로 만들 필요도 없다.

## 4. $2 \times 2$ 손계산

$D=2$이고 올바른 image-text 쌍이 같은 단위 벡터라고 하자.

$$
V=
\begin{bmatrix}
1 & 0 \\
0 & 1
\end{bmatrix}
,\qquad
T=
\begin{bmatrix}
1 & 0 \\
0 & 1
\end{bmatrix}
$$

$\alpha=1$이면 similarity와 logit은 같다.

$$
A=VT^{\mathsf{T}}
=
\begin{bmatrix}
1 & 0 \\
0 & 1
\end{bmatrix}
$$

첫 row에서 정답 확률은 다음과 같다.

$$
p_{11}
=
\frac{e^1}{e^1+e^0}
=
\frac{e}{e+1}
\approx 0.731059
$$

두 row와 두 column이 대칭이므로 네 cross entropy 항이 모두 같다.

$$
\mathcal{L}_{CLIP}
=
-\log(0.731059)
=
\log(1+e^{-1})
\approx 0.313262
$$

$\alpha$를 크게 하면 이 완벽히 정렬된 예의 loss는 더 작아진다. 그러나 실제 batch에 잘못된 positive나 서로 같은 의미의 false negative가 있으면 큰 scale이 그 label noise도 날카롭게 증폭한다.

## 5. NumPy 수작업 검증

아래 코드는 실행 가능하다. `logsumexp`를 직접 구현해 큰 logit에서도 overflow를 피하고, analytic gradient와 central finite difference를 비교한다.

```python
import numpy as np

def logsumexp(x: np.ndarray, axis: int) -> np.ndarray:
    m = np.max(x, axis=axis, keepdims=True)
    return np.squeeze(m, axis=axis) + np.log(
        np.exp(x - m).sum(axis=axis)
    )

def symmetric_clip_loss(logits: np.ndarray) -> float:
    n = logits.shape[0]
    if logits.shape != (n, n):
        raise ValueError("logits must be square")
    target = np.arange(n)
    row = -logits[target, target] + logsumexp(logits, axis=1)
    col = -logits[target, target] + logsumexp(logits, axis=0)
    return float(0.5 * (row.mean() + col.mean()))

v = np.eye(2, dtype=np.float64)
t = np.eye(2, dtype=np.float64)
logits = v @ t.T
loss = symmetric_clip_loss(logits)
expected = np.log1p(np.exp(-1.0))
np.testing.assert_allclose(loss, expected, rtol=0.0, atol=1e-12)

row_prob = np.exp(logits) / np.exp(logits).sum(axis=1, keepdims=True)
row_grad = (row_prob - np.eye(2)) / 2.0

eps = 1e-6
plus = logits.copy()
minus = logits.copy()
plus[0, 1] += eps
minus[0, 1] -= eps
numeric = (
    (-plus.diagonal().mean() + logsumexp(plus, axis=1).mean())
    - (-minus.diagonal().mean() + logsumexp(minus, axis=1).mean())
) / (2.0 * eps)
np.testing.assert_allclose(numeric, row_grad[0, 1], atol=1e-8)

print(f"loss={loss:.6f}")
print(f"row_grad_01={row_grad[0, 1]:.6f}")
```

예상 출력은 다음과 같다.

```text
loss=0.313262
row_grad_01=0.134471
```

## 6. 실행 가능한 PyTorch 최소 구현

다음 예제는 작은 image encoder와 text encoder를 함께 학습하고 zero-shot logit까지 만든다. 실제 CLIP의 backbone 크기를 재현하는 코드는 아니지만 loss, shape, normalization, scale 계약은 실행 가능하다.

```python
import math
import torch
from torch import nn
import torch.nn.functional as F

class TinyCLIP(nn.Module):
    def __init__(self, vocab_size: int, embed_dim: int = 16):
        super().__init__()
        self.image_encoder = nn.Sequential(
            nn.Conv2d(3, 8, kernel_size=3, stride=2, padding=1),
            nn.GELU(),
            nn.AdaptiveAvgPool2d(1),
            nn.Flatten(),
        )
        self.image_projection = nn.Linear(8, embed_dim, bias=False)
        self.token_embedding = nn.Embedding(vocab_size, 12, padding_idx=0)
        self.text_projection = nn.Linear(12, embed_dim, bias=False)
        self.logit_scale_log = nn.Parameter(
            torch.tensor(math.log(1.0 / 0.07))
        )

    def encode_image(self, images: torch.Tensor) -> torch.Tensor:
        features = self.image_encoder(images)
        return F.normalize(self.image_projection(features), dim=-1)

    def encode_text(
        self, token_ids: torch.Tensor, attention_mask: torch.Tensor
    ) -> torch.Tensor:
        tokens = self.token_embedding(token_ids)
        mask = attention_mask.unsqueeze(-1).to(tokens.dtype)
        pooled = (tokens * mask).sum(dim=1) / mask.sum(dim=1).clamp_min(1.0)
        return F.normalize(self.text_projection(pooled), dim=-1)

    def forward(
        self,
        images: torch.Tensor,
        token_ids: torch.Tensor,
        attention_mask: torch.Tensor,
    ) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        image_embeddings = self.encode_image(images)
        text_embeddings = self.encode_text(token_ids, attention_mask)
        scale = self.logit_scale_log.exp().clamp(max=100.0)
        logits = scale * image_embeddings @ text_embeddings.T
        labels = torch.arange(logits.shape[0], device=logits.device)
        loss_i = F.cross_entropy(logits, labels)
        loss_t = F.cross_entropy(logits.T, labels)
        return 0.5 * (loss_i + loss_t), image_embeddings, text_embeddings

torch.manual_seed(7)
model = TinyCLIP(vocab_size=32)
images = torch.randn(4, 3, 16, 16)
token_ids = torch.tensor([
    [1, 2, 3, 0],
    [4, 5, 0, 0],
    [6, 7, 8, 9],
    [10, 11, 0, 0],
])
attention_mask = token_ids.ne(0)

loss, image_embeddings, text_embeddings = model(
    images, token_ids, attention_mask
)
assert image_embeddings.shape == (4, 16)
assert text_embeddings.shape == (4, 16)
torch.testing.assert_close(
    image_embeddings.norm(dim=-1), torch.ones(4), atol=1e-5, rtol=1e-5
)
torch.testing.assert_close(
    text_embeddings.norm(dim=-1), torch.ones(4), atol=1e-5, rtol=1e-5
)
loss.backward()
assert torch.isfinite(loss)
assert all(
    parameter.grad is None or torch.isfinite(parameter.grad).all()
    for parameter in model.parameters()
)

# 세 class prompt를 미리 encoding했다고 가정한 zero-shot 분류
class_tokens = torch.tensor([
    [12, 13, 0],
    [14, 15, 0],
    [16, 17, 0],
])
class_mask = class_tokens.ne(0)
with torch.no_grad():
    class_embeddings = model.encode_text(class_tokens, class_mask)
    zero_shot_logits = (
        model.logit_scale_log.exp().clamp(max=100.0)
        * image_embeddings[:2]
        @ class_embeddings.T
    )
assert zero_shot_logits.shape == (2, 3)
print(tuple(image_embeddings.shape), tuple(zero_shot_logits.shape))
print(f"loss={loss.item():.6f}")
```

`attention_mask`가 전부 0인 문장을 허용하지 않는 것이 더 좋은 입력 계약이다. 예제는 분모를 보호하지만, 빈 문장을 정상 prompt로 취급한다는 뜻은 아니다.

## 7. C++ 예제

아래 C++17 코드는 외부 tensor library 없이 $2 \times 2$ logit의 대칭 loss를 계산한다. **실행 가능한 수치 검증용 예제**이며 전체 encoder 구현은 아니다.

```cpp
#include <array>
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>

using Matrix2 = std::array<std::array<double, 2>, 2>;

double logsumexp(double a, double b) {
    const double maximum = a > b ? a : b;
    return maximum + std::log(std::exp(a - maximum) + std::exp(b - maximum));
}

double symmetric_clip_loss(const Matrix2& logits) {
    double row_loss = 0.0;
    double column_loss = 0.0;
    for (std::size_t i = 0; i < 2; ++i) {
        row_loss += -logits[i][i]
            + logsumexp(logits[i][0], logits[i][1]);
        column_loss += -logits[i][i]
            + logsumexp(logits[0][i], logits[1][i]);
    }
    return 0.25 * (row_loss + column_loss);
}

int main() {
    const Matrix2 logits{{{{1.0, 0.0}}, {{0.0, 1.0}}}};
    const double loss = symmetric_clip_loss(logits);
    const double expected = std::log1p(std::exp(-1.0));
    assert(std::abs(loss - expected) < 1e-12);
    std::cout << std::fixed << std::setprecision(6)
              << "loss=" << loss << '\n';
}
```

예상 출력은 `loss=0.313262`다. 실제 배포에서는 image와 text encoder의 matrix multiplication을 Eigen, oneDNN, ONNX Runtime 같은 backend에 맡기되, 정규화 축과 embedding 순서를 golden test로 고정해야 한다.

## 8. C# 예제

아래 C# 예제도 동일한 $2 \times 2$ 계산을 수행한다. **실행 가능한 수치 검증용 예제**다.

```csharp
using System;

public static class ClipLossExample
{
    private static double LogSumExp(double a, double b)
    {
        double maximum = Math.Max(a, b);
        return maximum
            + Math.Log(Math.Exp(a - maximum) + Math.Exp(b - maximum));
    }

    private static double SymmetricClipLoss(double[,] logits)
    {
        if (logits.GetLength(0) != 2 || logits.GetLength(1) != 2)
            throw new ArgumentException("Expected a 2x2 matrix.");

        double rowLoss = 0.0;
        double columnLoss = 0.0;
        for (int i = 0; i < 2; ++i)
        {
            rowLoss += -logits[i, i]
                + LogSumExp(logits[i, 0], logits[i, 1]);
            columnLoss += -logits[i, i]
                + LogSumExp(logits[0, i], logits[1, i]);
        }
        return 0.25 * (rowLoss + columnLoss);
    }

    public static void Main()
    {
        double[,] logits = {{1.0, 0.0}, {0.0, 1.0}};
        double loss = SymmetricClipLoss(logits);
        double expected = Math.Log(1.0 + Math.Exp(-1.0));
        if (Math.Abs(loss - expected) >= 1e-12)
            throw new Exception("Golden loss mismatch.");
        Console.WriteLine($"loss={loss:F6}");
    }
}
```

예상 출력은 C++과 같은 `loss=0.313262`다.

## 9. 프레임워크 간 shape·layout·dtype 대응

| 의미 | PyTorch | C++/ONNX 관례 | C#/ONNX Runtime 관례 | 주의점 |
| --- | --- | --- | --- | --- |
| image input | `NCHW`, `float32` | model metadata를 따름 | dense tensor shape 명시 | `NHWC`를 조용히 넣지 않는다 |
| token id | `(N,L)`, `int64` | `int64_t` | `long` | `int32` model도 있으므로 signature 확인 |
| attention mask | `(N,L)`, `bool` | `bool` 또는 integer | `bool` 또는 `long` | padding 방향과 mask 의미 확인 |
| image embedding | `(N,D)` | row-major가 흔함 | `(N,D)` | row별 L2 normalize |
| text embedding | `(K,D)` | row-major가 흔함 | `(K,D)` | prompt 순서가 class id |
| similarity | `V @ T.T` | GEMM, `(N,K)` | matrix multiply, `(N,K)` | transpose flag 확인 |
| mixed precision | encoder는 `float16` 가능 | backend별 | provider별 | norm·softmax는 `float32` 권장 |

가장 위험한 계약은 tokenizer다. vocabulary, byte-pair merge 규칙, 시작·종료 token, context length, truncation, padding이 training 때와 하나라도 다르면 text encoder가 실행은 되면서도 의미가 달라진다.

## 10. 테스트와 디버깅

### 10.1 최소 단위 테스트

다음 순서로 문제를 좁힌다.

1. image와 text embedding shape가 모두 $(N,D)$인지 확인한다.
2. 모든 row norm이 허용 오차 안에서 1인지 확인한다.
3. logit shape가 $(N,N)$인지 확인한다.
4. 올바른 pair label이 `0,1,...,N-1`인지 확인한다.
5. row loss와 transposed column loss를 둘 다 계산했는지 확인한다.
6. 동일한 embedding을 넣은 golden case에서 diagonal logit이 가장 큰지 확인한다.
7. extreme logit에서도 loss와 gradient가 finite인지 확인한다.
8. batch 순서 하나를 text 쪽에서만 바꾸면 loss가 증가하는지 확인한다.

### 10.2 자주 생기는 버그

| 증상 | 가능 원인 | 확인 방법 |
| --- | --- | --- |
| loss가 계속 $\log N$ 근처 | encoder가 상수 embedding 출력 | batch row 간 cosine 분산 확인 |
| diagonal accuracy가 우연 수준 | image와 caption shuffle 불일치 | sample id를 양쪽에 함께 기록 |
| 한 방향 loss만 낮음 | transpose 또는 label 축 오류 | row·column top-1을 따로 출력 |
| `NaN` 발생 | 0 norm, 큰 scale, 불안정 softmax | norm 최소값·scale·dtype 기록 |
| 단일 GPU는 정상, 분산은 실패 | global pair index 오류 | rank offset을 포함한 label 확인 |
| zero-shot 결과가 언어마다 급변 | prompt/tokenizer mismatch | token id와 truncation 위치 비교 |

### 10.3 분산 학습에서의 label

각 rank에 local batch $B$개, world size가 $R$이면 global logit은 보통 $(B,BR)$ 또는 global gather 뒤 $(BR,BR)$이다. rank $r$의 local image가 가리킬 positive text index는 단순 `0..B-1`이 아니라 다음 offset을 포함해야 한다.

$$
y_i=rB+i
$$

feature gather가 gradient를 보존하는지, 다른 rank feature를 상수 negative로 취급하는지는 구현 선택이다. 두 구현의 유효 batch와 gradient가 같다고 가정하면 재현성이 깨진다.

## 11. 성능·메모리·수치 안정성

similarity matrix 계산량은 $O(N^2D)$, 저장량은 $O(N^2)$다. `float32` logit 하나는 4 byte이므로 $N=32768$이면 한 방향 행렬만 약 4 GiB다.

$$
32768^2 \times 4
=
4294967296\text{ bytes}
$$

실제 학습은 분산 행렬 곱, local loss, feature gather, chunking 등을 조합한다. 논문의 큰 global batch 숫자를 한 GPU tensor로 그대로 만들면 메모리가 먼저 소진된다.

실무 체크 포인트는 다음과 같다.

- embedding normalize와 `logsumexp`는 가능하면 `float32`로 계산한다.
- `exp(logit_scale_log)`가 무한대로 가지 않도록 범위와 finite 여부를 기록한다.
- matrix multiplication은 `float16` 또는 `bfloat16`을 쓸 수 있지만 loss를 무조건 같은 dtype에 둘 필요는 없다.
- 같은 batch에 거의 동일한 caption이 여러 개 있으면 서로 false negative가 된다.
- batch가 작으면 negative 다양성이 줄고, batch가 크면 통신량과 $N^2$ logit 비용이 커진다.
- gradient accumulation은 encoder update batch는 키우지만, 각 microbatch에서 보는 negative 수를 자동으로 늘리지는 않는다.
- text embedding은 prompt가 고정된 zero-shot 서비스에서 미리 계산하고 캐시한다.

## 12. 원문의 생성형 AI 설명을 배포 관점에서 교정

> 원문 교정 4: “DALL-E와 Stable Diffusion이 생성 픽셀의 CLIP cosine similarity를 높이며 이미지를 깎는다”는 하나의 일반 원리로 묶으면 부정확하다. 표준 latent diffusion 계열에서는 CLIP 계열 text encoder의 hidden state가 cross-attention conditioning으로 사용될 수 있지만, 매 step마다 완성 이미지와 문장의 CLIP cosine을 직접 최적화하는 것과는 다르다. 모델·버전별 conditioning 경로를 확인해야 한다.

CLIP 자체는 image generator가 아니라 encoder 쌍이다. 생성 모델에서 쓰이더라도 다음 구성요소를 구분해야 한다.

| 구성요소 | 입력 | 출력 | 역할 |
| --- | --- | --- | --- |
| CLIP text encoder | token id | text hidden state 또는 embedding | 언어 조건 |
| CLIP image encoder | image | image embedding | 검색·평가·image condition 등에 사용 가능 |
| denoiser | noisy latent와 조건 | noise 또는 velocity 예측 | 생성 dynamics |
| decoder | latent | image | pixel 공간 복원 |

## 13. 실무 실패 사례

### 사례 A: 서로 다른 사진의 같은 caption

batch에 고양이 사진 두 장이 있고 caption이 둘 다 `고양이 사진`이라면, 대각선 규칙은 한 caption만 positive로 두고 다른 하나는 negative로 취급한다. loss가 데이터 의미와 충돌한다.

대응 방법은 dataset에서 중복을 줄이고, 같은 의미의 여러 positive를 허용하는 multi-positive loss를 검토하며, sample id와 caption hash를 관찰하는 것이다.

### 사례 B: service tokenizer가 training tokenizer와 다름

ONNX text encoder만 배포하고 애플리케이션에서 임의 tokenizer를 붙이면 shape는 맞아도 embedding이 망가질 수 있다. tokenizer artifact와 model을 하나의 version으로 묶고 golden token id를 CI에서 비교해야 한다.

### 사례 C: prompt 하나만으로 class benchmark를 고정

`개`, `개의 사진`, `흐릿한 개 사진`은 다른 embedding을 만든다. prompt ensemble을 쓰면 class별 여러 문장을 정규화해 평균내고 다시 정규화한다.

$$
\bar{t}_k
=
\operatorname{normalize}
\left(
\frac{1}{M}
\sum_{m=1}^{M}t_{k,m}
\right)
$$

하지만 benchmark prompt를 test 결과를 보며 반복 수정하면 사실상 test set에 맞춘 선택이 된다. prompt 목록도 실험 설정으로 versioning해야 한다.

### 사례 D: similarity threshold를 모든 모델에 재사용

cosine similarity는 정규화되어도 model version, 데이터 도메인, prompt에 따라 분포가 변한다. retrieval threshold나 거절 기준은 새 model별 validation set에서 다시 calibration한다.

## 14. 배포 설계

zero-shot image classification 서비스는 다음처럼 분리할 수 있다.

1. model 배포 시 class prompt를 text encoder에 넣는다.
2. prompt별 embedding을 평균·정규화해 class matrix $(K,D)$를 만든다.
3. class matrix와 prompt version을 캐시에 저장한다.
4. 요청 image를 image encoder로 embedding $(1,D)$로 만든다.
5. $(1,D)@(D,K)$를 계산하고 scale과 softmax를 적용한다.
6. top-k label, score, model version, prompt version을 반환한다.

이 구조는 요청마다 text encoder를 실행하지 않아 latency를 줄인다. class 목록이 자주 바뀌는 서비스라면 text encoder를 별도 endpoint로 두되, 서로 다른 image/text model version의 embedding을 섞지 않도록 joint model id를 강제한다.

ONNX export 뒤에는 다음 golden data를 최소 한 세트 보관한다.

- 전처리된 image tensor와 image embedding
- token id·attention mask와 text embedding
- 정규화 전후 norm
- logit scale
- 최종 similarity와 top-k 순서

## 17. 연습문제 해답

### 해답 1

image와 text embedding은 각각 $(8,512)$, similarity matrix는 $(8,8)$이다.

### 해답 2

모델이 의미적 방향을 개선하는 대신 norm을 키워 logit 차이를 확대할 수 있다. modality별 norm 차이도 similarity를 오염시킨다. L2 정규화는 방향만 비교하게 하고, 전체 sharpness는 별도 logit scale이 담당하게 한다.

### 해답 3

각 방향에서 정답 확률은 $1/2$이므로 loss는 다음과 같다.

$$
-\log(1/2)=\log 2 \approx 0.693147
$$

두 방향 평균도 같은 값이다.

### 해답 4

rank offset은 $2 \times 16=32$, 세 번째 sample의 local index는 2이므로 global index는 $34$다.

### 해답 5

class 목록, prompt template, tokenizer, text encoder, projection weight가 고정되면 캐시할 수 있다. 이 가운데 하나가 바뀌거나 embedding dtype·정규화 규칙이 바뀌면 폐기하고 다시 계산해야 한다.

## 핵심 요약

- CLIP은 image encoder와 text encoder를 같은 $D$차원 단위 구면에 정렬한다.
- similarity $S=VT^{\mathsf{T}}$와 scaled logit $A=\alpha S$를 구분해야 한다.
- 학습 parameter는 보통 logit scale의 로그이며 $\alpha=\exp(s)=1/\tau$다.
- 대칭 loss는 image-to-text row CE와 text-to-image column CE의 평균이다.
- off-diagonal pair를 모두 cosine $-1$로 만드는 것이 아니라, 올바른 pair를 경쟁자보다 높게 ranking한다.
- zero-shot 분류는 class prompt embedding을 classifier weight처럼 사용한다.
- tokenizer·전처리·prompt·model version은 하나의 배포 계약이다.
- 큰 batch는 negative를 늘리지만 $O(N^2)$ logit 메모리와 분산 통신을 요구한다.
- 중복 caption은 false negative가 될 수 있고, gradient accumulation만으로 negative 수가 늘지는 않는다.
- CLIP encoder와 diffusion denoiser의 역할을 구분해야 생성 pipeline을 정확히 이해할 수 있다.
