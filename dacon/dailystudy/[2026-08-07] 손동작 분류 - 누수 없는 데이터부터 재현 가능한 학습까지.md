## 1. 오늘의 구현 목표

## 2. 선수 지식과 기호

이미지 batch, 클래스 수, 모델 출력 logits를 다음과 같이 쓴다.

$$
X \in \mathbb{R}^{N \times C \times H \times W},
\qquad
y \in \{0,\ldots,K-1\}^{N},
\qquad
Z=f_{\theta}(X) \in \mathbb{R}^{N \times K}
$$

- $N$: batch 크기
- $C$: 채널 수, RGB라면 3
- $H,W$: 입력 높이와 너비
- $K$: 클래스 수
- $\theta$: 학습 가능한 파라미터
- $Z_{n,k}$: 샘플 $n$이 클래스 $k$라고 보는 정규화 전 점수

PyTorch의 일반적인 계약은 다음과 같다.

| 경계 | shape | dtype | layout 또는 의미 |
| --- | --- | --- | --- |
| OpenCV 입력 | `(H, W, 3)` | `uint8` | HWC, 기본 BGR |
| 전처리 후 이미지 | `(3, H, W)` | `float32` | CHW, RGB |
| `DataLoader` batch | `(N, 3, H, W)` | `float32` | NCHW |
| 정답 | `(N,)` | `int64` | class index |
| 모델 출력 | `(N, K)` | `float32` | logits, softmax 이전 |
| 예측 | `(N,)` | `int64` | `argmax(dim=1)` |

`CrossEntropyLoss`에는 one-hot 벡터나 softmax 확률이 아니라 `(N, K)` logits와 `(N,)` `int64` class index를 넣는다.

## 3. 원본 구현을 실행 계약으로 다시 읽기

원본의 큰 흐름인 CSV 로드, 이미지 경로 수집, 변환, `Dataset`, 분할, CNN, 학습·검증은 올바른 출발점이다. 다만 교육용 셀 사이에 숨어 있는 전제를 운영 가능한 코드에서는 명시해야 한다.

| 원본의 전제 또는 표현 | 위험 | 이번 구현의 수정 |
| --- | --- | --- |
| 정렬한 JPG 목록과 CSV 라벨 순서가 같다고 가정 | 파일 누락·추가 시 이후 라벨이 모두 한 칸씩 밀릴 수 있음 | 파일 ID를 key로 `merge`하고 one-to-one 및 누락을 검사 |
| 경로를 `split('/')`로 분해 | Windows 경로에서 깨짐 | `pathlib.Path(path).stem` 사용 |
| `train_test_split(..., random_state=42)`만 사용 | 희소 클래스가 한쪽에서 사라질 수 있음 | 최소한 `stratify=labels`; 동일 촬영자라면 group split 우선 |
| ImageNet 평균·표준편차를 무조건 사용 | scratch 모델과 다른 카메라 분포에서는 최선이라는 보장이 없음 | pretrained 계약이면 ImageNet 통계, scratch면 train-only 통계도 실험 |
| 64 입력은 모델 파라미터를 줄임 | 합성곱 kernel 파라미터 수는 입력 해상도와 무관함 | MAC·activation과 flatten head 파라미터를 구분 |
| batch 평균 loss를 batch 수로 다시 평균 | 마지막 batch가 작으면 샘플 평균과 달라짐 | `loss * batch_size`를 누적해 전체 샘플 수로 나눔 |
| 정규화된 tensor를 바로 `imshow` | 색 범위가 왜곡됨 | `x * std + mean`으로 역정규화 후 시각화 |
| accuracy만 기록 | 클래스 불균형과 특정 손동작 붕괴를 숨김 | confusion matrix, per-class recall, macro F1 추가 |

라벨 `'10-1' -> '10'`, `'10-2' -> '0'` 치환은 데이터셋의 공식 클래스 정의라면 가능하다. 그러나 서로 다른 원시 클래스가 같은 정수로 합쳐지므로, 일반적인 숫자 정리로 취급해서는 안 된다. 매핑 테이블을 버전 관리하고 치환 전후 클래스 수와 충돌을 검사해야 한다.

## 4. 데이터 계약: 경로와 라벨은 같은 ID로 결합한다

### 4.1 안전한 manifest 만들기

설명용 코드다. 실제 CSV의 ID 컬럼 이름과 파일 확장자는 프로젝트에 맞춰 조정해야 한다.

```python
from pathlib import Path

import pandas as pd


def build_manifest(csv_path: Path, image_dir: Path) -> pd.DataFrame:
    labels = pd.read_csv(csv_path, dtype={"id": "string", "label": "string"})
    labels = labels.assign(id=labels["id"].str.strip())

    label_map = {"10-1": 10, "10-2": 0}
    labels["label"] = labels["label"].replace(label_map).astype("int64")

    if labels["id"].duplicated().any():
        raise ValueError("CSV id must be unique")

    images = pd.DataFrame(
        {
            "id": [path.stem for path in image_dir.glob("*.jpg")],
            "path": [str(path) for path in image_dir.glob("*.jpg")],
        }
    )
    if images["id"].duplicated().any():
        raise ValueError("image stem must be unique")

    merged = labels.merge(images, on="id", how="outer", validate="one_to_one", indicator=True)
    missing = merged.loc[merged["_merge"] != "both", ["id", "_merge"]]
    if not missing.empty:
        raise ValueError(f"CSV/image mismatch:\n{missing.head(10)}")

    return merged.drop(columns="_merge").sort_values("id").reset_index(drop=True)
```

숫자 파일명 정렬은 표현 순서를 편하게 만들 뿐, 라벨의 진실을 보장하지 않는다. `1.jpg`, `2.jpg`, `10.jpg`를 자연 정렬해도 CSV 두 번째 행이 반드시 `2.jpg`라는 근거는 없다. 결합 key가 근거다.

### 4.2 split의 우선순위

손 사진은 같은 사람, 같은 배경, 연속 프레임이 매우 비슷할 수 있다. 따라서 split 기준은 다음 순서로 선택한다.

1. **배포 상황을 재현하는 group split**: 사람 ID, 촬영 세션, 기기 ID 가운데 누수를 가장 잘 막는 key로 분리한다.
2. group 정보가 없으면 **stratified split**: 각 클래스 비율을 보존한다.
3. 데이터가 매우 작으면 여러 group fold로 변동성까지 보고한다.

동일 사람의 연속 프레임을 무작위로 나누면 검증 정확도는 높아도 새로운 사람에게 실패할 수 있다. 이것은 모델 문제가 아니라 평가 설계 문제다.

## 5. 전처리: 학습과 평가의 경계를 보존한다

픽셀 $x \in [0,255]$를 채널별 평균 $\mu_c$와 표준편차 $\sigma_c$로 정규화하면 다음과 같다.

$$
\widetilde{x}_{c,h,w}
=
\frac{x_{c,h,w}/255-\mu_c}{\sigma_c}
$$

scratch 모델에서 데이터셋 통계를 쓸 때 $\mu_c,\sigma_c$는 **train split에서만** 계산한다. validation까지 포함해 통계를 계산하면 라벨은 아니더라도 평가 분포의 정보가 학습 파이프라인에 들어온다.

| 단계 | 학습 | 검증·테스트 |
| --- | --- | --- |
| decode | RGB 변환, 실패 검사 | 동일 |
| 기하 변환 | 허용된 범위의 random crop·flip·rotation | deterministic resize 또는 center crop |
| 색 변환 | 장비 변화와 맞을 때만 jitter | 없음 |
| 정규화 | train-only 통계 또는 pretrained 계약 | 학습과 정확히 같은 통계 |
| tensor 변환 | CHW `float32` | 동일 |

손동작의 좌우 방향이 라벨 의미를 바꾼다면 horizontal flip은 label-preserving augmentation이 아니다. 증강은 시각적으로 자연스러운가가 아니라 **정답을 보존하는가**로 결정한다.

## 6. 분류 손실을 logits에서 유도하기

샘플 $n$의 softmax 확률은 다음과 같다.

$$
p_{n,k}
=
\frac{\exp(Z_{n,k})}
{\sum_{j=0}^{K-1}\exp(Z_{n,j})}
$$

정답 $y_n$에 대한 negative log-likelihood는 다음과 같다.

$$
\ell_n
=
-\log p_{n,y_n}
=
-Z_{n,y_n}
+
\log\left(\sum_{j=0}^{K-1}\exp(Z_{n,j})\right)
$$

큰 logit에서 overflow를 피하려면 $m_n=\max_j Z_{n,j}$를 빼서 log-sum-exp를 계산한다.

$$
\ell_n
=
-Z_{n,y_n}
+m_n
+
\log\left(\sum_{j=0}^{K-1}\exp(Z_{n,j}-m_n)\right)
$$

batch mean loss는 다음과 같다.

$$
L
=
\frac{1}{N}\sum_{n=0}^{N-1}\ell_n
$$

logit에 대한 gradient는 오차의 방향을 간단히 보여 준다.

$$
\frac{\partial L}{\partial Z_{n,k}}
=
\frac{1}{N}
\left(p_{n,k}-\mathbf{1}[k=y_n]\right)
$$

정답 클래스 확률은 올리고 나머지 클래스 확률은 내리는 방향이다. `CrossEntropyLoss` 앞에 softmax를 붙이면 이 안정적인 logits 경로를 깨고 gradient도 달라진다.

## 7. NumPy로 loss와 gradient를 독립 검증하기

다음은 **독립 실행 가능한 검증 코드**다. PyTorch 없이 수식과 중앙차분 gradient를 비교한다.

```python
import numpy as np


def cross_entropy(logits: np.ndarray, targets: np.ndarray) -> tuple[float, np.ndarray]:
    if logits.ndim != 2 or targets.shape != (logits.shape[0],):
        raise ValueError("shape mismatch")
    shifted = logits - logits.max(axis=1, keepdims=True)
    exp_values = np.exp(shifted)
    probabilities = exp_values / exp_values.sum(axis=1, keepdims=True)
    rows = np.arange(logits.shape[0])
    loss = -np.log(probabilities[rows, targets]).mean()
    gradient = probabilities.copy()
    gradient[rows, targets] -= 1.0
    gradient /= logits.shape[0]
    return float(loss), gradient


logits = np.array([[2.0, 0.0, -1.0], [1000.0, 1001.0, 999.0]], dtype=np.float64)
targets = np.array([0, 1], dtype=np.int64)
loss, analytic = cross_entropy(logits, targets)

epsilon = 1e-5
numeric = np.zeros_like(logits)
for row in range(logits.shape[0]):
    for column in range(logits.shape[1]):
        plus = logits.copy()
        minus = logits.copy()
        plus[row, column] += epsilon
        minus[row, column] -= epsilon
        numeric[row, column] = (
            cross_entropy(plus, targets)[0] - cross_entropy(minus, targets)[0]
        ) / (2.0 * epsilon)

np.testing.assert_allclose(analytic, numeric, rtol=1e-6, atol=1e-6)
assert np.isfinite(loss)
print(f"loss={loss:.6f}, max_gradient_error={np.abs(analytic - numeric).max():.3e}")
```

## 8. tensor shape을 끝까지 추적하기

오늘의 작은 CNN은 해상도를 고정 길이 head에 직접 새기지 않도록 adaptive average pooling을 사용한다.

| 단계 | 연산 | 출력 shape | 누적 의미 |
| --- | --- | --- | --- |
| 입력 | RGB batch | `(N, 3, 16, 16)` | 정규화된 손 이미지 |
| block 1 | `Conv2d(3, 8, 3, padding=1)` | `(N, 8, 16, 16)` | 저수준 패턴 |
| downsample 1 | `MaxPool2d(2)` | `(N, 8, 8, 8)` | 공간 길이 절반 |
| block 2 | `Conv2d(8, 16, 3, padding=1)` | `(N, 16, 8, 8)` | 조합된 패턴 |
| downsample 2 | `MaxPool2d(2)` | `(N, 16, 4, 4)` | 공간 길이 절반 |
| adaptive pool | `AdaptiveAvgPool2d((2, 2))` | `(N, 16, 2, 2)` | head 입력 고정 |
| flatten | `flatten(1)` | `(N, 64)` | batch 축 보존 |
| classifier | `Linear(64, K)` | `(N, K)` | logits |

두 합성곱의 파라미터 수는 bias 포함 다음과 같다.

$$
P_{\mathrm{conv1}}=8(3\cdot3\cdot3+1)=224
$$

$$
P_{\mathrm{conv2}}=16(8\cdot3\cdot3+1)=1168
$$

분류 head는 다음과 같다.

$$
P_{\mathrm{head}}=K(16\cdot2\cdot2+1)=65K
$$

입력 해상도를 줄여도 두 합성곱의 파라미터 수는 그대로다. 대신 feature map 위치 수가 줄어 MAC와 activation 메모리가 감소한다. 반면 원본처럼 공간 전체를 flatten하는 head는 해상도에 따라 파라미터 수도 바뀐다.

## 9. 완전한 PyTorch 학습·평가·테스트 구현

다음 코드는 외부 이미지 없이 **그대로 실행 가능**하다. 실제 손 사진 대신 클래스별 공간 패턴을 가진 작은 합성 이미지를 사용해 데이터 분할, train-only 정규화, 학습, 평가, confusion matrix, checkpoint payload, 재현성 테스트를 한 번에 검증한다.

```python
import random
from dataclasses import dataclass
from typing import Iterable

import numpy as np
import torch
from torch import nn
from torch.utils.data import DataLoader, Dataset, Subset


SEED = 20260807


def seed_everything(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.use_deterministic_algorithms(True)


class PatternDataset(Dataset[tuple[torch.Tensor, torch.Tensor]]):
    """세 클래스의 공간·채널 패턴을 가진 재현 가능한 uint8 이미지 집합."""

    def __init__(self, samples_per_class: int = 30, image_size: int = 16) -> None:
        generator = torch.Generator().manual_seed(17)
        images: list[torch.Tensor] = []
        labels: list[int] = []
        for label in range(3):
            for _ in range(samples_per_class):
                image = torch.randint(
                    0, 24, (3, image_size, image_size), dtype=torch.uint8, generator=generator
                )
                if label == 0:
                    image[0, :, : image_size // 2] += 180
                elif label == 1:
                    image[1, : image_size // 2, :] += 180
                else:
                    index = torch.arange(image_size)
                    image[2, index, index] += 220
                    image[2, index, image_size - 1 - index] += 220
                images.append(image)
                labels.append(label)
        self.images = torch.stack(images)
        self.labels = torch.tensor(labels, dtype=torch.long)

    def __len__(self) -> int:
        return len(self.labels)

    def __getitem__(self, index: int) -> tuple[torch.Tensor, torch.Tensor]:
        return self.images[index], self.labels[index]


def stratified_indices(labels: torch.Tensor, val_fraction: float, seed: int) -> tuple[list[int], list[int]]:
    generator = torch.Generator().manual_seed(seed)
    train_indices: list[int] = []
    val_indices: list[int] = []
    for class_id in labels.unique(sorted=True).tolist():
        class_indices = torch.where(labels == class_id)[0]
        order = class_indices[torch.randperm(len(class_indices), generator=generator)]
        val_count = max(1, round(len(order) * val_fraction))
        val_indices.extend(order[:val_count].tolist())
        train_indices.extend(order[val_count:].tolist())
    return train_indices, val_indices


class NormalizeSubset(Dataset[tuple[torch.Tensor, torch.Tensor]]):
    def __init__(
        self,
        subset: Subset[tuple[torch.Tensor, torch.Tensor]],
        mean: torch.Tensor,
        std: torch.Tensor,
    ) -> None:
        self.subset = subset
        self.mean = mean.view(3, 1, 1)
        self.std = std.view(3, 1, 1)

    def __len__(self) -> int:
        return len(self.subset)

    def __getitem__(self, index: int) -> tuple[torch.Tensor, torch.Tensor]:
        image, label = self.subset[index]
        image = image.to(torch.float32) / 255.0
        return (image - self.mean) / self.std, label


def train_statistics(dataset: PatternDataset, indices: Iterable[int]) -> tuple[torch.Tensor, torch.Tensor]:
    images = dataset.images[list(indices)].to(torch.float32) / 255.0
    mean = images.mean(dim=(0, 2, 3))
    std = images.std(dim=(0, 2, 3)).clamp_min(1e-6)
    return mean, std


class SmallCNN(nn.Module):
    def __init__(self, num_classes: int = 3, pooled_size: int = 2) -> None:
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 8, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(8, 16, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
        )
        self.pool = nn.AdaptiveAvgPool2d((pooled_size, pooled_size))
        self.classifier = nn.Linear(16 * pooled_size * pooled_size, num_classes)

    def forward(self, images: torch.Tensor) -> torch.Tensor:
        if images.ndim != 4 or images.shape[1] != 3:
            raise ValueError("images must have shape (N, 3, H, W)")
        features = self.pool(self.features(images))
        return self.classifier(features.flatten(1))


@dataclass(frozen=True)
class Metrics:
    loss: float
    accuracy: float
    macro_f1: float
    confusion: torch.Tensor


def metrics_from_confusion(confusion: torch.Tensor) -> tuple[float, float]:
    true_positive = confusion.diag().to(torch.float64)
    precision = true_positive / confusion.sum(dim=0).clamp_min(1)
    recall = true_positive / confusion.sum(dim=1).clamp_min(1)
    f1 = 2 * precision * recall / (precision + recall).clamp_min(1e-12)
    accuracy = true_positive.sum() / confusion.sum().clamp_min(1)
    return float(accuracy), float(f1.mean())


def run_epoch(
    model: nn.Module,
    loader: DataLoader[tuple[torch.Tensor, torch.Tensor]],
    criterion: nn.Module,
    optimizer: torch.optim.Optimizer | None,
) -> Metrics:
    training = optimizer is not None
    model.train(training)
    loss_sum = 0.0
    sample_count = 0
    confusion = torch.zeros(3, 3, dtype=torch.int64)

    context = torch.enable_grad() if training else torch.inference_mode()
    with context:
        for images, targets in loader:
            if training:
                optimizer.zero_grad(set_to_none=True)
            logits = model(images)
            loss = criterion(logits, targets)
            if training:
                loss.backward()
                optimizer.step()

            batch_size = targets.numel()
            loss_sum += float(loss.detach()) * batch_size
            sample_count += batch_size
            predictions = logits.argmax(dim=1)
            flat = targets * 3 + predictions
            confusion += torch.bincount(flat, minlength=9).reshape(3, 3)

    accuracy, macro_f1 = metrics_from_confusion(confusion)
    return Metrics(loss_sum / sample_count, accuracy, macro_f1, confusion)


def experiment(seed: int, pooled_size: int = 2) -> tuple[list[tuple[float, float]], dict[str, object]]:
    seed_everything(seed)
    dataset = PatternDataset()
    train_ids, val_ids = stratified_indices(dataset.labels, val_fraction=0.2, seed=seed)

    assert set(train_ids).isdisjoint(val_ids)
    assert sorted(train_ids + val_ids) == list(range(len(dataset)))
    assert torch.bincount(dataset.labels[train_ids], minlength=3).tolist() == [24, 24, 24]
    assert torch.bincount(dataset.labels[val_ids], minlength=3).tolist() == [6, 6, 6]

    mean, std = train_statistics(dataset, train_ids)
```

### 9.1 실제 이미지로 교체할 때

합성 `PatternDataset`만 실제 manifest 기반 `Dataset`으로 바꾼다. 모델, `run_epoch`, 지표, checkpoint 계약은 유지한다.

```python
from pathlib import Path

import cv2
import torch
from torch.utils.data import Dataset


class ManifestDataset(Dataset):
    def __init__(self, frame, transform) -> None:
        self.frame = frame.reset_index(drop=True)
        self.transform = transform

    def __len__(self) -> int:
        return len(self.frame)

    def __getitem__(self, index: int):
        row = self.frame.iloc[index]
        image = cv2.imread(str(Path(row.path)), cv2.IMREAD_COLOR)
        if image is None:
            raise RuntimeError(f"failed to decode image: {row.path}")
        image = cv2.cvtColor(image, cv2.COLOR_BGR2RGB)
        image = self.transform(image=image)["image"]
        label = torch.tensor(int(row.label), dtype=torch.long)
        return image, label
```

decode 실패를 검은 이미지로 대체하면 데이터 장애가 조용히 학습 신호로 들어간다. 경로와 원인을 포함해 즉시 실패시키고, 별도 데이터 검증 단계에서 격리하는 편이 안전하다.

## 10. epoch loss가 왜 샘플 가중 평균이어야 하는가

`CrossEntropyLoss()`의 기본 `reduction="mean"`일 때 batch $b$의 loss를 $L_b$, 샘플 수를 $n_b$라고 하자. 데이터셋 전체 평균은 다음과 같다.

$$
L_{\mathrm{epoch}}
=
\frac{\sum_b n_b L_b}{\sum_b n_b}
$$

원본처럼 다음을 계산하면

$$
\frac{1}{B}\sum_b L_b
$$

각 batch가 동일한 무게를 가진다. 마지막 batch가 작을 때 그 안의 각 샘플이 더 큰 비중을 차지한다. `drop_last=True`로 숨길 문제가 아니다. 학습 데이터 일부를 버릴 수 있고 validation에서는 특히 부적절하다.

## 11. 평가: accuracy 하나에서 confusion matrix로

confusion matrix $M$에서 행은 실제 클래스, 열은 예측 클래스라고 하자.

$$
M_{i,j}
=
\sum_{n=0}^{N-1}
\mathbf{1}[y_n=i]
\mathbf{1}[\widehat{y}_n=j]
$$

클래스 $k$의 precision과 recall은 다음과 같다.

$$
\mathrm{Precision}_k
=
\frac{M_{k,k}}{\sum_i M_{i,k}}
$$

$$
\mathrm{Recall}_k
=
\frac{M_{k,k}}{\sum_j M_{k,j}}
$$

$$
F1_k
=
\frac{2\,\mathrm{Precision}_k\,\mathrm{Recall}_k}
{\mathrm{Precision}_k+\mathrm{Recall}_k}
$$

macro F1은 $K$개 클래스의 $F1_k$를 같은 가중치로 평균한다. 표본이 적은 손동작을 계속 놓쳐도 전체 accuracy가 높게 보이는 문제를 줄인다. 분모가 0인 클래스 처리 규칙도 metric library 설정과 함께 기록한다.

## 12. 단위 테스트와 디버깅 순서

### 12.1 빠른 테스트 목록

| 테스트 | 실패가 뜻하는 것 |
| --- | --- |
| manifest ID one-to-one | 중복 파일, 중복 CSV 행, 누락 데이터 |
| train과 validation index 교집합이 공집합 | 직접적인 split 누수 |
| 각 split의 class count | stratification 또는 group coverage 문제 |
| 한 샘플 shape `(3,H,W)`와 dtype `float32` | decode·layout·tensor 변환 문제 |
| label 범위 `0 <= y < K`, dtype `int64` | class mapping 문제 |
| logits shape `(N,K)`와 finite 값 | model head 또는 수치 문제 |
| 한 batch overfit | optimizer·loss·gradient·label 연결 문제 |
| 두 실행 history 동일 | seed·shuffle·비결정 연산 문제 |
| checkpoint reload 출력 동일 | 저장 누락 또는 전처리 계약 누락 |

### 12.2 학습이 안 될 때의 순서

1. augmentation과 multiprocessing을 끈다.
2. 8~32개 샘플만 두고 거의 100%로 overfit되는지 본다.
3. 입력 min/max/mean/std와 라벨 histogram을 출력한다.
4. logits, loss, gradient norm이 finite인지 본다.
5. parameter가 optimizer에 포함됐는지 확인한다.
6. train mode와 eval mode가 올바른지 확인한다.
7. 그 다음 learning rate, scheduler, architecture를 바꾼다.

작은 batch도 외우지 못하는 모델에 더 큰 증강이나 더 복잡한 scheduler를 추가하면 원인만 가려진다.

## 13. 재현성 계약

seed 하나만 고정하면 충분하지 않다.

| 상태 | 저장 또는 고정할 것 |
| --- | --- |
| Python·NumPy·PyTorch RNG | 각 seed와 필요하면 RNG state |
| split | index 목록 또는 manifest의 split 컬럼 |
| `DataLoader` | shuffle generator, worker seed, worker 수 |
| 모델 | architecture config와 `state_dict` |
| optimizer·scheduler | `state_dict`와 현재 epoch·step |
| 데이터 | manifest checksum, 전처리 config, class map |
| 환경 | Python·PyTorch·CUDA·driver 버전, device |

결정론 옵션은 디버깅과 회귀 테스트에 유용하지만 일부 GPU kernel을 느리게 하거나 지원하지 않을 수 있다. 운영 benchmark는 결정론 여부를 결과와 함께 기록해야 한다.

checkpoint에서 모델 가중치만 저장하면 추론은 재개할 수 있어도 학습을 정확히 이어갈 수 없다. momentum, scheduler step, AMP scaler 같은 상태가 사라지기 때문이다.

## 14. ablation을 실험답게 만드는 법

위 실행 코드는 adaptive pooling grid `1x1`과 `2x2`를 비교한다. `2x2` head weight는 `1x1`의 네 배다. 그러나 정확한 ablation은 한 번의 seed와 최종 accuracy만 비교하지 않는다.

1. 가설을 먼저 쓴다: `2x2`는 위치 정보를 더 보존하지만 head가 커진다.
2. pooling grid 이외의 split, seed, epoch, optimizer, augmentation을 고정한다.
3. 최소 여러 seed의 평균과 표준편차를 보고한다.
4. accuracy와 macro F1뿐 아니라 parameter 수, latency, peak memory도 비교한다.
5. 가장 좋은 run만 선택하지 않고 모든 run을 남긴다.

권장 결과 표는 다음과 같다.

| 실험 | 변경점 | macro F1 평균±표준편차 | head 파라미터 | p50 latency | peak memory |
| --- | --- | ---: | ---: | ---: | ---: |
| A | adaptive pool `1x1` | 측정값 | $17K$ | 측정값 | 측정값 |
| B | adaptive pool `2x2` | 측정값 | $65K$ | 측정값 | 측정값 |

## 15. C++17 예제: 안정적 cross entropy와 confusion matrix

다음 코드는 **의존성 없이 실행 가능**하며 Python 수식과 같은 logits 계약을 검증한다. 완전한 CNN 학습 엔진이 아니라 loss·metric 경계의 동등 구현이다.

<!-- test:cpp:start -->
```cpp
#include <algorithm>
#include <array>
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>
#include <vector>

double cross_entropy(const std::vector<double>& logits, int target) {
    assert(target >= 0 && target < static_cast<int>(logits.size()));
    const double maximum = *std::max_element(logits.begin(), logits.end());
    double denominator = 0.0;
    for (double value : logits) {
        denominator += std::exp(value - maximum);
    }
    return -logits.at(target) + maximum + std::log(denominator);
}

int main() {
    const std::array<std::vector<double>, 2> logits{{
        {2.0, 0.0, -1.0},
        {1000.0, 1001.0, 999.0},
    }};
    const std::array<int, 2> targets{{0, 1}};
    std::array<std::array<int, 3>, 3> confusion{};
    double loss_sum = 0.0;

    for (std::size_t index = 0; index < logits.size(); ++index) {
        loss_sum += cross_entropy(logits[index], targets[index]);
        const int prediction = static_cast<int>(
            std::max_element(logits[index].begin(), logits[index].end()) - logits[index].begin()
        );
        ++confusion[targets[index]][prediction];
    }

    const double loss = loss_sum / static_cast<double>(logits.size());
    assert(std::isfinite(loss));
    assert(confusion[0][0] == 1 && confusion[1][1] == 1);
    std::cout << std::fixed << std::setprecision(6)
              << "loss=" << loss << " correct=2" << '\n';
}
```

## 16. C# 예제: 같은 logits 계약 검증

다음 코드도 **의존성 없이 실행 가능**하다. 실제 TorchSharp 또는 ONNX Runtime 경계에서도 출력은 `float[N,K]`, 정답은 정수 index라는 계약을 유지한다.

<!-- test:csharp:start -->
```csharp
using System;

public static class Program
{
    private static double CrossEntropy(double[] logits, int target)
    {
        if (target < 0 || target >= logits.Length)
            throw new ArgumentOutOfRangeException(nameof(target));

        double maximum = logits[0];
        foreach (double value in logits)
            maximum = Math.Max(maximum, value);

        double denominator = 0.0;
        foreach (double value in logits)
            denominator += Math.Exp(value - maximum);

        return -logits[target] + maximum + Math.Log(denominator);
    }

    private static int ArgMax(double[] values)
    {
        int index = 0;
        for (int i = 1; i < values.Length; ++i)
            if (values[i] > values[index]) index = i;
        return index;
    }

    public static void Main()
    {
        double[][] logits =
        {
            new double[] { 2.0, 0.0, -1.0 },
            new double[] { 1000.0, 1001.0, 999.0 },
        };
        int[] targets = { 0, 1 };
        int[,] confusion = new int[3, 3];
        double loss = 0.0;

        for (int i = 0; i < logits.Length; ++i)
        {
            loss += CrossEntropy(logits[i], targets[i]);
            confusion[targets[i], ArgMax(logits[i])]++;
        }
        loss /= logits.Length;

        if (double.IsNaN(loss) || double.IsInfinity(loss))
            throw new Exception("loss must be finite");
        if (confusion[0, 0] != 1 || confusion[1, 1] != 1)
            throw new Exception("confusion matrix mismatch");

        Console.WriteLine($"loss={loss:F6} correct=2");
    }
}
```

## 17. 프레임워크 간 shape·layout·dtype 대응

| 개념 | PyTorch Python | C++ 추론 API의 일반적 형태 | C# 추론 API의 일반적 형태 |
| --- | --- | --- | --- |
| 이미지 저장 | `uint8[H,W,C]` | `uint8_t` HWC buffer | `byte[H,W,C]` 또는 연속 배열 |
| 모델 입력 | `float32[N,C,H,W]` | `float*` NCHW | `float[]` NCHW |
| 라벨 | `torch.int64[N]` | `int64_t[N]` | `long[]` |
| logits | `float32[N,K]` | `float[N*K]` | `float[]` shape metadata `(N,K)` |
| channel 변환 | `permute(2,0,1)` | index 재배열 또는 전처리 kernel | loop 또는 tensor transpose |
| 연속성 | `contiguous()` 필요 가능 | stride를 직접 확인 | tensor shape·stride 확인 |

ONNX export 전에 다음을 확인한다.

1. 입력 이름, NCHW shape, `float32` dtype를 고정한다.
2. dynamic batch 또는 dynamic height·width가 정말 필요한지 결정한다.
3. Python 전처리와 C++/C# 전처리의 resize 보간, RGB 순서, scale, mean, std를 golden image로 비교한다.
4. Python과 배포 runtime의 logits를 tolerance 안에서 비교한다.
5. class index를 사용자 표시 문자열로 바꾸는 mapping을 모델 artifact와 함께 버전 관리한다.

## 18. 성능·메모리·수치 안정성

### 18.1 병목을 측정하는 순서

1. decode와 augmentation 시간을 별도로 측정한다.
2. GPU라면 host-to-device 복사와 kernel 시간을 동기화해 측정한다.
3. `num_workers`, `pin_memory`, prefetch를 한 번에 하나씩 바꾼다.
4. batch size를 늘릴 때 throughput과 peak memory를 함께 본다.
5. AMP는 속도뿐 아니라 logits·loss·gradient의 finite 여부를 검사한다.

activation의 대략적인 저장량은 원소 수와 dtype byte 수의 곱이다.

$$
M_{\mathrm{activation}}
\approx
NCHW \times \mathrm{bytes(dtype)}
$$

학습에서는 backward를 위해 여러 중간 activation을 저장하므로 한 feature map의 크기만으로 peak memory를 예측할 수 없다. profiler로 측정해야 한다.

### 18.2 수치 안전 체크

- loss에는 logits를 직접 전달한다.
- 확률을 로그로 바꿔야 하면 `log_softmax`를 쓴다.
- normalization의 표준편차에 작은 하한을 둔다.
- AMP에서는 gradient scaling과 non-finite skip 횟수를 기록한다.
- metric 누적은 충분한 정밀도와 정수 confusion matrix를 사용한다.

## 19. 실무 실패 사례

### 19.1 높은 검증 정확도, 낮은 현장 정확도

연속 촬영 프레임이 무작위 split 양쪽에 들어갔다. 모델은 손 모양보다 사람과 배경을 외웠다. person/session group split으로 다시 평가하고, worst-group metric을 추가해야 한다.

### 19.2 특정 클래스만 전부 다른 클래스로 예측

CSV 행과 정렬된 파일 목록이 한 파일 누락 뒤부터 어긋났다. 전체 loss는 내려갈 수도 있어 발견이 늦다. ID 기반 manifest join, 샘플 썸네일·라벨 감사, confusion matrix가 필요하다.

### 19.3 Python은 정상인데 C# 앱은 정확도가 무너짐

Python은 RGB와 $[0,1]$ scale을 사용했지만 앱은 BGR `uint8`을 그대로 넣었다. 모델 문제가 아니라 전처리 ABI 불일치다. 고정 이미지의 전처리 tensor checksum과 logits golden test를 배포 CI에 둔다.

### 19.4 resume 후 loss가 갑자기 튐

모델만 저장하고 optimizer momentum과 scheduler step을 저장하지 않았다. checkpoint schema를 versioning하고 resume 직후 learning rate와 global step을 로그로 확인한다.

## 20. 배포·모니터링 관점

배포 artifact에는 다음을 함께 둔다.

- 모델 graph와 weight
- 입력 shape·layout·dtype
- resize와 normalization 설정
- class-to-index와 index-to-label mapping
- 학습 데이터·코드 commit과 metric
- runtime·opset 버전
- golden 입력과 허용 오차가 있는 golden logits

운영에서 정답은 늦게 들어올 수 있다. 그 전에는 입력 decode 실패율, 밝기·색 분포, 예측 confidence, 클래스 빈도, latency, out-of-memory를 감시한다. 정답이 들어오면 per-class recall, macro F1, calibration, 사람·기기·환경 slice를 계산한다.

confidence가 높다는 사실은 예측이 맞다는 뜻이 아니다. temperature scaling 같은 calibration도 validation과 별도 calibration split 또는 교차 검증 설계가 필요하다.

## 21. 구현 체크리스트

### 데이터

- [ ] CSV와 파일을 ID로 one-to-one 결합했다.
- [ ] 누락·중복·decode 실패를 학습 전에 검사했다.
- [ ] class mapping을 명시적으로 저장했다.
- [ ] 사람·세션·기기 누수를 막는 split key를 검토했다.
- [ ] normalization 통계는 train split에서만 계산했다.

### 학습

- [ ] image는 NCHW `float32`, target은 `(N,)` `int64`다.
- [ ] logits에 softmax를 붙이지 않고 `CrossEntropyLoss`에 넣었다.
- [ ] `optimizer.zero_grad(set_to_none=True)`를 각 step 전에 호출한다.
- [ ] epoch loss를 샘플 수로 가중한다.
- [ ] validation은 `eval()`과 `inference_mode()`를 사용한다.

### 검증과 재현성

- [ ] 한 batch overfit과 negative shape test가 있다.
- [ ] accuracy와 macro F1, confusion matrix를 함께 본다.
- [ ] split·seed·환경·checkpoint schema를 기록했다.
- [ ] ablation은 한 변수만 바꾸고 여러 seed로 비교한다.
- [ ] checkpoint reload 후 logits가 일치한다.

### 배포

- [ ] Python과 C++/C# 전처리를 golden tensor로 비교했다.
- [ ] ONNX runtime logits를 Python logits와 비교했다.
- [ ] class mapping과 normalization을 모델과 함께 배포한다.
- [ ] latency, 오류율, drift, slice metric을 모니터링한다.

## 22. 연습문제

batch 크기가 32, 32, 6이고 각 batch mean loss가 0.4, 0.5, 1.2다. batch 평균들의 단순 평균과 샘플 가중 epoch loss를 구하라.

### 문제 2

세 클래스 confusion matrix가 다음과 같을 때 클래스 1의 precision과 recall을 구하라. 행은 실제, 열은 예측이다.

$$
M=
\begin{bmatrix}
8 & 1 & 1 \\
2 & 6 & 2 \\
0 & 1 & 9
\end{bmatrix}
$$

### 문제 3

동일 촬영자의 연속 이미지가 100장씩 있고 촬영자마다 손과 배경이 다르다. 왜 stratified random split만으로 충분하지 않은가?

### 문제 4

원본 `SimpleCNN`의 두 합성곱은 그대로 두고 입력을 `64x64`에서 `32x32`로 줄였다. 합성곱 파라미터 수, 합성곱 MAC, flatten head의 `in_features`는 각각 어떻게 변하는가?

### 문제 5

Python 모델과 C# 앱의 logits가 크게 다르다. 모델 변환 오류라고 결론 내리기 전에 비교할 다섯 전처리 항목을 쓰라.

## 23. 연습문제 해답

### 해답 1

단순 평균은 다음과 같다.

$$
\frac{0.4+0.5+1.2}{3}=0.7
$$

샘플 가중 평균은 다음과 같다.

$$
\frac{32(0.4)+32(0.5)+6(1.2)}{32+32+6}
=
\frac{36}{70}
\approx 0.514286
$$

작은 마지막 batch의 높은 loss가 단순 평균에서는 과대 반영된다.

### 해답 2

클래스 1의 true positive는 6이다. 클래스 1로 예측한 수는 두 번째 열의 합 $1+6+1=8$이고, 실제 클래스 1의 수는 두 번째 행의 합 $2+6+2=10$이다.

$$
\mathrm{Precision}_1=\frac{6}{8}=0.75
$$

$$
\mathrm{Recall}_1=\frac{6}{10}=0.6
$$

### 해답 3

stratification은 라벨 비율만 보존한다. 같은 촬영자의 거의 동일한 프레임이 양쪽 split에 들어가는 것은 막지 못한다. 모델이 손동작보다 사람·배경·카메라 특징을 외울 수 있으므로 촬영자 또는 세션을 group key로 분리해야 한다.

### 해답 4

합성곱 kernel shape은 입력 공간 크기와 무관하므로 파라미터 수는 같다. 같은 stride 구조라면 feature map 면적이 대략 1/4이 되어 합성곱 MAC도 대략 1/4이 된다. 두 번 pooling 뒤 공간 길이는 `16x16`에서 `8x8`이 되므로 flatten head의 `in_features`도 $32\cdot16\cdot16$에서 $32\cdot8\cdot8$, 즉 1/4이 된다.

### 해답 5

RGB/BGR 순서, HWC/NCHW layout, `uint8`에서 `float32`로의 scale, resize 알고리즘과 크기, 채널별 mean/std와 연산 순서를 비교한다. 같은 이미지의 전처리 완료 tensor를 먼저 맞춘 뒤 모델 runtime을 조사한다.

## 24. 핵심 요약

1. 파일 정렬과 CSV 행 순서는 라벨 연결의 근거가 아니며 ID 기반 join이 필요하다.
2. 손 이미지에서는 class stratification보다 촬영자·세션 group 누수 방지가 더 중요할 수 있다.
3. train-only 통계와 학습 전용 랜덤 증강으로 평가 경계를 지킨다.
4. `CrossEntropyLoss`에는 softmax 이전 logits와 `int64` class index를 전달한다.
5. epoch loss는 batch 수가 아니라 샘플 수로 가중한다.
6. confusion matrix와 macro F1이 accuracy에 숨은 클래스별 실패를 드러낸다.
7. 재현성은 seed뿐 아니라 split, shuffle, 환경, optimizer 상태, 전처리 config의 계약이다.
8. ablation은 한 변수만 바꾸고 여러 seed와 성능·비용 지표를 함께 비교한다.
9. C++/C# 배포에서 가장 흔한 실패는 layout, color, scale, normalization 불일치다.
10. 모델 개선 전에 한 batch overfit, manifest, shape, dtype, gradient부터 검증한다.
