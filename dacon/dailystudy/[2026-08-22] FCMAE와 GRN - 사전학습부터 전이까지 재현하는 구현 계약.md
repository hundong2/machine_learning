원본은 FCMAE가 CNN의 2차원 격자와 masked autoencoder를 연결하는 이유, 그리고 ConvNeXt V2의 GRN을 소개한다. 1회차 문서는 sparse active set, masked MSE와 GRN 수식을 직관적으로 추적했다. 이번 2회차는 설명을 반복하지 않고 **mask 생성부터 checkpoint, linear probe, full fine-tuning까지 다시 실행할 수 있는 계약**으로 내린다.

## 학습 목표

이 글을 마치면 다음을 구현하고 검증할 수 있다.

1. sample마다 정확히 같은 수의 patch를 가리는 재현 가능한 mask generator를 만든다.
2. `patchify` 순서와 prediction head의 channel 순서를 golden tensor로 고정한다.
3. masked patch만 평균하는 loss와 빈 mask 방어를 구현한다.
4. dense 검증 모델과 실제 sparse encoder의 경계를 명확히 구분한다.
5. GRN의 `NHWC`와 `NCHW` 구현이 forward·backward에서 동등한지 검사한다.
6. label 없는 pretraining, frozen linear probe, full fine-tuning을 서로 다른 실험으로 실행한다.
7. seed, optimizer, RNG와 checkpoint를 포함해 exact replay를 검증한다.
8. C++, C#, NumPy와 PyTorch의 layout·dtype·epsilon 계약을 맞춘다.
9. throughput, memory, 수치 안정성과 배포 실패를 release gate로 바꾼다.

## 선수 지식과 기호

convolution, automatic differentiation, MSE, cross entropy와 optimizer의 기본 사용법을 알고 있다고 가정한다.

| 기호 | 정의 |
| --- | --- |
| $B$ | batch 크기 |
| $C$ | 이미지 또는 feature channel 수 |
| $H,W$ | 이미지 높이와 너비 |
| $P$ | 정사각 patch 한 변 |
| $G_h,G_w$ | patch grid의 높이와 너비 |
| $L=G_hG_w$ | sample당 patch 수 |
| $D=P^2C$ | 펼친 pixel patch의 차원 |
| $r$ | mask ratio |
| $M\in\{0,1\}^{B\times L}$ | `1=masked`, `0=visible`인 mask |
| $E$ | encoder embedding 차원 |
| $K$ | downstream class 수 |

이미지와 convolution feature는 `BCHW`, patch sequence는 `BLD`, GRN의 기본 구현은 `BHWC`를 사용한다. 논리적 layout과 실제 memory format은 별개이므로 둘을 혼용하지 않는다.

## 1. 이번 회차의 구현 경계

FCMAE의 논문 규모 sparse training을 작은 글 한 편에서 복제하는 것은 목표가 아니다. 대신 두 층으로 경계를 나눈다.

- **계약 모델:** dense PyTorch 연산으로 mask, patch ordering, loss, GRN, pretrain과 transfer의 정확성을 빠르게 검증한다.
- **성능 모델:** sparse backend에서 active coordinate가 보존되고 실제 연산량이 줄어드는지 별도 benchmark한다.

계약 모델에서 masked token을 0으로 만들거나 learned token으로 바꾸어도 dense kernel은 모든 위치를 계산한다. 그러므로 아래 실행 예제를 “sparse FCMAE가 빨라진다는 증명”으로 해석하면 안 된다. 성능 주장은 실제 sparse library와 목표 GPU에서만 검증할 수 있다.

구현에서 자주 깨지는 계약은 다음과 같다.

- mask ratio를 Bernoulli 확률로만 처리해 sample마다 masked count가 달라진다.
- `mask=1`의 뜻이 data loader와 loss에서 뒤집힌다.
- `patchify`는 `channel,row,column` 순서인데 decoder는 다른 순서로 출력한다.
- masked MSE의 분모에 pixel 차원 $D$를 두 번 반영한다.
- mask가 0개인 batch에서 `0/0`이 발생한다.
- `NCHW`에 `dim=(1,2)`인 GRN 코드를 그대로 적용한다.
- pretraining decoder까지 downstream serving graph에 남긴다.
- linear probe에서 encoder parameter가 optimizer에 들어가거나 BatchNorm state가 변한다.
- 재현성을 seed 하나로 끝내고 mask generator와 data order state를 저장하지 않는다.

## 2. 원본과 1회차에서 구현 관점으로 바로잡을 점

| 원본의 표현 또는 축약 | 이번 구현의 정확한 계약 |
| --- | --- |
| CNN은 MAE를 받아들일 수 없다 | dense zero masking은 mask pattern과 계산 효율에 문제가 있지만 학습 자체가 불가능한 것은 아니다. FCMAE는 sparse convolution으로 이 설계를 개선한다. |
| masked patch는 메모리에서 완전히 지운다 | ViT sequence에서는 token drop이 자연스럽지만 CNN sparse backend는 coordinate와 active feature를 관리한다. backend 자료구조까지 확인해야 한다. |
| 75%를 가린다 | ViT MAE의 대표 설정이다. ConvNeXt V2 FCMAE의 대표 mask ratio는 60%다. 실제 masked count는 정수화 규칙에 따라 달라진다. |
| GRN은 강한 channel에 penalty를 준다 | 상대 response를 입력으로 학습 가능한 calibration을 한다. 출력 효과의 부호와 크기는 $\gamma$에 의존한다. |
| GRN이 죽은 neuron을 모두 살린다 | feature diversity 개선을 의도하지만 개별 neuron 부활을 보장하지 않는다. effective rank와 downstream metric으로 검증한다. |
| CNN의 가벼움이 edge에서 우월하다 | architecture 이름만으로 latency를 보장할 수 없다. sparse pretraining과 dense downstream inference를 분리해 측정한다. |

## 3. mask 생성은 확률이 아니라 개수 계약이다

sample당 보이는 patch 수를 다음처럼 내림으로 고정한다고 하자.

$$
L_{keep}=\left\lfloor L(1-r)\right\rfloor
$$

masked patch 수는 다음이다.

$$
L_{mask}=L-L_{keep}
$$

$H=W=16$, $P=4$이면 $G_h=G_w=4$, $L=16$이다. $r=0.5$이면 sample마다 8개를 가린다. 구현은 각 행의 random score를 정렬해 처음 $L_{mask}$개 index를 고른다.

$$
\pi_b=\operatorname{argsort}(u_b),
\qquad
M_{b,\pi_b(j)}=1\quad (0\le j\lt L_{mask})
$$

이 방식의 장점은 batch마다 loss 분모가 예측 가능하고 분산 실험 간 mask budget을 맞추기 쉽다는 점이다. 반면 정렬 비용이 있으므로 대규모 시스템에서는 top-k나 backend 전용 sampling을 benchmark한다.

### 3.1 분산 학습 seed

모든 rank에 같은 seed를 주면 서로 다른 이미지에 같은 mask pattern이 반복될 수 있다. 다음처럼 의미를 분리한다.

$$
s_{mask}=\operatorname{hash}(s_{run},\ epoch,\ global\_step,\ rank)
$$

재시작 시 exact replay가 필요하면 단순히 seed만 저장하지 말고 generator state, sampler epoch, global step을 checkpoint에 함께 저장한다.

## 4. patchify와 shape 추적

입력 $X\in\mathbb{R}^{B\times C\times H\times W}$를 겹치지 않는 patch로 나눈다.

$$
G_h=H/P,
\qquad
G_w=W/P,
\qquad
T=\operatorname{patchify}(X)\in\mathbb{R}^{B\times L\times D}
$$

이 문서의 flatten 순서는 `grid-row -> grid-column -> channel -> patch-row -> patch-column`이다. PyTorch 코드로는 `unfold`, `permute(0,2,3,1,4,5)`, `reshape` 순서다.

| 단계 | 연산 | shape |
| --- | --- | --- |
| 입력 | RGB image | `(B,3,16,16)` |
| patch view | `4x4`, stride 4 | `(B,3,4,4,4,4)` |
| 축 이동 | grid를 앞쪽으로 | `(B,4,4,3,4,4)` |
| flatten | patch sequence | `(B,16,48)` |
| encoder | patch embedding | `(B,16,E)` |
| mask token 삽입 | masked 위치 교체 | `(B,16,E)` |
| grid 복원 | decoder GRN 입력 | `(B,4,4,E')` |
| pixel prediction | patch별 RGB | `(B,16,48)` |

$H$ 또는 $W$가 $P$로 나누어떨어지지 않으면 silently crop하지 않고 오류를 내는 것이 기본 계약이다. padding을 허용한다면 원본 크기, padded size와 valid-pixel mask를 loss에 함께 전달한다.

## 5. masked reconstruction loss

prediction과 target을 각각 $\hat{T},T\in\mathbb{R}^{B\times L\times D}$라 하자. patch별 MSE는 다음이다.

$$
e_{b,l}
=
\frac{1}{D}
\sum_{d=1}^{D}
\left(\hat{T}_{b,l,d}-T_{b,l,d}\right)^2
$$

masked patch만 모은 global mean은 다음이다.

$$
\mathcal{L}_{mask}
=
\frac{
\sum_{b=1}^{B}\sum_{l=1}^{L}M_{b,l}e_{b,l}
}{
\sum_{b=1}^{B}\sum_{l=1}^{L}M_{b,l}
}
$$

sample별 masked count가 같으면 sample mean의 평균과 global mean이 같다. count가 다르면 두 reduction은 서로 다른 objective다. 분산 학습에서 rank별 분자와 분모를 각각 all-reduce해야 global mean과 같아진다. rank별 loss scalar를 단순 평균하면 masked count가 작은 rank에 과도한 가중치가 생긴다.

### 5.1 pixel normalization 선택

MAE 계열에서는 patch 내부 pixel을 patch별 평균과 분산으로 정규화한 target을 선택할 수 있다.

$$
T'_{b,l,d}
=
\frac{T_{b,l,d}-\mu_{b,l}}
{\sqrt{\sigma^2_{b,l}+\epsilon}}
$$

이 옵션은 단순 수치 안정화가 아니라 학습 과업을 바꾼다. raw pixel target과 normalized target의 checkpoint를 같은 실험으로 비교하지 않는다.

## 6. NumPy golden: mask, loss와 GRN layout

아래 코드는 **실행 가능한 독립 검증**이다. PyTorch 없이 mask count, masked MSE와 `NHWC` GRN의 수치를 확인한다.

```python
import numpy as np


def exact_mask(batch: int, patches: int, ratio: float, seed: int) -> np.ndarray:
    masked = int(patches * ratio)
    if not 0 < masked < patches:
        raise ValueError("masked count must be in (0, patches)")
    rng = np.random.default_rng(seed)
    order = np.argsort(rng.random((batch, patches)), axis=1)
    mask = np.zeros((batch, patches), dtype=np.float32)
    rows = np.arange(batch)[:, None]
    mask[rows, order[:, :masked]] = 1.0
    return mask


mask = exact_mask(batch=2, patches=16, ratio=0.5, seed=7)
assert mask.shape == (2, 16)
assert np.array_equal(mask.sum(axis=1), np.array([8.0, 8.0]))

target = np.zeros((2, 16, 3), dtype=np.float64)
pred = np.zeros_like(target)
pred[mask.astype(bool)] = 2.0
per_patch = ((pred - target) ** 2).mean(axis=-1)
loss = (per_patch * mask).sum() / mask.sum()
assert loss == 4.0

# B,H,W,C = 1,1,2,2; channel norm은 각각 5와 12다.
x = np.array([[[[3.0, 0.0], [4.0, 12.0]]]], dtype=np.float64)
gx = np.linalg.norm(x, axis=(1, 2), keepdims=True)
nx = gx / (gx.mean(axis=-1, keepdims=True) + 1e-12)
y = x + 0.5 * (x * nx) + 0.25
expected = np.array([[[[4.132352941, 0.25],
                       [5.426470588, 20.720588235]]]])
np.testing.assert_allclose(y, expected, rtol=0.0, atol=1e-9)
print(f"masked={mask.sum(axis=1).tolist()}, loss={loss:.1f}")
print("grn=", np.round(y.reshape(-1), 9).tolist())
```

## 7. GRN forward와 backward 계약

GRN 입력을 $X\in\mathbb{R}^{B\times H\times W\times C}$라 하자. batch별 channel의 공간 L2 norm은 다음이다.

$$
G_{b,c}
=
\sqrt{
\sum_{h=1}^{H}\sum_{w=1}^{W}X_{b,h,w,c}^2
}
$$

channel 평균으로 상대 response를 만든다.

$$
N_{b,c}
=
\frac{G_{b,c}}
{\frac{1}{C}\sum_{j=1}^{C}G_{b,j}+\epsilon}
$$

출력은 다음이다.

$$
Y_{b,h,w,c}
=
X_{b,h,w,c}
+
\gamma_cN_{b,c}X_{b,h,w,c}
+
\beta_c
$$

$\gamma=0$, $\beta=0$이면 초기 forward는 identity다. 그러나 $\gamma$와 $\beta$에는 첫 backward부터 gradient가 흐른다. $\gamma=0$일 때 $N$을 만드는 경로의 upstream gradient는 곱셈 때문에 차단될 수 있다. ControlNet의 zero convolution이나 LoRA의 zero branch와 마찬가지로 **초기 출력 identity**와 **모든 parameter가 첫 step부터 같은 크기로 학습됨**은 서로 다른 주장이다.

### 7.1 `NCHW` 대응

`NCHW`에서 spatial reduction은 `(2,3)`, channel 평균은 `dim=1`, parameter shape는 `(1,C,1,1)`이다. 두 구현을 비교할 때 같은 $\gamma$, $\beta$, $\epsilon$을 넣고 다음을 검사한다.

1. `NCHW -> NHWC -> NCHW` forward가 직접 `NCHW` 식과 일치한다.
2. 같은 scalar loss에서 input gradient가 일치한다.
3. $\gamma$, $\beta$ gradient가 일치한다.
4. all-zero input, $H=1$, $W=1$에서도 finite하다.

reduction은 `float16`보다 `float32`에서 수행한 뒤 원래 dtype으로 되돌리는 편이 안전하다. 하지만 이 casting도 graph와 target runtime의 계약에 포함해야 한다.

## 8. PyTorch 완전 실행 예제

아래 코드는 **실행 가능한 교육용 계약 모델**이다. 실제 sparse convolution을 쓰지 않으므로 throughput benchmark가 아니다. label 없는 pretraining, linear probe, full fine-tuning, scratch ablation과 exact replay를 한 번에 실행한다.

```python
import copy
import random

import numpy as np
import torch
from torch import nn


torch.set_num_threads(1)


def seed_all(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.use_deterministic_algorithms(True)


def patchify(x: torch.Tensor, patch: int = 4) -> torch.Tensor:
    batch, channels, height, width = x.shape
    if height % patch or width % patch:
        raise ValueError("height and width must be divisible by patch")
    return (
        x.unfold(2, patch, patch)
        .unfold(3, patch, patch)
        .permute(0, 2, 3, 1, 4, 5)
        .reshape(batch, -1, channels * patch * patch)
    )


def exact_mask(
    batch: int,
    patches: int,
    ratio: float,
    generator: torch.Generator,
) -> torch.Tensor:
    masked = int(patches * ratio)
    if not 0 < masked < patches:
        raise ValueError("masked count must be in (0, patches)")
    order = torch.rand((batch, patches), generator=generator).argsort(dim=1)
    mask = torch.zeros((batch, patches), dtype=torch.bool)
    mask.scatter_(1, order[:, :masked], True)
    return mask


def masked_mse(
    prediction: torch.Tensor,
    target: torch.Tensor,
    mask: torch.Tensor,
) -> torch.Tensor:
    if prediction.shape != target.shape or mask.shape != prediction.shape[:2]:
        raise ValueError("prediction, target, and mask shapes do not agree")
    count = mask.sum()
    if count == 0:
        raise ValueError("at least one masked patch is required")
    per_patch = (prediction - target).square().mean(dim=-1)
    return (per_patch * mask).sum() / count


class GRN(nn.Module):
    """BHWC GRN; norm reduction은 float32에서 수행한다."""

    def __init__(self, channels: int) -> None:
        super().__init__()
        self.gamma = nn.Parameter(torch.zeros(1, 1, 1, channels))
        self.beta = nn.Parameter(torch.zeros(1, 1, 1, channels))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        gx = torch.linalg.vector_norm(
            x.float(), dim=(1, 2), keepdim=True
        ).to(x.dtype)
        nx = gx / (gx.mean(dim=-1, keepdim=True) + 1e-6)
        return x + self.gamma * (x * nx) + self.beta


class Decoder(nn.Module):
    def __init__(self, embed: int, patch_dim: int) -> None:
        super().__init__()
        self.fc1 = nn.Linear(embed, 2 * embed)
        self.grn = GRN(2 * embed)
        self.fc2 = nn.Linear(2 * embed, patch_dim)

    def forward(self, z: torch.Tensor, grid_h: int, grid_w: int) -> torch.Tensor:
        z = torch.nn.functional.gelu(self.fc1(z))
        z = z.reshape(z.shape[0], grid_h, grid_w, -1)
        z = self.grn(z).reshape(z.shape[0], grid_h * grid_w, -1)
        return self.fc2(z)


class TinyFCMAE(nn.Module):
    def __init__(self, patch: int = 4, embed: int = 24) -> None:
        super().__init__()
        self.patch = patch
        patch_dim = 3 * patch * patch
        self.encoder = nn.Sequential(
            nn.Linear(patch_dim, embed),
            nn.GELU(),
            nn.Linear(embed, embed),
        )
        self.mask_token = nn.Parameter(torch.zeros(1, 1, embed))
        self.decoder = Decoder(embed, patch_dim)

    def forward(
        self, x: torch.Tensor, mask: torch.Tensor
    ) -> tuple[torch.Tensor, torch.Tensor]:
        target = patchify(x, self.patch)
        encoded = self.encoder(target)
        encoded = torch.where(mask.unsqueeze(-1), self.mask_token, encoded)
        grid_h = x.shape[2] // self.patch
        grid_w = x.shape[3] // self.patch
        return self.decoder(encoded, grid_h, grid_w), target


def make_data(seed: int = 17, count: int = 96) -> tuple[torch.Tensor, torch.Tensor]:
    generator = torch.Generator().manual_seed(seed)
    labels = torch.arange(count) % 2
    images = 0.05 * torch.randn(count, 3, 16, 16, generator=generator)
    images[labels == 0, :, :, 3:7] += 1.0
    images[labels == 1, :, 9:13, :] += 1.0
    return images, labels.long()


def pretrain(seed: int) -> tuple[TinyFCMAE, list[float]]:
    seed_all(seed)
    images, _ = make_data()
    model = TinyFCMAE()
    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-3)
    mask_generator = torch.Generator().manual_seed(seed + 1)
    history = []
    for step in range(35):
        indices = torch.arange(step * 16, (step + 1) * 16) % len(images)
        mask = exact_mask(16, 16, 0.5, mask_generator)
        prediction, target = model(images[indices], mask)
        loss = masked_mse(prediction, target, mask)
        optimizer.zero_grad(set_to_none=True)
        loss.backward()
        optimizer.step()
        history.append(loss.item())
    return model, history


class Classifier(nn.Module):
    def __init__(self, encoder: nn.Module, embed: int = 24) -> None:
        super().__init__()
        self.encoder = encoder
        self.head = nn.Linear(embed, 2)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        features = self.encoder(patchify(x, 4)).mean(dim=1)
        return self.head(features)


def downstream(
    encoder: nn.Module,
    freeze: bool,
    seed: int,
) -> tuple[float, list[float], Classifier]:
    seed_all(seed)
    images, labels = make_data()
    train_indices = torch.arange(72)
    valid_indices = torch.arange(72, 96)
    model = Classifier(copy.deepcopy(encoder))
    for parameter in model.encoder.parameters():
        parameter.requires_grad = not freeze
    optimizer = torch.optim.AdamW(
        [p for p in model.parameters() if p.requires_grad], lr=1e-2
    )
    history = []
    for _ in range(40):
        logits = model(images[train_indices])
        loss = nn.functional.cross_entropy(logits, labels[train_indices])
        optimizer.zero_grad(set_to_none=True)
        loss.backward()
        optimizer.step()
        history.append(loss.item())
    model.eval()
    with torch.no_grad():
        prediction = model(images[valid_indices]).argmax(dim=1)
        accuracy = (prediction == labels[valid_indices]).float().mean().item()
    return accuracy, history, model
```

1. pretraining loss 감소만으로 downstream representation이 좋다고 결론 내리지 않는다.
2. linear probe, fine-tuning, scratch baseline을 같은 split과 seed로 나란히 실행한다.

## 9. pretraining·linear probe·fine-tuning의 차이

| 단계 | trainable parameter | optimizer state | 평가 목적 |
| --- | --- | --- | --- |
| pretraining | encoder, decoder, mask token | SSL 전용 | label 없는 reconstruction 학습 |
| linear probe | 새 linear head만 | 새로 생성 | frozen representation의 선형 분리성 |
| full fine-tuning | encoder와 task head | 새로 생성하는 것이 기본 | downstream 적응 성능 |
| scratch baseline | 무작위 encoder와 task head | 새로 생성 | pretraining의 실제 이득 측정 |

linear probe에서는 단순히 `requires_grad=False`만 확인하지 말고 다음도 검사한다.

- optimizer parameter group에 encoder가 없다.
- encoder gradient가 `None`이다.
- stateful normalization layer가 있다면 `train()` 동작을 의도적으로 결정한다.
- probe 전후 encoder `state_dict`가 byte 단위로 같다.

full fine-tuning에서 pretraining optimizer state를 그대로 가져오면 decoder parameter와 downstream head mapping이 어긋날 수 있다. optimizer를 새로 만들고 encoder와 head에 다른 learning rate를 쓰는 discriminative fine-tuning을 별도 실험으로 둔다.

## 10. ablation과 재현성 설계

한 번에 하나의 원인만 바꾸고 compute budget을 기록한다.

| 실험 | 고정 항목 | 변경 항목 | 주 metric |
| --- | --- | --- | --- |
| mask ratio | data, epoch, architecture, seed | `0.4`, `0.6`, `0.75` | linear probe, images/s |
| target normalization | mask와 optimizer | raw pixel, patch-normalized pixel | reconstruction와 downstream metric |
| GRN | 같은 block과 초기화 | GRN on/off | effective rank, fine-tune accuracy |
| encoder 계산 | 같은 mask | dense surrogate, real sparse | step time, peak memory, active count |
| transfer | 같은 pretrained weight | frozen, full fine-tune | accuracy, calibration |

### 10.1 exact replay gate

같은 환경에서 다음을 모두 검사한다.

1. loss history가 element-wise로 같다.
2. model parameter와 buffer가 `torch.equal`이다.
3. mask sequence가 같다.
4. data sample order가 같다.
5. AMP scaler와 scheduler state가 같다.

GPU kernel이나 sparse backend가 nondeterministic하면 exact match 대신 허용 오차와 원인을 명시한다. 재현성을 위해 성능이 크게 떨어지는 설정을 강제해야 한다면 exact replay 실험과 production throughput 실험을 분리한다.

## 11. C++ golden 예제

아래 코드는 **실행 가능한 C++17 예제**다. framework 의존성 없이 `NHWC` GRN 한 sample의 값을 계산한다.

```cpp
#include <array>
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>

int main() {
    // H=1, W=2, C=2; memory order는 NHWC다.
    const std::array<double, 4> x{3.0, 0.0, 4.0, 12.0};
    std::array<double, 2> norm{};
    for (int position = 0; position < 2; ++position) {
        for (int channel = 0; channel < 2; ++channel) {
            const double value = x[position * 2 + channel];
            norm[channel] += value * value;
        }
    }
    for (double& value : norm) value = std::sqrt(value);
    const double mean = (norm[0] + norm[1]) / 2.0;
    std::array<double, 4> y{};
    for (int position = 0; position < 2; ++position) {
        for (int channel = 0; channel < 2; ++channel) {
            const int index = position * 2 + channel;
            const double relative = norm[channel] / mean;
            y[index] = x[index] + 0.5 * x[index] * relative + 0.25;
        }
    }
    const std::array<double, 4> expected{
        4.132352941, 0.25, 5.426470588, 20.720588235
    };
    for (int i = 0; i < 4; ++i) {
        assert(std::abs(y[i] - expected[i]) < 1e-9);
        std::cout << std::fixed << std::setprecision(9) << y[i]
                  << (i == 3 ? '\n' : ' ');
    }
}
```

production 구현은 batch stride, dynamic shape, SIMD와 accumulation dtype을 추가해야 한다. 이 예제의 목적은 layout과 수식의 golden value를 고정하는 것이다.

## 12. C# golden 예제

아래 코드는 **실행 가능한 C# 예제**다. C++과 같은 `NHWC` flat buffer와 `double`을 사용한다.

```csharp
using System;

public static class GrnGolden
{
    public static void Main()
    {
        double[] x = { 3.0, 0.0, 4.0, 12.0 };
        double[] norm = new double[2];

            }
        }
        for (int channel = 0; channel < 2; channel++)
            norm[channel] = Math.Sqrt(norm[channel]);

        double mean = (norm[0] + norm[1]) / 2.0;
        double[] expected = { 4.132352941, 0.25, 5.426470588, 20.720588235 };
        for (int position = 0; position < 2; position++)
        {
            for (int channel = 0; channel < 2; channel++)

                double y = x[index] + 0.5 * x[index] * relative + 0.25;

            }

```

## 13. 프레임워크 간 shape·layout·dtype 대응

| 의미 | PyTorch | NumPy | C++/C# 계약 |
| --- | --- | --- | --- |
| 이미지 입력 | `(B,C,H,W)` | 같은 논리 shape | explicit stride가 있는 flat buffer |
| patch sequence | `(B,L,D)` | `(B,L,D)` | flatten order를 schema로 저장 |
| GRN 기본 | `(B,H,W,C)` | axis `(1,2)` reduction | `NHWC` contiguous 예제 |
| GRN `NCHW` | axis `(2,3)` | axis `(2,3)` | 별도 kernel 또는 transpose |
| mask | `torch.bool`, `(B,L)` | `bool` 또는 `float32` | byte mask와 `1=masked` 명시 |
| norm accumulation | 권장 `float32` 이상 | 예제 `float64` | 예제 `double`, production 별도 |
| parameter broadcast | `(1,1,1,C)` | 같은 shape | channel index로 직접 접근 |

PyTorch의 `channels_last` memory format은 tensor shape를 `BHWC`로 바꾸지 않는다. shape가 `BCHW`인 tensor에 memory format만 channels-last로 바꾼 경우 GRN reduction axis는 여전히 `(2,3)`이다.

export 전에 patch ordering을 model metadata에 기록한다. `D=P^2C`가 같더라도 `channel-first patch flatten`과 `pixel-interleaved flatten`은 완전히 다른 target이다.

## 14. 테스트와 디버깅

### 14.1 최소 단위 테스트

- `patchify`의 첫 두 patch 시작값을 작은 증가 수열로 검증한다.
- 각 sample의 `mask.sum()`이 정확히 $L_{mask}$인지 확인한다.
- mask ratio 0, 1과 shape mismatch가 즉시 실패하는지 확인한다.
- prediction이 masked target보다 정확히 2 클 때 loss가 4인지 확인한다.
- `NHWC`와 `NCHW` GRN의 forward·input gradient를 비교한다.
- $\gamma=\beta=0$에서 GRN output이 input과 같은지 확인한다.
- 같은 seed의 pretraining history와 `state_dict`가 정확히 같은지 확인한다.
- linear probe 뒤 encoder state가 변하지 않았는지 확인한다.
- 빈 GT가 아니라 빈 mask를 별도 오류로 다룬다.

### 14.2 실패 증상별 진단

| 증상 | 가능한 원인 | 확인 방법 |
| --- | --- | --- |
| loss가 비정상적으로 작음 | visible patch에만 loss를 계산 | mask convention과 selected index 출력 |
| loss가 `NaN` | 빈 mask 또는 half norm overflow | mask count, reduction dtype 검사 |
| reconstruction은 좋고 probe는 나쁨 | 쉬운 pixel shortcut 또는 과업 불일치 | scratch·linear probe·fine-tune 비교 |
| exact replay 실패 | mask RNG나 sample order state 누락 | step별 mask hash와 batch index 저장 |
| sparse가 dense보다 느림 | coordinate overhead와 작은 active tensor | stage별 kernel time과 active count 측정 |
| GRN output shape는 맞지만 성능 하락 | reduction axis 오류 | 손계산 `(1,1,2,2)` golden 비교 |
| fine-tune 첫 step 급변 | optimizer state 재사용 또는 LR 과대 | 새 optimizer와 layer별 LR 비교 |
| ONNX 결과 불일치 | dynamic reduction·cast·epsilon 차이 | intermediate norm과 relative response 비교 |

## 15. 성능·메모리·수치 안정성

### 15.1 sparse 계산량을 active ratio와 동일시하지 않는다

visible ratio가 $q=1-r$이어도 runtime은 $q$배가 아니다.

$$
T_{sparse}
=
T_{coordinate}
+T_{gather/scatter}
+T_{active\ kernel}
+T_{launch}
$$

작은 feature에서는 고정 overhead 때문에 dense kernel이 더 빠를 수 있다. 다음을 같은 hardware, batch, dtype과 augmentation에서 측정한다.

- end-to-end images/s와 step latency 분포
- encoder와 decoder의 개별 시간
- peak allocated와 reserved memory
- stage별 active coordinate 수
- data loader wait와 host-to-device copy
- dense surrogate와 real sparse backend의 결과 parity

### 15.2 GRN 수치 안정성

공간 L2 norm은 제곱합이므로 큰 activation과 넓은 feature map에서 `float16` overflow가 가능하다. norm reduction은 `float32`로 올리고, 출력 dtype은 명시적으로 되돌린다. all-zero feature에서는 $G=0$이므로 $\epsilon$이 반드시 필요하다.

epsilon을 너무 크게 두면 작은 response의 상대 비율을 눌러 GRN 의미가 달라진다. framework 기본값에 맡기지 말고 checkpoint config와 export metadata에 기록한다.

### 15.3 reconstruction head memory

pixel head의 마지막 차원은 $D=P^2C$다. patch 수와 곱하면 원본 pixel 수와 같다.

$$
LD
=
\frac{HW}{P^2}P^2C
=
HWC
$$

원소 수가 같아도 `Linear`, `Conv2d`, layout copy와 kernel shape에 따라 memory bandwidth와 latency는 달라진다. 큰 $P$가 자동으로 decoder를 싸게 만들지는 않는다.

## 16. 실무 실패 사례

### 사례 A: dense 검증 모델을 sparse 성능 결과로 보고

팀은 mask token을 넣은 dense ConvNeXt로 정확도를 확인한 뒤 “60% mask이므로 FLOPs도 60% 줄었다”고 보고했다. profiler에서는 모든 grid position의 convolution이 실행됐다. 해결은 정확성 계약 모델과 실제 sparse benchmark를 별도 artifact로 관리하는 것이다.

### 사례 B: distributed loss denominator 오류

rank 0에는 masked patch 400개, rank 1에는 200개가 있었지만 rank별 mean loss를 단순 평균했다. 실제 global patch mean과 다른 gradient가 만들어졌다. 분자와 masked count를 각각 all-reduce하고 마지막에 나눈다.

### 사례 C: probe에서 encoder가 조용히 변경

parameter는 freeze했지만 encoder를 `train()`에 두어 running-stat buffer가 갱신됐다. 이후 probe 결과가 실행 순서에 따라 바뀌었다. freeze policy에 parameter뿐 아니라 buffer와 stochastic layer mode를 포함한다.

### 사례 D: pretraining 성능을 downstream 성공으로 오해

reconstruction loss는 꾸준히 낮아졌지만 defect classification linear probe가 chance였다. mask가 너무 작아 local texture 복사가 쉬웠고 target 도메인의 핵심 결함은 드물었다. mask ratio, crop 정책, probe와 fine-tuning metric을 함께 평가해 pretext shortcut을 발견했다.

### 사례 E: GRN axis 오류가 broadcast로 숨음

`NCHW` tensor에 `dim=(1,2)`를 적용했는데 결과 shape가 broadcast 가능해 runtime error가 나지 않았다. offline accuracy만 떨어졌다. 작은 golden tensor와 intermediate response telemetry를 release test에 추가했다.

## 17. 배포 관점

FCMAE decoder는 pretraining artifact이고 downstream 서비스에는 보통 필요하지 않다. artifact 경계를 다음처럼 나눈다.

1. **pretraining checkpoint:** encoder, decoder, mask token, optimizer, scheduler, AMP scaler, mask RNG, sampler state.
2. **transfer package:** encoder weight, architecture, normalization, patch와 layout schema.
3. **task checkpoint:** encoder와 classifier·detector head, label mapping, fine-tuning recipe.
4. **serving graph:** dense encoder와 task head, preprocessing과 postprocessing만 포함.
5. **monitoring schema:** latency, input shape·dtype, embedding norm, confidence, data drift.

ONNX export에서는 GRN이 norm, mean, division, multiplication과 addition으로 분해된다. target runtime이 dynamic $H,W$, reduction axis, cast와 epsilon을 동일하게 처리하는지 golden input으로 비교한다. sparse pretraining graph 전체를 serving graph로 export하는 것이 목표가 아니다.

### 17.1 checkpoint 필수 필드

- source commit과 dependency version
- architecture와 patch flatten order
- mask ratio, count rounding, mask convention
- target normalization과 epsilon
- dataset revision, split hash와 preprocessing
- global step, epoch, sampler와 RNG state
- optimizer, scheduler와 AMP scaler
- encoder-only export key mapping
- linear probe와 fine-tune 결과 및 seed

## 18. 실무 체크리스트

### 데이터와 mask

- [ ] $H,W$가 $P$로 나누어떨어지거나 valid-pixel mask가 있다.
- [ ] `1=masked`, `0=visible`을 schema와 test에 고정했다.
- [ ] sample별 masked count와 실제 ratio를 기록한다.
- [ ] rank별 mask RNG와 data sampler를 재시작할 수 있다.
- [ ] target normalization이 experiment ID에 포함된다.

### 모델과 loss

- [ ] patchify와 decoder flatten 순서가 golden test로 같다.
- [ ] masked patch만 loss에 포함한다.
- [ ] 빈 mask와 shape mismatch가 즉시 실패한다.
- [ ] sparse encoder가 active coordinate를 퍼뜨리지 않는지 확인했다.
- [ ] GRN reduction axis, dtype, epsilon과 parameter shape가 맞다.
- [ ] all-zero와 extreme activation에서 output·gradient가 finite하다.

### 전이와 평가

- [ ] linear probe encoder가 parameter·buffer 모두 고정된다.
- [ ] full fine-tuning과 scratch baseline의 split·budget이 같다.
- [ ] pretraining loss와 downstream metric을 함께 기록한다.
- [ ] same-seed exact replay 또는 허용 오차가 문서화됐다.
- [ ] ablation은 한 번에 하나의 원인만 바꾼다.

### 성능과 배포

- [ ] sparse와 dense를 실제 target hardware에서 측정했다.
- [ ] peak memory, step time과 active count를 함께 기록했다.
- [ ] decoder와 mask generator를 serving graph에서 제거했다.
- [ ] ONNX 또는 target runtime의 GRN parity를 확인했다.
- [ ] encoder key mapping과 preprocessing metadata를 보존했다.

## 19. 연습문제

### 문제 1

$H=192$, $W=256$, $P=32$, $r=0.6$이고 $L_{keep}=\lfloor L(1-r)\rfloor$일 때 $G_h,G_w,L,L_{keep},L_{mask}$를 구하라.

### 문제 2

두 rank의 masked loss 분자와 count가 각각 $(120,40)$, $(100,20)$이다. rank mean의 단순 평균과 올바른 global mean을 구하라.

### 문제 3

`NCHW` shape `(8,96,14,14)`에서 GRN의 spatial reduction axis, channel mean axis와 $\gamma$ shape를 쓰라.

### 문제 4

$\gamma=0$, $\beta=0$인 GRN이 forward identity임을 보이고, 왜 첫 backward에서 모든 upstream branch parameter가 같은 크기의 gradient를 받는다고 결론 낼 수 없는지 설명하라.

### 문제 5

reconstruction loss는 낮아지는데 linear probe가 chance인 원인을 세 가지 쓰고, 이를 구분할 ablation을 제안하라.

### 문제 6

linear probe에서 encoder parameter는 freeze했지만 encoder의 stateful buffer가 바뀌었다. 어떤 검사를 추가해야 하는가?

## 20. 연습문제 해답

### 해답 1

$$
G_h=192/32=6,
\qquad
G_w=256/32=8,
\qquad
L=48
$$

$$
L_{keep}=\lfloor48\cdot0.4\rfloor=19,
\qquad
L_{mask}=48-19=29
$$

설정 ratio는 0.6이지만 실제 masked fraction은 $29/48\approx0.6042$다.

### 해답 2

rank별 mean은 $120/40=3$, $100/20=5$이므로 단순 평균은 4다. 올바른 global mean은 다음이다.

$$
\frac{120+100}{40+20}
=
\frac{220}{60}
\approx3.6667
$$

### 해답 3

spatial reduction은 `(2,3)`, channel mean은 `dim=1`, $\gamma$와 $\beta$ shape는 `(1,96,1,1)`이다. memory format이 channels-last여도 논리 shape가 `NCHW`이면 축은 변하지 않는다.

### 해답 4

$\gamma=\beta=0$이면 $Y=X$다. $\gamma$에는 $NX$를 통한 gradient가, $\beta$에는 broadcast 합 gradient가 흐를 수 있다. 그러나 $N$을 계산하는 branch의 gradient는 $\gamma$와 곱해지므로 초기에는 차단될 수 있다. identity 출력과 동시 학습 보장은 다르다.

### 해답 5

mask가 너무 쉬워 local 복사가 가능한 경우, pretraining 도메인과 downstream 도메인이 다른 경우, encoder capacity나 학습 시간이 부족한 경우가 있다. mask ratio·block masking ablation, in-domain pretraining, compute-matched longer training, linear probe와 full fine-tuning 비교로 원인을 나눈다.

### 해답 6

probe 전후 encoder의 전체 `state_dict`를 비교해야 한다. parameter만 아니라 running mean·variance 같은 buffer도 포함한다. encoder의 `train/eval` mode와 stochastic layer 동작도 명시한다.

## 핵심 요약

- FCMAE 구현은 mask convention, 정확한 count, patch ordering과 masked denominator에서 시작한다.
- dense 계약 모델은 정확성을 검증하지만 sparse 계산 절감을 증명하지 않는다.
- 분산 masked MSE는 rank별 scalar mean이 아니라 분자와 count를 합쳐야 한다.
- GRN은 spatial L2 response를 channel 평균으로 정규화하고 학습 가능한 calibration을 더한다.
- `NHWC`와 `NCHW`는 reduction axis와 parameter broadcast shape가 다르다.
- pretraining loss 감소만으로 representation 품질을 보장할 수 없다.
- linear probe, full fine-tuning과 scratch baseline을 같은 split·budget으로 비교한다.
- exact replay에는 model seed뿐 아니라 mask RNG, sampler, optimizer와 scaler state가 필요하다.
- sparse throughput은 active ratio, coordinate overhead와 target hardware를 함께 측정한다.
- downstream serving에는 보통 pretraining decoder와 mask generator를 포함하지 않는다.
