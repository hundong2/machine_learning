## 학습 목표

1회차에는 두 예측의 차이를 확대하는 CFG의 확률적 직관과 scale 관례를 배웠다. 이번에는 그 설명을 학습부터 배포까지 재현 가능한 실행 계약으로 바꾼다. 이 글을 마치면 다음을 할 수 있다.

- condition dropout을 포함한 noise-prediction 학습 loop를 구현한다.
- null condition을 단순한 영벡터와 구분하고 학습·추론에서 같은 규칙을 유지한다.
- conditional·unconditional branch를 한 batch로 묶되 sample pairing을 보존한다.
- `epsilon`, `sample`, `v_prediction`을 공통 표현으로 변환한 뒤 CFG를 적용한다.
- $g=0$, $g=1$, 동일 branch, batch permutation 불변식을 단위 테스트로 고정한다.
- guidance scale과 dropout 확률의 ablation을 같은 seed와 평가 집합으로 비교한다.
- NumPy, PyTorch, C++와 C#의 shape·layout·dtype 계약을 맞춘다.
- ONNX 배포에서 dynamic batch, scheduler metadata와 branch 순서를 보존한다.

## 선수 지식과 기호

조건부 확률, DDPM 정방향 과정, noise-prediction loss, DDIM 또는 DDPM sampler 한 step, PyTorch broadcasting을 알고 있으면 된다.

| 기호 | 정의 | 대표 shape |
| --- | --- | --- |
| $x_0$ | clean sample | $(N,C,H,W)$ |
| $x_t$ | timestep $t$의 noisy sample | $(N,C,H,W)$ |
| $c$ | 원래 condition | class id 또는 token sequence |
| $c_{\varnothing}$ | 학습된 null condition | embedding 후 $(N,L,D)$ 또는 $(N,D)$ |
| $m$ | condition 유지 mask, 유지면 1 | $(N,1)$ 또는 $(N,1,1)$ |
| $p_{\mathrm{drop}}$ | condition dropout 확률 | scalar |
| $\epsilon_u$ | null condition noise prediction | $(N,C,H,W)$ |
| $\epsilon_c$ | 실제 condition noise prediction | $(N,C,H,W)$ |
| $g$ | 이 글의 guidance scale | scalar 또는 $(N,1,1,1)$ |
| $\bar{\alpha}_t$ | $t$까지 signal 보존율 | $(N,1,1,1)$ |

이 글은 다음 scale 관례를 사용한다.

$$
\hat{\epsilon}_{\mathrm{cfg}}
=
\epsilon_u
+
g(\epsilon_c-\epsilon_u)
$$

따라서 $g=0$은 unconditional, $g=1$은 conditional prediction이다. 원 논문의 추가 guidance 계수를 $w$라 쓰고 $(1+w)\epsilon_c-w\epsilon_u$로 구현했다면 두 관례는 $g=1+w$로 대응한다. 숫자만 복사하지 말고 식을 함께 기록해야 한다.

## 1. 원본을 구현 관점에서 다시 읽기

원본은 CFG의 핵심 벡터 식과 batch 결합을 잘 보여 주지만, 실행 가능한 시스템에는 빠진 계약이 있다.

| 원본의 표현 또는 생략 | 구현에서의 수정 |
| --- | --- |
| classifier guidance의 몰락 | 별도 noisy classifier 비용이 있는 유효한 방법이며 CFG와 trade-off가 다르다. |
| 두 branch 차이는 classifier gradient와 완벽히 동일 | 확률적 score 관계를 유한한 neural network가 근사한 값이다. |
| 추론의 세 줄 연산이 CFG의 전부 | 학습 시 condition dropout과 null condition 정의가 먼저 필요하다. |
| $7.5$는 황금 비율 | 모델·sampler·step 수·prediction type마다 평가로 선택한다. |
| $g>20$에서 고정적으로 붕괴 | 실패 임계값은 모델과 수치 계약에 의존한다. |
| empty prompt embedding 대신 zero도 무방 | tokenizer, special token과 text encoder를 거친 null 분포를 보존해야 한다. |
| batch 결합은 U-Net 계산을 절약 | 호출 overhead는 줄지만 branch 두 개의 FLOP과 peak activation은 남는다. |
| negative prompt는 나쁜 개념의 정확한 반대 | negative-conditioned branch에서 positive-conditioned branch 쪽으로 외삽할 뿐이다. |

이번 구현의 핵심은 CFG를 독립적인 후처리 한 줄이 아니라 다음 파이프라인의 일부로 보는 것이다.

```text
training sample
  -> timestep·noise sample
  -> condition dropout
  -> denoiser target 학습
  -> checkpoint + null-condition contract

sampling request
  -> latent·timestep 복제
  -> null·positive condition 정렬
  -> paired denoiser output
  -> prediction type 변환
  -> CFG FP32 혼합
  -> scheduler step
```

## 2. condition dropout이 만드는 두 역할

### 2.1 학습 목적 함수

CFG는 하나의 denoiser가 conditional과 unconditional 함수를 모두 배워야 한다. 각 sample마다 Bernoulli mask를 뽑는다.

$$
m_i
\sim
\operatorname{Bernoulli}(1-p_{\mathrm{drop}})
$$

condition embedding은 다음처럼 선택한다.

$$
\tilde{e}_i
=
m_i e(c_i)
+
(1-m_i)e(c_{\varnothing})
$$

noise prediction 학습은 다음과 같다.

$$
\mathcal{L}
=
\frac{1}{N}
\sum_{i=1}^{N}
\left\|
\epsilon_i
-
\epsilon_{\theta}(x_{t_i},t_i,\tilde{e}_i)
\right\|_2^2
$$

$p_{\mathrm{drop}}=0$이면 모델은 학습 중 null branch를 보지 못한다. 추론 때 CFG 식을 계산할 수는 있어도 $\epsilon_u$가 distribution shift에 놓인다. 반대로 dropout이 지나치게 크면 conditional sample이 줄어 condition fidelity가 약해질 수 있다. 확률은 보편 상수가 아니라 ablation 대상이다.

### 2.2 sample 단위 mask

dropout mask는 embedding 원소마다 뽑는 일반 dropout과 다르다. 한 sample의 condition 전체를 null로 바꿔야 한다.

```text
잘못된 mask: (N, L, D)  -> token·feature 일부만 무작위 제거
권장 mask:   (N, 1, 1)  -> sample의 condition 전체를 유지 또는 제거
```

distributed training에서는 rank마다 독립 RNG를 사용하더라도 global dropped ratio를 기록한다. 작은 batch에서는 한 rank의 batch가 전부 conditional 또는 전부 null이 될 수 있으므로, step 단위가 아니라 충분한 window에서 비율을 본다.

### 2.3 null condition은 값이 아니라 프로토콜이다

text-conditioned 모델의 null condition은 보통 empty string을 정상 tokenizer와 text encoder에 통과시킨 결과다. 다음이 모두 계약에 포함된다.

- tokenizer와 vocabulary version
- beginning·end·padding special token
- attention mask
- sequence length와 padding 방향
- text encoder와 projection weight
- embedding dtype

영벡터는 이 프로토콜과 일반적으로 같지 않다. class-conditioned 모델은 별도의 null class id를 두는 편이 명확하다. null id가 실제 class 범위와 충돌하지 않도록 `num_classes`를 예약 id로 고정한다.

## 3. prediction type보다 먼저 또는 나중에 혼합할 수 있는가

### 3.1 선형 변환이면 동등하다

같은 $x_t$, timestep과 scheduler 계수에서 `epsilon`, `sample`, `v_prediction` 사이 변환은 model output에 대해 affine이다. 예를 들어 $v$ prediction에서 다음과 같다.

$$
\hat{x}_0
=
\sqrt{\bar{\alpha}_t}x_t
-
\sqrt{1-\bar{\alpha}_t}v
$$

$$
\hat{\epsilon}
=
\sqrt{1-\bar{\alpha}_t}x_t
+
\sqrt{\bar{\alpha}_t}v
$$

branch 두 개가 정확히 같은 $x_t$와 $t$를 공유하고 clipping 같은 비선형 연산이 없다면 raw $v$를 CFG로 혼합한 뒤 변환하는 것과 각 branch를 $\epsilon$으로 변환한 뒤 혼합하는 것은 동등하다.

### 3.2 비선형 후처리는 순서를 바꾼다

다음 연산이 branch별 변환 사이에 끼면 동등성이 깨진다.

- `pred_x0` clipping
- dynamic thresholding
- norm 기반 guidance rescale
- quantization과 saturation
- branch마다 다른 scheduler coefficient

따라서 manifest에는 단지 `prediction_type=v_prediction`만 쓰지 말고 `convert -> cfg -> rescale -> scheduler` 같은 순서를 기록한다. golden tensor도 raw branch output, guided output, next latent 세 경계에서 저장한다.

## 4. tensor shape와 batch pairing

### 4.1 권장 concat 계약

입력이 다음과 같다고 하자.

| tensor | CFG 전 shape | CFG denoiser 입력 shape | layout·dtype |
| --- | --- | --- | --- |
| latent | $(N,C,H,W)$ | $(2N,C,H,W)$ | `NCHW`, model dtype |
| timestep | $(N)$ | $(2N)$ | `int64` 또는 model contract |
| context | $(N,L,D)$ | $(2N,L,D)$ | `NLD`, model dtype |
| context mask | $(N,L)$ | $(2N,L)$ | `bool` 또는 `int64` |
| output | 없음 | $(2N,C,H,W)$ | latent와 같은 layout |

batch 순서는 다음 하나로 고정한다.

```text
latent_2n  = cat([x, x])
time_2n    = cat([t, t])
context_2n = cat([null, cond])
mask_2n    = cat([null_mask, cond_mask])
output     = cat([unconditional_output, conditional_output])
```

그 뒤 `output.chunk(2, dim=0)`으로 두 branch를 복원한다. `repeat_interleave`와 `cat`을 섞으면 sample이 조용히 바뀐다.

### 4.2 concrete shape 추적

$N=3$, $C=4$, $H=W=64$, $L=77$, $D=768$이면 다음과 같다.

```text
x_t                 (3, 4, 64, 64)
cat([x_t, x_t])     (6, 4, 64, 64)
null_context        (3, 77, 768)
cond_context        (3, 77, 768)
cat([null, cond])   (6, 77, 768)
denoiser output     (6, 4, 64, 64)
chunk outputs       each (3, 4, 64, 64)
guided output       (3, 4, 64, 64)
```

batch size가 짝수라는 검사만으로는 pairing 오류를 잡지 못한다. sample별 sentinel condition으로 output identity를 확인하는 테스트가 필요하다.

## 5. NumPy 수작업 검증

다음 코드는 실행 가능한 golden test다. 선형 invariant와 FP16 cancellation 위험을 함께 확인한다.

```python
import numpy as np


def cfg(uncond, cond, scale):
    u = np.asarray(uncond, dtype=np.float32)
    c = np.asarray(cond, dtype=np.float32)
    if u.shape != c.shape:
        raise ValueError(f"shape mismatch: {u.shape} vs {c.shape}")
    g = np.asarray(scale, dtype=np.float32)
    out = u + g * (c - u)
    if not np.isfinite(out).all():
        raise FloatingPointError("non-finite CFG output")
    return out


u = np.array([[1.0, -1.0], [0.5, 2.0]], dtype=np.float32)
c = np.array([[0.0, 3.0], [1.5, -2.0]], dtype=np.float32)

np.testing.assert_allclose(cfg(u, c, 0.0), u)
np.testing.assert_allclose(cfg(u, c, 1.0), c)
np.testing.assert_allclose(cfg(u, u, 17.0), u)
np.testing.assert_allclose(
    cfg(u, c, 2.0),
    np.array([[-1.0, 7.0], [2.5, -6.0]], dtype=np.float32),
)

# sample마다 다른 scale: (N, 1)이 feature 축으로 broadcast된다.
scale = np.array([[0.0], [2.0]], dtype=np.float32)
per_sample = cfg(u, c, scale)
np.testing.assert_allclose(per_sample[0], u[0])
np.testing.assert_allclose(per_sample[1], [2.5, -6.0])

# subtraction은 FP32에서 수행한다. FP16에서는 큰 공통값의 작은 차이가 사라진다.
u16 = np.array([4096.0], dtype=np.float16)
c16 = np.array([4097.0], dtype=np.float16)
assert float(c16[0] - u16[0]) == 0.0

print("golden", cfg(u, c, 2.0).tolist())
print("per_sample", per_sample.tolist())
print("fp16_delta", float(c16[0] - u16[0]))
```

예상 출력은 다음과 같다.

```text
golden [[-1.0, 7.0], [2.5, -6.0]]
per_sample [[1.0, -1.0], [2.5, -6.0]]
fp16_delta 0.0
```

실제 model output이 FP16이어도 두 branch를 FP32로 올린 뒤 빼고 곱하면 cancellation과 overflow 위험을 줄일 수 있다. scheduler가 요구하는 dtype으로는 혼합 뒤 되돌린다.

## 6. PyTorch 완전 구현

아래 코드는 설명용 조각이 아니라 실행 가능한 synthetic 학습·평가 프로그램이다. 작은 denoiser가 두 class의 noise target을 배우며, condition dropout과 paired CFG, exact replay를 시험한다.

```python
import copy
import math
import random

import numpy as np
import torch
from torch import nn


def seed_everything(seed):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.use_deterministic_algorithms(True)


class TinyDenoiser(nn.Module):
    def __init__(self, features=4, classes=2, hidden=32):
        super().__init__()
        self.null_id = classes
        self.cond = nn.Embedding(classes + 1, 8)
        self.net = nn.Sequential(
            nn.Linear(features + 1 + 8, hidden),
            nn.SiLU(),
            nn.Linear(hidden, hidden),
            nn.SiLU(),
            nn.Linear(hidden, features),
        )

    def forward(self, x_t, t, condition):
        if x_t.ndim != 2 or t.shape != (x_t.shape[0], 1):
            raise ValueError("expected x_t=(N,F), t=(N,1)")
        if condition.shape != (x_t.shape[0],):
            raise ValueError("condition must have shape (N,)")
        return self.net(torch.cat([x_t, t, self.cond(condition)], dim=1))


def make_batch(generator, batch=64):
    label = torch.randint(0, 2, (batch,), generator=generator)
    mean = torch.where(label[:, None] == 0, -1.0, 1.0)
    x0 = mean + 0.15 * torch.randn(batch, 4, generator=generator)
    t = torch.rand(batch, 1, generator=generator) * 0.8 + 0.1
    alpha_bar = torch.cos(t * math.pi / 2.0).square()
    noise = torch.randn(batch, 4, generator=generator)
    x_t = alpha_bar.sqrt() * x0 + (1.0 - alpha_bar).sqrt() * noise
    return x_t, t, label, noise


def drop_condition(label, null_id, probability, generator):
    # sample 단위 Bernoulli mask이며 embedding 원소 dropout이 아니다.
    dropped = torch.rand(label.shape, generator=generator) < probability
    return torch.where(dropped, torch.full_like(label, null_id), label), dropped


def train_once(seed, drop_probability, steps=180):
    seed_everything(seed)
    model = TinyDenoiser()
    optimizer = torch.optim.AdamW(model.parameters(), lr=4e-3, weight_decay=0.0)
    generator = torch.Generator().manual_seed(seed + 1)
    history = []
    dropped_total = 0
    sample_total = 0

    model.train()
    for _ in range(steps):
        x_t, t, label, target_noise = make_batch(generator)
        used_condition, dropped = drop_condition(
            label, model.null_id, drop_probability, generator
        )
        prediction = model(x_t, t, used_condition)
        loss = (prediction - target_noise).square().mean()
        optimizer.zero_grad(set_to_none=True)
        loss.backward()
        nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()
        history.append(float(loss.detach()))
        dropped_total += int(dropped.sum())
        sample_total += dropped.numel()

    return model, history, dropped_total / sample_total


@torch.no_grad()
def paired_cfg(model, x_t, t, condition, scale):
    n = x_t.shape[0]
    if t.shape != (n, 1) or condition.shape != (n,):
        raise ValueError("paired inputs have inconsistent batch dimensions")
    null = torch.full_like(condition, model.null_id)
    x_2n = torch.cat([x_t, x_t], dim=0)
    t_2n = torch.cat([t, t], dim=0)
    condition_2n = torch.cat([null, condition], dim=0)
    output_2n = model(x_2n, t_2n, condition_2n)
    if output_2n.shape != (2 * n, x_t.shape[1]):
        raise RuntimeError("denoiser output contract changed")
    uncond, cond = output_2n.chunk(2, dim=0)
    guided = uncond.float() + float(scale) * (cond.float() - uncond.float())
    if not torch.isfinite(guided).all():
        raise FloatingPointError("non-finite guided prediction")
    return guided, uncond.float(), cond.float()


def evaluate_null_branch(model, seed=999):
    generator = torch.Generator().manual_seed(seed)
    x_t, t, label, noise = make_batch(generator, batch=256)
    null = torch.full_like(label, model.null_id)
    with torch.no_grad():
        prediction = model(x_t, t, null)
    return float((prediction - noise).square().mean())


model, history, dropped_ratio = train_once(7, 0.2)
replay, replay_history, replay_ratio = train_once(7, 0.2)
assert history == replay_history
assert dropped_ratio == replay_ratio
for key, value in model.state_dict().items():
    assert torch.equal(value, replay.state_dict()[key])

generator = torch.Generator().manual_seed(123)
x_t, t, label, _ = make_batch(generator, batch=8)
g0, uncond, cond = paired_cfg(model, x_t, t, label, 0.0)
g1, _, _ = paired_cfg(model, x_t, t, label, 1.0)
same, same_u, _ = paired_cfg(
    model, x_t, t, torch.full_like(label, model.null_id), 9.0
)
torch.testing.assert_close(g0, uncond, rtol=0.0, atol=0.0)
torch.testing.assert_close(g1, cond, rtol=1e-6, atol=1e-6)
torch.testing.assert_close(same, same_u, rtol=1e-6, atol=1e-6)

# dropout ablation: null branch를 학습하지 않은 모델과 같은 평가 집합에서 비교한다.
no_drop, _, no_drop_ratio = train_once(7, 0.0)
null_mse = evaluate_null_branch(model)
no_drop_null_mse = evaluate_null_branch(no_drop)

print("shape", tuple(g1.shape))
print("loss", f"{history[0]:.6f}", "->", f"{history[-1]:.6f}")
print("drop_ratio", f"{dropped_ratio:.4f}", "no_drop", f"{no_drop_ratio:.4f}")
print("null_mse", f"{null_mse:.6f}", "no_drop", f"{no_drop_null_mse:.6f}")
print("exact_replay", True)
```

2026-08-27 로컬 실행 결과는 다음과 같다.

```text
shape (8, 4)
loss 1.008693 -> 0.174251
drop_ratio 0.1969 no_drop 0.0000
null_mse 0.296078 no_drop 0.613790
exact_replay True
```

이 실험은 synthetic 문제이므로 실제 생성 품질의 증거가 아니다. 목적은 다음 계약을 작은 비용으로 회귀 테스트하는 것이다.

- condition dropout이 sample 단위로 일어난다.
- 같은 seed에서 loss history와 parameter가 정확히 재현된다.
- $g=0$과 $g=1$ invariant가 branch output과 일치한다.
- 두 condition이 같으면 어떤 scale에서도 output이 같다.
- null branch를 실제로 학습했는지 독립 평가 loss로 관찰한다.

## 7. sampler와 연결할 때의 경계

### 7.1 한 step의 올바른 순서

`epsilon` prediction checkpoint라면 다음 순서가 가장 감사하기 쉽다.

```text
1. model(x_t, t, null) -> epsilon_u
2. model(x_t, t, cond) -> epsilon_c
3. FP32 CFG            -> guided_epsilon
4. optional rescale    -> rescaled_epsilon
5. scheduler step      -> x_s
```

`v_prediction` checkpoint는 raw $v_u$, $v_c$를 혼합하는 정책과 branch별 $\epsilon$ 변환 후 혼합하는 정책 중 하나를 고정한다. 이론상 선형 동등성이 있더라도 clipping·rescale 순서가 다르면 golden output이 달라진다.

### 7.2 scale schedule

상수 $g$ 대신 timestep별 $g_t$를 쓸 수 있다.

$$
\hat{\epsilon}_t
=
\epsilon_{u,t}
+
g_t(\epsilon_{c,t}-\epsilon_{u,t})
$$

이 경우 `guidance_scale=7.5` 한 값만 저장해서는 재현할 수 없다. schedule type, parameter와 실제 timestep 배열을 함께 기록한다. step index와 training timestep을 혼동하지 않는다.

### 7.3 guidance rescale

큰 scale에서 guided prediction의 표준편차가 conditional prediction보다 과도하게 커질 수 있다. 한 가지 실용적 아이디어는 guided tensor를 conditional tensor의 통계에 맞춘 뒤 원래 guided tensor와 보간하는 것이다.

$$
r
=
\frac{\operatorname{std}(\epsilon_c)}
{\operatorname{std}(\hat{\epsilon}_{\mathrm{cfg}})+\varepsilon}
$$

$$
\epsilon_{\mathrm{rescaled}}
=
\rho r\hat{\epsilon}_{\mathrm{cfg}}
+
(1-\rho)\hat{\epsilon}_{\mathrm{cfg}}
$$

표준편차를 어느 축에서 계산하는지 명시한다. 보통 sample마다 channel·spatial 축을 줄이고 batch 축은 섞지 않는다. $\rho$, $\varepsilon$, unbiased 여부도 metadata에 넣는다.

## 8. 테스트와 디버깅

### 8.1 최소 단위 테스트

| 테스트 | 입력 | 기대 결과 | 잡는 버그 |
| --- | --- | --- | --- |
| scale zero | $g=0$ | guided = unconditional | scale 관례 혼용 |
| scale one | $g=1$ | guided = conditional | 원 논문식 혼용 |
| equal branch | $\epsilon_u=\epsilon_c$ | 모든 $g$에서 동일 | 산술·broadcast 오류 |
| shape mismatch | 서로 다른 branch shape | 즉시 오류 | silent broadcast |
| pairing sentinel | sample마다 다른 condition id | 같은 sample끼리 pair | concat/interleave 혼용 |
| permutation equivariance | batch 순열 후 복원 | 원 output과 동일 | batch state 누수 |
| finite extreme | 큰 유한 branch·scale | 정책대로 finite 또는 명시 오류 | FP16 overflow |
| scheduler golden | 고정 branch·coefficient | 고정 next latent | prediction type·순서 오류 |

### 8.2 pairing sentinel

테스트용 denoiser가 `output[i] = sample_id + 100 * condition_id`를 반환하게 만든다. null id와 positive id가 출력에 드러나므로 `repeat_interleave`와 `cat` 혼용을 즉시 발견할 수 있다. 실제 U-Net의 시각 품질만 비교하면 sample swap이 stochastic variation처럼 보일 수 있다.

### 8.3 자주 보는 증상

| 증상 | 가능한 원인 | 첫 확인 |
| --- | --- | --- |
| $g=1$인데 conditional-only와 다름 | scale 식·branch 순서 오류 | raw branch tensor 비교 |
| batch 1은 맞고 batch 2부터 깨짐 | pairing 또는 attention mask 순서 | sentinel test |
| Python과 ONNX shape는 같은데 결과가 다름 | timestep dtype·prediction type | graph input과 manifest |
| 큰 scale에서 NaN | FP16 subtraction·multiply overflow | CFG 구간 FP32 실행 |
| prompt를 바꿔도 결과가 비슷함 | dropout 과다·condition mask 오류 | conditional sample 비율·attention |
| negative prompt가 오히려 개념을 강화 | linear semantic assumption 실패 | 두 branch와 prompt별 평가 |

## 10. C++ 후처리 예제

다음 코드는 표준 라이브러리만 사용하는 실행 가능한 C++17 golden test다. model runtime과 무관한 CFG 경계를 검증한다.

```cpp
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>
#include <stdexcept>
#include <vector>

std::vector<float> Cfg(const std::vector<float>& uncond,
                       const std::vector<float>& cond,
                       float scale) {
    if (uncond.size() != cond.size()) {
        throw std::invalid_argument("branch size mismatch");
    }
    std::vector<float> output(uncond.size());
    for (std::size_t i = 0; i < output.size(); ++i) {
        output[i] = uncond[i] + scale * (cond[i] - uncond[i]);
        if (!std::isfinite(output[i])) {
            throw std::runtime_error("non-finite CFG output");
        }
    }
    return output;
}

int main() {
    const std::vector<float> u{1.0F, -1.0F, 0.5F, 2.0F};
    const std::vector<float> c{0.0F, 3.0F, 1.5F, -2.0F};
    const auto g0 = Cfg(u, c, 0.0F);
    const auto g1 = Cfg(u, c, 1.0F);
    const auto g2 = Cfg(u, c, 2.0F);
    for (std::size_t i = 0; i < u.size(); ++i) {
        assert(g0[i] == u[i]);
        assert(g1[i] == c[i]);
    }
    const std::vector<float> expected{-1.0F, 7.0F, 2.5F, -6.0F};
    for (std::size_t i = 0; i < expected.size(); ++i) {
        assert(std::fabs(g2[i] - expected[i]) < 1e-6F);
    }
    std::cout << std::fixed << std::setprecision(1);
    for (float value : g2) std::cout << value << " ";
    std::cout << "\n";
}
```

예상 출력은 `-1.0 7.0 2.5 -6.0`이다. 실제 runtime에서는 tensor가 contiguous인지, element 수가 $NCHW$와 일치하는지, model output이 FP16이면 FP32 buffer로 변환했는지 먼저 검사한다.

## 11. C# 후처리 예제

다음 코드는 외부 패키지 없는 실행 가능한 C# 예제다.

```csharp
using System;

public static class Program
{
    static float[] Cfg(float[] uncond, float[] cond, float scale)
    {
        if (uncond.Length != cond.Length)
            throw new ArgumentException("branch size mismatch");
        var output = new float[uncond.Length];
        for (int i = 0; i < output.Length; ++i)
        {
            output[i] = uncond[i] + scale * (cond[i] - uncond[i]);
            if (float.IsNaN(output[i]) || float.IsInfinity(output[i]))
                throw new ArithmeticException("non-finite CFG output");
        }
        return output;
    }

    static void Close(float actual, float expected)
    {
        if (Math.Abs(actual - expected) > 1e-6f)
            throw new Exception($"expected {expected}, got {actual}");
    }

    public static void Main()
    {
        float[] u = { 1.0f, -1.0f, 0.5f, 2.0f };
        float[] c = { 0.0f, 3.0f, 1.5f, -2.0f };
        float[] expected = { -1.0f, 7.0f, 2.5f, -6.0f };
        float[] g0 = Cfg(u, c, 0.0f);
        float[] g1 = Cfg(u, c, 1.0f);
        float[] g2 = Cfg(u, c, 2.0f);
        for (int i = 0; i < u.Length; ++i)
        {
            Close(g0[i], u[i]);
            Close(g1[i], c[i]);
            Close(g2[i], expected[i]);
        }
        Console.WriteLine(string.Join(" ", Array.ConvertAll(g2, x => x.ToString("F1"))));
    }
}
```

C# tensor API가 `NHWC`를 기본으로 보여 주더라도 flat CFG 산술 자체는 element-wise라 layout에 무관하다. 그러나 branch tensor 두 개가 같은 physical order라는 전제가 필요하다. 한 branch만 transpose한 뒤 shape metadata만 같게 만들면 값이 조용히 섞인다.

## 12. 프레임워크 간 대응

| 의미 | PyTorch | C++ runtime | C# runtime | 주의점 |
| --- | --- | --- | --- | --- |
| latent | `Tensor[N,C,H,W]` | `float*` + shape | `DenseTensor<float>` 등 | 보통 `NCHW` |
| text context | `Tensor[N,L,D]` | runtime tensor | runtime tensor | padding mask도 같은 order |
| timestep | 흔히 `int64` | `int64_t` | `long` | 일부 graph는 float embedding 입력 |
| branch concat | `torch.cat(..., dim=0)` | batch buffer 두 구간 | batch buffer 두 구간 | unconditional 먼저 |
| raw output | model dtype | FP16/FP32 | FP16/FP32 | prediction type metadata 필요 |
| CFG accumulator | `float32` 권장 | `float` | `float` | subtraction·scale 순서 고정 |
| scheduler coefficient | FP32 이상 | `float`/`double` | `float`/`double` | table index와 timestep 분리 |

PyTorch의 non-contiguous view를 native runtime으로 넘길 때는 contiguous copy 여부를 확인한다. zero-copy 최적화보다 먼저 branch와 layout의 정확성을 golden tensor로 잠근다.

## 13. 성능과 메모리

### 13.1 batch-concat과 sequential two-pass

| 방식 | denoiser 호출 | FLOP | peak activation | 적합한 상황 |
| --- | ---: | ---: | ---: | --- |
| batch-concat | step당 1회 | branch 2개분 | 높음 | GPU utilization과 launch overhead가 중요 |
| sequential | step당 2회 | branch 2개분 | 낮음 | memory 제한, batch 1 고정 runtime |
| scale 1 conditional-only | step당 1회 | branch 1개분 | 낮음 | 이 글 관례에서 정확히 $g=1$ |
| scale 0 unconditional-only | step당 1회 | branch 1개분 | 낮음 | unconditional sample |

batch-concat이 항상 빠르지는 않다. batch 2에서 attention workspace가 커져 느린 kernel로 바뀌거나 memory pressure가 생길 수 있다. target device에서 end-to-end latency, kernel time과 peak memory를 함께 잰다.

### 13.2 cache 가능한 것

sampling loop 동안 prompt가 고정되면 다음을 loop 밖으로 뺀다.

- null·positive tokenization
- text encoder output
- attention mask
- timestep-independent projection

latent와 timestep embedding, cross-attention 결과는 step마다 달라지므로 무조건 cache하면 안 된다. prompt edit, batch 크기와 encoder version을 cache key에 포함한다.

### 13.3 수치 안정성

branch 오차를 각각 $\delta_u$, $\delta_c$라 하면 guided 오차는 다음과 같다.

$$
\delta_{\mathrm{cfg}}
=
(1-g)\delta_u
+
g\delta_c
$$

$g$가 커질수록 condition 방향뿐 아니라 두 model error도 확대한다. step별로 다음을 제한적으로 기록한다.

- branch와 guided output의 `abs_max`
- finite failure count
- branch difference norm
- rescale 전후 표준편차
- sampler next latent의 dynamic range

모든 tensor를 장기 저장하면 비용과 개인정보 문제가 생긴다. 통계와 샘플링 비율, 보존 기간을 운영 정책으로 정한다.

## 14. 실무 실패 사례

### 사례 1: 학습에는 null class가 없었다

class embedding이 `num_classes`개뿐인데 추론 코드가 마지막 class를 null처럼 사용했다. 실제 class 하나가 unconditional branch로 재사용되어 CFG가 특정 class에서 멀어지는 방향을 만들었다.

해결은 `num_classes + 1` embedding과 예약 null id를 checkpoint schema에 넣고, training dropout count를 metric으로 확인하는 것이다.

### 사례 2: latent와 context의 결합 순서가 다르다

latent는 `[x0,x0,x1,x1]`, context는 `[u0,u1,c0,c1]`였다. shape 검사는 모두 통과했지만 서로 다른 sample의 branch가 혼합됐다.

해결은 concat 규칙을 하나로 통일하고 sample id가 드러나는 sentinel denoiser를 CI에 넣는 것이다.

### 사례 3: scheduler는 `v_prediction`, 앱은 `epsilon`으로 해석했다

Python pipeline과 C# 앱 모두 `(N,4,H,W)`를 출력해 integration shape test는 통과했다. 앱은 guided $v$를 noise로 간주해 DDIM 식에 넣었고 몇 step 뒤 dynamic range가 폭증했다.

해결은 prediction type과 변환 순서를 model artifact의 필수 metadata로 만들고 첫 step의 raw·guided·next latent golden을 비교하는 것이다.

### 사례 4: FP16에서 branch 차이가 사라진다

$\epsilon_u$와 $\epsilon_c$가 큰 공통 성분과 작은 차이를 가졌고 FP16 subtraction이 condition signal을 반올림해 없앴다. scale을 올려도 prompt 반영이 개선되지 않았다.

해결은 branch output을 FP32로 변환해 subtraction과 scale을 수행하고, target backend의 mixed-precision 결과를 FP32 reference와 비교하는 것이다.

### 사례 5: 성능 최적화가 오히려 latency를 늘린다

두 branch를 한 batch로 합쳐 호출 수는 줄었지만 mobile GPU의 peak memory가 커지고 tiling이 늘었다. 평균 latency만 보면 일부 장치의 thermal throttling도 놓쳤다.

해결은 sequential과 concat을 warm-up 후 여러 percentile, peak memory와 energy로 비교하고 device class별 정책을 허용하는 것이다.

## 15. 배포 관점

### 15.1 ONNX graph 경계

| export 범위 | 장점 | 단점 |
| --- | --- | --- |
| denoiser만 | branch output 디버깅이 쉽다 | host CFG와 copy 비용 |
| denoiser + CFG | branch order와 산술을 graph에 고정 | scale·batch dynamic 설계 필요 |
| sampler step 포함 | host overhead가 작다 | scheduler 교체와 golden 분리가 어렵다 |

첫 배포는 denoiser와 CFG 경계를 분리해 raw branch를 비교하기 쉽게 만든다. 실제 profile에서 host overhead가 병목임을 확인한 뒤 fusion한다.

### 15.2 manifest 예시

```json
{
  "latent_layout": "NCHW",
  "context_layout": "NLD",
  "model_dtype": "float16",
  "cfg_accumulator_dtype": "float32",
  "prediction_type": "v_prediction",
  "batch_order": "unconditional_then_conditional",
  "scale_formula": "u + g * (c - u)",
  "postprocess_order": ["convert", "cfg", "rescale", "scheduler"],
  "null_condition": "empty_prompt_encoder_output",
  "dynamic_batch": true
}
```

JSON은 설명용 schema지만 값은 실제 export pipeline과 함께 검증해야 한다. 특히 `dynamic_batch=true`가 runtime delegate에서도 정말 batch 2를 허용하는지 target device smoke test가 필요하다.

### 15.3 운영 모니터링

- model·scheduler·text encoder version별 latency와 finite failure
- guidance scale·sampler·step 수 분포
- prompt 길이 bucket별 rejection과 failure rate
- branch difference norm의 급격한 drift
- concat에서 sequential fallback한 비율
- safety filter와 사용자 품질 피드백

prompt 원문이나 생성물을 저장할 때는 동의, 접근 제어, 보존 기간과 삭제 절차를 먼저 정한다. 디버깅 편의가 개인정보 수집의 자동 허가가 되지 않는다.

## 18. 해답

### 해답 1

차이는 $\epsilon_c-\epsilon_u=[-1,4]$다. 따라서 $g=0$은 $[1,-1]$, $g=1$은 $[0,3]$, $g=2$는 $[-1,7]$이다.

### 해답 2

latent는 $(8,4,64,64)$, context는 $(8,77,768)$가 된다. denoiser output은 보통 $(8,4,64,64)$이며 batch 축으로 둘로 나누면 각 branch는 $(4,4,64,64)$다. guided output도 $(4,4,64,64)$다.

### 해답 3

$g=1+w$이므로 $g=7.5$다. `7.5`라는 숫자만 보고 같은 식이라 가정하면 안 된다.

### 해답 4

모델은 null condition 입력에서 target noise를 예측하도록 학습되지 않았다. empty prompt의 shape는 맞아도 condition embedding 분포가 학습 support 밖이며 $\epsilon_u$의 의미와 calibration이 보장되지 않는다.

### 해답 5

latent는 `[x0,x0,x1,x1]`이고 context는 `[u0,u1,c0,c1]`다. pair는 `(x0,u0)`, `(x0,u1)`, `(x1,c0)`, `(x1,c1)`가 되어 sample별 null·conditional 쌍이 아니다. latent도 `cat([x,x])`로 `[x0,x1,x0,x1]`를 만들어야 한다.

### 해답 6

scale 식, branch chunk 순서, latent·timestep의 복제 순서, context·attention mask의 concat 순서를 먼저 확인한다. 그 다음 dtype, stochastic layer의 eval mode와 scheduler 전처리가 같은지 본다.

### 해답 7

항상 같지 않다. prediction type 변환은 같은 $x_t,t$에서 affine이지만 branch별 clipping은 비선형이다. CFG 전후 어느 지점에서 clipping하는지에 따라 결과가 달라진다.

### 해답 8

batch 1 graph를 null과 conditional condition으로 순차 두 번 호출해 두 output을 저장하고 host 또는 별도 element-wise graph에서 CFG를 계산한다. 또는 같은 weight를 dynamic batch나 batch 2 graph로 다시 export할 수 있다. 둘 다 재학습은 필요 없다.

## 19. 핵심 요약

- CFG는 추론 한 줄이 아니라 condition dropout으로 두 branch를 학습하는 과정부터 시작한다.
- null condition은 영벡터가 아니라 tokenizer·encoder·mask까지 포함한 프로토콜이다.
- 이 글의 $u+g(c-u)$ 관례에서 $g=0$은 unconditional, $g=1$은 conditional이다.
- batch-concat은 `[x,x]`, `[null,cond]` 순서를 함께 지켜야 sample pairing이 보존된다.
- prediction type 변환은 affine일 수 있지만 clipping·rescale 같은 비선형 연산의 순서는 결과를 바꾼다.
- $g=0$, $g=1$, equal branch, sentinel pairing은 값싼 핵심 회귀 테스트다.
- CFG 산술을 FP32로 수행하면 FP16 cancellation과 overflow 위험을 줄일 수 있다.
- dropout 확률과 scale은 고정된 황금값이 아니라 동일 seed·prompt suite의 ablation으로 정한다.
- 배포 manifest에는 prediction type, batch order, scale 식, null condition과 후처리 순서가 필요하다.
- batch-concat과 sequential two-pass는 FLOP보다 latency·peak memory를 target device에서 비교해야 한다.
