## 오늘의 질문

1회차에서는 SSD가 여러 해상도에서 default box를 예측하고 FPN이 깊은 의미를 고해상도 feature에 전달한다는 원리를 배웠다. 이번에는 그 설명을 다음 실행 경로로 고정한다.

```text
image -> C3/C4/C5 -> P3/P4/P5 -> class/box head
      -> default boxes -> IoU matching -> encoded targets
      -> localization loss + hard-negative classification loss
      -> decode -> score filter -> NMS -> metric
```

핵심 질문은 shape만 맞는 코드를 넘어선다.

- head의 $j$번째 예측과 default box의 $j$번째 항목이 정말 같은 위치와 비율인가?
- IoU threshold보다 낮은 작은 정답도 최소 한 개의 positive를 얻는가?
- 쉬운 배경 수천 개가 classification gradient를 지배하지 않게 어떻게 고르는가?
- 홀수 입력에서 top-down feature를 정확히 어떤 크기로 확대하는가?
- 빈 이미지와 positive가 없는 batch를 손실 함수가 어떻게 처리하는가?
- 같은 seed, 같은 manifest, 같은 정렬 규칙으로 학습을 다시 재현할 수 있는가?

오늘은 원본 [02-05.YOLO.md](../05.ImageClassification/02-05.YOLO.md)의 SSD·FPN 구간과 1회차 문서를 비교해 `anchor -> match -> loss -> feature pyramid` 경계를 구현한다. 역사적 비유와 default box 기초 공식은 짧게 복습하고, 완전한 tensor 계약·테스트·ablation에 집중한다.

## 선수 지식과 기호

- normalized `cxcywh`와 `xyxy` box
- IoU, softmax cross entropy, Smooth L1 loss

- PyTorch `ModuleList`, `interpolate`, `permute`, `reshape`

| 기호 | 뜻 |
| --- | --- |
| $N$ | batch 크기 |
| $L$ | feature level 수 |
| $H_k,W_k$ | level $k$의 spatial 크기 |
| $A_k$ | cell당 default box 수 |
| $B$ | 모든 level의 default box 총수 |
| $C$ | background를 포함한 class 수 |

| $g=(g_x,g_y,g_w,g_h)$ | 정답 box |

| $r$ | positive당 negative 최대 비율 |

총 default box 수는 다음과 같다.

$$
B=\sum_{k=1}^{L}H_kW_kA_k
$$

논리적 head 출력은 class가 `[N,B,C]`, box가 `[N,B,4]`다.

## 1. 원본과 1회차에서 이번에 확장하는 것

원본은 SSD의 여섯 feature map과 선형 scale, FPN의 top-down·lateral addition을 소개한다. 구현 단계에서는 다음 경계를 더 엄격하게 고쳐야 한다.

| 원본 또는 흔한 축약 | 이번 구현 계약 |
| --- | --- |
| SSD는 작은 객체를 잘 찾는다 | resize 뒤 객체가 사라지거나 matcher가 positive를 주지 못하면 작은 객체 recall은 여전히 0이다. level별 positive 수를 측정한다. |
| default box는 anchor와 같은 역할이다 | 역할은 유사하지만 scale, extra ratio-1 box, variance, flatten 순서가 구현 artifact의 일부다. |
| IoU threshold 이상만 positive다 | 각 정답의 best default box를 먼저 강제로 positive로 만들고 threshold match를 합친다. |
| background가 많으면 일부를 버린다 | 현재 모델의 per-anchor classification loss로 순위를 정하고 stable tie-break와 최대 비율을 고정한다. |
| FPN은 upsample 후 더한다 | `scale_factor=2`가 아니라 lateral tensor의 정확한 spatial size로 맞춘다. |
| $P_k=\operatorname{Conv}_{1\times1}(C_k)+\operatorname{Up}(P_{k+1})$ | 재귀 중간 feature $M_k$와 aliasing을 줄이는 최종 $3\times3$ output $P_k$를 구분한다. |
| 모든 최신 detector가 FPN을 쓴다 | 널리 쓰이지만 단일 고해상도 feature, PAN, BiFPN 등 다른 선택도 있다. 요구 latency와 객체 크기로 결정한다. |

1회차는 box 수, scale, FPN shape를 설명했다. 오늘 새로 추가하는 것은 다음이다.

1. 정답별 최소 한 positive를 보장하는 matcher
2. stable hard-negative mining과 positive 정규화
3. 완전한 FPN·SSD head·MultiBox loss backward
4. 빈 이미지 정책과 level별 진단 metric
5. seed replay와 negative ratio ablation

## 2. default box와 flatten 순서를 하나의 계약으로 묶기

### 2.1 생성 순서

level $k$, row $i$, column $j$, aspect ratio $a$ 순서로 순회한다고 고정한다. cell 중심은 다음과 같다.

$$
d_x=\frac{j+0.5}{W_k},\qquad d_y=\frac{i+0.5}{H_k}
$$

scale이 $s_k$일 때 ratio $a$의 폭과 높이는 다음과 같다.

$$
d_w=s_k\sqrt{a},\qquad d_h=\frac{s_k}{\sqrt{a}}
$$

같은 순서를 head에도 적용해야 한다.

```text
level -> row -> column -> anchor -> class-or-box-channel
```

head가 `[N,A_k C,H_k,W_k]`를 출력하면 다음 순서로 바꾼다.

```text
[N, A_k*C, H_k, W_k]
-> [N, H_k, W_k, A_k*C]
-> [N, H_k*W_k*A_k, C]
```

`reshape` 전에 anchor와 class channel이 실제로 어떤 축에 interleave됐는지 확인해야 한다. channel이 `class-major`인데 `anchor-major`로 해석해도 shape는 동일해 조용히 잘못된다.

### 2.2 수작업 shape 추적

세 level이 `17 x 21`, `9 x 11`, `5 x 6`이고 cell마다 box가 2개라면 다음과 같다.

| level | spatial | $A_k$ | box 수 |
| --- | --- | --- | --- |
| `P3` | `17 x 21` | 2 | 714 |
| `P4` | `9 x 11` | 2 | 198 |
| `P5` | `5 x 6` | 2 | 60 |
| 합계 | - | - | 972 |

background 포함 class 수가 3이면 raw class channel은 level마다 6이고, logical class tensor는 `[N,972,3]`이다. box raw channel은 level마다 8이고 logical box tensor는 `[N,972,4]`다.

## 3. IoU 매칭을 단계별로 유도하기

### 3.1 pairwise IoU

default box를 $d_i$, 정답을 $g_j$라 하면 IoU matrix $J$의 shape은 `[B,M]`이다.

$$
J_{ij}=\frac{|d_i\cap g_j|}{|d_i\cup g_j|}
$$

$M$은 이미지마다 다르므로 matcher는 일반적으로 이미지별로 실행한다. 모든 이미지를 최대 $M$까지 padding하면 mask를 빠뜨리지 않도록 주의한다.

### 3.2 두 단계 positive 결정

먼저 각 default box가 가장 잘 겹치는 정답을 구한다.

$$
j_i^*=\operatorname*{argmax}_j J_{ij}
$$

그다음 각 정답이 가장 잘 겹치는 default box도 구한다.

$$
i_j^*=\operatorname*{argmax}_i J_{ij}
$$

positive mask는 threshold match와 강제 match의 합집합이다.

$$
m_i^+=\mathbb{1}[J_{i,j_i^*}\ge\tau]\lor\mathbb{1}[i\in\{i_j^*\}]
$$

강제 match가 없으면 작은 정답의 최고 IoU가 0.49이고 threshold가 0.5일 때 positive가 하나도 생기지 않는다. 단, 서로 다른 두 정답이 같은 default box 하나를 best로 선택할 수 있다. 실전 matcher는 충돌을 해결하는 bipartite assignment 또는 우선순위 규칙을 가져야 하며, 강제 match 이후에도 정답별 match count를 assert해야 한다.

### 3.3 ignore 영역

positive threshold와 negative threshold를 다르게 두면 그 사이를 ignore로 둘 수 있다.

$$
m_i^-=\mathbb{1}[J_{i,j_i^*}<\tau_{neg}]
$$

$$
m_i^{ignore}=1-m_i^+-m_i^-
$$

오늘 최소 구현은 단일 threshold를 써 positive가 아닌 box를 negative candidate로 둔다. production에서는 crowd, difficult, padding target을 포함한 ignore mask를 별도 schema로 관리한다.

## 4. box regression target과 round trip

default box $d$에서 정답 $g$로 가는 target은 다음과 같다.

$$
t_x=\frac{g_x-d_x}{v_{xy}d_w},\qquad
t_y=\frac{g_y-d_y}{v_{xy}d_h}
$$

$$
t_w=\frac{\log(g_w/d_w)}{v_{wh}},\qquad
t_h=\frac{\log(g_h/d_h)}{v_{wh}}
$$

decode는 정확한 역함수여야 한다.

$$
\hat g_x=d_x+v_{xy}d_w\hat t_x,\qquad
\hat g_y=d_y+v_{xy}d_h\hat t_y
$$

$$
\hat g_w=d_w\exp(v_{wh}\hat t_w),\qquad
\hat g_h=d_h\exp(v_{wh}\hat t_h)
$$

학습과 배포가 $v_{xy},v_{wh}$를 다르게 쓰면 중심은 선형으로 어긋나고 크기는 지수적으로 폭발한다. 이 두 값은 code constant가 아니라 model artifact의 metadata다.

## 5. NumPy oracle: 생성·매칭·mining을 독립 검증하기

다음은 **실행 가능한 독립 검증 예제**다. PyTorch 구현을 호출하지 않고 box 생성 순서, 강제 match, round trip, stable hard-negative mining을 확인한다.

```python
import numpy as np


def make_default_boxes(feature_shapes, scales, ratios):
    boxes = []
    for (height, width), scale, level_ratios in zip(
        feature_shapes, scales, ratios, strict=True
    ):
        for row in range(height):
            for col in range(width):
                cx = (col + 0.5) / width
                cy = (row + 0.5) / height
                for ratio in level_ratios:
                    root = np.sqrt(ratio)
                    boxes.append([cx, cy, scale * root, scale / root])
    return np.asarray(boxes, dtype=np.float64)


def cxcywh_to_xyxy(boxes):
    center = boxes[:, :2]
    half = boxes[:, 2:] / 2.0
    return np.concatenate([center - half, center + half], axis=1)


def pairwise_iou(boxes_a, boxes_b):
    a = cxcywh_to_xyxy(boxes_a)
    b = cxcywh_to_xyxy(boxes_b)
    top_left = np.maximum(a[:, None, :2], b[None, :, :2])
    bottom_right = np.minimum(a[:, None, 2:], b[None, :, 2:])
    intersection = np.prod(np.maximum(bottom_right - top_left, 0.0), axis=2)
    area_a = np.prod(np.maximum(a[:, 2:] - a[:, :2], 0.0), axis=1)
    area_b = np.prod(np.maximum(b[:, 2:] - b[:, :2], 0.0), axis=1)
    union = area_a[:, None] + area_b[None, :] - intersection
    return intersection / np.maximum(union, 1e-12)


def match(defaults, ground_truth, threshold=0.5):
    if len(ground_truth) == 0:
        return np.zeros(len(defaults), dtype=bool), np.full(len(defaults), -1)
    iou = pairwise_iou(defaults, ground_truth)
    best_gt = iou.argmax(axis=1)
    best_iou = iou[np.arange(len(defaults)), best_gt]
    positive = best_iou >= threshold
    # 이 작은 oracle은 정답별 best anchor가 서로 다름을 요구한다.
    forced = iou.argmax(axis=0)
    if len(np.unique(forced)) != len(forced):
        raise ValueError("forced-match collision requires a production matcher")
    for gt_index, anchor_index in enumerate(forced):
        positive[anchor_index] = True
        best_gt[anchor_index] = gt_index
    assert set(best_gt[positive].tolist()) >= set(range(len(ground_truth)))
    return positive, best_gt


def encode(ground_truth, defaults, variance=(0.1, 0.2)):
    if np.any(ground_truth[:, 2:] <= 0.0) or np.any(defaults[:, 2:] <= 0.0):
        raise ValueError("box width and height must be positive")
    vxy, vwh = variance
    center = (ground_truth[:, :2] - defaults[:, :2]) / (vxy * defaults[:, 2:])
    size = np.log(ground_truth[:, 2:] / defaults[:, 2:]) / vwh
    return np.concatenate([center, size], axis=1)


def decode(offsets, defaults, variance=(0.1, 0.2)):
    vxy, vwh = variance
    center = defaults[:, :2] + vxy * defaults[:, 2:] * offsets[:, :2]
    size = defaults[:, 2:] * np.exp(vwh * offsets[:, 2:])
    return np.concatenate([center, size], axis=1)


def hard_negative_mask(losses, positive, ratio=3, min_negatives=0):
    losses = np.asarray(losses, dtype=np.float64)
    positive = np.asarray(positive, dtype=bool)
    candidates = np.flatnonzero(~positive)
    wanted = max(ratio * int(positive.sum()), min_negatives)
    wanted = min(wanted, len(candidates))
    # mergesort는 동점일 때 원래 anchor index 순서를 보존한다.
    order = np.argsort(-losses[candidates], kind="mergesort")
    selected = np.zeros_like(positive)
    selected[candidates[order[:wanted]]] = True
    return selected


defaults = make_default_boxes(
    feature_shapes=[(2, 2), (1, 1)],
    scales=[0.4, 0.7],
    ratios=[[1.0], [1.0]],
)
assert defaults.shape == (5, 4)
assert np.allclose(defaults[0], [0.25, 0.25, 0.4, 0.4])
assert np.allclose(defaults[-1], [0.5, 0.5, 0.7, 0.7])

ground_truth = np.asarray(
    [[0.25, 0.25, 0.36, 0.44], [0.75, 0.75, 0.35, 0.35]],
    dtype=np.float64,
)
positive, best_gt = match(defaults, ground_truth, threshold=0.95)
assert positive.sum() == 2  # threshold가 높아도 정답마다 하나를 강제한다.
matched_defaults = defaults[positive]
matched_ground_truth = ground_truth[best_gt[positive]]
offsets = encode(matched_ground_truth, matched_defaults)
restored = decode(offsets, matched_defaults)
assert np.allclose(restored, matched_ground_truth, atol=1e-12)

losses = np.asarray([0.1, 0.9, 0.9, 0.2, 0.8])
positive_for_mining = np.asarray([True, False, False, False, False])
negative = hard_negative_mask(losses, positive_for_mining, ratio=2)
assert np.flatnonzero(negative).tolist() == [1, 2]

empty_positive = np.zeros(5, dtype=bool)
negative_for_empty = hard_negative_mask(
    losses, empty_positive, ratio=3, min_negatives=2
)
assert np.flatnonzero(negative_for_empty).tolist() == [1, 2]
print("numpy oracle passed:", positive.tolist(), offsets.round(6).tolist())
```

이 oracle은 의도적으로 복잡한 충돌 해결을 숨기지 않는다. 두 정답이 같은 anchor를 강제 선택하면 실패시켜 production matcher가 필요함을 알린다. 작은 테스트가 모호한 정책을 조용히 승인하면 실제 dataset에서 정답 하나가 사라진다.

## 6. hard-negative mining과 MultiBox loss

### 6.1 왜 모든 negative를 합하지 않는가

anchor $i$의 background 포함 classification loss를 $\ell_i^{cls}$라고 하자. positive가 $N_+$개일 때 negative 후보 중 loss가 큰 순서로 최대 $rN_+$개를 고른다.

$$
\mathcal{H}=\operatorname{TopK}\left(\{\ell_i^{cls}:m_i^+=0\},\min(rN_+,N_-)\right)
$$

MultiBox loss의 한 형태는 다음과 같다.

$$
\mathcal{L}=\frac{1}{\max(N_+,1)}
\left(
\sum_{i:m_i^+=1}\operatorname{SmoothL1}(\hat t_i,t_i)
+\sum_{i:m_i^+=1\lor i\in\mathcal{H}}\operatorname{CE}(z_i,y_i)
\right)
$$

hard-negative mining은 Focal Loss가 아니다. 전자는 선택하지 않은 negative의 gradient를 정확히 0으로 만들고, 후자는 모든 예제에 연속적인 가중치를 준다. 다음 Part에서 이 차이를 ablation한다.

### 6.2 positive가 0일 때

빈 이미지에서 $N_+=0$이면 단순한 `r * N_pos` 규칙은 negative도 0개 골라 classification loss가 0이 된다. 가능한 정책은 다음과 같다.

- 최소 negative 수를 골라 빈 이미지도 background 학습에 사용한다.
- 빈 이미지를 별도 background batch로 구성한다.
- 원 논문 재현을 우선해 0 loss로 두되 빈 이미지 비율을 제한한다.

정답은 하나가 아니다. 중요한 것은 정책을 config에 기록하고 test로 고정하는 것이다. 오늘 PyTorch 예제는 `min_negatives=2`를 사용한다.

### 6.3 동점과 결정성

여러 negative loss가 같을 때 GPU `topk`의 순서가 backend마다 다를 수 있다. 최종 loss 값은 같을 수 있지만 선택된 anchor와 gradient 위치가 달라진다. exact replay가 필요하면 stable sort 또는 `(loss, -anchor_index)` 같은 명시적 tie-break를 사용한다. 대규모 학습에서는 결정성 비용을 benchmark하고 tolerance 기반 재현성을 선택할 수도 있다.

## 7. FPN의 shape 계약

backbone feature가 다음과 같다고 하자.

| feature | 입력 shape | stride의 의미 |
| --- | --- | --- |
| `C3` | `[N,32,17,21]` | 가장 높은 해상도 |
| `C4` | `[N,64,9,11]` | 중간 해상도 |
| `C5` | `[N,128,5,6]` | 가장 깊은 의미 |

lateral projection으로 channel을 $F=24$로 맞춘다.

$$
M_5=\operatorname{Conv}_{1\times1}(C_5)
$$

$$
M_4=\operatorname{Conv}_{1\times1}(C_4)+\operatorname{Resize}(M_5,(H_4,W_4))
$$

$$
M_3=\operatorname{Conv}_{1\times1}(C_3)+\operatorname{Resize}(M_4,(H_3,W_3))
$$

최종 output은 다음과 같다.

$$
P_k=\operatorname{Conv}_{3\times3}(M_k)
$$

`M5`의 `5 x 6`을 2배로 만들면 `10 x 12`지만 `C4`는 `9 x 11`이다. 정확한 target size를 쓰면 odd input과 서로 다른 padding convention을 안전하게 처리한다. 다만 resize로 shape만 맞았다고 feature의 실제 좌표 중심이 정렬된 것은 아니다. backbone의 padding과 stride convention도 golden input으로 검증해야 한다.

## 8. PyTorch: FPN·SSD head·loss를 끝까지 실행하기

다음은 **실행 가능한 교육용 구현**이다. 실제 SSD backbone과 data loader 전체를 복제하지 않지만, feature 생성부터 loss와 backward, 재현성, negative ratio ablation까지 완결한다.

```python
import copy
import random

import numpy as np
import torch
from torch import nn
from torch.nn import functional as F


def seed_everything(seed):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.use_deterministic_algorithms(True)


class TinyBackbone(nn.Module):
    def __init__(self):
        super().__init__()
        self.stem = nn.Conv2d(3, 16, 3, stride=2, padding=1)
        self.c3 = nn.Conv2d(16, 32, 3, stride=2, padding=1)
        self.c4 = nn.Conv2d(32, 64, 3, stride=2, padding=1)
        self.c5 = nn.Conv2d(64, 128, 3, stride=2, padding=1)

    def forward(self, image):
        x = F.relu(self.stem(image))
        c3 = F.relu(self.c3(x))
        c4 = F.relu(self.c4(c3))
        c5 = F.relu(self.c5(c4))
        return [c3, c4, c5]


class TinyFPN(nn.Module):
    def __init__(self, out_channels=24):
        super().__init__()
        self.lateral = nn.ModuleList(
            [nn.Conv2d(ch, out_channels, 1) for ch in (32, 64, 128)]
        )
        self.output = nn.ModuleList(
            [nn.Conv2d(out_channels, out_channels, 3, padding=1) for _ in range(3)]
        )

    def forward(self, features):
        c3, c4, c5 = features
        m5 = self.lateral[2](c5)
        m4 = self.lateral[1](c4) + F.interpolate(
            m5, size=c4.shape[-2:], mode="nearest"
        )
        m3 = self.lateral[0](c3) + F.interpolate(
            m4, size=c3.shape[-2:], mode="nearest"
        )
        return [layer(value) for layer, value in zip(
            self.output, (m3, m4, m5), strict=True
        )]


class SSDHead(nn.Module):
    def __init__(self, channels=24, anchors=2, classes=3):
        super().__init__()
        self.classes = classes
        self.anchors = anchors
        self.class_heads = nn.ModuleList(
            [nn.Conv2d(channels, anchors * classes, 3, padding=1) for _ in range(3)]
        )
        self.box_heads = nn.ModuleList(
            [nn.Conv2d(channels, anchors * 4, 3, padding=1) for _ in range(3)]
        )

    def forward(self, pyramid):
        class_outputs = []
        box_outputs = []
        for feature, class_head, box_head in zip(
            pyramid, self.class_heads, self.box_heads, strict=True
        ):
            n = feature.shape[0]
            class_raw = class_head(feature)
            box_raw = box_head(feature)
            class_outputs.append(
                class_raw.permute(0, 2, 3, 1).reshape(n, -1, self.classes)
            )
            box_outputs.append(box_raw.permute(0, 2, 3, 1).reshape(n, -1, 4))
        return torch.cat(class_outputs, dim=1), torch.cat(box_outputs, dim=1)


def stable_hard_negative(losses, positive, ratio=3, min_negatives=2):
    selected = torch.zeros_like(positive)
    for batch_index in range(losses.shape[0]):
        candidates = torch.nonzero(~positive[batch_index], as_tuple=False).flatten()
        wanted = max(ratio * int(positive[batch_index].sum()), min_negatives)
        wanted = min(wanted, int(candidates.numel()))
        # stable=True로 동점에서 작은 anchor index를 보존한다.
        order = torch.argsort(
            losses[batch_index, candidates], descending=True, stable=True
        )
        selected[batch_index, candidates[order[:wanted]]] = True
    return selected


def multibox_loss(class_logits, box_offsets, class_target, box_target, ratio=3):
    positive = class_target > 0
    per_anchor_class = F.cross_entropy(
        class_logits.transpose(1, 2), class_target, reduction="none"
    )
    negative = stable_hard_negative(
        per_anchor_class.detach(), positive, ratio=ratio, min_negatives=2
    )
    selected = positive | negative
    class_loss = per_anchor_class[selected].sum()
    if positive.any():
        box_loss = F.smooth_l1_loss(
            box_offsets[positive], box_target[positive], reduction="sum"
        )
    else:
        box_loss = box_offsets.sum() * 0.0
    normalizer = positive.sum().clamp(min=1)
    return (class_loss + box_loss) / normalizer, negative


class TinyDetector(nn.Module):
    def __init__(self):
        super().__init__()
        self.backbone = TinyBackbone()
        self.fpn = TinyFPN()
        self.head = SSDHead()

    def forward(self, image):
        return self.head(self.fpn(self.backbone(image)))


def run_once(seed=20260813, negative_ratio=3):
    seed_everything(seed)
    model = TinyDetector()
    image = torch.randn(2, 3, 65, 81)
    class_logits, box_offsets = model(image)
    assert class_logits.shape == (2, 972, 3)
    assert box_offsets.shape == (2, 972, 4)

    class_target = torch.zeros(2, 972, dtype=torch.long)
    class_target[0, [0, 713, 971]] = torch.tensor([1, 2, 1])
    class_target[1, [10, 911]] = torch.tensor([2, 1])
    box_target = torch.zeros_like(box_offsets)
    box_target[0, 713] = torch.tensor([0.1, -0.1, 0.2, -0.2])

    loss, negative = multibox_loss(
        class_logits, box_offsets, class_target, box_target, ratio=negative_ratio
    )
    loss.backward()
    assert torch.isfinite(loss)
    assert int(negative[0].sum()) == negative_ratio * 3
    assert int(negative[1].sum()) == negative_ratio * 2
    assert all(parameter.grad is not None for parameter in model.parameters())
    snapshot = {name: value.grad.detach().clone() for name, value in model.named_parameters()}
    return float(loss.detach()), snapshot, class_logits.detach(), box_offsets.detach()


loss_a, grad_a, class_a, box_a = run_once()
loss_b, grad_b, class_b, box_b = run_once()
assert loss_a == loss_b
assert torch.equal(class_a, class_b)
assert torch.equal(box_a, box_b)
assert all(torch.equal(grad_a[name], grad_b[name]) for name in grad_a)

loss_ratio_1, _, _, _ = run_once(negative_ratio=1)
assert loss_ratio_1 != loss_a
print(
    "pytorch pipeline passed:",
    class_a.shape,
    box_a.shape,
    f"ratio1={loss_ratio_1:.6f}",
    f"ratio3={loss_a:.6f}",
)
```

이 코드는 target matcher를 NumPy oracle과 분리했다. production training loop에서는 dataset annotation을 matcher에 넣어 `class_target`, `box_target`, `ignore_mask`, `matched_gt_index`를 cache하거나 batch마다 만든다. cache할 때 augmentation으로 좌표가 바뀌면 target도 무효가 된다는 점을 주의한다.

## 9. 완전한 학습·평가 루프의 경계

모델 코드만으로 재현 가능한 detector가 되지는 않는다. 학습 step은 다음 artifact를 기록해야 한다.

```text
batch image ids
augmentation parameters
feature level shapes
default-box config hash
positive / ignored / selected-negative counts by level
classification and localization loss before normalization
gradient norm
optimizer learning rate and scaler state
```

평가 단계는 학습 target을 사용하지 않고 다음 순서를 따른다.

1. 각 level output을 학습과 동일한 순서로 concatenate한다.
2. box offset을 같은 variance로 decode한다.
3. softmax를 한 번만 적용하고 background channel을 제거한다.
4. class별 score threshold와 pre-NMS top-k를 적용한다.
5. class별 NMS 후 원본 이미지 좌표로 되돌린다.
6. 고정된 IoU·AP 정의로 metric을 계산한다.

validation loss와 detection AP는 다른 질문에 답한다. loss가 감소해도 decode, class map, resize 역변환이 잘못되면 AP는 0일 수 있다. 작은 synthetic image 한 장에 완벽한 raw output을 주입하는 end-to-end golden test가 필요하다.

## 10. C++17: box round trip과 stable mining

다음은 **실행 가능한 C++17 예제**다. 외부 tensor library 없이 배포 경계의 scalar 공식을 검증한다.

```cpp
#include <algorithm>
#include <array>
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>
#include <numeric>
#include <vector>

using Box = std::array<double, 4>;

Box Encode(const Box& ground_truth, const Box& anchor) {
    assert(ground_truth[2] > 0.0 && ground_truth[3] > 0.0);
    assert(anchor[2] > 0.0 && anchor[3] > 0.0);
    return {
        (ground_truth[0] - anchor[0]) / (0.1 * anchor[2]),
        (ground_truth[1] - anchor[1]) / (0.1 * anchor[3]),
        std::log(ground_truth[2] / anchor[2]) / 0.2,
        std::log(ground_truth[3] / anchor[3]) / 0.2,
    };
}

Box Decode(const Box& offset, const Box& anchor) {
    return {
        anchor[0] + 0.1 * anchor[2] * offset[0],
        anchor[1] + 0.1 * anchor[3] * offset[1],
        anchor[2] * std::exp(0.2 * offset[2]),
        anchor[3] * std::exp(0.2 * offset[3]),
    };
}

std::vector<int> HardNegatives(
    const std::vector<double>& loss,
    const std::vector<bool>& positive,
    int ratio
) {
    const int positive_count = static_cast<int>(
        std::count(positive.begin(), positive.end(), true)
    );
    std::vector<int> candidates;
    for (int index = 0; index < static_cast<int>(loss.size()); ++index) {
        if (!positive[index]) candidates.push_back(index);
    }
    std::stable_sort(candidates.begin(), candidates.end(), [&](int left, int right) {
        return loss[left] > loss[right];
    });
    const int wanted = std::min(ratio * positive_count, static_cast<int>(candidates.size()));
    candidates.resize(wanted);
    std::sort(candidates.begin(), candidates.end());
    return candidates;
}

int main() {
    const Box anchor{0.5, 0.5, 0.4, 0.2};
    const Box ground_truth{0.54, 0.48, 0.44, 0.18};
    const Box offset = Encode(ground_truth, anchor);
    const Box restored = Decode(offset, anchor);
    for (int index = 0; index < 4; ++index) {
        assert(std::abs(restored[index] - ground_truth[index]) < 1e-12);
    }
    const std::vector<int> selected = HardNegatives(
        {0.1, 0.9, 0.9, 0.2, 0.8},
        {true, false, false, false, false},
        2
    );
    assert((selected == std::vector<int>{1, 2}));
    std::cout << std::fixed << std::setprecision(6)
              << offset[0] << " " << offset[1] << " "
              << restored[2] << " " << restored[3] << "\n";
}
```

예상 출력은 `1.000000 -1.000000 0.440000 0.180000`이다.

## 11. C#: box round trip과 stable mining

다음은 **실행 가능한 C# 예제**다. LINQ의 정렬이 같다고 암묵적으로 가정하지 않고 동점에서 index를 두 번째 key로 사용한다.

```csharp
using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;

public static class SsdContract
{
    static double[] Encode(double[] groundTruth, double[] anchor)
    {
        if (groundTruth[2] <= 0.0 || groundTruth[3] <= 0.0 ||
            anchor[2] <= 0.0 || anchor[3] <= 0.0)
            throw new ArgumentException("width and height must be positive");
        return new[] {
            (groundTruth[0] - anchor[0]) / (0.1 * anchor[2]),
            (groundTruth[1] - anchor[1]) / (0.1 * anchor[3]),
            Math.Log(groundTruth[2] / anchor[2]) / 0.2,
            Math.Log(groundTruth[3] / anchor[3]) / 0.2,
        };
    }

    static double[] Decode(double[] offset, double[] anchor)
    {
        return new[] {
            anchor[0] + 0.1 * anchor[2] * offset[0],
            anchor[1] + 0.1 * anchor[3] * offset[1],
            anchor[2] * Math.Exp(0.2 * offset[2]),
            anchor[3] * Math.Exp(0.2 * offset[3]),
        };
    }

    static int[] HardNegatives(double[] loss, bool[] positive, int ratio)
    {
        int positiveCount = positive.Count(value => value);
        return Enumerable.Range(0, loss.Length)
            .Where(index => !positive[index])
            .OrderByDescending(index => loss[index])
            .ThenBy(index => index)
            .Take(ratio * positiveCount)
            .OrderBy(index => index)
            .ToArray();
    }

    public static void Main()
    {
        double[] anchor = {0.5, 0.5, 0.4, 0.2};
        double[] groundTruth = {0.54, 0.48, 0.44, 0.18};
        double[] offset = Encode(groundTruth, anchor);
        double[] restored = Decode(offset, anchor);
        for (int index = 0; index < 4; ++index)
            if (Math.Abs(restored[index] - groundTruth[index]) >= 1e-12)
                throw new Exception("round trip failed");

        int[] selected = HardNegatives(
            new[] {0.1, 0.9, 0.9, 0.2, 0.8},
            new[] {true, false, false, false, false},
            2
        );
        if (!selected.SequenceEqual(new[] {1, 2}))
            throw new Exception("stable mining failed");
        Console.WriteLine(string.Format(
            CultureInfo.InvariantCulture,
            "{0:F6} {1:F6} {2:F6} {3:F6}",
            offset[0], offset[1], restored[2], restored[3]
        ));
    }
}
```

예상 출력은 C++과 같은 `1.000000 -1.000000 0.440000 0.180000`이다.

## 12. 프레임워크 간 shape·layout·dtype 대응

| 경계 | PyTorch Python | C++ runtime 예 | C# runtime 예 | 검증 포인트 |
| --- | --- | --- | --- | --- |
| 입력 image | `[N,3,H,W]`, `float32` | contiguous `NCHW` buffer | `DenseTensor<float>` 등 | RGB/BGR, stride, normalization |
| level feature | `[N,F,H_k,W_k]` | backend별 `NCHW`/`NHWC` | runtime metadata 조회 | output 이름과 spatial size |
| raw class | `[N,A_kC,H_k,W_k]` | flat pointer | flat array | anchor-major channel schema |
| logical class | `[N,B,C]` | offset 계산 | offset 계산 | level·row·col·anchor 순서 |
| raw box | `[N,4A_k,H_k,W_k]` | flat pointer | flat array | `dx,dy,dw,dh` 순서 |
| default box | `[B,4]`, `float32` | `std::array<float,4>` | `float[4]` | `cxcywh`, normalized 좌표 |
| class target | `[N,B]`, `int64` | `int64_t` 또는 backend type | `long` | background id와 ignore id |
| positive mask | `[N,B]`, `bool` | byte/bool buffer | `bool[]` | padding과 ignore 분리 |

ONNX가 class output을 `[N,B,C]`로 직접 내보내면 애플리케이션의 reshape 실수를 줄일 수 있다. 반면 level별 raw output을 유지하면 dynamic resolution과 custom decoder에 유연하다. 어느 방식을 쓰든 output name, shape equation, flatten 순서를 schema에 넣는다.

FP16 또는 BF16 graph라도 IoU, `log`, `exp`, loss reduction은 FP32로 올려 계산하는 편이 안전하다. 배포 decode의 `exp` 입력에는 학습·검증으로 정한 범위 clamp를 적용하고 clamp count를 기록한다.

## 13. 테스트·디버깅

### 13.1 default box 테스트

- level별 count가 $H_kW_kA_k$와 같다.
- 첫·중간·마지막 anchor의 중심과 scale이 golden과 같다.
- 중심은 $(j+0.5)/W_k$, $(i+0.5)/H_k$를 따른다.
- ratio 순서를 바꾸면 config hash가 달라진다.
- head에 연속 index를 넣어 decoder의 flatten index와 대조한다.

### 13.2 matcher 테스트

- IoU가 threshold 이상인 anchor가 positive다.
- threshold가 매우 높아도 각 정답에 하나 이상의 positive가 있다.
- 정답이 0개면 모든 anchor가 background candidate다.
- 퇴화 정답과 범위 밖 class id는 matcher 전에 실패한다.
- 강제 match 충돌, crowd, ignore 정책을 별도 test로 둔다.
- level별·class별 positive count를 dataset 샘플에서 확인한다.

### 13.3 loss 테스트

- positive 1개와 ratio 3이면 negative가 최대 3개다.
- negative loss 동점에서는 작은 anchor index가 먼저다.
- 선택되지 않은 negative의 class logit gradient는 0이다.
- negative anchor의 box offset gradient는 0이다.
- 빈 이미지의 `min_negatives` 정책이 의도한 loss를 만든다.
- positive 정규화 전·후 loss를 따로 검산한다.

### 13.4 FPN·head 테스트

- 홀수 입력 `65 x 81`에서 `P3/P4/P5`가 `17 x 21`, `9 x 11`, `5 x 6`이다.
- 모든 level channel이 $F$로 같다.
- total box axis가 head와 default box에서 같다.
- `P3`, `P4`, `P5` 순서를 이름으로 고정한다.
- 모든 parameter에 finite gradient가 도달한다.
- 같은 seed 재실행에서 허용한 결정성 수준을 만족한다.

### 13.5 디버깅 지도

| 증상 | 먼저 볼 값 | 흔한 원인 |
| --- | --- | --- |
| box가 규칙적으로 한 칸씩 이동 | anchor index fingerprint | head와 generator의 flatten 순서 불일치 |
| positive가 거의 없음 | 정답별 best IoU, level별 count | scale·ratio 부적합 또는 강제 match 누락 |
| class loss가 localization보다 압도적 | selected negative 수 | 모든 background 합산 또는 정규화 오류 |
| 빈 이미지 loss가 항상 0 | `N_pos`, `min_negatives` | positive 기반 mining의 경계 정책 누락 |
| FPN addition shape error | lateral과 top-down shape | `scale_factor=2` 사용 |
| shape는 맞지만 AP가 0 | class map, variance, decode golden | background id 또는 box schema 불일치 |
| AMP에서 box가 Inf | raw `tw,th`, `exp` clamp count | 낮은 정밀도에서 지수 overflow |
| 재실행 gradient 위치가 다름 | 동점 negative indices | 비결정적 `topk` tie-break |

최종 AP부터 보지 않는다. `feature shape -> anchor count/order -> pairwise IoU -> forced match -> selected negative -> encoded target -> raw head -> decoded box` 순서로 작은 artifact를 비교한다.

## 14. 성능·메모리·수치 안정성

### 14.1 IoU matrix

한 이미지의 IoU matrix는 $B\times M$이다. SSD300의 $B=8732$, 정답 $M=100$이면 FP32 matrix만 약 3.33 MiB다.

$$
8732\times100\times4=3{,}492{,}800\ \mathrm{bytes}
$$

batch를 padding해 한꺼번에 계산하면 최대 정답 수 기준으로 메모리를 쓴다. 이미지별 loop는 단순하지만 GPU utilization이 낮을 수 있다. chunked IoU나 vectorized matcher를 선택할 때 결과와 tie-break가 oracle과 같은지 확인한다.

### 14.2 prediction과 FPN activation

오늘 예제의 logical output 원소 수는 다음과 같다.

$$
N\times972\times(3+4)
$$

실제 메모리는 output보다 고해상도 `P3`, backbone activation, optimizer state가 지배하기 쉽다. `P2`를 추가하면 작은 객체에는 도움이 될 수 있지만 spatial 면적과 anchor 수가 크게 늘어 matcher·NMS 비용도 증가한다.

### 14.3 mining 비용

전체 sort는 이미지마다 대략 $O(B\log B)$다. 필요한 negative 수만 작다면 `topk`가 빠르지만 tie-break 결정성이 다를 수 있다. 학습 throughput과 exact replay 중 무엇이 필요한지 정하고 다음을 함께 측정한다.

- images/s와 data loader 대기 시간
- matcher, sort/top-k, forward, backward 시간
- peak allocated·reserved memory
- positive와 selected negative 수 분포
- FP32, AMP의 loss·AP parity와 NaN count

### 14.4 안정성 guard

- box width와 height는 encode 전에 양수인지 검사한다.
- IoU union은 작은 epsilon으로 보호한다.
- `log(g_w/d_w)`는 FP32에서 계산한다.
- decode의 exponent를 검증된 범위로 clamp한다.
- loss normalizer는 0이 되지 않게 하되 빈 이미지 정책을 숨기지 않는다.
- NaN·Inf가 생긴 image id와 anchor index를 함께 기록한다.

| --- | --- | --- | --- |
| negative ratio 1 vs 3 | raw logits, positive mask | class loss, AP, selected count | 더 많은 hard negative의 이득과 비용 |
| forced match on vs off | anchors, threshold | unmatched GT, small-object recall | 최소 positive 보장의 효과 |
| `P3` only vs `P3/P4/P5` | backbone, total steps | 크기별 AP, latency | multi-scale head의 기여 |
| FPN on vs lateral only | head parameter 수 | small/medium/large AP | top-down semantic 전달의 기여 |
| nearest vs bilinear | align convention | AP, export parity | resize kernel의 민감도 |
| FP32 vs AMP | seed, batch order | loss drift, NaN, throughput | 정밀도 trade-off |

한 번에 하나의 요인만 바꾼다. `P3` only는 anchor 수와 negative 수까지 바뀌므로 단순히 FPN의 순수 효과라고 과장하지 말고 compute-matched 실험을 추가한다.

## 16. 실무 실패 사례

### 사례 A: anchor 수는 같지만 순서가 다름

Python head는 `row -> column -> ratio`로 펼쳤고 C++ decoder는 `ratio -> row -> column`로 생성했다. 두 쪽 모두 8732개여서 shape 검사와 메모리 접근은 성공했지만 모든 box가 규칙적으로 어긋났다.

대응은 raw head에 anchor index를 encode한 synthetic tensor를 넣고 첫·경계·마지막 값을 모든 runtime에서 비교하는 것이다.

### 사례 B: 강제 match가 정답 하나를 덮어씀

가까운 두 작은 정답이 같은 default box를 best로 골랐다. 단순 대입이 뒤 정답으로 앞 정답의 match를 덮어썼고, 정답별 positive count를 보지 않아 발견이 늦었다.

대응은 강제 match 뒤 모든 정답의 match count를 assert하고 충돌 시 bipartite assignment나 명시적 재할당을 사용한다.

### 사례 C: 빈 이미지가 학습에서 사라짐

positive 0개라 hard-negative도 0개가 되었고 손실이 0이었다. 배경 전용 이미지가 dataset의 30%였지만 모델은 이를 전혀 학습하지 않았다.

대응은 빈 이미지 정책과 최소 negative 수를 config에 넣고 빈 이미지 전용 unit test와 batch metric을 둔다.

### 사례 D: FPN output 이름이 export에서 바뀜

Python은 dictionary 순회 순서에 기대 `P3/P4/P5`를 연결했고 export 최적화 뒤 output ordering이 바뀌었다. channel 수가 같아 head는 실행됐지만 anchor scale이 잘못 붙었다.

대응은 level 이름과 stride를 output metadata에 고정하고 positional ordering만 믿지 않는다.

### 사례 E: hard-negative mining이 label leakage를 만듦

negative 순위를 정할 때 evaluation annotation의 ignore 정보나 미래 augmentation 결과를 잘못 섞었다. loss는 좋아졌지만 실제 배포 분포 성능이 재현되지 않았다.

대응은 matcher 입력 provenance와 augmentation seed를 batch artifact에 기록하고 train/validation target pipeline을 분리한다.

## 17. 배포 관점

model file과 함께 다음 schema를 versioning한다.

- 입력 이름, dynamic shape 범위, RGB/BGR, `NCHW`/`NHWC`, dtype
- resize·letterbox·normalization과 원본 좌표 역변환
- `P3/P4/P5` 이름, stride, head output shape
- scale, aspect ratio, center offset, anchor flatten 순서
- box format, variance, decode clamp, clipping
- background id, class map hash, softmax 적용 위치
- score threshold, pre-NMS top-k, NMS IoU, max detections
- golden image, raw level outputs, anchor fingerprint, final detections
- runtime·opset·precision과 허용 오차

### 배포 전 parity 단계

1. Python eager와 export graph의 level별 raw output을 비교한다.
2. 같은 default box artifact 또는 같은 generator golden을 사용한다.
3. decode 직후 normalized box를 비교한다.
4. score filtering과 NMS 전 후보를 비교한다.
5. 최종 원본 pixel 좌표와 class를 비교한다.
6. 빈 장면, 혼잡 장면, 극단 aspect ratio를 benchmark한다.

오늘 환경에서 ONNX package와 대상 production runtime이 설치됐다고 가정하지 않는다. 실제 package가 없으면 PyTorch·NumPy·C++·C# scalar 경계를 검증하고 ONNX parity는 미검증으로 보고한다. 배포 승인은 실제 target runtime에서 별도로 받아야 한다.

### 운영 모니터링

- level별 positive proxy와 NMS 전후 후보 수
- class별 detection count와 confidence histogram
- width·height·aspect ratio와 clip 비율
- decode clamp, NaN, Inf count
- input 해상도·blur·밝기 drift
- preprocessing, inference, postprocessing의 p50·p95·p99
- 지연 annotation이 있으면 크기별 AP와 unmatched GT

raw output drift와 postprocessing drift를 분리한다. raw가 같은데 detection이 달라지면 anchor, decode, class map, NMS를 먼저 의심한다.

## 19. 연습문제

### 문제 1

`P3=20 x 20`, `P4=10 x 10`, `P5=5 x 5`이고 cell당 anchor가 각각 4, 6, 6개다. 총 box 수를 구하라.

### 문제 2

정답의 모든 IoU가 0.5 threshold보다 낮지만 최고 IoU가 0.42다. 강제 match가 있을 때와 없을 때 학습 target이 어떻게 달라지는가?

### 문제 3

positive가 7개이고 ratio가 3이며 negative 후보가 100개다. 몇 개를 선택하는가? 후보가 12개뿐이면 몇 개인가?

### 문제 4

default box $d=(0.5,0.5,0.4,0.2)$, 정답 $g=(0.54,0.48,0.44,0.18)$, $v_{xy}=0.1$, $v_{wh}=0.2$일 때 $t_x,t_y$를 구하라.

### 문제 5

`C4` spatial shape이 `9 x 11`, `M5`가 `5 x 6`이다. `scale_factor=2`가 실패하는 이유와 안전한 코드를 설명하라.

### 문제 6

negative loss가 anchor 1과 2에서 모두 0.9이고 하나만 골라야 한다. exact replay를 위한 tie-break를 하나 제시하라.

### 문제 7

Python raw output은 C++과 같지만 최종 box만 다르다. 확인할 경계를 순서대로 세 가지 쓰라.

## 20. 해답

### 해답 1

$$
20\times20\times4+10\times10\times6+5\times5\times6=2350
$$

### 해답 2

강제 match가 없으면 이 정답은 positive를 하나도 얻지 못해 localization과 foreground classification gradient가 없다. 강제 match가 있으면 최고 IoU 0.42인 anchor를 positive로 지정해 최소 한 학습 신호를 만든다.

### 해답 3

$3\times7=21$이므로 후보가 100개면 21개를 고른다. 후보가 12개면 상한에 걸려 12개를 고른다.

### 해답 4

$$
t_x=\frac{0.54-0.50}{0.1\times0.4}=1
$$

$$
t_y=\frac{0.48-0.50}{0.1\times0.2}=-1
$$

### 해답 5

`5 x 6`을 두 배로 만들면 `10 x 12`여서 `9 x 11`과 더할 수 없다. `F.interpolate(m5, size=c4.shape[-2:], mode="nearest")`처럼 lateral의 정확한 spatial size를 지정한다.

### 해답 6

loss 내림차순을 첫 key로, anchor index 오름차순을 두 번째 key로 사용한다. 따라서 두 값이 같으면 anchor 1을 먼저 고른다.

### 해답 7

첫째 default box 순서·값을 비교한다. 둘째 variance와 decode 결과를 비교한다. 셋째 score threshold·class별 NMS와 letterbox 역변환을 비교한다. raw가 같으므로 backbone이나 head보다 후처리 경계를 먼저 본다.

## 핵심 요약

- SSD 구현의 핵심은 여러 head를 붙이는 것보다 예측과 default box의 flatten 순서를 동일하게 유지하는 것이다.
- 각 정답의 best anchor를 강제로 positive로 지정해야 작은 정답이 threshold 아래에서 사라지지 않는다.
- encode와 decode는 같은 variance를 사용하는 역함수이며 NumPy·C++·C# golden으로 고정할 수 있다.
- hard-negative mining은 positive 수에 비례해 어려운 배경만 선택하며 Focal Loss와 다른 이산 선택 방법이다.
- positive가 0인 이미지의 최소 negative 정책과 동점 tie-break를 명시해야 학습과 재현성이 모호하지 않다.
- FPN은 재귀 중간값 $M_k$와 최종 output $P_k$를 구분하고 odd shape에서 정확한 lateral size로 확대한다.
- MultiBox loss는 localization과 선택된 classification loss를 $\max(N_+,1)$로 정규화하되 항별 값을 함께 기록한다.
- 배포 장애는 shape 오류보다 level naming, anchor order, variance, background id, letterbox 역변환 불일치에서 자주 생긴다.
- raw output, decoded 후보, 최종 detection을 단계별로 비교해야 model 문제와 후처리 문제를 빠르게 분리할 수 있다.
