## 학습 목표

1회차에는 LoRA의 저랭크 업데이트, 초기 gradient, shape와 merge 직관을 배웠다. 이번에는 그 설명을 재현 가능한 이미지 분류 학습·평가·배포 계약으로 바꾼다. 이 글을 마치면 다음을 할 수 있다.

- 기존 `nn.Linear`를 값 손실 없이 LoRA 계층으로 교체하고 target module을 이름으로 검증한다.
- base parameter 동결, optimizer parameter group, 초기 함수 보존을 assertion으로 고정한다.
- $A$, $B$의 forward와 backward를 index 식으로 유도하고 tensor shape를 추적한다.
- 작은 이미지 분류 문제에서 학습·평가·checkpoint 복원을 끝까지 재현한다.
- rank 1과 rank 2를 같은 데이터·seed·step budget으로 비교한다.
- merge·unmerge를 상태 머신으로 구현하고 중복 병합을 거부한다.
- adapter-only checkpoint와 manifest가 base revision, scaling, layout을 검증하게 한다.
- NumPy, PyTorch, C++와 C# 결과를 같은 golden 값으로 교차 검증한다.
- mixed precision, optimizer state, 양자화, ONNX와 동적 adapter serving의 실패를 진단한다.

## 선수 지식과 기호

행렬 곱, rank, chain rule, `nn.Linear`, AdamW, train/eval mode를 알고 있으면 된다. 이미지 예제는 $8\times8$ grayscale image를 네 사분면 평균 feature로 바꾸지만, 같은 계약은 ViT의 attention projection과 ConvNeXt의 pointwise projection에도 적용된다.

| 기호 | 정의 | shape |
| --- | --- | --- |
| $X$ | 마지막 feature 축을 가진 입력 | $(M,d_{\mathrm{in}})$ |
| $W_0$ | 고정된 base weight | $(d_{\mathrm{out}},d_{\mathrm{in}})$ |
| $b_0$ | 고정된 base bias | $(d_{\mathrm{out}})$ |
| $A$ | down projection | $(r,d_{\mathrm{in}})$ |
| $B$ | up projection | $(d_{\mathrm{out}},r)$ |
| $r$ | adapter rank | positive integer |
| $\alpha$ | adapter scale hyperparameter | scalar |
| $s$ | 실제 multiplier $\alpha/r$ | scalar |
| $H$ | rank bottleneck $XA^\top$ | $(M,r)$ |
| $\Delta W$ | scaled update $sBA$ | $(d_{\mathrm{out}},d_{\mathrm{in}})$ |
| $Y$ | base와 adapter를 합친 출력 | $(M,d_{\mathrm{out}})$ |

PyTorch `Linear`는 weight를 `(out_features, in_features)`로 저장하고 입력의 마지막 축에 적용한다. 본문의 행렬 식과 checkpoint schema는 이 convention만 사용한다.

## 1. 원본을 구현 관점에서 다시 읽기

원본의 핵심은 “큰 base weight는 고정하고 작은 두 factor만 학습한다”는 것이다. 실제 코드로 옮길 때는 다음 축약을 보완해야 한다.

| 원본의 표현 또는 코드 | 구현 계약에서의 교정 |
| --- | --- |
| $W_0\in\mathbb{R}^{d\times k}$인데 $BA\in\mathbb{R}^{k\times d}$ | PyTorch convention인 `(out,in)`, `(r,in)`, `(out,r)`로 고정한다. |
| $BA$를 그대로 더한다 | scaling convention $s=\alpha/r$를 manifest에 저장하고 정확히 한 번 적용한다. |
| `linear.weight`만 freeze한다 | bias를 포함한 base parameter 전체를 freeze하고 optimizer ID까지 검사한다. |
| LoRA parameter만 학습하므로 매우 빠르다 | trainable state는 줄지만 frozen forward와 activation은 남는다. wall-clock은 실제 장치에서 측정한다. |
| merge하면 원본과 속도가 100% 같다 | graph 연산 수는 같아질 수 있지만 dtype, quantization, artifact loading과 kernel 선택까지 같다는 보장은 없다. |
| rank가 작을수록 추상 스타일을 학습한다 | rank는 업데이트 공간의 차원 상한이다. 의미론적 역할은 데이터와 target module에 따라 달라진다. |
| 작은 adapter 파일이면 어느 base에도 붙일 수 있다 | 같은 shape의 다른 revision도 조용히 오동작한다. base hash와 target 이름을 검사한다. |

이번 구현의 전체 경로는 다음과 같다.

```text
8 x 8 image
  -> deterministic quadrant feature (N, 4)
  -> frozen Linear(4, 3)
  -> LoRA A( r, 4 ) and B( 3, r )
  -> logits (N, 3)
  -> teacher-logit regression + class accuracy
  -> adapter-only state + manifest
  -> fresh base에 strict load
  -> split/merged/unmerged parity
```

## 2. forward를 shape 계약으로 만들기

### 2.1 row-batch 식

PyTorch의 row-batch 식은 다음과 같다.

$$
Y
=
XW_0^\top+b_0+s(XA^\top)B^\top
$$

연산을 순서대로 쓰면 다음과 같다.

$$
X\in\mathbb{R}^{M\times d_{\mathrm{in}}}
\xrightarrow{A^\top}
H\in\mathbb{R}^{M\times r}
\xrightarrow{B^\top}
Z\in\mathbb{R}^{M\times d_{\mathrm{out}}}
$$

그리고 $Y=XW_0^\top+b_0+sZ$다. 입력이 `(N,L,D)`라면 PyTorch는 `(N,L)`을 leading dimension으로 보존하므로 $M=NL$로 생각할 수 있다.

### 2.2 이미지 분류 예제의 shape

오늘 예제의 입력은 `(N,1,8,8)`이다. `unfold`로 겹치지 않는 네 개의 `(4,4)` 사분면을 만들고 각각 평균을 낸다.

| 단계 | tensor | shape | dtype |
| --- | --- | --- | --- |
| 입력 image | `images` | `(N,1,8,8)` | `float32` |
| 사분면 view | `patches` | `(N,1,2,2,4,4)` | `float32` |
| 사분면 평균 | `features` | `(N,4)` | `float32` |
| rank bottleneck | `features @ A.T` | `(N,r)` | `float32` |
| base logits | `features @ W0.T + b0` | `(N,3)` | `float32` |
| adapter logits | `s * bottleneck @ B.T` | `(N,3)` | `float32` |
| 최종 logits | base + adapter | `(N,3)` | `float32` |

`unfold`가 반환한 view의 축 순서는 고정해야 한다. `(N,1,2,2,4,4)`를 바로 `flatten(1)`하면 pixel 64개가 되므로, 마지막 두 축을 평균한 뒤에 `(N,4)`로 펼친다.

### 2.3 parameter와 optimizer state

full weight와 LoRA trainable parameter 수는 각각 다음과 같다.

$$
P_{\mathrm{full}}
=
d_{\mathrm{out}}d_{\mathrm{in}}
$$

$$
P_{\mathrm{LoRA}}
=
r(d_{\mathrm{in}}+d_{\mathrm{out}})
$$

AdamW가 FP32 parameter, gradient, first moment, second moment를 모두 별도 저장한다고 단순화하면 trainable tensor 관련 bytes는 대략 다음과 같다.

$$
M_{\mathrm{AdamW}}
\approx
16P
\text{ bytes}
$$

실제 mixed-precision optimizer는 master weight와 scaler 때문에 달라질 수 있다. 이 식은 frozen base storage나 activation을 포함하지 않는 비교용 상한 모델이다.

## 3. backward와 초기화 유도

### 3.1 index 식

adapter 출력의 한 원소는 다음과 같다.

$$
Z_{m,o}
=
s
\sum_{q=1}^{r}
\sum_{i=1}^{d_{\mathrm{in}}}
X_{m,i}A_{q,i}B_{o,q}
$$

상류 gradient를 $G_{m,o}=\partial\mathcal{L}/\partial Z_{m,o}$라 두면 $B$의 gradient는 다음과 같다.

$$
\frac{\partial\mathcal{L}}{\partial B_{o,q}}
=
s
\sum_m
G_{m,o}
\sum_i X_{m,i}A_{q,i}
$$

$A$의 gradient는 다음과 같다.

$$
\frac{\partial\mathcal{L}}{\partial A_{q,i}}
=
s
\sum_m
\sum_o
G_{m,o}B_{o,q}X_{m,i}
$$

### 3.2 $A$ random, $B=0$ 초기화

초기 상태를 다음과 같이 둔다.

$$
A^{(0)}\ne0,
\qquad
B^{(0)}=0
$$

그러면 $\Delta W^{(0)}=0$이므로 첫 forward는 base와 같다. 첫 backward에서는 $B$ gradient가 일반적으로 0이 아니지만 $A$ gradient는 $B^{(0)}$ 때문에 0이다. 첫 optimizer step이 $B$를 움직인 뒤 다음 backward부터 $A$도 학습된다.

둘을 모두 0으로 두면 두 gradient가 동시에 0이라 학습이 시작되지 않는다. 반대로 둘을 모두 random으로 두면 초기 함수 보존을 잃는다.

### 3.3 scaling을 한 번만 적용하기

raw factor를 저장한다면 forward와 merge 모두 같은 $s$를 한 번만 사용해야 한다.

$$
Y_{\mathrm{split}}
=
XW_0^\top+b_0+s(XA^\top)B^\top
$$

$$
W_{\mathrm{merged}}
=
W_0+sBA
$$

checkpoint가 이미 scaled $B$를 저장하는 schema라면 loader가 다시 $s$를 곱하면 안 된다. 이 글의 schema는 **raw $A$, raw $B$, 별도 `alpha`, 별도 `rank`**를 저장한다.

## 4. NumPy 수작업과 golden 검증

다음은 **실행 가능한 예제**다. split 경로와 merged 경로, rank 상한을 독립적인 NumPy 계산으로 검사한다.

```python
import numpy as np

x = np.array([[1.0, -2.0, 0.5]])
w0 = np.array([
    [1.0, 0.0, -1.0],
    [0.5, 2.0, 1.0],
])
b0 = np.array([0.25, -0.5])
a = np.array([[2.0, -1.0, 0.5]])
b = np.array([[0.4], [-0.2]])
alpha = 2.0
rank = 1
scale = alpha / rank

h = x @ a.T
base = x @ w0.T + b0
adapter = scale * (h @ b.T)
split = base + adapter
delta_w = scale * (b @ a)
merged = x @ (w0 + delta_w).T + b0

np.testing.assert_allclose(h, [[4.25]])
np.testing.assert_allclose(base, [[0.75, -3.5]])
np.testing.assert_allclose(adapter, [[3.4, -1.7]])
np.testing.assert_allclose(split, [[4.15, -5.2]])
np.testing.assert_allclose(merged, split)
assert np.linalg.matrix_rank(delta_w) == 1

print("bottleneck:", h.tolist())
print("split:", split.tolist())
print("rank(delta):", np.linalg.matrix_rank(delta_w))
```

손으로 $h=2(1)+(-1)(-2)+0.5(0.5)=4.25$다. $s=2$이므로 adapter 출력은 $2\cdot4.25(0.4,-0.2)=(3.4,-1.7)$이고 최종 출력은 $(4.15,-5.2)$다.

## 5. PyTorch 완전 구현

다음은 **실행 가능한 단일 Python 프로그램**이다. 외부 dataset 없이 image 생성, feature 추출, LoRA 학습, 평가, rank ablation, exact replay, checkpoint 복원, merge 상태 검사를 수행한다.

```python
import copy
import json
import math
from dataclasses import asdict, dataclass

import torch
from torch import nn
from torch.nn import functional as F


def seed_everything(seed: int) -> None:
    torch.manual_seed(seed)
    torch.use_deterministic_algorithms(True)


def quadrant_features(images: torch.Tensor) -> torch.Tensor:
    if images.ndim != 4 or images.shape[1:] != (1, 8, 8):
        raise ValueError("expected images shaped (N, 1, 8, 8)")
    patches = images.unfold(2, 4, 4).unfold(3, 4, 4)
    assert patches.shape[1:] == (1, 2, 2, 4, 4)
    return patches.mean(dim=(-1, -2)).flatten(1)


class LoRALinear(nn.Module):
    def __init__(
        self,
        base: nn.Linear,
        rank: int,
        alpha: float,
    ) -> None:
        super().__init__()
        if rank <= 0 or rank > min(base.in_features, base.out_features):
            raise ValueError("rank is outside the supported range")
        self.in_features = base.in_features
        self.out_features = base.out_features
        self.rank = rank
        self.alpha = float(alpha)
        self.scale = self.alpha / self.rank

        self.weight = nn.Parameter(base.weight.detach().clone(), requires_grad=False)
        if base.bias is None:
            self.register_parameter("bias", None)
        else:
            self.bias = nn.Parameter(base.bias.detach().clone(), requires_grad=False)

        self.lora_a = nn.Parameter(torch.empty(rank, self.in_features))
        self.lora_b = nn.Parameter(torch.zeros(self.out_features, rank))
        nn.init.kaiming_uniform_(self.lora_a, a=math.sqrt(5))
        self.register_buffer("is_merged", torch.tensor(False), persistent=False)

    def delta_weight(self) -> torch.Tensor:
        return self.scale * (self.lora_b @ self.lora_a)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        y = F.linear(x, self.weight, self.bias)
        if not bool(self.is_merged):
            y = y + self.scale * F.linear(F.linear(x, self.lora_a), self.lora_b)
        return y

    @torch.no_grad()
    def merge(self) -> None:
        if bool(self.is_merged):
            raise RuntimeError("adapter is already merged")
        delta = self.delta_weight().to(device=self.weight.device, dtype=torch.float32)
        merged = self.weight.float() + delta
        self.weight.copy_(merged.to(self.weight.dtype))
        self.is_merged.fill_(True)

    @torch.no_grad()
    def unmerge_from(self, immutable_base: torch.Tensor) -> None:
        if not bool(self.is_merged):
            raise RuntimeError("adapter is not merged")
        self.weight.copy_(immutable_base)
        self.is_merged.fill_(False)

    def adapter_state(self) -> dict[str, torch.Tensor]:
        return {
            "lora_a": self.lora_a.detach().clone(),
            "lora_b": self.lora_b.detach().clone(),
        }


@dataclass(frozen=True)
class AdapterManifest:
    schema_version: int
    base_revision: str
    target_module: str
    in_features: int
    out_features: int
    rank: int
    alpha: float
    orientation: str
    dtype: str


def load_adapter_strict(
    layer: LoRALinear,
    state: dict[str, torch.Tensor],
    manifest: AdapterManifest,
    expected_base_revision: str,
    expected_target: str,
) -> None:
    if manifest.schema_version != 1:
        raise ValueError("unsupported adapter schema")
    if manifest.base_revision != expected_base_revision:
        raise ValueError("base revision mismatch")
    if manifest.target_module != expected_target:
        raise ValueError("target module mismatch")
    expected = (
        layer.in_features,
        layer.out_features,
        layer.rank,
        layer.alpha,
        "A=(rank,in);B=(out,rank)",
    )
    actual = (
        manifest.in_features,
        manifest.out_features,
        manifest.rank,
        manifest.alpha,
        manifest.orientation,
    )
    if actual != expected:
        raise ValueError("adapter contract mismatch")
    if state["lora_a"].shape != layer.lora_a.shape:
        raise ValueError("lora_a shape mismatch")
    if state["lora_b"].shape != layer.lora_b.shape:
        raise ValueError("lora_b shape mismatch")
    with torch.no_grad():
        layer.lora_a.copy_(state["lora_a"].to(layer.lora_a))
        layer.lora_b.copy_(state["lora_b"].to(layer.lora_b))


W0 = torch.tensor([
    [1.0, -0.5, 0.2, 0.0],
    [-0.4, 0.8, -0.3, 0.6],
    [0.1, -0.2, 0.9, -0.7],
])
B_TRUE = torch.tensor([
    [1.2, 0.0],
    [0.0, 1.0],
    [-0.8, -0.9],
])
A_TRUE = torch.tensor([
    [1.0, -1.0, 0.5, 0.0],
    [0.0, 0.7, -0.4, 1.0],
])
BIAS0 = torch.tensor([0.1, -0.2, 0.05])


def make_split(seed: int, count: int) -> tuple[torch.Tensor, torch.Tensor]:
    generator = torch.Generator().manual_seed(seed)
    images = torch.randn(count, 1, 8, 8, generator=generator)
    features = quadrant_features(images)
    teacher_weight = W0 + B_TRUE @ A_TRUE
    teacher_logits = F.linear(features, teacher_weight, BIAS0)
    return images, teacher_logits


def make_base() -> nn.Linear:
    base = nn.Linear(4, 3)
    with torch.no_grad():
        base.weight.copy_(W0)
        base.bias.copy_(BIAS0)
    return base


def train_once(rank: int, seed: int = 17) -> dict[str, object]:
    seed_everything(seed)
    train_images, train_targets = make_split(101, 512)
    test_images, test_targets = make_split(202, 256)
    layer = LoRALinear(make_base(), rank=rank, alpha=float(rank))

    trainable = {name for name, p in layer.named_parameters() if p.requires_grad}
    assert trainable == {"lora_a", "lora_b"}
    optimizer = torch.optim.AdamW(
        [layer.lora_a, layer.lora_b],
        lr=0.05,
        weight_decay=0.0,
    )

    train_x = quadrant_features(train_images)
    test_x = quadrant_features(test_images)
    with torch.no_grad():
        torch.testing.assert_close(layer(train_x), F.linear(train_x, W0, BIAS0))

    first_loss = None
    first_grad_a = None
    first_grad_b = None
    history = []
    for step in range(301):
        optimizer.zero_grad(set_to_none=True)
        prediction = layer(train_x)
        loss = F.mse_loss(prediction, train_targets)
        loss.backward()
        if step == 0:
            first_loss = float(loss.detach())
            first_grad_a = float(layer.lora_a.grad.norm())
            first_grad_b = float(layer.lora_b.grad.norm())
        optimizer.step()
        if step in (0, 50, 100, 200, 300):
            history.append(float(loss.detach()))

    with torch.no_grad():
        test_prediction = layer(test_x)
        test_mse = float(F.mse_loss(test_prediction, test_targets))
        predicted_class = test_prediction.argmax(dim=1)
        target_class = test_targets.argmax(dim=1)
        accuracy = float((predicted_class == target_class).float().mean())

    return {
        "layer": layer,
        "history": history,
        "first_loss": first_loss,
        "first_grad_a": first_grad_a,
        "first_grad_b": first_grad_b,
        "test_mse": test_mse,
        "accuracy": accuracy,
        "test_x": test_x,
    }


rank1 = train_once(rank=1)
rank2 = train_once(rank=2)
rank2_replay = train_once(rank=2)

assert rank1["first_grad_a"] == 0.0
assert rank1["first_grad_b"] > 0.0
assert rank2["test_mse"] < rank1["test_mse"]
assert rank2["accuracy"] >= rank1["accuracy"]
assert rank2["history"] == rank2_replay["history"]
for key, value in rank2["layer"].adapter_state().items():
    torch.testing.assert_close(value, rank2_replay["layer"].adapter_state()[key], rtol=0, atol=0)

layer = rank2["layer"]
test_x = rank2["test_x"]
immutable_base = layer.weight.detach().clone()
with torch.no_grad():
    split_output = layer(test_x)
    layer.merge()
    merged_output = layer(test_x)
    torch.testing.assert_close(merged_output, split_output, rtol=1e-5, atol=1e-6)
    try:
        layer.merge()
        raise AssertionError("double merge was not rejected")
    except RuntimeError:
        pass
    layer.unmerge_from(immutable_base)
    torch.testing.assert_close(layer.weight, immutable_base, rtol=0, atol=0)
    torch.testing.assert_close(layer(test_x), split_output, rtol=1e-5, atol=1e-6)

manifest = AdapterManifest(
    schema_version=1,
    base_revision="tiny-vision-sha256:7f3a",
    target_module="classifier",
    in_features=4,
    out_features=3,
    rank=2,
    alpha=2.0,
    orientation="A=(rank,in);B=(out,rank)",
    dtype="float32",
)
serialized_manifest = json.dumps(asdict(manifest), sort_keys=True)
fresh = LoRALinear(make_base(), rank=2, alpha=2.0)
load_adapter_strict(
    fresh,
    layer.adapter_state(),
    manifest,
    expected_base_revision="tiny-vision-sha256:7f3a",
    expected_target="classifier",
)
with torch.no_grad():
    torch.testing.assert_close(fresh(test_x), split_output, rtol=0, atol=0)

bad_manifest = AdapterManifest(**{
    **asdict(manifest),
    "base_revision": "wrong-revision",
})
try:
    load_adapter_strict(
        fresh,
        layer.adapter_state(),
        bad_manifest,
        expected_base_revision="tiny-vision-sha256:7f3a",
        expected_target="classifier",
    )
    raise AssertionError("wrong base revision was not rejected")
except ValueError:
    pass

print("rank1:", round(rank1["test_mse"], 6), round(rank1["accuracy"], 6))
print("rank2:", round(rank2["test_mse"], 6), round(rank2["accuracy"], 6))
print("first gradients:", rank2["first_grad_a"], round(rank2["first_grad_b"], 6))
print("manifest:", serialized_manifest)
print("all LoRA contract tests passed")
```

같은 로컬 환경에서 실행한 결과는 다음과 같았다. 이 숫자는 알고리즘의 보편 성능이 아니라 위 synthetic teacher와 고정 seed에 대한 regression oracle이다.

| rank | test logit MSE | teacher class accuracy |
| --- | ---: | ---: |
| 1 | 0.052296 | 0.875000 |
| 2 | 0.000000 | 1.000000 |

rank 2 첫 backward의 gradient norm은 $\lVert\nabla_A\rVert=0$, $\lVert\nabla_B\rVert=0.016830$이었다. 같은 seed로 rank 2를 다시 실행했을 때 loss history와 adapter tensor가 정확히 일치했다.

### 5.1 이 코드가 검증하는 것

- dataset RNG와 parameter RNG를 분리해 같은 입력과 초기화를 재현한다.
- base weight와 bias 모두 `requires_grad=False`다.
- optimizer에는 `lora_a`, `lora_b`만 들어간다.
- $B=0$ 초기 forward가 frozen base와 같다.
- 첫 backward에서 $A$ gradient는 0이고 $B$ gradient는 nonzero다.
- rank ablation은 데이터, seed, optimizer, step budget을 고정한다.
- 같은 seed의 loss history와 adapter tensor가 bitwise 동일하다.
- split, merged, restored split 출력이 tolerance 안에서 같다.
- 중복 merge를 예외로 막고 unmerge는 immutable base에서 복원한다.
- 다른 base revision의 adapter를 shape가 같아도 거부한다.

### 5.2 왜 subtract 방식 unmerge를 쓰지 않았는가

낮은 precision에서 `weight += delta; weight -= delta`를 반복하면 반올림 오차가 누적될 수 있다. 구현은 호출자가 보관한 immutable base tensor를 다시 복사한다. production에서는 base state dict나 content-addressed cache가 이 역할을 맡는다.

### 5.3 target module 교체기

실제 모델에서는 이름 suffix만 보고 무조건 교체하지 않는다. 다음은 **설명용 코드**이며, 실행 전 model 구조에 맞는 allowlist를 작성해야 한다.

```python
def inject_lora(model, target_names, rank, alpha):
    replaced = []
    for full_name in target_names:
        parent_name, child_name = full_name.rsplit(".", 1)
        parent = model.get_submodule(parent_name)
        child = getattr(parent, child_name)
        if not isinstance(child, torch.nn.Linear):
            raise TypeError(f"{full_name} is not Linear")
        setattr(parent, child_name, LoRALinear(child, rank, alpha))
        replaced.append(full_name)
    if replaced != list(target_names):
        raise RuntimeError("target replacement order mismatch")
    return replaced
```

`endswith("q_proj")` 같은 광범위한 규칙은 이름 충돌로 예상 밖의 module을 바꿀 수 있다. dry-run에서 exact name, type, weight shape, parameter count를 출력하고 승인된 목록과 비교한다.

## 6. checkpoint와 재개 학습 계약

adapter-only checkpoint는 inference tensor만 저장하면 작다. 그러나 학습을 정확히 재개하려면 두 상태를 구분해야 한다.

### 6.1 배포용 adapter artifact

- raw `lora_a`, raw `lora_b`
- base model immutable revision 또는 weight hash
- exact target module name과 module type
- `in_features`, `out_features`, rank, $\alpha$
- orientation과 scaling convention
- adapter dtype과 기대 compute dtype
- tokenizer 또는 image preprocessing revision
- schema version과 생성 코드 revision

### 6.2 재개 학습 checkpoint

배포 artifact에 더해 다음이 필요하다.

- optimizer parameter group과 moment state
- learning-rate scheduler state
- gradient scaler state
- Python, NumPy, CPU와 accelerator RNG state
- sampler epoch와 data cursor
- accumulation step과 global step
- train/eval mode 및 dropout 확률

optimizer state 없이 adapter tensor만 load하면 같은 지점에서 추론은 가능하지만 **학습 trajectory 재개**는 아니다.

## 7. C++ 예제

다음은 **실행 가능한 C++17 예제**다. NumPy와 같은 `(out,in)` convention으로 split과 merged 출력을 비교한다.

```cpp
#include <array>
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>

int main() {
    constexpr int kIn = 3;
    constexpr int kOut = 2;
    constexpr int kRank = 1;
    const std::array<double, kIn> x{1.0, -2.0, 0.5};
    const double w0[kOut][kIn]{{1.0, 0.0, -1.0}, {0.5, 2.0, 1.0}};
    const std::array<double, kOut> bias{0.25, -0.5};
    const double a[kRank][kIn]{{2.0, -1.0, 0.5}};
    const double b[kOut][kRank]{{0.4}, {-0.2}};
    const double scale = 2.0;

    std::array<double, kRank> hidden{};
    std::array<double, kOut> split{};
    std::array<double, kOut> merged{};

    for (int q = 0; q < kRank; ++q)
        for (int i = 0; i < kIn; ++i)
            hidden[q] += a[q][i] * x[i];

    for (int o = 0; o < kOut; ++o) {
        split[o] = bias[o];
        merged[o] = bias[o];
        for (int i = 0; i < kIn; ++i) {
            split[o] += w0[o][i] * x[i];
            double delta = 0.0;
            for (int q = 0; q < kRank; ++q)
                delta += scale * b[o][q] * a[q][i];
            merged[o] += (w0[o][i] + delta) * x[i];
        }
        for (int q = 0; q < kRank; ++q)
            split[o] += scale * b[o][q] * hidden[q];
        assert(std::abs(split[o] - merged[o]) < 1e-12);
    }

    assert(std::abs(split[0] - 4.15) < 1e-12);
    assert(std::abs(split[1] + 5.20) < 1e-12);
    std::cout << std::fixed << std::setprecision(2)
              << split[0] << " " << split[1] << "\n";
}
```

BLAS나 oneDNN으로 바꿀 때는 logical shape뿐 아니라 row-major·column-major, leading dimension, transpose flag를 manifest 또는 binding code에 고정한다.

## 8. C# 예제

다음은 **실행 가능한 C# 예제**다. 같은 golden 출력을 managed array loop로 계산한다.

```csharp
using System;

public static class Program
{
    public static void Main()
    {
        double[] x = { 1.0, -2.0, 0.5 };
        double[,] w0 = {
            { 1.0, 0.0, -1.0 },
            { 0.5, 2.0, 1.0 }
        };
        double[] bias = { 0.25, -0.5 };
        double[,] a = { { 2.0, -1.0, 0.5 } };
        double[,] b = { { 0.4 }, { -0.2 } };
        double scale = 2.0;
        int inputSize = w0.GetLength(1);
        int outputSize = w0.GetLength(0);
        int rank = a.GetLength(0);
        double[] hidden = new double[rank];
        double[] split = new double[outputSize];
        double[] merged = new double[outputSize];

        for (int q = 0; q < rank; q++)
            for (int i = 0; i < inputSize; i++)
                hidden[q] += a[q, i] * x[i];

        for (int o = 0; o < outputSize; o++)
        {
            split[o] = bias[o];
            merged[o] = bias[o];
            for (int i = 0; i < inputSize; i++)
            {
                split[o] += w0[o, i] * x[i];
                double delta = 0.0;
                for (int q = 0; q < rank; q++)
                    delta += scale * b[o, q] * a[q, i];
                merged[o] += (w0[o, i] + delta) * x[i];
            }
            for (int q = 0; q < rank; q++)
                split[o] += scale * b[o, q] * hidden[q];
            if (Math.Abs(split[o] - merged[o]) >= 1e-12)

        }

        if (Math.Abs(split[0] - 4.15) >= 1e-12 ||

```

ONNX Runtime C# binding에서는 `DenseTensor<float>`의 logical dimension과 underlying buffer 순서를 함께 확인한다. C#의 `double[,]` 예제는 정확성 oracle이지 고성능 serving 구현이 아니다.

## 9. framework 간 shape·layout·dtype 대응

| 환경 | base weight | $A$ | $B$ | 입력 계산 | 주의점 |
| --- | --- | --- | --- | --- | --- |
| PyTorch `Linear` | `(out,in)` | `(r,in)` | `(out,r)` | `F.linear(X,W)` | 내부적으로 `X @ W.T`다. |
| NumPy row batch | `(out,in)` | `(r,in)` | `(out,r)` | `X @ W.T` | 1D와 2D 입력의 broadcast를 구분한다. |
| C++ row-major loop | `[out][in]` | `[r][in]` | `[out][r]` | 명시적 index | BLAS transpose flag와 leading dimension을 검사한다. |
| C# multidimensional array | `[out,in]` | `[r,in]` | `[out,r]` | 명시적 index | runtime tensor buffer와 메모리 특성이 다르다. |
| ONNX `MatMul` | initializer에 따라 다름 | graph에 따라 다름 | graph에 따라 다름 | transpose node 포함 가능 | 이름이 아니라 initializer shape와 graph edge를 본다. |
| ViT token | projection weight는 `(out,in)` | 동일 | 동일 | `(N,L,in) -> (N,L,out)` | leading `(N,L)` 축은 유지된다. |
| `Conv2d 1x1` | `(out,in,1,1)` | 구현별 | 구현별 | `NCHW` channel projection | `Linear` adapter를 reshape만 해 load할 수 있는지 검증한다. |

### 9.1 fused `qkv`

fused attention projection이 `(3D,D)` weight라 해도 checkpoint가 항상 `q,k,v` 연속 순서라는 보장은 없다. 다음 선택은 서로 다른 schema다.

- 전체 `(3D,D)`에 하나의 adapter를 붙인다.
- `q`, `k`, `v` slice마다 별도 adapter를 붙인다.
- `q`, `v`만 학습하고 `k` update는 0으로 둔다.

target name만 저장하지 말고 slice order, offset, factor orientation을 저장한다. shape가 맞는 잘못된 slice는 exception 없이 품질을 무너뜨린다.

### 9.2 dtype 승격

base가 FP16, adapter가 FP32라면 split 경로에서 두 출력의 dtype을 어디서 맞출지 결정해야 한다. merge는 다음 순서가 안전한 기준선이다.

1. immutable FP32 base master를 준비한다.
2. $BA$와 scaling을 FP32에서 계산한다.
3. FP32 merged reference를 만든다.
4. serving dtype으로 한 번 cast한다.
5. split FP32, merged FP32, serving output을 계층별·최종 metric으로 비교한다.

작은 $\Delta W$ 원소는 FP16 base에 더할 때 사라질 수 있다. parameter max error만 보지 말고 representative logits와 accuracy도 비교한다.

## 10. 테스트와 디버깅

### 10.1 단위 테스트 최소 집합

- [ ] target module exact name과 type이 allowlist와 같은가?
- [ ] 교체 직후 base와 LoRA output이 tolerance 안에서 같은가?
- [ ] trainable parameter가 `lora_a`, `lora_b`뿐인가?
- [ ] optimizer parameter ID 집합이 trainable parameter ID 집합과 같은가?
- [ ] 첫 backward에서 $\lVert\nabla_A\rVert=0$, $\lVert\nabla_B\rVert>0$인가?
- [ ] 두 번째 backward부터 $A$ gradient가 열리는가?
- [ ] arbitrary leading shape에서 마지막 feature 축만 바뀌는가?
- [ ] rank, $\alpha$, orientation, base hash mismatch를 loader가 거부하는가?
- [ ] split·merged output이 dtype별 tolerance 안에서 같은가?
- [ ] double merge와 unmerged 상태의 unmerge를 거부하는가?
- [ ] immutable base 복원 뒤 base hash가 원본과 같은가?
- [ ] 같은 seed의 loss history, adapter tensor, 평가 metric이 같은가?

### 10.2 증상별 진단

| 증상 | 가능성 높은 원인 | 첫 검사 |
| --- | --- | --- |
| 초기 output이 base와 다름 | $B$ nonzero, scaling 중복, base copy 실패 | `delta_weight().abs().max()`와 base state 비교 |
| loss가 줄지 않음 | $A$, $B$ 둘 다 0, optimizer 누락, graph detach | gradient norm과 optimizer parameter ID |
| base가 학습 후 변함 | bias 미동결, optimizer에 base 포함, in-place merge | 학습 전후 base tensor hash |
| rank를 늘려도 개선 없음 | target module이 틀림, preprocessing 오류, learning rate 문제 | module hook과 adapter output norm |
| merge 후 오차가 큼 | scaling 두 번, transpose 오류, dtype cast | FP32 layer-level split/merge 비교 |
| adapter 교체 뒤 drift 누적 | add/subtract 반복, immutable base 부재 | base-only golden output 재검사 |
| checkpoint load는 되지만 품질 붕괴 | 다른 base revision, fused slice 순서 오류 | manifest hash와 golden input-output |
| 분산 실행만 재현 실패 | rank별 RNG·sampler·reduction 순서 차이 | RNG state와 all-reduce 설정 기록 |

### 10.3 negative test를 먼저 만든다

운영 loader의 중요한 품질은 잘못된 artifact를 **조용히 허용하지 않는 것**이다. 최소한 다음 fixture를 준비한다.

- 올바른 shape지만 다른 base hash
- 같은 module 이름이지만 다른 module type
- 전치된 $A$ 또는 $B$
- rank는 같지만 $\alpha$가 다른 manifest
- pre-scaled factor인데 raw factor라고 표시한 schema
- 일부 target module이 누락된 state
- adapter dtype이 runtime allowlist 밖인 경우

## 11. rank ablation을 공정하게 읽기

오늘 실행 코드의 true update는 $B_{\mathrm{true}}A_{\mathrm{true}}$이고 rank가 최대 2다. rank 2가 이 update를 표현할 수 있는 반면 rank 1은 일반적으로 근사만 가능하다.

그러나 결과를 “rank 2가 항상 우월하다”로 일반화하면 안 된다. 공정한 비교에는 다음을 고정하거나 함께 기록한다.

| 항목 | 오늘의 통제 | 실무에서 추가할 것 |
| --- | --- | --- |
| train/test data | 같은 tensor | split hash, augmentation seed |
| initialization seed | 17 | rank별 initializer scale |
| optimizer | AdamW, 같은 learning rate | scheduler, betas, epsilon |
| update budget | 301 step | example/token 수와 wall-clock |
| scaling | $\alpha/r=1$ | rsLoRA 등 다른 convention |
| target module | classifier 하나 | module별 rank와 총 parameter 수 |
| metric | logit MSE, accuracy | calibration, base regression, latency |

rank가 커지면 trainable parameter, optimizer state와 unmerged compute가 늘어난다. validation 성능이 같다면 더 작은 rank가 배포상 유리할 수 있다.

## 12. 성능·메모리·수치 안정성

### 12.1 unmerged 연산량

base matrix multiply의 곱셈량을 대략 $Md_{\mathrm{in}}d_{\mathrm{out}}$라 하면 adapter 추가량은 다음과 같다.

$$
Mrd_{\mathrm{in}}
+
Mrd_{\mathrm{out}}
$$

상대적인 산술 비율은 다음과 같다.

$$
\rho
=
\frac{r(d_{\mathrm{in}}+d_{\mathrm{out}})}
{d_{\mathrm{in}}d_{\mathrm{out}}}
$$

작은 GEMM 두 개는 kernel launch와 낮은 hardware utilization 때문에 이 비율보다 더 비쌀 수 있다. batch, token 수, rank, target device별로 p50·p95를 측정한다.

### 12.2 무엇이 줄고 무엇이 남는가

줄어드는 항목은 trainable gradient, optimizer state, distributed gradient communication, adapter checkpoint다. 남는 항목은 frozen base weight, base forward activation, adapter bottleneck activation, kernel workspace다.

gradient checkpointing은 activation을 줄이지만 recomputation을 늘린다. QLoRA 계열은 base storage를 더 줄일 수 있지만 dequantization compute, quantization metadata와 별도 수치 오차를 추가한다.

### 12.3 수치 안정성 검사

- $\lVert A\rVert_F$, $\lVert B\rVert_F$, $\lVert\Delta W\rVert_F$를 layer별로 기록한다.
- adapter output과 base output norm 비율을 감시한다.
- FP16에서는 overflow뿐 아니라 작은 update의 underflow·rounding loss를 확인한다.
- merge tolerance는 dtype과 layer 크기에 근거해 정하고 무작정 넓히지 않는다.
- NaN·Inf가 발견되면 loss scale, learning rate, input norm, adapter scale 순으로 좁힌다.

## 13. 실무 실패 사례

### 사례 1: bias만 학습했다

원본 코드처럼 base weight만 freeze하고 bias는 남겼다. optimizer가 전체 `model.parameters()`를 받아 loss는 줄었지만, adapter는 parameter group에서 누락되어 있었다.

**예방:** trainable name 집합과 optimizer parameter ID 집합을 학습 시작 전에 equality assertion으로 고정한다.

### 사례 2: 같은 shape의 다른 base에 붙였다

adapter와 target weight shape가 같아 load가 성공했지만 base revision이 달랐다. exception은 없고 accuracy만 급락했다.

**예방:** content hash, exact revision, preprocessing revision을 manifest에 넣고 하나라도 다르면 거부한다.

### 사례 3: scaling을 두 번 적용했다

학습 framework가 scaled $B$를 저장했는데 serving loader가 다시 $\alpha/r$를 곱했다. 작은 rank에서는 문제가 눈에 띄지 않다가 큰 $\alpha$에서 logits가 포화됐다.

**예방:** factor가 raw인지 pre-scaled인지 schema로 구분하고 reference $\lVert\Delta W\rVert_F$를 저장한다.

### 사례 4: FP16 merge·unmerge가 base를 오염시켰다

adapter hot-swap 때 동일 FP16 weight에 delta를 반복해서 더하고 뺐다. 시간이 지나 adapter를 꺼도 base-only golden과 달라졌다.

**예방:** immutable base에서 매번 merged artifact를 새로 만들거나 adapter를 split 경로로 유지한다.

### 사례 5: target 이름 규칙이 너무 넓었다

`name.endswith("proj")` 규칙이 attention output뿐 아니라 classifier projection까지 교체했다. parameter 수는 늘었고 학습은 진행됐지만 비교 실험의 target이 달라졌다.

**예방:** exact allowlist, module type, original shape, replacement count를 dry-run artifact로 남긴다.

### 사례 6: adapter-only checkpoint로 exact resume를 기대했다

$A$, $B$만 저장하고 AdamW moment와 RNG state를 버렸다. 같은 global step에서 재시작했지만 loss trajectory가 달라졌다.

**예방:** 배포 artifact와 resume checkpoint를 별도 schema로 관리한다.

## 14. 배포 선택과 ONNX 계약

### 14.1 merged artifact

장점은 graph가 원래 `Gemm` 또는 `MatMul` 하나로 돌아가 runtime 최적화가 단순하다는 것이다. 단점은 adapter마다 전체 model artifact가 필요하고 hot-swap 비용이 커진다는 것이다.

배포 단계는 다음처럼 고정한다.

1. base와 adapter manifest를 strict 검증한다.
2. FP32에서 $sBA$를 계산한다.
3. immutable FP32 base에 한 번 merge한다.
4. representative input으로 split reference와 비교한다.
5. 필요하면 calibration 후 serving dtype으로 quantize한다.
6. ONNX export 뒤 initializer hash와 graph output을 다시 비교한다.

### 14.2 dynamic adapter graph

base 경로와 두 adapter matmul을 graph에 남기면 adapter tensor만 교체할 수 있다. 대신 runtime이 작은 GEMM을 효율적으로 처리해야 하며 rank가 engine build-time shape로 고정될 수 있다.

ONNX에서 확인할 항목은 다음과 같다.

- initializer의 실제 logical shape와 dtype
- `Transpose`, `MatMul`, `Gemm`의 연결 순서
- scaling constant가 정확히 한 번만 존재하는지
- batch와 token 축의 dynamic dimension
- constant folding이 교체할 adapter를 initializer로 굳히지 않았는지
- CPU·GPU execution provider의 output tolerance

현재 로컬에 `onnx`와 `onnxruntime`이 없다면 export 성공을 주장하지 않는다. PyTorch split·merge parity를 대체 검증으로 남기고 target runtime 검증을 배포 gate로 유지한다.

### 14.3 운영 모니터링

request에는 개인정보를 남기지 않는 범위에서 base revision, adapter ID·revision, scale, merged artifact hash를 기록한다. adapter별로 다음을 분리 집계한다.

- load 거부와 base hash mismatch 수
- task accuracy, calibration, base-only regression
- p50·p95 latency와 peak memory
- NaN·Inf, output norm drift와 saturation
- rollback 횟수와 실패한 adapter revision

긴급 rollback은 새 merge의 역연산이 아니라 검증된 immutable base artifact로 라우팅한다.

## 16. 연습문제

### 문제 1

$d_{\mathrm{in}}=768$, $d_{\mathrm{out}}=2304$, $r=8$인 fused `qkv` projection에서 full weight와 LoRA trainable parameter 수를 구하라. bias는 제외한다.

### 문제 2

$A$는 random, $B=0$일 때 첫 backward에서 $A$ gradient가 0이고 $B$ gradient는 일반적으로 nonzero인 이유를 식으로 설명하라.

### 문제 3

입력이 `(N,L,D)=(4,197,768)`, rank 8, 출력 2304일 때 bottleneck과 adapter 출력 shape를 쓰라.

### 문제 4

adapter tensor shape가 모두 맞는데도 다른 base revision이면 load를 거부해야 하는 이유를 쓰라.

### 문제 5

FP16 weight에 delta를 반복 add/subtract하지 않고 adapter hot-swap을 구현하는 방법 두 가지를 제안하라.

### 문제 6

rank 4와 rank 16 실험의 validation accuracy가 같았다. 배포 결정을 위해 추가로 비교할 항목 네 가지를 쓰라.

## 17. 해답

### 해답 1

full weight는 다음과 같다.

$$
768\times2304
=
1{,}769{,}472
$$

LoRA parameter는 다음과 같다.

$$
8(768+2304)
=
24{,}576
$$

따라서 이 weight의 trainable parameter만 비교하면 72배 적다.

### 해답 2

$A$ gradient에는 $B$가 곱해지므로 $B=0$이면 0이다. 반면 $B$ gradient는 $G^\top(XA^\top)$에 비례하고 $A$와 입력이 nonzero이면 첫 backward부터 nonzero가 될 수 있다.

### 해답 3

입력의 leading dimension은 유지된다. bottleneck은 `(4,197,8)`, $B$까지 지난 adapter 출력은 `(4,197,2304)`다.

### 해답 4

LoRA factor는 특정 $W_0$ 주변에서 학습한 변화량이다. shape가 같은 다른 $W_0$에 더하면 수학적으로 실행은 되지만 학습한 함수와 다른 함수가 된다. base hash와 golden output이 필요하다.

### 해답 5

첫째, immutable FP32 base에서 adapter마다 merged weight를 새로 만들고 serving dtype으로 한 번 cast한다. 둘째, base는 그대로 두고 adapter를 별도 split matmul 경로로 실행한다.

### 해답 6

총 trainable parameter와 optimizer memory, unmerged p95 latency, adapter artifact size, base-only regression, calibration, merge error 중 최소 네 가지를 비교한다. 품질이 같으면 더 작은 rank가 운영 비용에서 유리할 가능성이 높다.

## 핵심 요약

1. LoRA 구현의 첫 계약은 `(out,in)`, `(r,in)`, `(out,r)` shape와 $s=\alpha/r$를 한 convention으로 고정하는 것이다.
2. base weight뿐 아니라 bias, optimizer parameter group, target module 목록까지 freeze 경계에 포함한다.
3. $A$ random·$B=0$은 초기 함수를 보존하고 첫 step의 gradient gate를 $B$부터 연다.
4. rank ablation은 데이터, seed, optimizer, step budget, scaling과 target module을 통제해야 해석할 수 있다.
5. adapter-only 배포 artifact와 optimizer·RNG까지 포함한 exact-resume checkpoint는 다른 산출물이다.
6. merge는 상태 머신으로 관리하고, unmerge는 낮은 precision의 subtract가 아니라 immutable base 복원을 우선한다.
7. manifest는 base hash, exact target, rank, $\alpha$, orientation, dtype과 schema version을 검증해야 한다.
8. ONNX와 양자화 배포는 export 성공이 아니라 split·merged·runtime output과 task metric parity로 완료한다.
