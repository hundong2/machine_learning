## 오늘의 질문

Spatial Pyramid Pooling(SPP)은 여러 크기의 adaptive pooling 결과를 이어 붙여 가변 공간 크기를 고정 길이 벡터로 바꾼다. 이 한 문장만으로 모델을 구현할 수는 있지만, 학습·체크포인트·다른 언어의 추론 코드까지 안전하게 연결하려면 더 엄격한 질문이 필요하다.

- `(1, 2, 4)`와 `(4, 2, 1)`은 길이가 같은데 왜 서로 호환되지 않는가?
- 최종 벡터의 인덱스 하나가 어느 level, channel, bin을 뜻하는지 어떻게 계산하는가?
- 겹치는 adaptive bin과 여러 level을 통과한 gradient가 실제로 누적되는가?
- 입력 높이·너비가 바뀌어도 forward와 backward가 독립 구현과 일치하는가?
- 세밀한 level을 추가한 정확도 향상이 파라미터·메모리 증가를 정당화하는가?

오늘은 SPP를 단순한 layer가 아니라 **순서, shape, 값, gradient를 모두 포함하는 실행 계약**으로 구현한다. 1회차 문서가 adaptive bin의 직관과 기본 shape를 다뤘다면, 이번에는 독립 NumPy oracle, PyTorch module, property test, 체크포인트 검증, 재현 가능한 학습·평가 ablation을 하나의 흐름으로 묶는다.

## 1. 원본과 1회차에서 이어받을 것

원본 `02-03.SPP.md`는 SPP-Net의 역사, 여러 격자의 pooling, 고정 길이 FC 입력, 객체 탐지로의 연결을 설명한다. 원본 예제의 핵심 구조는 다음과 같다.

1. 특징 맵을 여러 `output_size`로 adaptive pooling한다.
2. 각 결과를 batch별로 펼친다.
3. level 결과를 지정한 순서대로 concatenate한다.

이 구조는 맞다. 다만 원본의 다음 설명은 구현 계약으로 그대로 사용하면 안 된다.

> 원문 설명: $k=\lceil a/n \rceil$, $s=\lfloor a/n \rfloor$인 고정 pooling이면 임의의 $a$를 항상 정확히 $n$칸으로 만든다.

$a=10$, $n=4$이면 $k=3$, $s=2$이며 padding 없는 표준 pooling 출력은 5칸이다.

$$
\left\lfloor \frac{10-3}{2} \right\rfloor + 1 = 5
$$

따라서 오늘 구현은 kernel과 stride를 추정하지 않고 목표 출력 크기를 연산자에 직접 전달한다. 한 축의 bin $i$는 다음 경계를 쓴다.

$$
s(i; A,n)=\left\lfloor \frac{iA}{n} \right\rfloor
$$

$$
e(i; A,n)=\left\lceil \frac{(i+1)A}{n} \right\rceil
$$

1회차 SPP 문서는 이 경계와 출력 길이, max·average의 차이, 기본 Python/C++/C# 예제를 다뤘다. 오늘은 같은 $4 \times 4$ 수작업 예제를 반복하지 않고 다음 구현 공백을 채운다.

- 직렬화된 feature의 offset을 명시한다.
- backward를 독립적으로 구현한다.
- level permutation을 checkpoint 호환성 오류로 취급한다.
- 나누어떨어지지 않는 여러 shape를 자동 생성해 검사한다.
- 위치 민감 합성 데이터에서 level 선택을 ablation한다.

## 2. SPP를 직렬화 계약으로 정의하기

### 2.1 기호 정의

입력은 NCHW layout의 tensor라고 하자.

$$
X \in \mathbb{R}^{N \times C \times H \times W}
$$

$L$개의 level을 순서가 있는 tuple로 둔다.

$$
\mathcal{G}=((p_0,q_0),(p_1,q_1),\ldots,(p_{L-1},q_{L-1}))
$$

$p_l$과 $q_l$은 level $l$의 출력 높이와 너비다. 전통적인 정사각형 SPP `(1, 2, 4)`는 다음의 축약이다.

$$
\mathcal{G}=((1,1),(2,2),(4,4))
$$

level $l$의 pooling 결과를 $P^{(l)}$이라 하면 shape은 다음과 같다.

$$
P^{(l)} \in \mathbb{R}^{N \times C \times p_l \times q_l}
$$

최종 feature 길이는 다음과 같다.

$$
D=C\sum_{l=0}^{L-1}p_lq_l
$$

### 2.2 level offset

level $l$이 최종 벡터에서 시작하는 위치를 $o_l$로 정의한다.

$$
o_0=0
$$

$$
o_l=C\sum_{r=0}^{l-1}p_rq_r \qquad (l>0)
$$

level 내부를 `channel -> row -> column` 순서로 펼치면 channel $c$, bin $(i,j)$의 최종 index는 다음과 같다.

$$
k(l,c,i,j)=o_l+c(p_lq_l)+iq_l+j
$$

이 식은 단순한 설명이 아니다. Python, C++, C#, ONNX 후처리가 모두 공유해야 할 ABI에 가깝다.

예를 들어 $C=2$, level 순서가 `((2, 2), (1, 1))`이면 다음과 같다.

| level $l$ | grid | 원소 수 | 시작 offset $o_l$ | 끝 exclusive |
| ---: | --- | ---: | ---: | ---: |
| 0 | $2 \times 2$ | $2 \times 4=8$ | 0 | 8 |
| 1 | $1 \times 1$ | $2 \times 1=2$ | 8 | 10 |

`((1, 1), (2, 2))`로 순서를 바꾸면 길이 $D=10$은 같지만 offset과 모든 feature 의미가 달라진다. shape test만으로는 이 오류를 잡을 수 없다.

### 2.3 순서는 set이 아니라 schema다

level은 수학적 집합처럼 정렬해도 되는 값이 아니다. 다음 항목을 하나의 schema로 versioning해야 한다.

```text
schema_version=spp-v2
layout=NCHW
pool=max
levels=2x2,1x1
flatten=level,channel,row,column
dtype=float32
features=10
```

체크포인트를 읽을 때 `features`만 비교해서는 부족하다. `levels`와 `flatten`까지 일치해야 한다.

## 3. Tensor shape와 offset 추적

batch $N=3$, channel $C=8$, level `((1, 1), (2, 3), (4, 2))`를 사용해 보자. 입력 공간 크기는 서로 달라도 된다.

| 단계 | 입력 A | 입력 B | 계약 |
| --- | --- | --- | --- |
| backbone 출력 | `(3, 8, 9, 13)` | `(3, 8, 15, 11)` | NCHW |
| level 0 | `(3, 8, 1, 1)` | 동일 | offset 0 |
| level 1 | `(3, 8, 2, 3)` | 동일 | offset 8 |
| level 2 | `(3, 8, 4, 2)` | 동일 | offset 56 |
| concatenate | `(3, 120)` | `(3, 120)` | $8(1+6+8)$ |
| classifier | `(3, K)` | `(3, K)` | 같은 weight 사용 |

offset 계산은 다음과 같다.

$$
o_0=0
$$

$$
o_1=8(1)=8
$$

$$
o_2=8(1+6)=56
$$

마지막 level의 channel 3, row 2, column 1은 다음 index에 저장된다.

$$
k(2,3,2,1)=56+3(4 \times 2)+2(2)+1=85
$$

이처럼 offset 표와 단일 index 계산을 테스트 fixture에 넣으면 언어 간 flatten 오류를 빠르게 찾을 수 있다.

## 4. Forward와 backward 수학

### 4.1 Forward

level $l$의 bin $(i,j)$가 포함하는 영역을 $B^{(l)}_{ij}$라 하자. max SPP 출력은 다음과 같다.

$$
P^{(l)}_{ncij}=\max_{(h,w)\in B^{(l)}_{ij}}X_{nchw}
$$

최종 벡터 $Z$는 level 순서대로 flatten한 결과다.

$$
Z_{n,k(l,c,i,j)}=P^{(l)}_{ncij}
$$

### 4.2 Backward

각 bin에서 선택된 argmax 위치를 $a(l,n,c,i,j)$라 하자. upstream gradient를 $G=\partial \mathcal{L}/\partial Z$로 두면 입력 gradient는 선택된 모든 경로의 합이다.

$$
\frac{\partial \mathcal{L}}{\partial X_{nchw}}
=
\sum_{l,c',i,j}
G_{n,k(l,c',i,j)}
\mathbf{1}[c'=c]
\mathbf{1}[a(l,n,c',i,j)=(h,w)]
$$

같은 위치가 겹치는 두 bin의 max이거나 여러 level에서 반복 선택되면 gradient가 누적된다. 구현에서 단순 대입을 사용하면 마지막 gradient만 남는다. 그래서 NumPy oracle은 `np.add.at`으로 scatter-add해야 한다.

### 4.3 Tie와 미분 가능성

한 bin의 최대값이 여러 위치에 존재하면 max는 그 점에서 미분 가능하지 않다. framework는 내부 규칙에 따라 한 argmax를 선택한다. 따라서 backward golden test에는 모든 값이 서로 다른 입력을 사용한다. tie 동작은 별도의 backend contract test로 분리한다.

## 5. 독립 NumPy forward·backward oracle

다음 코드는 **실행 가능한 독립 예제**다. framework pooling을 호출하지 않고 경계, offset, argmax, scatter-add를 직접 구현한다.

```python
import math
from dataclasses import dataclass

import numpy as np


Grid = tuple[int, int]


@dataclass(frozen=True)
class SppSpec:
    levels: tuple[Grid, ...]
    pool: str = "max"
    layout: str = "NCHW"
    flatten: str = "level,channel,row,column"

    def validate(self) -> None:
        if not self.levels:
            raise ValueError("levels must not be empty")
        if any(ph <= 0 or pw <= 0 for ph, pw in self.levels):
            raise ValueError("every grid dimension must be positive")
        if len(set(self.levels)) != len(self.levels):
            raise ValueError("duplicate levels are forbidden")
        if self.pool != "max" or self.layout != "NCHW":
            raise ValueError("this oracle supports NCHW max pooling only")

    def features(self, channels: int) -> int:
        self.validate()
        return channels * sum(ph * pw for ph, pw in self.levels)

    def offsets(self, channels: int) -> tuple[int, ...]:
        cursor = 0
        result = []
        for ph, pw in self.levels:
            result.append(cursor)
            cursor += channels * ph * pw
        return tuple(result)


def _bounds(index: int, size: int, bins: int) -> tuple[int, int]:
    start = (index * size) // bins
    end = math.ceil((index + 1) * size / bins)
    return start, end


def spp_forward_numpy(
    x: np.ndarray, spec: SppSpec
) -> tuple[np.ndarray, np.ndarray]:
    """Return flat output and flat input indices selected by max.

    x: (N, C, H, W)
    output, argmax: (N, D)
    """
    spec.validate()
    if x.ndim != 4:
        raise ValueError("expected NCHW rank-4 input")
    batch, channels, height, width = x.shape
    if max(ph for ph, _ in spec.levels) > height:
        raise ValueError("level height exceeds input height")
    if max(pw for _, pw in spec.levels) > width:
        raise ValueError("level width exceeds input width")

    output = np.empty((batch, spec.features(channels)), dtype=x.dtype)
    argmax = np.empty(output.shape, dtype=np.int64)
    cursor = 0

    for out_h, out_w in spec.levels:
        for channel in range(channels):
            for i in range(out_h):
                hs, he = _bounds(i, height, out_h)
                for j in range(out_w):
                    ws, we = _bounds(j, width, out_w)
                    for n in range(batch):
                        region = x[n, channel, hs:he, ws:we]
                        local = int(region.argmax())
                        local_h, local_w = divmod(local, we - ws)
                        h, w = hs + local_h, ws + local_w
                        output[n, cursor] = x[n, channel, h, w]
                        argmax[n, cursor] = np.ravel_multi_index(
                            (n, channel, h, w), x.shape
                        )
                    cursor += 1

    return output, argmax


def spp_backward_numpy(
    grad_output: np.ndarray, argmax: np.ndarray, input_shape: tuple[int, ...]
) -> np.ndarray:
    if grad_output.shape != argmax.shape:
        raise ValueError("gradient and argmax shapes differ")
    grad_input = np.zeros(input_shape, dtype=grad_output.dtype)
    np.add.at(grad_input.ravel(), argmax.ravel(), grad_output.ravel())
    return grad_input


spec = SppSpec(levels=((2, 2), (1, 1)))
x = np.stack(
    [np.arange(15), np.arange(100, 115)], axis=0
).reshape(1, 2, 3, 5).astype(np.float64)
z, chosen = spp_forward_numpy(x, spec)
expected = np.array(
    [[7, 9, 12, 14, 107, 109, 112, 114, 14, 114]],
    dtype=np.float64,
)
np.testing.assert_array_equal(z, expected)
assert spec.offsets(channels=2) == (0, 8)

upstream = np.arange(1, z.size + 1, dtype=np.float64).reshape(z.shape)
dx = spp_backward_numpy(upstream, chosen, x.shape)
assert dx.sum() == upstream.sum()
assert dx[0, 0, 2, 4] == 4 + 9
assert dx[0, 1, 2, 4] == 8 + 10
print("NumPy golden:", z.tolist())
print("offsets:", spec.offsets(channels=2), "gradient sum:", dx.sum())
```

예상 핵심 출력은 `offsets: (0, 8)`과 `gradient sum: 55.0`이다. 위치 `(2,4)`는 $2 \times 2$ level의 마지막 bin과 $1 \times 1$ level에서 모두 최대이므로 gradient가 더해진다.

## 6. PyTorch 구현과 계약 검증

다음 코드는 **실행 가능하며 앞의 Python 블록과 같은 process에서 이어서 실행**한다. `SppSpec`을 module의 명시적 설정으로 사용하고, shape와 입력 dtype을 검사한다.

```python
from collections.abc import Sequence

import torch
from torch import Tensor, nn
from torch.nn import functional as F


class OrderedSpp(nn.Module):
    def __init__(self, levels: Sequence[Grid]) -> None:
        super().__init__()
        self.spec = SppSpec(tuple((int(h), int(w)) for h, w in levels))
        self.spec.validate()

    def output_features(self, channels: int) -> int:
        return self.spec.features(channels)

    def contract(self, channels: int) -> dict[str, object]:
        return {
            "schema_version": "spp-v2",
            "layout": self.spec.layout,
            "pool": self.spec.pool,
            "levels": [list(level) for level in self.spec.levels],
            "flatten": self.spec.flatten,
            "features": self.output_features(channels),
        }

    def forward(self, x: Tensor) -> Tensor:
        if x.ndim != 4:
            raise ValueError(f"expected NCHW rank 4, got {tuple(x.shape)}")
        if not x.is_floating_point():
            raise TypeError("SPP input must be floating point")
        height, width = x.shape[-2:]
        if any(ph > height or pw > width for ph, pw in self.spec.levels):
            raise ValueError("a level exceeds the input feature-map size")
        parts = [
            F.adaptive_max_pool2d(x, level).flatten(start_dim=1)
            for level in self.spec.levels
        ]
        return torch.cat(parts, dim=1)


def assert_contract_equal(expected: dict[str, object], actual: dict[str, object]) -> None:
    if expected != actual:
        differing = sorted(key for key in expected if expected[key] != actual.get(key))
        raise RuntimeError(f"incompatible SPP contract fields: {differing}")


layer = OrderedSpp(((2, 2), (1, 1))).double()
x_torch = torch.from_numpy(x.copy()).requires_grad_(True)
actual = layer(x_torch)
np.testing.assert_array_equal(actual.detach().numpy(), z)
actual.backward(torch.from_numpy(upstream))
np.testing.assert_array_equal(x_torch.grad.numpy(), dx)

saved = layer.contract(channels=2)
permuted = OrderedSpp(((1, 1), (2, 2))).contract(channels=2)
try:
    assert_contract_equal(saved, permuted)
except RuntimeError as error:
    assert "levels" in str(error)
else:
    raise AssertionError("level permutation must be rejected")

print("PyTorch forward/backward golden passed")
print("contract mismatch rejected")
```

### 6.1 왜 `flatten(start_dim=1)`인가

`flatten(start_dim=1)`은 batch 축을 보존하면서 각 level의 `(C, p_l, q_l)`을 C-row-column 순서로 펼친다. `x.view(batch, -1)`도 contiguous tensor에서는 같지만, layout 변환 뒤 비연속 tensor에서 실패할 수 있다. `reshape`는 필요하면 복사하므로 동작은 안전하지만 숨은 복사 비용을 profiler에서 확인해야 한다.

### 6.2 체크포인트에 contract를 함께 저장하기

다음은 **설명용 코드**다. 실제 프로젝트에서는 JSON schema나 typed config로 관리한다.

```python
checkpoint = {
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "spp_contract": model.spp.contract(channels=model.channels),
    "epoch": epoch,
}
torch.save(checkpoint, "checkpoint.pt")

loaded = torch.load("checkpoint.pt", map_location="cpu", weights_only=True)
assert_contract_equal(loaded["spp_contract"], model.spp.contract(model.channels))
model.load_state_dict(loaded["model"])
```

weight shape가 같더라도 level 순서가 다르면 예측 의미가 달라진다. 그래서 `load_state_dict` 앞에서 contract를 검사한다.

## 7. 가변 shape property test와 gradient 교차 검증

단일 golden vector는 순서 오류를 잘 잡지만 경계 반올림의 모든 경우를 대표하지 않는다. 다음 코드는 **실행 가능하며 앞 블록들과 이어서 실행**한다. $H,W \in [4,9]$의 36개 shape에서 두 batch, 두 channel, 세 level의 forward와 backward를 비교한다.

```python
rng = np.random.default_rng(20260810)
property_cases = 0

for height in range(4, 10):
    for width in range(4, 10):
        spec_case = SppSpec(((1, 1), (2, 3), (4, 2)))
        # 연속 분포에 작은 위치별 offset을 더해 tie 확률을 제거한다.
        values = rng.normal(size=(2, 2, height, width))
        values += np.arange(values.size).reshape(values.shape) * 1e-7
        values = values.astype(np.float64)

        expected_z, indices = spp_forward_numpy(values, spec_case)
        grad_z = rng.normal(size=expected_z.shape).astype(np.float64)
        expected_dx = spp_backward_numpy(grad_z, indices, values.shape)

        tensor = torch.from_numpy(values.copy()).requires_grad_(True)
        torch_z = OrderedSpp(spec_case.levels).double()(tensor)
        torch_z.backward(torch.from_numpy(grad_z))

        np.testing.assert_allclose(torch_z.detach().numpy(), expected_z, rtol=0, atol=0)
        # 겹친 경로의 부동소수점 덧셈 순서는 구현마다 다를 수 있다.
        np.testing.assert_allclose(tensor.grad.numpy(), expected_dx, rtol=0, atol=1e-12)
        assert torch_z.shape == (2, spec_case.features(channels=2))
        assert np.isfinite(tensor.grad.numpy()).all()
        property_cases += 1

print(f"property cases passed: {property_cases}")
```

36개의 shape 각각에서 실제로는 다음을 동시에 검사한다.

- $2 \times 2$개의 batch·channel 조합
- 정사각형과 직사각형 output grid
- 나누어떨어지는 축과 나머지가 있는 축
- level별 flatten 순서
- 겹치는 bin과 여러 level의 gradient 누적

Forward max 값은 같은 입력에서 정확히 일치해야 한다. 반면 backward는 여러 경로의 부동소수점 gradient를 더하는 순서가 다를 수 있으므로 `float64`에서 절대 오차 `1e-12`를 허용한다. 이 허용 오차는 첫 실행에서 관측한 최대 차이 약 $4.44 \times 10^{-16}$보다 충분히 크면서, 누적 누락 같은 실제 오류는 숨기지 않는다.

## 9. 완전한 학습·검증·평가 ablation

### 9.1 실험 질문

전역 max level `(1,)`은 강한 신호의 **존재**는 알지만 위치는 잃는다. 밝은 점이 어느 사분면에 있는지를 분류하는 합성 문제에서는 `(2,2)` level이 유용해야 한다. `(4,4)`까지 추가하면 더 많은 feature와 파라미터를 사용하지만, 사분면 분류에는 불필요할 수 있다.

이 실험은 SPP가 항상 우수함을 증명하지 않는다. level이 과제의 공간 해상도와 맞는지, 추가 feature가 검증 성능을 실제로 개선하는지를 재현 가능한 방식으로 확인하는 최소 ablation이다.

### 9.2 실행 가능한 전체 코드

다음 코드는 **실행 가능하며 `OrderedSpp` 정의 뒤에서 실행**한다. dataset 생성, split, train, validation, best checkpoint 복원, test 평가를 모두 포함한다.

```python
import copy
import random

import numpy as np
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset


SEED = 20260810


def seed_everything(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.use_deterministic_algorithms(True)


def make_quadrant_data(samples: int, seed: int) -> tuple[torch.Tensor, torch.Tensor]:
    generator = torch.Generator().manual_seed(seed)
    images = torch.randn(samples, 1, 8, 8, generator=generator) * 0.03
    labels = torch.arange(samples) % 4
    starts = ((1, 1), (1, 5), (5, 1), (5, 5))
    jitter = torch.randint(0, 2, (samples, 2), generator=generator)
    for index, label in enumerate(labels.tolist()):
        row, column = starts[label]
        row += int(jitter[index, 0])
        column += int(jitter[index, 1])
        images[index, 0, row, column] = 1.0
    permutation = torch.randperm(samples, generator=generator)
    return images[permutation], labels[permutation]


class SppClassifier(nn.Module):
    def __init__(self, levels: tuple[Grid, ...]) -> None:
        super().__init__()
        self.spp = OrderedSpp(levels)
        self.classifier = nn.Linear(self.spp.output_features(1), 4)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.classifier(self.spp(x))


@torch.no_grad()
def evaluate(model: nn.Module, loader: DataLoader) -> tuple[float, float]:
    model.eval()
    loss_sum = 0.0
    correct = 0
    count = 0
    for images, labels in loader:
        logits = model(images)
        loss_sum += nn.functional.cross_entropy(logits, labels, reduction="sum").item()
        correct += (logits.argmax(dim=1) == labels).sum().item()
        count += labels.numel()
    return loss_sum / count, correct / count


def train_one(levels: tuple[Grid, ...]) -> dict[str, float | int]:
    seed_everything(SEED)
    images, labels = make_quadrant_data(800, SEED)
    train_ds = TensorDataset(images[:560], labels[:560])
    valid_ds = TensorDataset(images[560:680], labels[560:680])
    test_ds = TensorDataset(images[680:], labels[680:])

    loader_generator = torch.Generator().manual_seed(SEED)
    train_loader = DataLoader(
        train_ds, batch_size=64, shuffle=True, generator=loader_generator
    )
    valid_loader = DataLoader(valid_ds, batch_size=120, shuffle=False)
    test_loader = DataLoader(test_ds, batch_size=120, shuffle=False)

    model = SppClassifier(levels)
    optimizer = torch.optim.SGD(model.parameters(), lr=0.4)
    best_loss = float("inf")
    best_state = None

    for _epoch in range(35):
        model.train()
        for batch_images, batch_labels in train_loader:
            optimizer.zero_grad(set_to_none=True)
            loss = nn.functional.cross_entropy(model(batch_images), batch_labels)
            loss.backward()
            optimizer.step()

        valid_loss, _ = evaluate(model, valid_loader)
        if valid_loss < best_loss:
            best_loss = valid_loss
            best_state = copy.deepcopy(model.state_dict())

    assert best_state is not None
    model.load_state_dict(best_state)
    test_loss, test_accuracy = evaluate(model, test_loader)
    parameters = sum(parameter.numel() for parameter in model.parameters())
    return {
        "features": model.spp.output_features(1),
        "parameters": parameters,
        "valid_loss": best_loss,
        "test_loss": test_loss,
        "test_accuracy": test_accuracy,
    }


ablations = {
    "global": ((1, 1),),
    "quadrant": ((1, 1), (2, 2)),
    "fine": ((1, 1), (2, 2), (4, 4)),
}
results = {name: train_one(levels) for name, levels in ablations.items()}

repeat = train_one(ablations["quadrant"])
assert results["quadrant"] == repeat
assert results["global"]["test_accuracy"] < 0.40
assert results["quadrant"]["test_accuracy"] > 0.95
assert results["fine"]["parameters"] > results["quadrant"]["parameters"]
for name, metrics in results.items():
    print(name, metrics)
```

### 9.3 결과를 읽는 법

실행 전 기대한 정성적 결과는 다음과 같다.

| 설정 | feature 수 | Linear 파라미터 | 예상 판단 |
| --- | ---: | ---: | --- |
| `(1)` | 1 | 8 | 위치 소실, chance 수준 |
| `(1,2)` | 5 | 24 | 사분면을 구분하기에 충분 |
| `(1,2,4)` | 21 | 88 | 정확도 이득 없이 비용 증가 가능 |

Linear 파라미터는 bias를 포함해 다음과 같다.

$$
P=KD+K
$$

여기서는 $K=4$다. 실제 실행 숫자는 환경의 PyTorch 버전에 따라 마지막 소수점이 달라질 수 있지만, seed와 deterministic algorithm을 고정한 같은 환경에서는 결과 dictionary가 정확히 재현되어야 한다.

오늘의 로컬 환경에서 실제 실행한 결과는 다음과 같다. `quadrant` 설정을 한 번 더 처음부터 실행했고 결과 dictionary가 정확히 일치했다.

| 설정 | feature | 파라미터 | best validation loss | test loss | test accuracy |
| --- | ---: | ---: | ---: | ---: | ---: |
| `global` | 1 | 8 | 1.384963 | 1.396663 | 0.183333 |
| `quadrant` | 5 | 24 | 0.029655 | 0.029842 | 1.000000 |
| `fine` | 21 | 88 | 0.022884 | 0.022987 | 1.000000 |

`fine`은 loss를 조금 더 낮췄지만 test accuracy는 `quadrant`와 같고 파라미터는 24개에서 88개로 늘었다. 이 작은 실험에서는 `(1,2)`가 정확도와 크기의 더 단순한 절충안이다. 실제 모델에서는 여러 seed와 latency까지 확인한 뒤 결정해야 한다.

### 9.4 실험 설계의 한계

- 합성 데이터는 밝은 점의 위치만으로 정답을 만든다.
- backbone이 없으므로 representation learning의 변수를 제거했다.
- `(4,4)`가 불필요하다는 결론은 이 과제에만 해당한다.
- 실제 데이터에서는 여러 seed의 평균·표준편차와 confidence interval이 필요하다.
- 파라미터 수 외에 target device latency와 memory를 함께 측정해야 한다.

## 10. C++17 golden vector 구현

다음은 **실행 가능한 C++17 예제**다. 두 channel의 $3 \times 5$ 입력을 level `(2,2)`, `(1,1)` 순서로 직렬화한다. 외부 ML library 없이 index 계약만 검증한다.

```cpp
#include <algorithm>
#include <cassert>
#include <cstddef>
#include <iostream>
#include <vector>

std::size_t ceil_div(std::size_t value, std::size_t divisor) {
    return (value + divisor - 1) / divisor;
}

void append_level_max(
    const std::vector<double>& x,
    std::size_t channels,
    std::size_t height,
    std::size_t width,
    std::size_t out_h,
    std::size_t out_w,
    std::vector<double>& output) {
    for (std::size_t c = 0; c < channels; ++c) {
        for (std::size_t i = 0; i < out_h; ++i) {
            const std::size_t hs = i * height / out_h;
            const std::size_t he = ceil_div((i + 1) * height, out_h);
            for (std::size_t j = 0; j < out_w; ++j) {
                const std::size_t ws = j * width / out_w;
                const std::size_t we = ceil_div((j + 1) * width, out_w);
                double best = x[(c * height + hs) * width + ws];
                for (std::size_t h = hs; h < he; ++h) {
                    for (std::size_t w = ws; w < we; ++w) {
                        best = std::max(best, x[(c * height + h) * width + w]);
                    }
                }
                output.push_back(best);
            }
        }
    }
}

int main() {
    std::vector<double> x;
    for (int value = 0; value < 15; ++value) x.push_back(value);
    for (int value = 100; value < 115; ++value) x.push_back(value);

    std::vector<double> output;
    append_level_max(x, 2, 3, 5, 2, 2, output);
    const std::size_t second_level_offset = output.size();
    append_level_max(x, 2, 3, 5, 1, 1, output);

    const std::vector<double> expected{
        7, 9, 12, 14, 107, 109, 112, 114, 14, 114
    };
    assert(second_level_offset == 8);
    assert(output == expected);
    std::cout << "C++ golden passed; offset=" << second_level_offset << '\n';
}
```

## 11. C# golden vector 구현

다음은 **실행 가능한 C# 예제**다. C++와 같은 NCHW 메모리와 level 순서를 사용한다.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public static class OrderedSppExample
{
    static int CeilDiv(int value, int divisor)
    {
        return (value + divisor - 1) / divisor;
    }

    static void AppendLevelMax(
        double[] x, int channels, int height, int width,
        int outH, int outW, List<double> output)
    {
        for (int c = 0; c < channels; c++)
        {
            for (int i = 0; i < outH; i++)
            {
                int hs = i * height / outH;
                int he = CeilDiv((i + 1) * height, outH);
                for (int j = 0; j < outW; j++)
                {
                    int ws = j * width / outW;
                    int we = CeilDiv((j + 1) * width, outW);
                    double best = x[(c * height + hs) * width + ws];
                    for (int h = hs; h < he; h++)
                        for (int w = ws; w < we; w++)
                            best = Math.Max(best, x[(c * height + h) * width + w]);
                    output.Add(best);
                }
            }
        }
    }

    public static void Main()
    {
        double[] x = Enumerable.Range(0, 15).Select(v => (double)v)
            .Concat(Enumerable.Range(100, 15).Select(v => (double)v)).ToArray();
        var output = new List<double>();
        AppendLevelMax(x, 2, 3, 5, 2, 2, output);
        int secondLevelOffset = output.Count;
        AppendLevelMax(x, 2, 3, 5, 1, 1, output);

        double[] expected = { 7, 9, 12, 14, 107, 109, 112, 114, 14, 114 };
        if (secondLevelOffset != 8 || !output.SequenceEqual(expected))
            throw new Exception("SPP serialization mismatch");
        Console.WriteLine("C# golden passed; offset=" + secondLevelOffset);
    }
}
```

## 12. 프레임워크 간 shape·layout·dtype 대응

### 12.1 오늘의 실행 검증 상태

- NumPy `2.3.5`와 PyTorch `2.13.0`에서 golden forward·backward, contract mismatch, 36개 가변 shape property case, dependency-free 단위 테스트를 실행해 통과했다.
- 첫 strict backward 비교에서 누적 순서 차이로 최대 약 $4.44 \times 10^{-16}$ 오차를 관측했다. 이를 근거로 `float64` backward 허용 오차를 `1e-12`로 명시했다.
- 완전한 학습·검증·test ablation 세 설정과 `quadrant` 재실행을 통과했다.
- 문서와 같은 C++17 코드를 Apple clang `21.0.0`으로 compile·실행해 `C++ golden passed; offset=8`을 확인했다.
- 문서와 같은 C# 코드를 Microsoft C# compiler `3.9.0`으로 compile하고 Mono에서 실행해 `C# golden passed; offset=8`을 확인했다.
- 로컬 Python 환경에는 `pytest`, `onnx`, `onnxruntime` package가 없다. `pytest` 대신 같은 assertion을 직접 실행했고, ONNX skeleton은 설명용으로만 표시했다. 따라서 export와 target runtime의 수치 일치는 미검증이며 배포 전에 실제 provider에서 검증해야 한다.

### 12.2 대응표

| 환경 | 일반 입력 layout | level 출력 | 기본 flatten 주의 | 권장 검증 |
| --- | --- | --- | --- | --- |
| PyTorch | NCHW | `(N,C,p,q)` | C-row-column | NumPy oracle |
| ONNX Runtime | model graph 계약 | exporter에 따름 | graph의 `Flatten`·`Concat` 축 | intermediate output |
| TensorFlow 계열 | NHWC가 흔함 | `(N,p,q,C)` 가능 | row-column-C가 되기 쉬움 | 명시적 transpose |
| LibTorch C++ | PyTorch와 동일하게 설계 가능 | NCHW | contiguous 여부 | saved golden vector |
| C# ONNX Runtime | flat buffer + shape | model metadata | 배열 자체는 layout을 모름 | input/output metadata |

동일 의미를 유지하려면 NHWC 결과를 바로 flatten하지 말고 NCHW 의미로 transpose한 뒤 직렬화한다.

$$
(N,p,q,C) \xrightarrow{\text{transpose}} (N,C,p,q) \xrightarrow{\text{flatten}} (N,Cpq)
$$

dtype 대응도 계약에 포함한다.

| dtype | 학습 | pooling 특징 | 주의점 |
| --- | --- | --- | --- |
| `float64` | oracle·`gradcheck` | reference에 적합 | 느리고 배포 지원 제한 |
| `float32` | 기본 학습·golden | 보편적 | backend별 작은 차이 가능 |
| `float16` | GPU mixed precision | max 자체는 비교 중심 | activation overflow·`NaN` 감시 |
| `bfloat16` | 지원 accelerator | 넓은 exponent | 낮은 mantissa 정밀도 |
| `int8` | 양자화 추론 | calibration 범위 중요 | padding용 `-inf` 표현 불가 |

max의 출력값은 덧셈 오차가 적지만 argmax가 바뀔 만큼 가까운 값에서는 낮은 정밀도가 gradient 경로와 결과를 바꿀 수 있다.

## 13. 디버깅 플레이북

### 증상 1: feature 길이는 같은데 정확도가 급락한다

가장 먼저 level 순서와 flatten 순서를 확인한다. `(1,2,4)`와 `(4,2,1)`은 같은 길이를 만들기 때문에 Linear weight load도 성공할 수 있다. 증가 수열 golden input과 level별 intermediate output을 비교한다.

### 증상 2: NumPy forward는 맞지만 backward가 다르다

다음 원인을 확인한다.

- tie가 있는 입력을 사용했다.
- 겹치는 bin의 gradient를 대입해 누적을 잃었다.
- level별 cursor를 batch 안에서 잘못 증가시켰다.
- upstream gradient 순서가 final vector schema와 다르다.

고유한 값의 입력과 `np.add.at` oracle로 다시 비교한다.

### 증상 3: 일부 해상도에서만 실패한다

나누어떨어지는 shape만 테스트했을 가능성이 높다. $H \bmod p_l$과 $W \bmod q_l$이 0이 아닌 사례, 높이와 너비가 서로 다른 사례, 최소 지원 shape를 parameterize한다.

### 증상 4: multi-language 값이 channel 단위로 섞인다

Python은 NCHW인데 다른 runtime에서 NHWC buffer를 받았을 수 있다. shape metadata만 바꾸는 reshape는 데이터 순서를 바꾸지 않는다. 실제 transpose가 필요하다.

### 증상 5: padding 경계에서 가짜 max가 생긴다

feature가 음수인데 padding을 0으로 채우면 padding이 선택될 수 있다. mask를 적용하거나 dtype이 표현할 수 있는 안전한 작은 값을 쓰고, 실제 영역이 없는 bin은 입력 단계에서 금지한다.

### 증상 6: 학습은 재현되지만 GPU 배포가 간헐적으로 다르다

tie, 정밀도, backend kernel 선택을 분리한다. 고유한 값의 `float32` golden test, mixed precision test, 실제 production device test를 별도로 둔다. tolerance와 argmax 정책을 명시한다.

## 14. 성능·메모리 분석

### 14.1 출력과 classifier 비용

SPP 출력 activation 수는 다음과 같다.

$$
A=N C\sum_l p_lq_l
$$

클래스 수 $K$인 Linear head의 weight 수는 다음과 같다.

$$
P_{\mathrm{weight}}=K C\sum_l p_lq_l
$$

$C=256$, $K=1000$에서 `(1,2,4)`의 제곱합은 21이므로 weight는 5,376,000개다. `(8,8)`을 추가하면 합이 85가 되어 약 4.05배가 된다.

$$
\frac{85}{21}\approx 4.05
$$

Adam 학습은 weight 외에도 gradient와 두 optimizer moment를 보관한다. 모두 `float32`라 단순 계산하면 이 Linear weight 관련 메모리만 대략 weight byte의 네 배가 될 수 있다.

### 14.2 여러 adaptive pooling 호출의 비용

각 level을 별도 operator로 실행하면 다음 비용이 반복될 수 있다.

- feature map memory read
- kernel launch
- level별 임시 output allocation
- concatenate를 위한 추가 write

최적화는 추정이 아니라 target device profile로 판단한다.

1. warm-up 후 p50, p95, p99 latency를 측정한다.
2. input shape bucket별로 나눈다.
3. level 수, Linear 크기, batch 크기를 독립 ablation한다.
4. channels-last 변환의 이득과 복사 비용을 함께 잰다.
5. export graph에서 불필요한 transpose·copy를 찾는다.

### 14.3 수치 안정성

- pooling 전 activation의 `NaN`, `Inf`, min, max를 관찰한다.
- max SPP의 tie 비율을 debug sampling으로 측정한다.
- average SPP로 바꿀 때는 큰 bin의 합산 정밀도를 검증한다.
- quantized runtime에서는 padding sentinel과 activation scale이 충돌하지 않는지 확인한다.

## 15. 실무 실패 사례

### 사례 A: schema 없는 checkpoint

팀 A가 `(1,2,4)`로 학습했고 팀 B가 코드 정리 중 level을 내림차순으로 정렬했다. 출력 길이가 같아 checkpoint load와 smoke test는 통과했지만 accuracy가 크게 하락했다.

**원인:** 순서가 configuration이 아니라 단순 list로 취급되었다.

**대응:** checkpoint에 `levels`, `pool`, `layout`, `flatten`, `features`, schema version을 저장하고 load 전에 exact match를 요구한다.

### 사례 B: backward oracle의 대입 버그

독립 구현이 `grad_input[index] = grad`를 사용했다. 겹친 bin과 여러 level에서 같은 argmax가 선택되면 마지막 값만 남아 framework가 틀렸다고 오판했다.

**원인:** max pooling backward가 scatter가 아니라 scatter-add라는 사실을 놓쳤다.

**대응:** `np.add.at` 또는 동등한 atomic accumulation을 사용하고 gradient sum invariant를 검사한다.

### 사례 C: validation이 아닌 training accuracy로 level 선택

`(1,2,4,8)`이 train accuracy를 높여 채택했지만 검증 성능은 같고 latency와 memory만 증가했다.

**원인:** 표현력 증가와 일반화 개선을 구분하지 않았다.

**대응:** 동일 split·seed·optimizer budget에서 validation metric, 여러 seed 분산, target latency를 함께 비교한다.

### 사례 D: dynamic model, static data pipeline

SPP는 가변 해상도를 처리했지만 `DataLoader`의 기본 collate가 서로 다른 shape를 stack하지 못했다.

**원인:** model head의 dynamic shape와 batch assembly를 같은 문제로 생각했다.

**대응:** aspect-ratio bucketing, batch padding과 mask, 지원 shape별 batching 정책을 별도로 구현·테스트한다.

### 사례 E: export는 성공했지만 runtime이 다른 값을 냄

ONNX export graph는 생성됐지만 target provider가 adaptive max pooling을 다른 subgraph로 변환하면서 dynamic shape 범위가 제한되었다.

**대응:** 최소·대표·최대 shape에서 intermediate level output과 final vector를 runtime별로 비교한다. export 성공을 수치 검증의 대체로 쓰지 않는다.

## 16. 배포 관점

### 16.1 ONNX 검증 순서

1. level을 model constant로 고정한다.
2. batch, height, width의 dynamic axis 정책을 명시한다.
3. export된 graph의 `MaxPool` 또는 변환 subgraph를 검사한다.
4. CPU reference provider에서 Python과 golden vector를 비교한다.
5. production provider에서 최소·대표·최대 shape를 다시 비교한다.
6. level별 intermediate tensor를 일시적으로 output으로 노출해 offset 이전 오류를 분리한다.
7. optimization 후 graph에서도 같은 검사를 반복한다.

### 16.2 설명용 export skeleton

다음은 **설명용 코드**이며, 로컬에 `onnx`와 `onnxruntime`이 설치되어 있을 때 실제 target opset으로 검증해야 한다.

```python
example = torch.randn(1, 8, 9, 13)
torch.onnx.export(
    model.eval(),
    example,
    "spp_classifier.onnx",
    input_names=["image"],
    output_names=["logits"],
    dynamic_axes={"image": {0: "batch", 2: "height", 3: "width"},
                  "logits": {0: "batch"}},
    opset_version=18,
    dynamo=True,
)
```

adaptive pooling의 dynamic shape 지원은 exporter, opset, runtime provider 조합에 따라 달라질 수 있다. 반드시 실제 조합에서 확인한다.

### 16.3 운영 모니터링

- 입력 $H,W$, aspect ratio, shape bucket 비율
- padding 비율과 padding sentinel 선택 횟수
- SPP 전 `NaN`·`Inf` 비율과 activation 범위
- schema version별 요청 수
- shape별 p50·p95·p99 latency와 peak memory
- golden canary의 level별 최대 절대 오차
- 지원하지 않는 최소 shape 거부 횟수

## 17. 원본의 역사적 연결을 구현 관점에서 읽기

원본은 SPP-Net이 전체 이미지의 convolution을 한 번 계산하고 여러 region proposal에서 feature를 재사용한 점을 강조한다. 이 방향은 객체 탐지의 공유 backbone과 region 단위 pooling으로 이어졌다.

다만 오늘 구현한 **전체 feature map용 SPP**와 다음 문서의 **region별 RoI Pooling**을 같은 함수로 생각하면 안 된다.

| 항목 | 전체-map SPP | RoI Pooling |
| --- | --- | --- |
| pooling 입력 | 전체 feature map | proposal이 가리키는 부분 영역 |
| 출력 단위 | 이미지당 한 벡터 | RoI마다 한 tensor/벡터 |
| 추가 입력 | level config | RoI 좌표와 batch index |
| 주요 오류 | level·flatten 순서 | 좌표 투영·양자화·빈 RoI |

공통 교훈은 pooling 결과의 shape만 고정해서는 부족하다는 것이다. SPP는 level schema를, RoI 계열은 좌표 convention까지 계약으로 고정해야 한다.

## 20. 해답

### 해답 1

grid 원소 수는 1, 6, 6이고 합은 13이다.

$$
D=3(1+6+6)=39
$$

offset은 다음과 같다.

$$
o_0=0,\qquad o_1=3,\qquad o_2=3(1+6)=21
$$

### 해답 2

level 2는 $p_2=3$, $q_2=2$이고 $o_2=21$이다.

$$
k=21+1(3 \times 2)+2(2)+0=31
$$

### 해답 3

두 설정 모두 level별 bin 수의 합이 $1+4=5$이므로 출력 길이와 Linear weight shape는 같다. 그러나 첫 설정의 index 0부터는 전역 level이고 두 번째 설정의 index 0부터는 $2 \times 2$ level이다. 같은 weight 열이 다른 의미의 feature와 곱해지므로 호환되지 않는다.

### 해답 4

backward는 모든 경로의 gradient를 더한다.

$$
1+2+3+4=10
$$

### 해답 5

`np.add.at(grad_input.ravel(), indices, values)`처럼 중복 index를 보존하는 scatter-add를 사용한다.

### 해답 6

기존 제곱합은 21, 새 제곱합은 85다.

$$
P_{\mathrm{old}}=100 \times 128 \times 21=268{,}800
$$

$$
P_{\mathrm{new}}=100 \times 128 \times 85=1{,}088{,}000
$$

### 해답 7

SPP는 model 내부의 출력 feature 길이만 고정한다. 서로 다른 $H,W$의 raw tensor는 기본 collate에서 하나의 dense batch로 stack할 수 없다. 비슷한 크기끼리 bucketing하거나 batch 내부 공통 크기로 padding하고 mask를 적용할 수 있다.

### 해답 8

reshape는 축의 의미에 맞게 원소를 재배열하지 않고 같은 연속 buffer에 새 shape만 부여한다. NHWC의 row-column-channel 순서를 NCHW의 channel-row-column 순서로 바꾸려면 transpose가 필요하다.

## 21. 핵심 요약

1. SPP의 level은 set이 아니라 순서가 있는 직렬화 schema다.
2. level $l$의 offset은 $o_l=C\sum_{r<l}p_rq_r$로 계산한다.
3. 최종 index는 `level -> channel -> row -> column` 순서를 수식과 metadata로 고정한다.
4. 원본의 고정 kernel·stride 공식은 모든 입력에서 목표 grid를 보장하지 않으므로 adaptive output size를 직접 지정한다.
5. 독립 NumPy oracle은 forward뿐 아니라 argmax와 scatter-add backward까지 구현해야 한다.
6. 겹치는 bin과 여러 level에서 같은 위치가 선택되면 gradient가 누적된다.
7. shape test만으로는 level permutation이나 layout 오류를 잡을 수 없으며 golden value test가 필요하다.
8. 체크포인트에는 `levels`, `pool`, `layout`, `flatten`, `features`, schema version을 함께 저장한다.
9. level ablation은 같은 split·seed·학습 budget에서 validation 성능과 파라미터·latency를 함께 비교한다.
10. 배포에서는 Python/C++/C# golden vector와 실제 ONNX provider의 동적 shape를 모두 검증한다.
