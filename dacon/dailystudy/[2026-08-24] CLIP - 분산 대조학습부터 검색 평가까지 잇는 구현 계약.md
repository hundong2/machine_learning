## 학습 목표

이 글을 마치면 다음을 할 수 있다.

- image/text embedding을 row 단위로 정규화하고 학습 가능한 logit scale을 안정적으로 갱신한다.
- local batch와 global gathered feature의 shape를 추적하고 rank offset이 있는 positive label을 만든다.
- 대칭 cross entropy, 양방향 retrieval metric, multi-positive relevance를 구분한다.
- NumPy oracle과 PyTorch 구현을 같은 golden case로 교차 검증한다.
- 완전한 작은 학습·평가 loop, ablation, exact replay test를 실행한다.
- prompt ensemble을 올바른 정규화 순서로 만들고 class 순서를 versioning한다.
- C++17과 C#에서 분산 label offset과 안정적인 local-to-global loss를 재현한다.
- dtype·layout·tokenizer·전처리·checkpoint·ONNX 경계를 배포 계약으로 고정한다.
- false negative, gather gradient 단절, label offset 오류, scale 폭주를 증상에서 원인까지 진단한다.

## 선수 지식과 기호

선수 지식은 matrix multiplication, cosine similarity, softmax cross entropy, PyTorch autograd, 데이터 병렬 학습의 rank 개념이다.

| 기호 | 의미 | shape 또는 범위 |
| --- | --- | --- |
| $R$ | data-parallel world size | 양의 정수 |
| $B_r$ | rank $r$의 local batch 크기 | 양의 정수 |
| $N$ | global batch 크기, $N=\sum_r B_r$ | 양의 정수 |
| $D$ | 공동 embedding 차원 | 양의 정수 |
| $Z_r^I,Z_r^T$ | rank $r$의 projection 출력 | $(B_r,D)$ |
| $V_r,T_r$ | row 정규화한 local embedding | $(B_r,D)$ |
| $V,T$ | rank 순서로 gather한 global embedding | $(N,D)$ |
| $s$ | 학습 parameter인 log scale | scalar |
| $a$ | 실제 logit scale, $a=\exp(s)$ | $a>0$ |
| $A_r^{I\to T}$ | local image 대 global text logit | $(B_r,N)$ |
| $A_r^{T\to I}$ | local text 대 global image logit | $(B_r,N)$ |
| $o_r$ | rank $r$ 앞에 있는 sample 수 | $o_r=\sum_{q<r}B_q$ |
| $y_{r,i}$ | local sample $i$의 global positive index | $o_r+i$ |
| $M$ | query-candidate relevance matrix | bool, $(N_q,N_c)$ |

## 1. 직관: 대각선이 아니라 ID 계약을 학습한다

단일 process에서 image와 text를 같은 순서로 넣으면 label은 `0, 1, ..., B-1`이다. 그래서 CLIP을 “대각선을 맞추는 학습”이라고 기억하기 쉽다. 그러나 분산 환경에서 각 rank는 global candidate 일부가 아니라 전체 gathered candidate와 경쟁한다. 진짜 계약은 대각선 모양이 아니라 다음 문장이다.

> local image/text가 가리키는 positive의 **global pair ID**가 두 방향에서 같아야 한다.

rank별 batch 크기가 모두 $B$라면 rank $r$의 offset은 $rB$다. batch 크기가 다르면 단순 곱셈을 쓰면 안 되고 앞 rank의 크기를 누적해야 한다.

$$
o_r=\sum_{q=0}^{r-1}B_q
$$

$$
y_{r,i}=o_r+i
$$

예를 들어 $R=2$, $B_0=B_1=2$일 때 rank 1의 local label은 `[0, 1]`이 아니라 `[2, 3]`이다. offset을 빼먹어도 loss는 계산되고 gradient도 생기므로 이 오류는 shape test만으로 잡히지 않는다.

## 2. 원문에서 구현 전에 바로잡을 점

### 2.1 closed-set과 open-vocabulary

> 원문: CLIP 이전의 모든 vision AI는 미리 정한 class 안에서만 동작한다고 설명한다.

> 수정: CLIP 이전에도 zero-shot·open-vocabulary 연구가 있었다. CLIP의 핵심 기여는 대규모 자연어-image pair와 단순한 dual-encoder contrastive objective를 결합해 전이 가능한 zero-shot classifier를 보인 것이다. 추론 때 후보 class prompt를 주므로 “무한한 class를 항상 정확히 인식한다”는 뜻도 아니다.

### 2.2 off-diagonal negative의 목표

> 원문: $N^2-N$개 negative similarity를 모두 $-1$에 가깝게 만든다고 설명한다.

> 수정: cross entropy는 positive logit을 같은 row와 column의 경쟁자보다 높게 만든다. 쉬운 negative의 gradient는 작아지고, 중복 caption이나 동의어는 실제로 false negative가 될 수 있다. 모든 negative를 기하학적으로 반대 방향에 놓을 필요도, 그렇게 놓을 수도 없다.

### 2.3 temperature parameterization

> 원문: temperature $\tau$를 직접 학습하는 것처럼 읽힌다.

> 수정: 구현은 보통 자유 parameter $s$를 저장하고 $a=\exp(s)=1/\tau$를 사용한다. checkpoint에는 `s`인지 `a`인지 이름·의미·초기값을 함께 기록해야 한다. `exp` 전후의 clamp 위치가 다르면 gradient도 달라진다.

### 2.4 생성 모델과 CLIP

> 원문: DALL-E와 Stable Diffusion이 생성 pixel의 CLIP cosine을 직접 높이며 그림을 만든다는 하나의 과정으로 묶는다.

> 수정: CLIP은 dual encoder다. 생성 모델은 버전에 따라 text hidden state를 cross-attention condition으로 쓰거나 별도 guidance를 쓸 수 있다. denoiser가 매 step 완성 image와 text의 CLIP cosine을 직접 최적화한다고 일반화하면 안 된다.

## 3. 단일 rank 수식에서 local-to-global 수식으로

### 3.1 projection과 정규화

projection 출력 한 row를 $z$라 하면 정규화 embedding은 다음과 같다.

$$
\operatorname{norm}(z)
=
\frac{z}{\max(\lVert z\rVert_2,\epsilon)}
$$

rank $r$에서 다음 shape가 유지되어야 한다.

| 단계 | image 경로 | text 경로 |
| --- | --- | --- |
| raw input | $(B_r,C,H,W)$, floating | $(B_r,L)$, integer token |
| encoder | $(B_r,D_I)$ | $(B_r,D_T)$ |
| projection | $(B_r,D)$ | $(B_r,D)$ |
| row normalize | $(B_r,D)$ | $(B_r,D)$ |
| differentiable gather | global $(N,D)$ | global $(N,D)$ |
| local-to-global logit | $(B_r,N)$ | $(B_r,N)$ |

### 3.2 logit scale

cosine similarity와 softmax logit을 구분한다.

$$
S_{ij}=v_i^{\mathsf T}t_j
$$

$$
A_{ij}=aS_{ij}=\exp(s)S_{ij}
$$

$S_{ij}$는 이상적으로 $[-1,1]$ 범위지만 $A_{ij}$는 scale 때문에 그보다 크다. mixed precision에서 `exp(s)`와 cross entropy를 낮은 정밀도로만 계산하면 overflow와 underflow가 쉬워진다. 이 글의 실행 코드는 embedding과 loss를 `float32` 이상에서 계산한다.

상한 $a_{\max}$를 둔다면 두 구현은 같지 않다.

$$
a=\min(\exp(s),a_{\max})
$$

$$
a=\exp(\min(s,\log a_{\max}))
$$

둘 다 상한 밖에서 gradient가 0이 될 수 있다. 실무에서는 optimizer step 뒤 `no_grad`로 $s$ 자체를 범위에 되돌리는 정책도 쓴다. 중요한 것은 한 정책을 선택해 train·resume·export에서 동일하게 적용하는 것이다.

### 3.3 local image-to-global text loss

rank $r$의 image row $i$가 global text $j$를 고르는 확률은 다음과 같다.

$$
p_{r,i,j}^{I\to T}
=
\frac{\exp(A_{r,i,j}^{I\to T})}
{\sum_{k=0}^{N-1}\exp(A_{r,i,k}^{I\to T})}
$$

$$
\mathcal L_r^{I\to T}
=
-\frac{1}{B_r}
\sum_{i=0}^{B_r-1}
\log p_{r,i,y_{r,i}}^{I\to T}
$$

text-to-image 방향도 candidate 축만 global image로 바뀐다.

$$
\mathcal L_r^{T\to I}
=
-\frac{1}{B_r}
\sum_{i=0}^{B_r-1}
\log p_{r,i,y_{r,i}}^{T\to I}
$$

$$
\mathcal L_r
=
\frac{\mathcal L_r^{I\to T}+\mathcal L_r^{T\to I}}{2}
$$

모든 $B_r$가 같다면 rank loss 평균이 global sample 평균과 같다. 크기가 다르면 rank별 단순 평균 대신 sample 수로 가중해야 한다.

### 3.4 gather의 gradient 계약

`all_gather`라는 이름만 같아도 autograd 의미는 다를 수 있다.

- differentiable gather: 다른 rank의 feature가 candidate가 되고 그 feature encoder로도 gradient가 돌아간다.
- detached gather: remote feature를 상수 negative로 취급한다.
- local loss: query는 local, candidate만 global이라 logit shape가 $(B_r,N)$이다.
- global loss: 모든 query와 candidate를 gather해 $(N,N)$ 전체 loss를 각 rank에서 계산한다.

이 네 선택은 memory, 통신, gradient scaling이 다르다. library API 이름보다 backward test로 계약을 확인해야 한다.

## 4. 검색 평가는 loss의 대각선 정확도가 아니다

### 4.1 양방향 Recall@K

image-to-text와 text-to-image retrieval은 query 축이 다르므로 따로 보고한다. query $q$의 top-$K$ candidate 집합을 $\operatorname{TopK}(q)$, relevant candidate 집합을 $\mathcal R(q)$라 하면 다음과 같다.

$$
\operatorname{Recall@K}
=
\frac{1}{N_q}
\sum_{q=1}^{N_q}
\mathbf 1
\left[
\operatorname{TopK}(q)\cap\mathcal R(q)\ne\varnothing
\right]
$$

한 image에 caption이 여러 개면 relevance matrix $M$의 한 row에 `True`가 여러 개다. 학습이 diagonal one-positive였더라도 평가는 모든 정답 caption을 relevant로 인정해야 한다.

### 4.2 tie와 candidate ID

동점 logit의 순서는 backend별로 달라질 수 있다. metric 재현성을 위해 다음 중 하나를 고정한다.

- stable sort와 candidate ID의 오름차순을 tie-break로 사용한다.
- 동점 전체를 같은 rank로 처리하는 metric 정의를 사용한다.

그리고 validation candidate pool의 ID와 순서를 artifact로 보관한다. “Recall@1이 달라졌다”는 현상이 모델 변화가 아니라 candidate 순서 변화일 수 있다.

## 5. NumPy 수작업 oracle

아래 코드는 **실행 가능**하다. rank 1의 두 query가 global candidate 네 개를 볼 때 올바른 offset label `[2, 3]`과 잘못된 local label `[0, 1]`을 비교한다. stable log-sum-exp, Recall@K, multi-positive relevance를 dependency-free oracle로 만든다.

```python
import numpy as np

def cross_entropy(logits: np.ndarray, labels: np.ndarray) -> float:
    if logits.ndim != 2 or labels.shape != (logits.shape[0],):
        raise ValueError("shape contract violated")
    maximum = logits.max(axis=1, keepdims=True)
    logsumexp = maximum[:, 0] + np.log(
        np.exp(logits - maximum).sum(axis=1)
    )
    return float((logsumexp - logits[np.arange(len(labels)), labels]).mean())

def recall_at_k(
    logits: np.ndarray, relevance: np.ndarray, k: int
) -> float:
    if logits.shape != relevance.shape:
        raise ValueError("logits and relevance must have the same shape")
    if not 1 <= k <= logits.shape[1]:
        raise ValueError("k is out of range")
    # mergesort는 동점에서 원래 candidate ID 순서를 보존한다.
    order = np.argsort(-logits, axis=1, kind="mergesort")[:, :k]
    hit = np.take_along_axis(relevance, order, axis=1).any(axis=1)
    return float(hit.mean())

logits = np.array([
    [0.0, 0.0, 4.0, 1.0],
    [0.0, 0.0, 1.0, 4.0],
], dtype=np.float64)
correct_labels = np.array([2, 3])
wrong_labels = np.array([0, 1])

correct_loss = cross_entropy(logits, correct_labels)
wrong_loss = cross_entropy(logits, wrong_labels)
assert correct_loss < wrong_loss

relevance = np.array([
    [False, False, True, False],
    [False, False, True, True],  # 두 caption 모두 relevant인 예
])
assert recall_at_k(logits, relevance, 1) == 1.0
assert recall_at_k(logits, relevance, 2) == 1.0

# prompt ensemble: 각 prompt normalize -> 평균 -> 다시 normalize
prompts = np.array([[3.0, 4.0], [0.0, 2.0]], dtype=np.float64)
prompts = prompts / np.linalg.norm(prompts, axis=1, keepdims=True)
class_embedding = prompts.mean(axis=0)
class_embedding /= np.linalg.norm(class_embedding)
np.testing.assert_allclose(np.linalg.norm(class_embedding), 1.0, atol=1e-12)

print(f"correct_loss={correct_loss:.9f}")
print(f"wrong_loss={wrong_loss:.9f}")
print(f"recall@1={recall_at_k(logits, relevance, 1):.1f}")
print("class_embedding=", np.round(class_embedding, 6))
```

잘못된 offset도 유한한 loss를 내므로 `isfinite` test만으로는 부족하다. 최소한 correct loss가 wrong-offset loss보다 낮은 golden case를 둬야 한다.

## 6. 실행 가능한 PyTorch 학습·평가 구현

다음 코드는 **실행 가능**한 작은 end-to-end 예제다. 실제 CLIP backbone을 축소 재현하려는 목적이 아니라 `pair -> encode -> normalize -> scale -> symmetric loss -> optimizer -> retrieval evaluation -> exact replay` 계약을 한 파일에서 검증한다.

```python
import copy
import math
import random
import numpy as np
import torch
from torch import nn
import torch.nn.functional as F

def seed_everything(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.use_deterministic_algorithms(True)

class TinyCLIP(nn.Module):
    def __init__(self, input_dim: int = 8, embed_dim: int = 16):
        super().__init__()
        self.image_encoder = nn.Linear(input_dim, embed_dim, bias=False)
        self.token_embedding = nn.Embedding(input_dim + 1, embed_dim)
        self.text_projection = nn.Linear(embed_dim, embed_dim, bias=False)
        self.logit_scale_log = nn.Parameter(
            torch.tensor(math.log(1.0 / 0.07), dtype=torch.float32)
        )

    def encode_image(self, images: torch.Tensor) -> torch.Tensor:
        return F.normalize(self.image_encoder(images.float()), dim=-1)

    def encode_text(self, token_ids: torch.Tensor) -> torch.Tensor:
        if token_ids.ndim != 2 or token_ids.shape[1] != 1:
            raise ValueError("expected token_ids with shape (B, 1)")
        features = self.token_embedding(token_ids[:, 0])
        return F.normalize(self.text_projection(features.float()), dim=-1)

    def scale(self) -> torch.Tensor:
        return self.logit_scale_log.float().exp()

def symmetric_loss(
    image_embeddings: torch.Tensor,
    text_embeddings: torch.Tensor,
    scale: torch.Tensor,
) -> torch.Tensor:
    if image_embeddings.shape != text_embeddings.shape:
        raise ValueError("paired embedding shapes must match")
    logits = scale * image_embeddings @ text_embeddings.T
    labels = torch.arange(logits.shape[0], device=logits.device)
    return 0.5 * (
        F.cross_entropy(logits.float(), labels)
        + F.cross_entropy(logits.T.float(), labels)
    )

def make_data() -> tuple[torch.Tensor, torch.Tensor]:
    # image i와 token i+1이 한 pair다.
    images = torch.eye(8, dtype=torch.float32)
    token_ids = torch.arange(1, 9, dtype=torch.long).unsqueeze(1)
    return images, token_ids

def recall_at_k(
    logits: torch.Tensor, relevance: torch.Tensor, k: int
) -> float:
    if logits.shape != relevance.shape:
        raise ValueError("metric shape mismatch")
    order = torch.argsort(logits, dim=1, descending=True, stable=True)[:, :k]
    hits = relevance.gather(1, order).any(dim=1)
    return float(hits.float().mean())

def evaluate(model: TinyCLIP) -> dict[str, float]:
    images, token_ids = make_data()
    with torch.no_grad():
        image_embeddings = model.encode_image(images)
        text_embeddings = model.encode_text(token_ids)
        logits = model.scale() * image_embeddings @ text_embeddings.T
        relevance = torch.eye(8, dtype=torch.bool)
    return {
        "i2t_r1": recall_at_k(logits, relevance, 1),
        "t2i_r1": recall_at_k(logits.T, relevance.T, 1),
        "scale": float(model.scale().detach()),
    }

def train_once(
    seed: int, symmetric: bool = True
) -> tuple[list[float], dict[str, torch.Tensor], dict[str, float]]:
    seed_everything(seed)
    images, token_ids = make_data()
    model = TinyCLIP()
    optimizer = torch.optim.AdamW(model.parameters(), lr=0.03, weight_decay=0.0)
    history: list[float] = []

    for _ in range(80):
        optimizer.zero_grad(set_to_none=True)
        image_embeddings = model.encode_image(images)
        text_embeddings = model.encode_text(token_ids)
        logits = model.scale() * image_embeddings @ text_embeddings.T
        labels = torch.arange(8)
        if symmetric:
            loss = 0.5 * (
                F.cross_entropy(logits.float(), labels)
                + F.cross_entropy(logits.T.float(), labels)
            )
        else:
            loss = F.cross_entropy(logits.float(), labels)
        loss.backward()
        assert all(
            p.grad is None or torch.isfinite(p.grad).all()
            for p in model.parameters()
        )
        optimizer.step()
        # train/resume/export가 공유해야 하는 scale 정책
        with torch.no_grad():
            model.logit_scale_log.clamp_(max=math.log(100.0))
        history.append(float(loss.detach()))

    state = {name: value.detach().clone() for name, value in model.state_dict().items()}
    return history, state, evaluate(model)

# shape, norm, loss, backward contract
seed_everything(23)
probe = TinyCLIP()
images, token_ids = make_data()
image_embeddings = probe.encode_image(images)
text_embeddings = probe.encode_text(token_ids)
assert image_embeddings.shape == (8, 16)
assert text_embeddings.shape == (8, 16)
torch.testing.assert_close(image_embeddings.norm(dim=1), torch.ones(8))
torch.testing.assert_close(text_embeddings.norm(dim=1), torch.ones(8))
loss = symmetric_loss(image_embeddings, text_embeddings, probe.scale())
loss.backward()
assert torch.isfinite(loss)

# 분산 offset을 한 process에서 simulation
global_text = F.normalize(torch.eye(4), dim=1)
rank1_image = global_text[2:].clone()
rank1_logits = 4.0 * rank1_image @ global_text.T
correct = F.cross_entropy(rank1_logits, torch.tensor([2, 3]))
wrong = F.cross_entropy(rank1_logits, torch.tensor([0, 1]))
assert correct < wrong

# train/eval과 one-way ablation
sym_history, sym_state, sym_metrics = train_once(31, symmetric=True)
one_history, _, one_metrics = train_once(31, symmetric=False)
assert sym_history[-1] < sym_history[0]
assert sym_metrics["i2t_r1"] == 1.0
assert sym_metrics["t2i_r1"] == 1.0

# exact replay: loss history와 모든 state tensor가 bitwise 동일
replay_history, replay_state, replay_metrics = train_once(31, symmetric=True)
assert sym_history == replay_history
assert sym_metrics == replay_metrics
assert sym_state.keys() == replay_state.keys()
for name in sym_state:
    torch.testing.assert_close(sym_state[name], replay_state[name], rtol=0, atol=0)

# prompt ensemble normalize -> mean -> renormalize
with torch.no_grad():
    prompt_ids = torch.tensor([[1], [2], [3]])
    prompt_embeddings = probe.encode_text(prompt_ids)
    class_embedding = F.normalize(prompt_embeddings.mean(dim=0), dim=0)
    torch.testing.assert_close(class_embedding.norm(), torch.tensor(1.0))

print(f"loss={sym_history[0]:.6f}->{sym_history[-1]:.6f}")
print("symmetric", sym_metrics)
print("one_way", one_metrics)
print(f"offset_loss={correct.item():.6f} wrong={wrong.item():.6f}")
```

이 synthetic task에서는 두 ablation이 모두 성공할 수 있다. 이것은 one-way loss가 일반적으로 충분하다는 결론이 아니라, 쉬운 identity task가 방향별 retrieval 차이를 드러내지 못한다는 실험 한계다. 실제 ablation은 image-to-text와 text-to-image metric을 별도로 보고, 여러 caption과 hard negative가 있는 validation set에서 반복해야 한다.

## 7. 실제 분산 loss의 구현 골격

다음은 **설명용 골격**이다. 실행하려면 `torchrun`으로 process group을 초기화하고, 사용 중인 PyTorch 버전에서 differentiable gather API의 backward 의미를 확인해야 한다.

```python
import torch
import torch.distributed as dist
import torch.distributed.nn.functional as dist_nn
import torch.nn.functional as F

def distributed_local_clip_loss(image_local, text_local, scale):
    if not dist.is_initialized():
        raise RuntimeError("initialize the process group first")
    local_batch = torch.tensor(
        [image_local.shape[0]], device=image_local.device, dtype=torch.long
    )
    gathered_sizes = dist_nn.all_gather(local_batch)
    sizes = torch.cat(gathered_sizes)
    if not torch.equal(sizes, sizes[0].expand_as(sizes)):
        raise ValueError("pad or implement variable-size gather explicitly")

    image_global = torch.cat(dist_nn.all_gather(image_local), dim=0)
    text_global = torch.cat(dist_nn.all_gather(text_local), dim=0)
    rank = dist.get_rank()
    offset = int(sizes[:rank].sum())
    labels = offset + torch.arange(image_local.shape[0], device=image_local.device)

    logits_i = scale.float() * image_local.float() @ text_global.float().T
    logits_t = scale.float() * text_local.float() @ image_global.float().T
    return 0.5 * (
        F.cross_entropy(logits_i, labels)
        + F.cross_entropy(logits_t, labels)
    )
```

실전에서는 다음 test를 별도 2-process CI job으로 둔다.

1. rank 0 label은 `[0, ..., B-1]`, rank 1 label은 `[B, ..., 2B-1]`인지 확인한다.
2. rank 1의 image loss가 rank 0 text encoder parameter에도 gradient를 만드는지 확인한다.
3. single-process global loss와 distributed sample-weighted loss가 허용 오차 안에서 같은지 확인한다.
4. 마지막 uneven batch를 drop할지, pad할지, variable gather할지 명시한다.
5. `DistributedSampler.set_epoch(epoch)` 호출과 seed가 checkpoint resume 뒤 동일한 순서를 만드는지 확인한다.

## 8. C++17 local-to-global golden test

아래 C++17 코드는 **실행 가능한 수치 검증용 예제**다. 전체 encoder가 아니라 rank 1의 $(2,4)$ logit, offset label, stable cross entropy, Recall@1을 검증한다.

```cpp
#include <array>
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>

using Row = std::array<double, 4>;
using Matrix = std::array<Row, 2>;

double cross_entropy(const Matrix& logits, const std::array<int, 2>& labels) {
    double loss = 0.0;
    for (std::size_t i = 0; i < logits.size(); ++i) {
        double maximum = logits[i][0];
        for (double value : logits[i]) maximum = std::max(maximum, value);
        double sum = 0.0;
        for (double value : logits[i]) sum += std::exp(value - maximum);
        loss += maximum + std::log(sum) - logits[i][labels[i]];
    }
    return loss / static_cast<double>(logits.size());
}

double recall_at_one(const Matrix& logits, const std::array<int, 2>& labels) {
    int hits = 0;
    for (std::size_t i = 0; i < logits.size(); ++i) {
        int best = 0;
        for (int j = 1; j < 4; ++j) {
            if (logits[i][j] > logits[i][best]) best = j;
        }
        hits += best == labels[i] ? 1 : 0;
    }
    return hits / 2.0;
}

int main() {
    const Matrix logits{{
        Row{{0.0, 0.0, 4.0, 1.0}},
        Row{{0.0, 0.0, 1.0, 4.0}},
    }};
    const std::array<int, 2> labels{{2, 3}};
    const double loss = cross_entropy(logits, labels);
    const double recall = recall_at_one(logits, labels);
    assert(std::abs(loss - 0.082886365) < 1e-9);
    assert(recall == 1.0);
    std::cout << std::fixed << std::setprecision(6)
              << "loss=" << loss << " recall@1=" << recall << '\n';
}
```

## 9. C# local-to-global golden test

아래 C# 코드도 **실행 가능한 수치 검증용 예제**이며 C++과 같은 값을 요구한다.

```csharp
using System;

public static class DistributedClipGolden
{
    private static double CrossEntropy(double[,] logits, int[] labels)
    {
        int rows = logits.GetLength(0);
        int columns = logits.GetLength(1);
        double loss = 0.0;
        for (int i = 0; i < rows; ++i)
        {
            double maximum = logits[i, 0];
            for (int j = 1; j < columns; ++j)
                maximum = Math.Max(maximum, logits[i, j]);
            double sum = 0.0;
            for (int j = 0; j < columns; ++j)
                sum += Math.Exp(logits[i, j] - maximum);
            loss += maximum + Math.Log(sum) - logits[i, labels[i]];
        }
        return loss / rows;
    }

    private static double RecallAtOne(double[,] logits, int[] labels)
    {
        int hits = 0;
        for (int i = 0; i < logits.GetLength(0); ++i)
        {
            int best = 0;
            for (int j = 1; j < logits.GetLength(1); ++j)
                if (logits[i, j] > logits[i, best]) best = j;
            if (best == labels[i]) ++hits;
        }
        return hits / 2.0;
    }

    public static void Main()
    {
        double[,] logits = {
            {0.0, 0.0, 4.0, 1.0},
            {0.0, 0.0, 1.0, 4.0},
        };
        int[] labels = {2, 3};
        double loss = CrossEntropy(logits, labels);
        double recall = RecallAtOne(logits, labels);
        if (Math.Abs(loss - 0.082886365) >= 1e-9 || recall != 1.0)
            throw new Exception("distributed CLIP golden mismatch");
        Console.WriteLine($"loss={loss:F6} recall@1={recall:F6}");
    }
}
```

## 10. 프레임워크 간 shape·layout·dtype 대응

| 의미 | PyTorch 학습 | C++/ONNX Runtime | C#/ONNX Runtime | 고정할 계약 |
| --- | --- | --- | --- | --- |
| image | `NCHW`, 보통 `float32` | model signature 확인 | `DenseTensor<float>` | RGB, resize, crop, mean/std |
| token ID | `(B,L)`, `torch.long` | `int64_t` 또는 model 지정 | `long` 또는 model 지정 | tokenizer version, special token |
| attention mask | `(B,L)` | bool/int signature | bool/long signature | 1이 valid인지 padding인지 |
| embedding | `(B,D)`, row-major view | contiguous buffer | `(B,D)` tensor | row normalize와 $\epsilon$ |
| prompt bank | `(K,M,D)` 또는 flatten | class-major 권장 | class-major 권장 | class→template→token 순서 |
| class embedding | `(K,D)` | GEMM candidate matrix | GEMM candidate matrix | 평균 전후 normalize |
| logit scale | scalar `float32` | model metadata 또는 output | model metadata 또는 output | `s`와 $a$를 혼동하지 않기 |
| similarity | `(N_q,N_c)` | transpose flag 확인 | transpose flag 확인 | query/candidate 축 |

이미지는 `NCHW`와 `NHWC`를 바꾸면 shape 오류가 나기 쉽지만 tokenizer mismatch는 shape가 정상이라 더 위험하다. vocabulary, BPE merge, Unicode normalization, begin/end token, truncation side, context length를 checkpoint와 함께 versioning한다.

## 11. 테스트와 디버깅

### 11.1 테스트 피라미드

1. scalar: stable log-sum-exp가 extreme logit에서 finite인지 검사한다.
2. shape: image/text projection이 같은 $D$인지 검사한다.
3. norm: 각 row norm이 1인지 검사한다.
4. pair: image/text shuffle에 동일 pair ID permutation을 적용했는지 검사한다.
5. offset: rank별 local label이 global candidate 위치를 가리키는지 검사한다.
6. backward: gathered remote feature까지 gradient가 가는지 검사한다.
7. metric: diagonal과 multi-positive relevance의 Recall@K golden을 분리한다.
8. replay: 같은 seed의 loss history와 checkpoint tensor가 bitwise 동일한지 검사한다.
9. export: Python과 target runtime의 embedding·top-k를 golden input으로 비교한다.

### 11.2 증상별 진단

| 증상 | 가능 원인 | 가장 작은 확인 |
| --- | --- | --- |
| loss가 $\log N$ 부근에서 멈춤 | constant embedding, pair shuffle 오류 | row variance와 pair ID 출력 |
| rank 0만 정상 | label offset 누락 | 각 rank 첫·끝 label 출력 |
| single GPU와 multi GPU가 크게 다름 | detached gather, loss scaling 차이 | remote parameter gradient 확인 |
| image-to-text만 좋음 | 한 방향만 학습·평가 | transposed loss와 metric 확인 |
| scale이 100에 붙음 | clamp 뒤 gradient 소실, 과도한 LR | $s$, $a$, gradient를 함께 기록 |
| zero-shot만 나쁨 | prompt/tokenizer/class 순서 불일치 | golden token ID와 class index 비교 |
| Recall@1이 실행마다 다름 | tie 처리·candidate 순서 변화 | stable sort와 candidate ID 고정 |
| 학습 loss는 낮고 검색 품질은 나쁨 | false negative·shortcut | multi-positive metric과 domain slice |
| mixed precision에서 `NaN` | norm·scale·CE가 낮은 정밀도 | 해당 연산만 `float32`로 승격 |

### 11.3 negative test

정상 입력만 검증하지 않는다.

- 빈 문장 또는 attention mask가 전부 false면 거부한다.
- image와 text local batch 크기가 다르면 거부한다.
- pair ID 중복이 허용되지 않는 one-positive loader에서는 중복을 거부한다.
- variable local batch를 지원하지 않는 gather라면 마지막 uneven batch를 명시적으로 거부한다.
- zero norm, `NaN`, `Inf` embedding을 logit 계산 전에 거부한다.
- prompt bank의 class 수와 label schema의 class 수가 다르면 배포를 거부한다.

### 12.1 저장할 상태

checkpoint에는 다음을 함께 둔다.

- 두 encoder와 projection weight
- `logit_scale_log`
- optimizer와 scheduler state
- global step, epoch, sampler epoch
- Python·NumPy·PyTorch RNG state
- image preprocessing과 tokenizer artifact hash
- pair manifest hash와 filtering version
- world size, global/local batch, gather 방식, loss reduction
- prompt template와 class schema version

### 12.2 유효한 ablation

| 질문 | 바꿀 것 | 고정할 것 | 함께 볼 metric |
| --- | --- | --- | --- |
| 대칭 loss가 필요한가 | one-way 대 symmetric | seed, pair, update 수 | i2t·t2i Recall@K |
| global negative가 필요한가 | local 대 gathered candidate | global batch 또는 compute budget | loss, 통신량, retrieval |
| prompt ensemble이 좋은가 | template 수 | encoder, class, validation | class별 accuracy, latency |
| scale 학습이 필요한가 | fixed 대 learned | 초기 scale, optimizer | loss, scale trace, calibration |
| multi-positive가 필요한가 | diagonal 대 relevance-aware loss | batch와 encoder | duplicate slice Recall@K |

microbatch accumulation은 optimizer가 보는 sample 수는 늘리지만 각 microbatch의 contrastive candidate 수를 자동으로 늘리지 않는다. candidate pool 크기를 맞추지 않은 채 “global batch만 같음”이라고 쓰면 ablation이 아니다.

## 13. 성능·메모리·수치 안정성

### 13.1 계산량과 저장량

global logit matrix의 계산량은 $O(N^2D)$, 저장량은 $O(N^2)$다. local loss라면 rank당 logit은 $(B_r,N)$이므로 저장량은 $O(B_rN)$이지만 모든 rank 합은 여전히 $O(N^2)$ 수준이다.

embedding gather payload는 modality 하나당 대략 다음과 같다.

$$
N D \times \operatorname{bytes(dtype)}
$$

$N=32768$, $D=768$, `float16`이면 modality 하나의 raw feature는 약 48 MiB지만 $(N,N)$ `float32` logit은 약 4 GiB다. 실제 peak에는 두 방향 logit, softmax workspace, gradient가 더해진다.

### 13.2 안정성 규칙

- projection 직후 row norm을 `float32`로 계산한다.
- cross entropy에는 probability를 직접 만들지 말고 logits를 전달한다.
- `logit_scale_log`, 실제 scale, 최대·최소 logit을 함께 관찰한다.
- `float16`의 작은 $\epsilon$에 의존하지 말고 normalize 연산 dtype을 명시한다.
- large candidate pool은 chunked top-k와 streaming metric을 검토한다.
- retrieval index에 저장할 embedding dtype을 바꾸면 threshold와 Recall을 다시 검증한다.

## 14. 실무 실패 사례

### 사례 A: 마지막 rank의 짧은 batch

dataset 크기가 world size와 batch의 배수가 아니어서 마지막 rank 크기가 달라졌다. fixed-size gather가 멈추거나, 더 나쁘게 pad sample이 진짜 negative로 들어간다.

대응은 `drop_last=True`, variable-size gather, mask를 둔 padding 중 하나를 선택하고 학습 sample 수와 bias를 기록하는 것이다.

### 사례 B: 중복 caption을 negative로 학습

서로 다른 image 두 장의 caption이 `고양이 사진`으로 같다. diagonal loss는 다른 caption row를 negative로 본다. dataset deduplication, pair group ID, multi-positive loss를 비교하고 중복률을 metric slice로 공개한다.

### 사례 C: gather는 됐지만 remote gradient가 없음

일반 collective 결과를 autograd tensor처럼 사용했지만 remote feature가 detach됐다. loss는 global negative를 보는 듯하지만 gradient 계약은 기대와 다르다. 2-process toy test에서 rank 1 loss만 backward하고 rank 0 encoder gradient를 직접 검사한다.

### 사례 D: prompt 평균 순서 오류

정규화하지 않은 prompt feature를 먼저 평균하면 norm이 큰 template이 class 방향을 지배한다. 각 prompt를 normalize하고 평균한 뒤 class vector를 다시 normalize한다. template 순서와 class 순서를 artifact로 저장한다.

### 사례 E: retrieval 평가의 false negative

한 image에 정답 caption이 5개인데 평가 manifest는 하나만 positive로 표시했다. 의미상 맞는 caption이 top-1이어도 오답 처리된다. pair ID가 아니라 semantic group ID로 relevance matrix를 만든다.

### 사례 F: 서로 다른 model version의 cache 혼합

text embedding cache는 v1인데 image encoder는 v2로 교체됐다. 두 embedding의 shape가 같아 요청은 성공하지만 공동 공간은 호환되지 않는다. cache key에 joint checkpoint hash, tokenizer hash, prompt hash, dtype을 포함한다.

## 15. 배포 관점

### 15.1 zero-shot 분류

1. class와 prompt template manifest를 고정한다.
2. text encoder로 $(K,M,D)$ prompt embedding을 만든다.
3. prompt별 normalize, class별 mean, class별 renormalize를 적용한다.
4. class matrix $(K,D)$를 model hash와 함께 cache한다.
5. image encoder 출력 $(B,D)$를 normalize한다.
6. $(B,D)@(D,K)$와 scale을 계산한다.
7. top-k, model ID, prompt ID, preprocessing ID를 반환한다.

softmax score는 후보 class 집합에 의존하므로 open-set confidence가 아니다. 거절 threshold는 target domain과 실제 class 후보 집합으로 calibration한다.

### 15.2 retrieval

gallery embedding은 offline에서 만들고 normalized vector와 item ID를 함께 index에 넣는다. online query도 같은 encoder version과 normalize 규칙을 써야 한다. approximate nearest neighbor index의 Recall은 model retrieval Recall과 별도로 측정한다.

### 15.3 ONNX와 target runtime

image encoder와 text encoder를 별도 graph로 내보낼 수 있지만 다음 요소는 graph 밖에도 남는다.

- image decode·resize·crop·RGB·normalization
- tokenizer와 attention mask
- prompt ensemble과 class mapping
- embedding cache와 ANN index
- scale 적용, top-k, threshold calibration

이 환경에서 `onnx`와 `onnxruntime`이 없다면 export 성공을 주장하지 않는다. 대신 PyTorch golden input/output을 보존하고 target runtime이 준비된 CI에서 embedding cosine, 최대 절대 오차, top-k parity를 검사한다.

## 16. 운영 모니터링

정답 label이 늦게 들어오는 서비스에서도 다음을 관찰할 수 있다.

- image/text embedding norm의 평균·분위수
- logit scale과 top-1/top-2 margin
- query 언어·길이·unknown token·truncation 비율
- class별 요청량과 거절률
- cache hit ratio와 model/cache hash mismatch 수
- ANN exact subset Recall
- duplicate caption과 near-duplicate image 비율
- delayed label이 있는 slice의 Recall@K·zero-shot accuracy

embedding 자체를 무제한 log로 남기면 개인정보와 저장 비용 문제가 생긴다. 집계 통계, 승인된 sample, hash 기반 추적을 사용한다.

한 image에 relevant caption이 세 개다. top-2 안에 그중 하나가 들어왔지만 diagonal caption은 없다. one-positive diagonal accuracy와 relevance 기반 Recall@2는 각각 어떻게 되는가?

### 문제 6

분산 실행에서 loss는 정상인데 rank 0 encoder가 rank 1 loss로부터 gradient를 받지 않는다. 가장 먼저 의심할 계약과 이를 확인할 test를 쓰라.

### 문제 7

class prompt cache를 폐기해야 하는 변경을 네 가지 쓰라.

## 19. 연습문제 해답

### 해답 1

rank 2 앞의 sample 수는 $4+4=8$이고 local index는 1이므로 global index는 $9$다.

### 해답 2

logit은 $(8,32)$다. rank 1 앞에 batch 8개가 있다면 label은 `[8, 9, ..., 15]`다.

### 해답 3

그대로 평균하면 norm 10인 prompt가 class 방향을 지배한다. 각 prompt를 row normalize하고, 평균한 다음 class vector를 다시 normalize한다.

### 해답 4

아니다. 각 microbatch에서 loss를 따로 계산하면 그 microbatch의 candidate만 negative다. encoder update에 누적된 sample은 늘지만 contrastive denominator가 자동으로 합쳐지지는 않는다.

### 해답 5

diagonal caption이 top-2에 없으므로 one-positive diagonal 기준은 실패다. relevant 세 개 중 하나가 top-2에 있으므로 relevance 기반 Recall@2는 성공이다.

### 해답 6

gather 결과가 remote rank에서 detach되는 계약을 먼저 의심한다. 2-process toy model에서 rank 1 local loss만 backward한 뒤 rank 0 encoder parameter gradient가 nonzero인지 확인한다.

### 해답 7

joint checkpoint, text encoder/projection, tokenizer, prompt template, class mapping, normalize 규칙, dtype 가운데 하나라도 바뀌면 폐기한다. 네 가지 이상을 고르면 된다.

## 핵심 요약

- CLIP의 본질적 label은 대각선 모양이 아니라 image-text global pair ID다.
- 분산 local loss의 positive는 $y_{r,i}=o_r+i$이고 uneven batch에서는 offset을 누적합으로 구한다.
- normalized similarity와 scaled logit을 구분하고 log scale의 update·상한 정책을 고정한다.
- gather API는 forward shape뿐 아니라 remote gradient와 loss reduction까지 test해야 한다.
- 학습의 diagonal one-positive와 평가의 multi-positive relevance는 서로 다른 schema다.
- image-to-text와 text-to-image Recall@K를 따로 보고 tie-break와 candidate ID를 고정한다.
- prompt ensemble은 각 prompt normalize, 평균, class vector renormalize 순서다.
- gradient accumulation은 global negative pool을 자동으로 키우지 않는다.
- tokenizer·전처리·joint model·prompt·cache hash가 하나의 배포 계약이다.
- ONNX·C++·C# runtime은 embedding 수치와 top-k를 Python golden과 비교해야 한다.
