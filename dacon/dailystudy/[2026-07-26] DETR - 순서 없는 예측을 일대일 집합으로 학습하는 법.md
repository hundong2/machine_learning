## 선수 지식과 기호

필요한 선수 지식은 CNN feature map, softmax와 cross entropy, bounding box, IoU, 행렬 곱, Transformer의 self-attention과 cross-attention 기초다.

| 기호 | 뜻 |
| --- | --- |
| $N$ | batch 크기 |
| $K$ | foreground class 수 |
| $Q$ | 고정 object query 수 |
| $M_n$ | batch의 $n$번째 영상에 있는 실제 객체 수 |
| $D$ | Transformer embedding 차원 |
| $H_f,W_f$ | backbone feature의 높이와 너비 |
| $S=H_fW_f$ | 펼친 영상 token 수 |
| $c_m$ | $m$번째 정답의 foreground class |
| $b_m$ | $m$번째 정답의 정규화된 box |
| $\hat{p}_q$ | $q$번째 query의 class 확률 분포 |
| $\hat{b}_q$ | $q$번째 query의 예측 box |
| $\varnothing$ | 실제 객체가 없음을 나타내는 `no-object` class |
| $\pi(m)$ | 정답 $m$에 일대일로 배정된 query index |

이 글에서 class logit은 `(N,Q,K+1)`, box는 `(N,Q,4)`다. 마지막 class가 $\varnothing$다. box는 특별한 언급이 없으면 영상 크기로 정규화된 `CXCYWH`, 즉 $(c_x,c_y,w,h)\in[0,1]^4$다.

## 1. 직관: 번호가 아니라 구성원이 중요한 출력

영상에 고양이와 강아지가 한 마리씩 있다고 하자. 다음 두 출력은 순서만 다르고 같은 탐지 결과다.

$$
\{
(\text{고양이},b_1),
(\text{강아지},b_2)
\}
$$

$$
\{
(\text{강아지},b_2),
(\text{고양이},b_1)
\}
$$

첫 번째 출력의 0번 slot이 반드시 고양이라는 규칙은 없다. 따라서 index별로 정답을 고정해 다음 loss를 계산하면 잘못이다.

$$
\mathcal{L}(\hat{y}_0,y_0)
+
\mathcal{L}(\hat{y}_1,y_1)
$$

먼저 예측과 정답을 가장 잘 맞는 일대일 쌍으로 정한 뒤 loss를 계산해야 한다. DETR는 이 단계를 bipartite matching으로 해결한다.

DETR의 $Q$개 query는 “첫 번째 query는 사람”처럼 미리 의미가 정해진 class template이 아니다. 학습되는 embedding slot이며, 영상 memory를 cross-attention으로 읽고 각자 class와 box 하나를 제안한다. 실제 객체가 $M<Q$개면 남은 $Q-M$개 query는 $\varnothing$를 예측하도록 학습한다.

## 2. FCOS와 DETR의 문제 분해 비교

| 질문 | FCOS | DETR |
| --- | --- | --- |
| 후보의 출발점 | FPN의 모든 spatial point | 고정된 $Q$개 object query |
| 후보 수 | 입력 해상도와 FPN shape에 따라 변함 | 모델 계약의 $Q$로 고정 |
| 정답 배정 | 내부 point, level range, tie-break | 전역 최소 비용 일대일 matching |
| box 표현 | point 기준 `LTRB` 거리 | 정규화된 `CXCYWH` |
| background | dense location별 negative | unmatched query의 $\varnothing$ |
| 중복 억제 | 보통 NMS 필요 | set loss로 학습해 NMS 없이 출력 |
| 작은 객체 | 고해상도 FPN level 활용 | 원형 DETR의 단일 저해상도 feature가 약점 |

둘 다 anchor의 scale·aspect ratio 열거를 없앴지만 같은 모델은 아니다. FCOS는 dense prediction을 유지하고 DETR는 출력 자체를 작은 고정 크기 집합으로 만든다.

## 3. 원본에서 구분하거나 바로잡을 점

원본의 큰 방향은 맞지만 실제 구현에서는 다음 경계를 명확히 해야 한다.

| 원본의 표현 | 정확한 구현 관점 |
| --- | --- |
| self-attention이 query끼리 대화해 중복을 없앰 | decoder self-attention이 관계 모델링을 돕지만 **일대일 matching을 사용하는 set loss**가 unique prediction을 직접 강제한다. 둘을 함께 봐야 한다. |
| 고정 $N$개 box를 무조건 출력 | 정확히는 $Q$개 slot마다 class logit과 box를 출력한다. 많은 slot은 $\varnothing$로 해석되어 최종 detection에서 제외된다. |
| matched prediction으로만 loss를 업데이트 | box loss는 matched query에만 적용하지만, class loss는 unmatched query에도 $\varnothing$ target으로 적용한다. |
| matching 식이 $N$개 padded GT 전체를 순열로 탐색 | 논문 설명은 GT를 $\varnothing$로 padding하지만 공식 구현은 `Q x M` 비용 행렬에서 $M$개 실제 GT만 query에 배정한다. unmatched query는 이후 class target에서 $\varnothing$가 된다. |
| class 비용은 “낮은 확률” | 원 논문 matching cost는 실제 class 확률의 음수 $-\hat{p}(c)$를 사용한다. training cross entropy는 $-\log\hat{p}(c)$를 사용한다. |
| box 거리와 class 비용만 사용 | 원형 DETR matcher는 class, L1 box, GIoU 비용을 결합한다. GIoU를 빼면 겹침의 기하를 matching에 반영하지 못한다. |
| 예제의 `pred_logits`가 foreground class만 포함 | 실제 class head는 $K+1$ logits를 내며 마지막 index가 $\varnothing$다. |
| `torch.rand(100,4)` box면 충분 | random 4-vector가 유효한 `CXCYWH`인지, 좌표가 정규화됐는지 계약을 밝혀야 한다. GIoU 계산 전 `XYXY` 변환도 필요하다. |
| DETR이 crowd에서 겹친 객체를 항상 더 잘 구별 | NMS 삭제는 겹침 삭제 오류를 피할 가능성을 주지만, crowd 성능을 자동 보장하지 않는다. annotation, query 수, feature 해상도, 학습 수렴의 영향을 받는다. |
| Transformer를 쓴 최근 모델을 모두 DETR 계열로 볼 수 있음 | Transformer 사용만으로 DETR는 아니다. direct set prediction과 일대일 matching이 핵심 구분이다. |

원본은 제1저자를 “니콜라 카리온”으로 적었는데, 검색과 인용에서는 논문 표기인 **Nicolas Carion**을 함께 쓰는 편이 안전하다.

검증 기준은 [DETR 원 논문](https://arxiv.org/abs/2005.12872)과 [공식 구현](https://github.com/facebookresearch/detr)이다.

## 4. 아키텍처와 tensor shape 추적

### 4.1 예시 입력 계약

작은 실행 예제를 위해 다음 값을 사용한다.

| 항목 | 값 |
| --- | ---: |
| batch | $N=2$ |
| 입력 | `(2,3,64,80)` |
| backbone stride | 4 |
| feature channel | $D=32$ |
| feature | `(2,32,16,20)` |
| 영상 token 수 | $S=16 \times 20=320$ |
| query 수 | $Q=5$ |
| foreground class | $K=3$ |

### 4.2 CNN feature를 sequence로 펼치기

CNN backbone과 `1x1` projection의 출력이 다음과 같다고 하자.

$$
F\in\mathbb{R}^{N\times D\times H_f\times W_f}
$$

교육용 코드는 현대 PyTorch의 `batch_first=True` 계약을 사용한다. 펼친 source shape는 다음과 같다.

$$
\operatorname{flatten}(F)
\in
\mathbb{R}^{N\times S\times D}
$$

예시에서는 다음과 같다.

```text
input                 (2, 3, 64, 80)
backbone feature      (2, 32, 16, 20)
flattened source      (2, 320, 32)
padding mask          (2, 320)
encoder memory        (2, 320, 32)
object queries        (2, 5, 32)
decoder states        (2, 5, 32)
class logits          (2, 5, 4)
normalized boxes      (2, 5, 4)
```

class logit의 마지막 차원이 4인 이유는 foreground 3개와 $\varnothing$ 1개다.

### 4.3 위치 정보가 필요한 이유

feature를 펼치면 token index만으로는 위·아래·왼쪽·오른쪽을 알 수 없다. 공간 positional encoding $P$를 더해 위치를 보존한다.

$$
Z_0=\operatorname{flatten}(F)+P
$$

padding이 있는 batch에서는 mask도 함께 전달해야 한다. mask shape는 보통 `(N,H_f,W_f)`에서 `(N,S)`로 펼치며, `True`를 무시할 위치로 사용하는지 프레임워크 계약을 확인해야 한다.

### 4.4 object query는 영상 patch가 아니다

영상 token은 backbone feature에서 오지만 object query embedding $E_q\in\mathbb{R}^{Q\times D}$는 학습 parameter다. batch마다 같은 초기 query embedding을 복제하되, cross-attention 결과는 영상마다 달라진다.

$$
E_q
\rightarrow
\mathbb{R}^{N\times Q\times D}
$$

decoder의 각 query는 encoder memory 전체를 읽고 최종 hidden state $h_q$를 만든다.

$$
\hat{p}_q
=
\operatorname{softmax}(W_ch_q)
$$

$$
\hat{b}_q
=
\operatorname{sigmoid}
\left(
\operatorname{MLP}(h_q)
\right)
$$

sigmoid 때문에 box 네 값은 $[0,1]$ 범위에 있다. 이 값은 pixel `XYXY`가 아니라 정규화된 `CXCYWH`다.

## 5. 순열 불변성을 만드는 일대일 matching

### 5.1 비용 행렬

실제 객체가 $M$개이고 query가 $Q$개라면 비용 행렬은 다음 shape다.

$$
C\in\mathbb{R}^{Q\times M}
$$

$C_{qm}$은 query $q$를 정답 $m$에 배정할 때의 비용이다.

$$
C_{qm}
=
-\lambda_{\mathrm{cls}}
\hat{p}_q(c_m)
+
\lambda_{L1}
\left\|
\hat{b}_q-b_m
\right\|_1
+
\lambda_{\mathrm{giou}}
\left(
1-\operatorname{GIoU}(\hat{b}_q,b_m)
\right)
$$

상수 1을 빼도 최적 배정은 같으므로 구현은 GIoU 항을 다음처럼 쓸 수 있다.

$$
C_{qm}^{\mathrm{giou}}
=
-\operatorname{GIoU}(\hat{b}_q,b_m)
$$

### 5.2 rectangular assignment

$Q\ge M$일 때 각 정답에 서로 다른 query 하나를 배정한다.

$$
\hat{\pi}
=
\operatorname*{arg\,min}_{\pi}
\sum_{m=1}^{M}
C_{\pi(m),m}
$$

제약 조건은 다음과 같다.

$$
\pi(m_1)\ne\pi(m_2)
\quad
\text{if}
\quad
m_1\ne m_2
$$

즉 한 query가 두 정답을 동시에 담당할 수 없다. $Q-M$개 query는 배정되지 않고 $\varnothing$ target을 받는다.

### 5.3 수작업으로 3개 query와 2개 GT 배정하기

결합 비용이 다음과 같다고 하자. 행은 query, 열은 GT다.

$$
C
=
\begin{bmatrix}
0.20 & 1.40 \\
0.80 & 0.25 \\
0.45 & 0.70
\end{bmatrix}
$$

가능한 injective assignment는 $3\times2=6$개다.

| GT 0 담당 | GT 1 담당 | 합계 |
| --- | --- | ---: |
| query 0 | query 1 | $0.20+0.25=0.45$ |
| query 0 | query 2 | $0.20+0.70=0.90$ |
| query 1 | query 0 | $0.80+1.40=2.20$ |
| query 1 | query 2 | $0.80+0.70=1.50$ |
| query 2 | query 0 | $0.45+1.40=1.85$ |
| query 2 | query 1 | $0.45+0.25=0.70$ |

최적 배정은 `GT 0 -> query 0`, `GT 1 -> query 1`이고 총비용은 0.45다. query 2는 unmatched이므로 class target이 $\varnothing$가 된다.

### 5.4 greedy가 실패하는 이유

각 GT가 독립적으로 가장 싼 query를 고르면 같은 query를 선택할 수 있다. 반대로 query 순서대로 가장 싼 GT를 고르면 앞선 선택이 뒤의 훨씬 좋은 조합을 막을 수 있다. Hungarian algorithm은 모든 일대일 제약을 고려해 총비용을 최소화한다.

matching은 discrete index를 고르는 연산이라 미분하지 않는다. `detach()`된 예측으로 index를 구한 뒤, 원래 tensor에서 선택한 값으로 loss를 계산해 gradient를 흘린다.

## 6. matching cost와 training loss는 다르다

두 단계의 목적을 분리해야 한다.

1. matching cost: 어떤 query가 어떤 GT를 담당할지 고른다.
2. training loss: 선택된 쌍과 unmatched query를 실제로 최적화한다.

### 6.1 class loss

matching 뒤 각 query의 target $t_q$를 만든다.

$$
t_q
=
\begin{cases}
c_m,
&
q=\hat{\pi}(m)
\\
\varnothing,
&
q\notin\operatorname{image}(\hat{\pi})
\end{cases}
$$

class loss는 모든 query에 계산한다.

$$
\mathcal{L}_{\mathrm{cls}}
=
-\sum_{q=1}^{Q}
w(t_q)
\log\hat{p}_q(t_q)
$$

$\varnothing$가 너무 많으므로 원형 DETR는 해당 class weight를 낮춘다. 흔한 값은 다음과 같다.

$$
w(\varnothing)=0.1
$$

이 값은 “background 확률을 0.1로 만들라”는 뜻이 아니라 cross entropy 기여도를 낮추는 weight다.

### 6.2 box loss

box loss는 matched query에만 적용한다.

$$
\mathcal{L}_{\mathrm{box}}
=
\sum_{m=1}^{M}
\left[
\lambda_{L1}
\left\|
b_m-\hat{b}_{\hat{\pi}(m)}
\right\|_1
+
\lambda_{\mathrm{giou}}
\left(
1-\operatorname{GIoU}
\left(
b_m,\hat{b}_{\hat{\pi}(m)}
\right)
\right)
\right]
$$

전체 loss는 보통 다음 결합이다.

$$
\mathcal{L}
=
\mathcal{L}_{\mathrm{cls}}
+
\mathcal{L}_{\mathrm{box}}
$$

실제 구현에서는 batch의 총 GT 수로 box loss를 정규화하고 distributed training이면 worker 사이에서 그 수를 동기화한다.

### 6.3 auxiliary decoder loss

원형 DETR는 마지막 decoder layer뿐 아니라 중간 layer의 출력에도 같은 종류의 loss를 붙인다. 각 layer마다 matching을 다시 계산할 수 있으며, 이는 초기 layer에도 직접 supervision을 줘 수렴을 돕는다.

중간 layer가 $L_d$개라면 class logit의 논리 shape는 다음처럼 볼 수 있다.

$$
\text{aux logits}
\in
\mathbb{R}^{(L_d-1)\times N\times Q\times(K+1)}
$$

ONNX로 export할 때 intermediate output을 배포에 쓰지 않는다면 제거해 graph와 메모리를 줄인다.

## 7. L1과 GIoU를 함께 쓰는 이유

### 7.1 좌표별 L1

정규화된 `CXCYWH` box의 L1 거리는 다음과 같다.

$$
\left\|
b-\hat{b}
\right\|_1
=
|c_x-\hat{c}_x|
+
|c_y-\hat{c}_y|
+
|w-\hat{w}|
+
|h-\hat{h}|
$$

좌표 차이를 직접 줄여 안정적인 신호를 준다. 그러나 같은 L1 거리라도 실제 겹침은 box 크기와 방향에 따라 달라질 수 있다.

### 7.2 IoU

`XYXY`로 바꾼 두 영역을 $A,B$라 하자.

$$
\operatorname{IoU}(A,B)
=
\frac{|A\cap B|}{|A\cup B|}
$$

두 box가 겹치지 않으면 IoU는 0이고, 이동 방향에 대한 유용한 차이를 주기 어렵다.

### 7.3 GIoU

$C$를 $A$와 $B$를 모두 포함하는 가장 작은 enclosing box라 하자.

$$
\operatorname{GIoU}(A,B)
=
\operatorname{IoU}(A,B)
-
\frac{
|C\setminus(A\cup B)|
}{
|C|
}
$$

겹치지 않아도 enclosing box의 빈 영역이 달라지므로 위치 관계를 구분한다. 범위는 다음과 같다.

$$
-1
\le
\operatorname{GIoU}
\le
1
$$

완전히 같으면 GIoU는 1이고 loss $1-\operatorname{GIoU}$는 0이다.

### 7.4 `CXCYWH`와 `XYXY`의 역할 분리

- L1: 정규화된 `CXCYWH`에서 계산
- GIoU: `XYXY`로 변환한 뒤 계산
- 화면 출력: 정규화 `XYXY`에 원본 영상 크기를 곱함

한 함수 안에서 pixel box와 normalized box를 섞으면 큰 영상의 L1만 과도하게 커진다.

## 8. NumPy와 SciPy로 matching 검증

다음 코드는 실행 가능하다. 작은 비용 행렬을 직접 만들고 모든 순열의 최솟값과 SciPy 결과를 교차 검증한다. 이 코드는 box geometry가 아니라 **assignment objective만** 격리한 golden test다.

```python
# RUNNABLE: numpy_detr_assignment
from itertools import permutations

import numpy as np
from scipy.optimize import linear_sum_assignment

cost = np.array(
    [
        [0.20, 1.40],
        [0.80, 0.25],
        [0.45, 0.70],
    ],
    dtype=np.float64,
)

# 각 GT column에 서로 다른 query row를 배정한다.
best_total = float("inf")
best_rows = None
num_queries, num_targets = cost.shape

for rows in permutations(range(num_queries), num_targets):
    total = sum(cost[rows[target], target] for target in range(num_targets))
    if total < best_total:
        best_total = total
        best_rows = rows

row_ind, col_ind = linear_sum_assignment(cost)
scipy_total = cost[row_ind, col_ind].sum()

print("brute force:", best_rows, best_total)
print("scipy:", row_ind.tolist(), col_ind.tolist(), scipy_total)

assert best_rows == (0, 1)
assert np.isclose(best_total, 0.45)
assert row_ind.tolist() == [0, 1]
assert col_ind.tolist() == [0, 1]
assert np.isclose(scipy_total, best_total)
```

## 9. PyTorch 구현: mini DETR, matcher, loss

### 9.1 구현 범위

다음 코드는 실행 가능한 교육용 축소 구현이다.

- 작은 CNN backbone
- learned 2D positional embedding
- 표준 `nn.Transformer`
- learned object query
- class head와 box MLP
- class·L1·GIoU matching
- unmatched query의 $\varnothing$ cross entropy
- matched query의 L1·GIoU loss
- empty-GT image가 섞인 batch
- backward와 shape assertion

실전 원형 DETR의 다단 ResNet, padding mask, decoder auxiliary loss, distributed normalization은 단순화를 위해 생략한다.

```python
# RUNNABLE: pytorch_mini_detr
import torch
from scipy.optimize import linear_sum_assignment
from torch import nn
from torch.nn import functional as F

torch.manual_seed(7)


def box_cxcywh_to_xyxy(boxes):
    cx, cy, w, h = boxes.unbind(-1)
    return torch.stack(
        [cx - 0.5 * w, cy - 0.5 * h, cx + 0.5 * w, cy + 0.5 * h],
        dim=-1,
    )


def box_area(boxes):
    size = (boxes[..., 2:] - boxes[..., :2]).clamp(min=0)
    return size[..., 0] * size[..., 1]


def pairwise_giou(boxes1, boxes2):
    area1 = box_area(boxes1)
    area2 = box_area(boxes2)

    lt = torch.maximum(boxes1[:, None, :2], boxes2[None, :, :2])
    rb = torch.minimum(boxes1[:, None, 2:], boxes2[None, :, 2:])
    inter_size = (rb - lt).clamp(min=0)
    inter = inter_size[..., 0] * inter_size[..., 1]
    union = area1[:, None] + area2[None, :] - inter
    iou = inter / union.clamp(min=1e-7)

    enclosing_lt = torch.minimum(boxes1[:, None, :2], boxes2[None, :, :2])
    enclosing_rb = torch.maximum(boxes1[:, None, 2:], boxes2[None, :, 2:])
    enclosing_size = (enclosing_rb - enclosing_lt).clamp(min=0)
    enclosing = enclosing_size[..., 0] * enclosing_size[..., 1]
    return iou - (enclosing - union) / enclosing.clamp(min=1e-7)


class BoxMLP(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(dim, dim),
            nn.ReLU(),
            nn.Linear(dim, dim),
            nn.ReLU(),
            nn.Linear(dim, 4),
        )

    def forward(self, x):
        return self.layers(x)


class MiniDETR(nn.Module):
    def __init__(self, num_classes=3, num_queries=5, dim=32):
        super().__init__()
        self.backbone = nn.Sequential(
            nn.Conv2d(3, 16, kernel_size=3, stride=2, padding=1),
            nn.ReLU(),
            nn.Conv2d(16, dim, kernel_size=3, stride=2, padding=1),
            nn.ReLU(),
        )
        self.row_embed = nn.Embedding(32, dim // 2)
        self.col_embed = nn.Embedding(32, dim // 2)
        self.query_embed = nn.Embedding(num_queries, dim)
        self.transformer = nn.Transformer(
            d_model=dim,
            nhead=4,
            num_encoder_layers=2,
            num_decoder_layers=2,
            dim_feedforward=64,
            dropout=0.0,
            batch_first=True,
        )
        self.class_embed = nn.Linear(dim, num_classes + 1)
        self.box_embed = BoxMLP(dim)

    def forward(self, images):
        features = self.backbone(images)
        n, d, h, w = features.shape

        rows = self.row_embed(torch.arange(h, device=images.device))
        cols = self.col_embed(torch.arange(w, device=images.device))
        pos = torch.cat(
            [
                cols.unsqueeze(0).expand(h, -1, -1),
                rows.unsqueeze(1).expand(-1, w, -1),
            ],
            dim=-1,
        )
        pos = pos.flatten(0, 1).unsqueeze(0).expand(n, -1, -1)
        src = features.flatten(2).transpose(1, 2)

        queries = self.query_embed.weight.unsqueeze(0).expand(n, -1, -1)
        states = self.transformer(src + pos, queries)
        return {
            "pred_logits": self.class_embed(states),
            "pred_boxes": self.box_embed(states).sigmoid(),
            "feature_shape": tuple(features.shape),
        }


@torch.no_grad()
def match_one(logits, boxes, target, class_cost=1.0, l1_cost=5.0, giou_cost=2.0):
    labels = target["labels"]
    target_boxes = target["boxes"]
    if labels.numel() == 0:
        empty = torch.empty(0, dtype=torch.int64, device=logits.device)
        return empty, empty

    probabilities = logits.float().softmax(-1)
    cost_class = -probabilities[:, labels]
    cost_l1 = torch.cdist(boxes.float(), target_boxes.float(), p=1)
    cost_giou = -pairwise_giou(
        box_cxcywh_to_xyxy(boxes.float()),
        box_cxcywh_to_xyxy(target_boxes.float()),
    )
    cost = class_cost * cost_class + l1_cost * cost_l1 + giou_cost * cost_giou

    query_idx, target_idx = linear_sum_assignment(cost.cpu().numpy())
    return (
        torch.as_tensor(query_idx, dtype=torch.int64, device=logits.device),
        torch.as_tensor(target_idx, dtype=torch.int64, device=logits.device),
    )


def detr_loss(outputs, targets, num_classes=3):
    logits = outputs["pred_logits"]
    boxes = outputs["pred_boxes"]
    matches = [
        match_one(logits[n], boxes[n], targets[n])
        for n in range(logits.shape[0])
    ]

    # 모든 query는 기본적으로 no-object target이다.
    target_classes = torch.full(
        logits.shape[:2],
        fill_value=num_classes,
        dtype=torch.int64,
        device=logits.device,
    )
    for batch_idx, (query_idx, target_idx) in enumerate(matches):
        if query_idx.numel() > 0:
            target_classes[batch_idx, query_idx] = targets[batch_idx]["labels"][target_idx]

    class_weight = torch.ones(num_classes + 1, device=logits.device)
    class_weight[-1] = 0.1
    loss_ce = F.cross_entropy(logits.transpose(1, 2), target_classes, class_weight)

    predicted_matched = []
    target_matched = []
    for batch_idx, (query_idx, target_idx) in enumerate(matches):
        if query_idx.numel() > 0:
            predicted_matched.append(boxes[batch_idx, query_idx])
            target_matched.append(targets[batch_idx]["boxes"][target_idx])

    if predicted_matched:
        predicted_matched = torch.cat(predicted_matched)
        target_matched = torch.cat(target_matched)
        loss_l1 = F.l1_loss(predicted_matched, target_matched, reduction="mean")
        giou = pairwise_giou(
            box_cxcywh_to_xyxy(predicted_matched),
            box_cxcywh_to_xyxy(target_matched),
        )
        loss_giou = (1.0 - torch.diag(giou)).mean()
    else:
        # graph를 유지하는 미분 가능한 0
        loss_l1 = boxes.sum() * 0.0
        loss_giou = boxes.sum() * 0.0

    total = loss_ce + 5.0 * loss_l1 + 2.0 * loss_giou
    return total, {
        "ce": loss_ce.detach(),
        "l1": loss_l1.detach(),
        "giou": loss_giou.detach(),
    }, matches


model = MiniDETR(num_classes=3, num_queries=5, dim=32)
images = torch.randn(2, 3, 64, 80)
targets = [
    {
        "labels": torch.tensor([0, 2]),
        "boxes": torch.tensor(
            [
                [0.30, 0.40, 0.20, 0.30],
                [0.72, 0.65, 0.16, 0.18],
            ],
            dtype=torch.float32,
        ),
    },
    {
        "labels": torch.empty(0, dtype=torch.int64),
        "boxes": torch.empty(0, 4),
    },
]

outputs = model(images)
loss, parts, matches = detr_loss(outputs, targets)
loss.backward()

print("feature:", outputs["feature_shape"])
print("logits:", tuple(outputs["pred_logits"].shape))
print("boxes:", tuple(outputs["pred_boxes"].shape))
print("matches:", [(q.tolist(), t.tolist()) for q, t in matches])
print("loss:", round(loss.item(), 6), {k: round(v.item(), 6) for k, v in parts.items()})

assert outputs["feature_shape"] == (2, 32, 16, 20)
assert outputs["pred_logits"].shape == (2, 5, 4)
assert outputs["pred_boxes"].shape == (2, 5, 4)
assert len(matches[0][0]) == 2
assert len(matches[1][0]) == 0
assert torch.isfinite(loss)
assert model.query_embed.weight.grad is not None
assert torch.isfinite(model.query_embed.weight.grad).all()
```

### 9.2 코드에서 꼭 읽어야 할 경계

- matcher의 `@torch.no_grad()`는 index 선택을 loss graph와 분리한다.
- `cost.cpu().numpy()`는 GPU와 CPU 사이 동기화를 만든다.
- 빈 GT에서는 빈 index를 반환하지만 모든 query의 $\varnothing$ class loss는 남는다.
- `class_weight[-1]=0.1`은 unmatched query를 무시하지 않고 낮은 weight로 학습한다.
- GIoU pairwise matrix에서 matched pair만 `diag`로 뽑는다.
- 교육용 model은 padding mask가 없으므로 batch의 모든 입력이 같은 유효 크기라고 가정한다.

## 10. C++ 예제: 작은 rectangular assignment 완전 탐색

다음 코드는 실행 가능하다. Hungarian algorithm 전체 구현이 아니라 $3\times2$ golden matrix의 가능한 배정을 완전 탐색한다. production에서는 검증된 linear assignment library를 사용해야 한다.

```cpp
// RUNNABLE: cpp_detr_assignment
#include <array>
#include <cassert>
#include <iomanip>
#include <iostream>
#include <limits>

int main() {
    constexpr int queries = 3;
    constexpr int targets = 2;
    const std::array<std::array<double, targets>, queries> cost{{
        {{0.20, 1.40}},
        {{0.80, 0.25}},
        {{0.45, 0.70}},
    }};

    double best = std::numeric_limits<double>::infinity();
    int best_q0 = -1;
    int best_q1 = -1;

    for (int q0 = 0; q0 < queries; ++q0) {
        for (int q1 = 0; q1 < queries; ++q1) {
            if (q0 == q1) {
                continue;
            }
            const double total = cost[q0][0] + cost[q1][1];
            if (total < best) {
                best = total;
                best_q0 = q0;
                best_q1 = q1;
            }
        }
    }

    std::cout << "GT0->Q" << best_q0
              << " GT1->Q" << best_q1
              << " total=" << std::fixed << std::setprecision(2)
              << best << '\n';

    assert(best_q0 == 0);
    assert(best_q1 == 1);
    assert(best > 0.449999 && best < 0.450001);
}
```

## 12. 프레임워크 간 shape·layout·dtype 대응

### 12.1 공통 tensor 계약

| 의미 | PyTorch 학습 | ONNX/runtime | C++ flat offset | C# flat offset |
| --- | --- | --- | --- | --- |
| 입력 영상 | `(N,3,H,W)` `float32` | 보통 `NCHW` `float32` | `((n*3+c)*H+y)*W+x` | 동일 |
| class logit | `(N,Q,K+1)` | `(N,Q,K+1)` | `(n*Q+q)*(K+1)+c` | 동일 |
| box | `(N,Q,4)` | `(N,Q,4)` | `(n*Q+q)*4+k` | 동일 |
| box 순서 | `cx,cy,w,h` | model metadata로 고정 | index 0,1,2,3 | index 0,1,2,3 |
| box 단위 | image-normalized | image-normalized | 원본 크기로 decode | 원본 크기로 decode |
| padding mask | `(N,H_f,W_f)` bool | export 설계에 따라 다름 | 보통 model 내부 | 보통 model 내부 |

runtime가 `NHWC` 입력을 선호하더라도 model이 `NCHW`로 export됐다면 host에서 transpose하거나 export graph에 transpose를 포함해야 한다. 이름만 보고 추측하지 말고 runtime session의 실제 input shape를 검사한다.

### 12.2 box decode

정규화 `CXCYWH`를 `XYXY`로 바꾼다.

$$
x_0=c_x-\frac{w}{2}
$$

$$
y_0=c_y-\frac{h}{2}
$$

$$
x_1=c_x+\frac{w}{2}
$$

$$
y_1=c_y+\frac{h}{2}
$$

원본 영상 크기가 $W_0,H_0$이면 pixel 좌표는 다음과 같다.

$$
(x_0W_0,\ y_0H_0,\ x_1W_0,\ y_1H_0)
$$

단, resize 뒤 padding한 입력을 썼다면 model input 좌표에서 padding을 제거하고 resize scale을 역적용해야 한다. 단순히 원본 크기만 곱하면 letterbox 영역에서 틀린다.

### 12.3 dtype

- 학습 forward는 mixed precision을 쓸 수 있다.
- matching cost의 softmax, L1, GIoU는 `float32`로 올리는 편이 안전하다.
- class training loss는 raw logit에 안정적인 fused cross entropy를 사용한다.
- box width·height와 enclosing area의 분모에는 작은 하한을 둔다.
- query index와 target label은 `int64` 계약이 흔하다.
- C++/C# 후처리가 `double`을 쓰더라도 model output은 대개 `float32`다.

## 13. 테스트와 디버깅

### 13.1 최소 단위 테스트

| 테스트 | 잡아내는 문제 |
| --- | --- |
| GT 순서를 바꿔도 총 set loss가 같은가 | 순열 불변성 파손 |
| 예측 query 순서를 바꿔도 최적 총비용이 같은가 | index 고정 loss |
| 동일 box의 GIoU가 1인가 | 좌표 변환 오류 |
| 겹치지 않는 box에서 GIoU가 finite인가 | 0 union·enclosing 처리 |
| 빈 GT에서 matcher가 빈 index를 반환하는가 | SciPy shape 오류 |
| 빈 GT에서도 class loss와 gradient가 finite인가 | 모든 loss를 0으로 만드는 버그 |
| $M>Q$를 거부하는가 | query capacity 부족 |
| padding pixel을 바꿔도 유효 영역 출력이 안정적인가 | padding mask 누락 |
| 같은 cost의 tie에서 총비용을 비교하는가 | raw index 과적합 테스트 |
| PyTorch와 ONNX raw output이 tolerance 안에 드는가 | export/layout 회귀 |

### 13.2 증상에서 원인 찾기

| 증상 | 우선 확인할 원인 |
| --- | --- |
| 모든 query가 $\varnothing$ | no-object weight 과대, class index 오류, matching cost scale 불균형 |
| 같은 객체를 여러 query가 출력 | matching/loss 연결 오류, 학습 부족, decoder 상호작용 부족 |
| box 중심은 맞고 크기만 이상 | `CXCYWH`와 `XYXY` 혼동 |
| 큰 영상에서만 box가 틀어짐 | normalized와 pixel 좌표 혼용 |
| batch 크기 1은 되고 padding batch는 실패 | mask flatten 순서 또는 polarity 오류 |
| 작은 객체가 거의 검출되지 않음 | feature stride, 해상도, resize, 원형 DETR의 단일-scale 한계 |
| loss가 갑자기 NaN | degenerate box, GIoU 분모, half precision geometry |
| GPU utilization이 주기적으로 떨어짐 | matching의 CPU sync와 data pipeline stall |
| ONNX score가 PyTorch와 다름 | softmax axis 또는 $\varnothing$ index 오류 |

### 13.3 matching cost scale 검사

class, L1, GIoU 비용의 평균과 표준편차를 따로 기록한다. 한 항이 다른 항보다 수십 배 크면 matching이 사실상 한 신호만 사용한다.

```text
cost/class mean, std
cost/l1 mean, std
cost/giou mean, std
matched class accuracy
matched box L1
matched GIoU
unmatched no-object probability
```

loss weight와 matcher weight는 이름이 비슷해도 서로 다른 설정일 수 있다. config에서 둘을 분리하고 실험 기록에 함께 남긴다.

## 14. 성능·메모리·수치 안정성

### 14.1 encoder self-attention

영상 token 수가 $S=H_fW_f$이면 dense self-attention score의 원소 수는 head당 대략 다음과 같다.

$$
S^2
=
(H_fW_f)^2
$$

feature의 높이와 너비를 각각 2배로 만들면 token은 4배가 되고 attention score는 16배가 된다.

$$
(4S)^2=16S^2
$$

작은 객체를 위해 해상도를 무작정 높이면 메모리와 latency가 급증한다. 이것이 multi-scale 또는 sparse/deformable attention 계열 설계가 등장한 이유 중 하나다.

### 14.2 decoder attention

- query self-attention: 대략 $O(Q^2D)$
- query-to-image cross-attention: 대략 $O(QSD)$
- class·box head: 대략 $O(QD)$

$Q$를 늘리면 최대 detection capacity는 늘지만 decoder 연산, class imbalance, matching 행 수가 함께 증가한다.

### 14.3 matching 비용

batch마다 `Q x M_n` cost matrix를 만든다. $Q=100$이고 일반 영상의 $M_n$이 작으면 행렬 자체는 크지 않지만, GPU tensor를 CPU SciPy로 보내는 동기화가 throughput을 끊을 수 있다.

프로파일링할 때 다음을 분리한다.

1. GPU forward
2. cost matrix 생성
3. device-to-host 복사와 동기화
4. linear assignment
5. loss gather와 backward

추론에는 GT도 matcher도 필요 없다. training-only dependency인 SciPy를 inference image에 포함하지 않는다.

### 14.4 수치 안정성

- matching class cost는 `softmax(float_logits)`에서 계산한다.
- training class loss는 확률에 `log`를 직접 씌우지 말고 raw logits의 cross entropy를 사용한다.
- invalid box는 GIoU 전에 검출한다.
- area와 union은 작은 양수로 clamp한다.
- mixed precision에서 box geometry만 `float32`로 올려도 NaN 위험을 줄일 수 있다.
- sigmoid가 0 또는 1 근처에서 포화하면 box head gradient가 작아질 수 있으므로 초기 출력 분포를 관찰한다.

## 15. 실무 실패 사례

### 사례 1: unmatched query를 loss에서 완전히 제외

팀이 “matched prediction으로만 loss를 계산한다”는 설명을 문자 그대로 구현했다. 남는 query에는 아무 penalty가 없어 같은 객체 주변에 높은 foreground 예측이 다수 생겼다.

수정은 unmatched query의 class target을 $\varnothing$로 두고 낮은 weight의 cross entropy를 적용하는 것이다. box loss만 matched query로 제한한다.

### 사례 2: matcher와 training loss에서 class index가 다름

학습 dataset label은 `0..K-1`, runtime metadata는 `1..K`, $\varnothing$는 별도 index였다. matcher는 label 0을 배경으로 읽고 class loss는 마지막 index를 배경으로 읽어 배정과 학습 목표가 충돌했다.

dataset adapter에서 foreground를 `0..K-1`, $\varnothing$를 정확히 `K`로 변환하고 golden target으로 고정해야 한다.

### 사례 3: padding mask polarity 반전

프레임워크 A는 `1=valid`, Transformer API는 `True=ignore`였다. mask를 그대로 전달하자 실제 영상은 가리고 padding만 attention했다. 고정 크기 입력 테스트는 padding이 없어 통과했다.

서로 다른 aspect ratio 두 영상을 한 batch에 넣고 padding pixel을 큰 값으로 바꾸는 metamorphic test가 이 문제를 잘 잡는다.

### 사례 4: `CXCYWH`를 `XYXY`로 해석

box 값 `(0.5,0.5,0.2,0.4)`를 좌상단·우하단으로 그리자 width가 음수가 되거나 화면 중앙에 작은 상자가 몰렸다. output 이름을 `boxes_cxcywh_normalized`로 바꾸고 decode를 단일 shared library로 고쳤다.

### 사례 5: query 수보다 GT가 많은 crop

crowd crop에 137개 객체가 남았는데 $Q=100$이었다. 일대일 assignment는 최대 100개만 담당할 수 있다. evaluator가 annotation 37개를 누락한 것처럼 보였지만 모델 capacity 계약 문제였다.

dataset의 이미지별 객체 수 분포를 보고 $Q$를 정하고, $M>Q$ sample은 명시적으로 거부하거나 crop 정책과 query 수를 재설계한다.

### 사례 6: 원본 크기로 바로 곱한 letterbox box

host는 resize 후 오른쪽과 아래에 padding했지만 output box에 원본 $W_0,H_0$만 곱했다. box는 padding 비율만큼 한쪽으로 밀렸다.

model input의 실좌표로 decode한 뒤 padding offset을 빼고 resize scale을 역적용해야 한다.

### 사례 7: matching tie를 index 동일성으로 테스트

동일 비용이 여럿인 matrix에서 SciPy 버전이나 backend가 다른 최적 index를 골랐다. 총비용은 같았지만 테스트가 실패했다.

유일한 최적해가 필요한 golden matrix를 사용하거나, tie가 의도된 테스트에서는 assignment의 유효성과 최적 총비용을 검사한다.

## 16. 배포 관점

### 16.1 model output 계약

가장 단순한 inference graph는 두 raw output만 낸다.

```text
pred_logits: float32[N,Q,K+1]
pred_boxes:  float32[N,Q,4]  # normalized CXCYWH
```

host 후처리는 다음 순서로 한다.

1. class 축에 softmax
2. $\varnothing$를 제외한 foreground max class와 score 선택
3. score threshold 또는 top-k 적용
4. `CXCYWH -> XYXY`
5. resize·padding 역변환
6. image 경계 clip
7. label metadata 매핑

원형 DETR의 목적은 NMS를 생략하는 것이다. 품질 문제가 보인다고 NMS를 조용히 추가하면 training/evaluation/deployment 계약이 달라진다. 추가 실험을 한다면 별도 ablation으로 기록한다.

### 16.2 ONNX export 체크

- [ ] input 이름, `NCHW`, RGB 순서, normalization 평균·표준편차를 고정한다.
- [ ] dynamic batch와 dynamic height·width 범위를 실제 runtime에서 시험한다.
- [ ] $Q$와 $K+1$이 model version metadata와 일치한다.
- [ ] class softmax axis가 마지막 축인지 확인한다.
- [ ] $\varnothing$ index가 정확히 $K$인지 확인한다.
- [ ] box가 normalized `CXCYWH`인지 golden sample로 확인한다.
- [ ] padding mask가 graph 안에서 올바르게 생성·전달되는지 확인한다.
- [ ] PyTorch와 runtime의 raw logits·boxes를 먼저 비교한다.
- [ ] host 후처리까지 적용한 label·score·pixel box를 다시 비교한다.
- [ ] 빈 detection과 최대 $Q$ detection 모두 처리한다.

### 16.3 query 수는 API 계약이다

runtime buffer를 `(1,100,...)`으로 고정했는데 새 model이 $Q=300$이면 overflow 또는 output truncation이 생긴다. session에서 output shape를 읽어 buffer를 할당하고, metadata의 query count와 다르면 시작 시 실패하도록 한다.

### 16.4 모니터링

운영에서는 다음 proxy를 model version별로 기록한다.

- 영상당 foreground threshold 통과 query 수
- $\varnothing$ 확률의 평균과 분위수
- class별 detection 수
- normalized box center·width·height 분포
- image 경계 밖으로 나가 clip된 box 비율
- query index별 foreground 선택 빈도
- 작은·중간·큰 box 비율
- preprocessing, model, post-processing latency

모든 query가 갑자기 높은 $\varnothing$ 확률을 내면 실제 빈 장면 증가보다 normalization, channel order, class axis 회귀를 먼저 확인한다.

## 17. 원형 DETR의 한계와 선택 trade-off

### 17.1 느린 수렴

원형 DETR는 dense detector보다 긴 학습 schedule과 auxiliary decoder loss의 도움을 받는다. 작은 데이터에 짧게 fine-tuning하고 “Transformer가 학습되지 않는다”고 결론 내리기 전에 다음을 확인한다.

- pretrained backbone 또는 detector weight 사용 여부
- backbone과 Transformer의 learning rate 분리
- auxiliary loss
- random resize·crop augmentation
- gradient clipping
- no-object weight와 matcher cost

### 17.2 작은 객체

단일 저해상도 feature는 작은 객체 정보를 잃기 쉽다. 해상도를 높이면 encoder attention 비용이 제곱으로 늘어난다.

선택지는 다음과 같다.

- 더 높은 해상도 feature: 단순하지만 메모리 증가
- multi-scale feature: 작은 객체에 유리하지만 구조 복잡
- sparse/deformable attention: 계산을 줄이지만 custom operation과 배포 복잡성 증가

기초 회차에서는 “DETR는 NMS가 없으니 항상 더 빠르다”는 결론을 피한다. backbone, token 수, decoder layer, runtime kernel, post-processing 전체를 측정해야 한다.

### 17.3 고정 query capacity

$Q$는 upper bound다. 보통 객체 수보다 충분히 크게 잡지만 지나치게 크면 unmatched class 비율과 decoder 비용이 늘어난다. dataset의 객체 수 분포와 latency budget을 함께 보고 정한다.

## 18. 체크리스트

### 데이터와 target

- [ ] foreground label이 `0..K-1`인가
- [ ] $\varnothing$ index가 정확히 `K`인가
- [ ] box가 normalized `CXCYWH`인가
- [ ] width와 height가 양수인가
- [ ] crop·resize 뒤 box와 label이 함께 갱신되는가
- [ ] 이미지별 $M_n\le Q$인가
- [ ] 빈 GT 이미지가 포함되는가

### 모델과 loss

- [ ] logits shape가 `(N,Q,K+1)`인가
- [ ] boxes shape가 `(N,Q,4)`인가
- [ ] padding mask shape와 polarity가 맞는가
- [ ] matcher가 class·L1·GIoU 비용을 의도한 weight로 결합하는가
- [ ] matching index 계산은 gradient graph 밖인가
- [ ] unmatched query에 $\varnothing$ class loss가 적용되는가
- [ ] box loss는 matched query에만 적용되는가
- [ ] empty batch의 box loss가 미분 가능한 0인가
- [ ] distributed GT normalization이 worker 사이에서 같은가
- [ ] auxiliary decoder loss가 config대로 적용되는가

### 테스트와 배포

- [ ] GT·query 순열 불변성 테스트가 있는가
- [ ] identical·disjoint·degenerate box의 GIoU를 테스트했는가
- [ ] PyTorch와 ONNX raw output을 비교했는가
- [ ] class softmax axis와 $\varnothing$ index를 확인했는가
- [ ] box decode와 resize·padding 역변환을 golden test로 고정했는가
- [ ] query count를 runtime에서 읽거나 version 계약으로 검사하는가
- [ ] inference package에서 SciPy matcher를 제외했는가
- [ ] NMS를 사용하지 않는 평가·배포 계약이 일치하는가

## 20. 해답

### 해답 1

$K+1=6$이므로 class logit은 `(4,100,6)`, box는 `(4,100,4)`다.

### 해답 2

가능한 낮은 조합을 비교한다.

- `GT 0 -> query 1`, `GT 1 -> query 0`: $0.2+0.1=0.3$
- `GT 0 -> query 2`, `GT 1 -> query 0`: $0.3+0.1=0.4$
- `GT 0 -> query 0`, `GT 1 -> query 1`: $0.6+0.4=1.0$

최적 배정은 `GT 0 -> query 1`, `GT 1 -> query 0`이고 총비용은 0.3이다.

### 해답 3

3개 matched query에는 foreground class loss와 L1·GIoU box loss가 적용된다. 7개 unmatched query에는 $\varnothing$ class loss가 적용되고 box loss는 적용되지 않는다.

### 해답 4

$$
x_0=0.5-\frac{0.2}{2}=0.4
$$

$$
y_0=0.4-\frac{0.6}{2}=0.1
$$

$$
x_1=0.5+\frac{0.2}{2}=0.6
$$

$$
y_1=0.4+\frac{0.6}{2}=0.7
$$

따라서 `(0.4,0.1,0.6,0.7)`이다.

### 해답 5

$$
S=25\times40=1000
$$

head당 attention score 원소 수는 다음과 같다.

$$
S^2=1{,}000{,}000
$$

높이와 너비를 각각 2배로 하면 token은 4배, score 원소 수는 16배가 된다.

### 해답 6

matcher는 빈 index 쌍을 반환한다. 모든 query의 class target은 $\varnothing$가 되어 class loss는 계산된다. matched box가 없으므로 L1과 GIoU loss는 graph를 유지하는 0으로 만든다.

### 해답 7

원형 DETR의 matching class cost는 정답 class 확률의 음수 $-\hat{p}(c)$를 사용한다. 실제 training class loss는 negative log-likelihood, 즉 $-\log\hat{p}(c)$ 형태의 cross entropy를 사용한다.

## 21. 핵심 요약

1. 객체 탐지 결과는 순서가 의미 없는 집합이므로 index 고정 loss가 아니라 순열 불변 loss가 필요하다.
2. DETR는 $Q$개 learned object query로 고정 크기 class·box 집합을 병렬 예측한다.
3. query는 class template이나 영상 patch가 아니라 encoder memory를 읽는 학습 slot이다.
4. Hungarian matching은 `Q x M` class·L1·GIoU 비용에서 실제 GT마다 서로 다른 query를 배정한다.
5. matching cost는 배정 index를 고르고 training loss는 그 index를 사용해 parameter를 갱신한다.
6. box loss는 matched query에만, class loss는 unmatched query의 $\varnothing$까지 모든 query에 적용한다.
7. L1은 좌표 차이를, GIoU는 실제 겹침과 enclosing geometry를 제공한다.
8. 중복 억제는 decoder 관계 모델링만이 아니라 일대일 set loss와 함께 만들어진다.
9. 원형 DETR는 NMS를 제거하지만 긴 수렴 시간, 작은 객체, 고해상도 attention 비용이라는 trade-off가 있다.
10. `NCHW`, `(N,Q,K+1)`, normalized `CXCYWH`, $\varnothing$ index, query count는 학습과 ONNX host가 공유해야 하는 계약이다.
11. 빈 GT, $M>Q$, padding mask, tie, degenerate box를 테스트하지 않으면 정상 샘플만으로는 치명적인 오류를 놓친다.
12. Python·C++·C#에서 같은 작은 cost matrix를 교차 검증하면 assignment의 행·열 의미와 일대일 제약을 빠르게 고정할 수 있다.
