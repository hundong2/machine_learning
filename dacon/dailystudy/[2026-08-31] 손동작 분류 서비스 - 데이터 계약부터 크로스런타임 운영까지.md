## 학습 목표

1회차에는 합성곱과 shape을 손으로 추적했고, 2회차에는 누수 없는 분할과 재현 가능한 학습 루프를 만들었다. 이번에는 [원본 손동작 분류 노트](../05.ImageClassification/02.ClassificationForHands.md)를 **학습 코드가 아니라 운영 가능한 서비스의 계약**으로 다시 읽는다.

학습을 마치면 다음을 할 수 있어야 한다.

1. 원본 이미지에서 배포 artifact까지 데이터 계보를 manifest로 고정한다.
2. 학습·검증·shadow·production 입력의 schema와 품질 게이트를 분리한다.
3. 처리량, 지연 시간, activation 메모리, batch 크기의 관계를 계산한다.
4. mixed precision에서 줄여도 되는 dtype과 FP32로 유지할 연산을 구분한다.
5. Python, C++17, C#에서 같은 전처리 tensor와 logits를 재현한다.
6. ONNX export를 model file이 아닌 전처리·label·runtime manifest와 함께 검증한다.
7. latency, 오류율, 입력 drift, confidence, calibration, slice 성능을 함께 감시한다.
8. 모델·데이터·runtime 장애를 golden test와 단계별 rollback으로 분리한다.

## 1. 세 번째 회차에서 바뀌는 질문

과거 글의 질문은 “정확히 학습되는가?”였다. 운영 단계에서는 질문이 다음처럼 바뀐다.

- 어떤 raw sample과 label mapping으로 이 모델을 만들었는가?
- Python에서 맞는 전처리가 모바일 C# 앱과 C++ edge service에서도 같은가?
- 평균 latency가 아니라 p95와 p99가 SLA 안에 드는가?
- confidence가 높아도 특정 사람·카메라·조명에서 무너지는가?
- 모델을 교체하지 않고 decoder, threshold, label map만 잘못 배포할 수 있는가?
- 정답이 늦게 도착하는 동안 어떤 leading indicator로 위험을 발견하는가?

운영 artifact는 단일 `model.onnx`가 아니다.

```text
release-2026-08-31/
  model.onnx
  manifest.json
  labels.json
  preprocess.json
  golden-input.rgb
  golden-tensor.f32
  golden-logits.f32
  metrics-baseline.json
  rollback.json
```

모델 파일의 hash가 같아도 `RGB/BGR`, resize 방식, label 순서가 달라지면 서로 다른 시스템이다.

## 2. 원본의 실제 전제와 운영 교정

원본은 CSV 로드, JPG glob, Albumentations, `Dataset`, 64×64 CNN, 학습·검증 loop를 한 흐름으로 보여 준다. 교육용 흐름은 유용하지만 다음 전제는 서비스 경계에서 명시해야 한다.

| 원본의 전제·표현 | 운영 실패 | 이번 회차의 교정 |
| --- | --- | --- |
| 정렬한 JPG 목록과 CSV 행 순서가 같다 | 파일 한 장 누락 뒤 모든 label이 밀림 | stable sample ID로 one-to-one join |
| `split('/')`로 파일명을 얻는다 | Windows 경로에서 깨짐 | `pathlib.Path.stem` 또는 URI parser |
| decode 성공을 가정한다 | 깨진 JPG를 검은 영상으로 대체해 조용히 오염 | decode 실패를 격리하고 원본 hash 기록 |
| ImageNet mean/std를 사용한다 | scratch 모델에도 최적이라고 오해 | pretrained ABI인지 train-only 통계인지 manifest에 기록 |
| 64×64라서 파라미터가 감소한다 | convolution parameter와 activation 비용을 혼동 | backbone parameter, MAC, activation, flatten head를 분리 계산 |
| `always_apply=False, p=1.0` | 설정 의미가 중복되고 버전 차이에 취약 | transform config를 version·hash하고 golden tensor로 검증 |
| batch loss를 batch 수로 평균 | 마지막 작은 batch가 같은 가중치를 가짐 | `loss * batch_size`를 sample 수로 나눔 |
| accuracy만 본다 | 희소 class와 새로운 사용자의 실패를 숨김 | slice recall, macro F1, calibration, reject rate 추가 |
| `64 -> 32 -> 16`을 고정 flatten | 다른 입력 크기에서 head가 깨짐 | input contract 고정 또는 adaptive pooling 사용 |

또한 원본의 “max pooling이 파라미터 수를 극적으로 줄인다”는 문장은 경계를 나눠 읽어야 한다. pooling 자체에는 학습 파라미터가 없고, 뒤의 flatten linear head 입력을 줄일 때 그 head의 파라미터를 줄인다. convolution의 kernel parameter 수는 pooling 이전 입력 해상도와 무관하다.

## 3. 데이터 계보와 split manifest

### 3.1 sample identity

파일명은 편리한 주소일 뿐 identity가 아니다. 같은 이름으로 파일이 교체될 수 있으므로 최소한 다음을 기록한다.

| 필드 | 예시 | 불변조건 |
| --- | --- | --- |
| `sample_id` | `sign-train/000123` | dataset revision 안에서 유일 |
| `content_sha256` | 64자리 hex | decode 전 raw byte 기준 |
| `label_raw` | `10-1` | 원시 annotation 보존 |
| `label_index` | `10` | `label_map_revision`으로 해석 |
| `subject_id` | `person-042` | group split key |
| `session_id` | `cam2-20260821-am` | 연속 frame 누수 방지 |
| `split` | `train` | manifest 생성 뒤 불변 |
| `consent_revision` | `v3` | 사용 가능 범위 추적 |

샘플 집합 $D$를 train, validation, test로 나눌 때 group key 집합이 겹치지 않아야 한다.

$$
G_{train}\cap G_{validation}=\varnothing
$$

$$
G_{train}\cap G_{test}=\varnothing
$$

같은 사람의 연속 frame을 무작위 행 분할하면 픽셀 수준의 근접 복제본이 양쪽에 들어간다. 이는 높은 validation accuracy를 만들지만 새로운 사람에 대한 일반화 증거는 아니다.

### 3.2 ingest 게이트

학습 job보다 먼저 별도 ingest job이 다음을 검사한다.

1. CSV schema, ID 유일성, label mapping의 전사성
2. raw byte hash 중복과 서로 다른 label의 동일 hash
3. decode 가능 여부, channel 수, EXIF orientation 적용 여부
4. 최소·최대 해상도, aspect ratio, 밝기, saturation 통계
5. subject·session별 class 분포와 split 교집합
6. train-only mean/std 및 그 계산 코드 revision

실패 sample을 임의의 검은 tensor로 바꾸지 않는다. 격리 목록과 원인을 artifact로 남기고, 허용 임계치를 넘으면 학습을 시작하지 않는다.

## 4. 전처리를 ABI로 정의하기

전처리는 “비슷하게 보이는 이미지”를 만드는 코드가 아니라 byte를 tensor로 변환하는 application binary interface다. 순서를 포함해 다음을 고정한다.

1. encoded byte decode
2. EXIF orientation
3. BGR에서 RGB로의 변환 여부
4. resize 크기, 보간법, coordinate convention
5. `uint8`에서 `float32`로 변환하고 $255$로 나누는 시점
6. channel별 mean·std와 epsilon
7. HWC에서 CHW로의 transpose
8. contiguous memory 보장

채널 $c$의 pixel $u_{h,w,c}\in\{0,\ldots,255\}$는 다음 tensor가 된다.

$$
x_{c,h,w}
=
\frac{u_{h,w,c}/255-\mu_c}{\sigma_c}
$$

연산 순서를 바꾸어 raw 0~255 값에서 mean을 빼면 완전히 다른 tensor다. 한 장의 golden image에 대해 전체 tensor byte 또는 tolerance 기반 배열 비교를 CI에 둔다.

### 4.1 resize가 같은 이름으로도 달라지는 이유

bilinear resize는 출력 위치가 입력의 어느 좌표를 가리키는지 정해야 한다. 1차원으로 단순화하면 half-pixel convention은 다음과 같다.

$$
x_{in}
=
\left(x_{out}+\frac{1}{2}\right)
\frac{W_{in}}{W_{out}}
-\frac{1}{2}
$$

runtime이 `align_corners` 또는 다른 좌표 convention을 쓰면 가장자리 pixel이 달라진다. “bilinear”라는 이름만 비교하지 말고 golden tensor를 비교해야 한다.

## 5. 시스템 전체의 tensor shape 추적

원본의 flatten head 대신 배포 입력 크기에 덜 취약한 global average pooling head를 사용한다.

| 경계 | shape | layout | dtype | 소유자 |
| --- | --- | --- | --- | --- |
| camera frame | `(H0,W0,3)` | HWC RGB 또는 BGR | `uint8` | capture |
| resized image | `(64,64,3)` | HWC RGB | `uint8` | preprocessor |
| normalized image | `(3,64,64)` | CHW RGB | `float32` | preprocessor |
| request batch | `(N,3,64,64)` | NCHW | `float32` 또는 `float16` | batcher |
| stem | `(N,16,32,32)` | NCHW | activation dtype | model |
| block 2 | `(N,32,16,16)` | NCHW | activation dtype | model |
| global pool | `(N,32,1,1)` | NCHW | activation dtype | model |
| flatten | `(N,32)` | row-major | activation dtype | model |
| logits | `(N,K)` | row-major | 보통 `float32` 출력 | postprocessor |
| probability | `(N,K)` | row-major | `float32` | decision layer |

global average pooling은 다음을 계산한다.

$$
g_{n,c}
=
\frac{1}{HW}
\sum_{h=0}^{H-1}
\sum_{w=0}^{W-1}
x_{n,c,h,w}
$$

분류 head는 $Z=gW^\top+b$이며 $W\in\mathbb{R}^{K\times32}$다. spatial flatten보다 head parameter가 작고 입력 크기 변화에 강하지만, 전처리 input contract까지 자동으로 해결하는 것은 아니다.

## 6. 처리량·지연 시간·batch의 수학

관측 구간 $T$초에 성공한 sample 수가 $M$이면 처리량은 다음과 같다.

$$
\operatorname{throughput}=\frac{M}{T}
$$

요청 latency는 queue, preprocess, inference, postprocess를 모두 포함한다.

$$
L_i
=
L_i^{queue}
+L_i^{pre}
+L_i^{infer}
+L_i^{post}
$$

평균만 보면 긴 꼬리가 숨는다. 정렬된 latency에서 p95를 계산할 때 nearest-rank 정의는 다음과 같다.

$$
P_{95}=L_{(\lceil0.95M\rceil)}
$$

dynamic batching은 GPU throughput을 높일 수 있지만 첫 요청이 batch를 기다리는 queue latency를 만든다. `max_batch_size`와 `max_wait_ms`를 함께 실험해야 한다. edge CPU에서 batch 1이 목표라면 큰 offline batch benchmark는 사용자 latency를 대표하지 않는다.

## 7. 메모리 예산을 먼저 세우기

tensor 하나의 raw 저장량은 다음과 같다.

$$
M_{tensor}
=
NCHW\cdot B
$$

예를 들어 `(32,32,16,16)` activation은 FP32에서 다음 크기다.

$$
32\cdot32\cdot16\cdot16\cdot4
=1{,}048{,}576\text{ bytes}
$$

FP16이면 절반이지만 학습 peak memory는 activation 하나의 합이 아니다.

$$
M_{peak}
\approx
M_{parameter}
+M_{gradient}
+M_{optimizer}
+M_{saved\ activation}
+M_{workspace}
$$

Adam은 parameter 외에 보통 FP32 first·second moment를 둔다. mixed precision이 activation을 줄여도 master weight와 optimizer state 때문에 parameter 관련 메모리가 절반이 되지 않을 수 있다. 실제 peak는 target device profiler로 측정한다.

## 8. mixed precision과 수치 안정성

convolution과 matrix multiplication은 FP16 또는 BF16으로 가속할 수 있지만 다음 경계는 주의한다.

- normalization 통계와 running statistic
- 큰 logits의 softmax·log-sum-exp
- 작은 loss의 gradient accumulation
- calibration metric과 drift histogram 집계
- CPU runtime에서 지원하지 않는 half kernel

안정적인 softmax는 $m_n=\max_k Z_{n,k}$를 먼저 뺀다.

$$
p_{n,k}
=
\frac{\exp(Z_{n,k}-m_n)}
{\sum_j\exp(Z_{n,j}-m_n)}
$$

AMP 학습에서는 gradient scaling을 사용하고, `unscale_` 뒤 finite gradient와 norm을 검사한다. 추론에서는 입력·weight dtype만 줄이지 말고 Python과 target runtime의 logits·class·confidence tolerance를 따로 정한다.

```python
from __future__ import annotations

import math
import time

import numpy as np
import torch
from torch import nn


MEAN = np.array([0.5, 0.5, 0.5], dtype=np.float32)
STD = np.array([0.25, 0.25, 0.25], dtype=np.float32)


def preprocess_hwc_rgb(image: np.ndarray) -> np.ndarray:
    if image.dtype != np.uint8 or image.ndim != 3 or image.shape[2] != 3:
        raise ValueError("expected HWC RGB uint8")
    tensor = image.astype(np.float32) / np.float32(255.0)
    tensor = (tensor - MEAN) / STD
    return np.ascontiguousarray(tensor.transpose(2, 0, 1))


def portable_head(chw: np.ndarray) -> np.ndarray:
    pooled = chw.mean(axis=(1, 2), dtype=np.float32)
    weight = np.array(
        [[0.5, -0.25, 0.75], [-0.5, 0.5, 0.25], [0.2, 0.1, -0.3]],
        dtype=np.float32,
    )
    bias = np.array([0.1, -0.2, 0.05], dtype=np.float32)
    return weight @ pooled + bias


def stable_softmax(logits: np.ndarray) -> np.ndarray:
    shifted = logits.astype(np.float64) - float(logits.max())
    values = np.exp(shifted)
    return values / values.sum()


def expected_calibration_error(
    probabilities: np.ndarray, targets: np.ndarray, bins: int = 5
) -> float:
    confidence = probabilities.max(axis=1)
    prediction = probabilities.argmax(axis=1)
    correct = prediction == targets
    edges = np.linspace(0.0, 1.0, bins + 1)
    ece = 0.0
    for index in range(bins):
        lower, upper = edges[index], edges[index + 1]
        selected = (confidence > lower) & (confidence <= upper)
        if selected.any():
            gap = abs(float(correct[selected].mean()) - float(confidence[selected].mean()))
            ece += float(selected.mean()) * gap
    return ece


def population_stability_index(reference: np.ndarray, current: np.ndarray) -> float:
    if reference.shape != current.shape or not np.isclose(reference.sum(), 1.0):
        raise ValueError("probability vectors must have the same shape and sum to one")
    if not np.isclose(current.sum(), 1.0):
        raise ValueError("current distribution must sum to one")
    epsilon = 1e-6
    q = np.clip(reference, epsilon, 1.0)
    p = np.clip(current, epsilon, 1.0)
    return float(np.sum((p - q) * np.log(p / q)))


class EdgeCNN(nn.Module):
    def __init__(self, classes: int = 3) -> None:
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 16, 3, stride=2, padding=1),
            nn.ReLU(),
            nn.Conv2d(16, 32, 3, stride=2, padding=1),
            nn.ReLU(),
            nn.AdaptiveAvgPool2d(1),
        )
        self.classifier = nn.Linear(32, classes)

    def forward(self, images: torch.Tensor) -> torch.Tensor:
        if images.ndim != 4 or images.shape[1:] != (3, 64, 64):
            raise ValueError("expected NCHW input with shape (N,3,64,64)")
        return self.classifier(self.features(images).flatten(1))


image = np.array(
    [
        [[255, 0, 127], [0, 255, 127]],
        [[64, 128, 192], [32, 16, 8]],
    ],
    dtype=np.uint8,
)
golden = preprocess_hwc_rgb(image)
expected = np.array(
    [
        [[2.0, -2.0], [-0.99607843, -1.4980392]],
        [[-2.0, 2.0], [0.00784326, -1.7490196]],
        [[-0.00784314, -0.00784314], [1.0117648, -1.8745098]],
    ],
    dtype=np.float32,
)
np.testing.assert_allclose(golden, expected, rtol=0.0, atol=2e-7)

head_logits = portable_head(golden)
head_probability = stable_softmax(head_logits)
assert head_logits.shape == (3,)
assert np.isclose(head_probability.sum(), 1.0)

torch.manual_seed(831)
model = EdgeCNN()
batch = torch.randn(4, 3, 64, 64)
targets = torch.tensor([0, 1, 2, 1], dtype=torch.long)
logits = model(batch)
loss = nn.functional.cross_entropy(logits, targets)
loss.backward()
assert logits.shape == (4, 3)
assert logits.dtype == torch.float32
assert all(parameter.grad is not None for parameter in model.parameters())
assert all(torch.isfinite(parameter.grad).all() for parameter in model.parameters())

model.eval()
latencies_ms = []
with torch.inference_mode():
    for _ in range(5):
        model(batch[:1])
    for _ in range(25):
        started = time.perf_counter_ns()
        model(batch[:1])
        latencies_ms.append((time.perf_counter_ns() - started) / 1e6)

probabilities = np.array(
    [[0.80, 0.10, 0.10], [0.20, 0.60, 0.20], [0.05, 0.15, 0.80], [0.55, 0.35, 0.10]],
    dtype=np.float64,
)
ece = expected_calibration_error(probabilities, np.array([0, 1, 1, 0]))
psi = population_stability_index(
    np.array([0.50, 0.30, 0.20]), np.array([0.30, 0.30, 0.40])
)
assert math.isfinite(ece) and 0.0 <= ece <= 1.0
assert math.isfinite(psi) and psi > 0.0

print("golden_checksum=", f"{float(golden.sum()):.9f}")
print("portable_logits=", np.round(head_logits, 6).tolist())
print("portable_probability=", np.round(head_probability, 6).tolist())
print("model_shape=", tuple(logits.shape), "loss=", f"{loss.item():.6f}")
print(
    "latency_ms=",
    f"median:{np.median(latencies_ms):.4f}",
    f"p95:{np.percentile(latencies_ms, 95):.4f}",
)
print("ece=", f"{ece:.6f}", "psi=", f"{psi:.6f}")
```

## 10. DataLoader와 입력 파이프라인 튜닝

성능을 올릴 때 먼저 시간을 다음 단계로 분해한다.

| 단계 | 측정 항목 | 흔한 병목 | 조정 후보 |
| --- | --- | --- | --- |
| storage | read latency, cache hit | 작은 파일 random I/O | shard, local cache |
| decode | images/s, 실패율 | JPEG CPU decode | worker 수, decoder backend |
| transform | CPU time/sample | Python augmentation | vectorized transform, 범위 축소 |
| host-to-device | copy time | pageable memory | pinned memory, async copy |
| inference | kernel time | 작은 batch launch overhead | compile, batch, fused kernel |
| queue | wait time | batch 형성 또는 overload | max wait, admission control |

`num_workers`를 CPU core 수로 무조건 맞추지 않는다. worker마다 decoder와 prefetch buffer가 있어 RAM과 file descriptor를 소비한다. 후보별로 warm-up 뒤 samples/s, p95, CPU, RAM을 함께 측정한다.

## 11. C++17 golden 전처리와 head

다음은 **의존성 없이 실행 가능한 C++17 코드**다. 실제 ONNX Runtime을 붙이기 전에 전처리와 postprocess 기준값을 고정한다.

<!-- test:cpp:start -->
```cpp
#include <array>
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>

int main() {
    constexpr int height = 2;
    constexpr int width = 2;
    constexpr int channels = 3;
    const std::array<unsigned char, 12> hwc{
        255, 0, 127, 0, 255, 127,
        64, 128, 192, 32, 16, 8
    };
    const std::array<float, 3> mean{0.5F, 0.5F, 0.5F};
    const std::array<float, 3> stddev{0.25F, 0.25F, 0.25F};
    std::array<float, 12> chw{};

    for (int h = 0; h < height; ++h) {
        for (int w = 0; w < width; ++w) {
            for (int c = 0; c < channels; ++c) {
                const int source = (h * width + w) * channels + c;
                const int target = (c * height + h) * width + w;
                chw[target] = (static_cast<float>(hwc[source]) / 255.0F - mean[c]) / stddev[c];
            }
        }
    }

    const std::array<std::array<float, 3>, 3> weight{{
        {{0.5F, -0.25F, 0.75F}},
        {{-0.5F, 0.5F, 0.25F}},
        {{0.2F, 0.1F, -0.3F}}
    }};
    const std::array<float, 3> bias{0.1F, -0.2F, 0.05F};
    std::array<float, 3> pooled{};
    std::array<float, 3> logits{};
    float checksum = 0.0F;

    for (int c = 0; c < channels; ++c) {
        for (int index = 0; index < height * width; ++index) {
            pooled[c] += chw[c * height * width + index];
            checksum += chw[c * height * width + index];
        }
        pooled[c] /= static_cast<float>(height * width);
    }
    for (int k = 0; k < 3; ++k) {
        logits[k] = bias[k];
        for (int c = 0; c < channels; ++c) {
            logits[k] += weight[k][c] * pooled[c];
        }
    }

    assert(std::abs(checksum - (-5.11372566F)) < 1e-5F);
    assert(logits[2] > logits[1] && logits[1] > logits[0]);
    std::cout << std::fixed << std::setprecision(6)
              << "checksum=" << checksum
              << " logits=" << logits[0] << " " << logits[1] << " " << logits[2] << "\n";
}
```

```csharp
using System;

public static class GoldenPreprocess
{
    public static void Main()

        const int height = 2;
```

## 13. 프레임워크 간 shape·layout·dtype 대응

| 경계 | PyTorch Python | C++ 서비스 | C# 앱 | 회귀 조건 |
| --- | --- | --- | --- | --- |
| decoded image | NumPy `uint8[H,W,3]` | `uint8_t*` HWC | `byte[]` HWC | raw hash·RGB sample |
| normalized input | `float32[N,3,64,64]` | contiguous `float*` | `DenseTensor<float>` | elementwise tolerance |
| model input name | `images` | session input metadata | session input metadata | exact string |
| logits | `float32[N,K]` | output buffer | output tensor | max absolute·relative error |

| confidence | stable softmax | FP32 accumulation | FP32 accumulation | class·score tolerance |

NHWC 최적화 runtime이 내부 transpose를 수행할 수는 있다. 그러나 외부 model contract가 NCHW라면 caller가 NHWC buffer를 shape만 NCHW로 붙여서는 안 된다. shape metadata와 memory order는 별개다.

## 15. quantization 의사결정

INT8이 항상 더 빠르거나 정확도 손실이 작은 것은 아니다. calibration set은 train에서 임의로 뽑기보다 production의 사람·피부색·조명·카메라·배경 slice를 대표해야 한다.

| 선택 | 장점 | 위험 | 필수 측정 |
| --- | --- | --- | --- |
| FP32 | 기준 정확도·호환성 | 메모리·latency | baseline |
| FP16 | GPU tensor core 활용 | overflow·CPU kernel 부재 | logits parity, latency |
| dynamic INT8 | linear weight 간편 양자화 | convolution 이득 제한 | target operator coverage |
| static INT8 | convolution까지 정수화 가능 | calibration drift | slice recall, saturation |

전체 accuracy 차이만 보지 않는다. class별 recall, reject rate, calibration, target latency와 binary size를 함께 비교한다. 배포 backend가 INT8 convolution을 FP32로 되돌리면 model size만 줄고 latency는 나빠질 수도 있다.

## 16. 모니터링: 정답 전과 정답 후를 나누기

### 16.1 정답이 오기 전

- request 수, decode 실패율, invalid shape·dtype 비율
- queue, preprocess, inference, end-to-end p50·p95·p99
- timeout, out-of-memory, runtime fallback 비율
- 밝기·contrast·channel mean, blur, aspect ratio drift
- predicted class 비율, confidence·entropy 분포, reject rate
- model·preprocess·label map revision별 traffic

예측 class 분포의 PSI는 다음과 같다.

$$
\operatorname{PSI}
=
\sum_{c=1}^{K}
(p_c-q_c)
\log\frac{p_c}{q_c}
$$

PSI는 drift 신호이지 품질 저하의 증명은 아니다. 실제 사용 패턴이 바뀌어 class 비율이 변할 수도 있다.

예측 entropy도 관찰한다.

$$
H(p_n)
=
-\sum_{k=1}^{K}p_{n,k}\log p_{n,k}
$$

entropy 급증은 입력 불명확성이나 전처리 장애를 시사할 수 있고, 비정상적으로 낮은 entropy는 saturation이나 잘못된 scale을 시사할 수 있다.

### 16.2 지연 정답이 도착한 뒤

- subject·device·lighting·class별 recall과 macro F1
- calibration curve와 expected calibration error
- false accept·false reject 비용
- human override와 재시도율
- champion·challenger paired difference

$M$개 bin의 ECE는 다음과 같다.

$$
\operatorname{ECE}
=
\sum_{m=1}^{M}
\frac{|B_m|}{N}
\left|
\operatorname{acc}(B_m)
-
\operatorname{conf}(B_m)
\right|
$$

ECE 하나도 bin 수에 민감하다. reliability diagram과 high-confidence error sample을 함께 본다.

## 17. 실무 실패 사례와 장애 분리

### 17.1 새 모델 배포 직후 모든 class가 이동

모델 hash와 golden logits는 맞았지만 `labels.json` 순서가 바뀌었다. 관측상 모델 품질 저하처럼 보이나 실제로는 postprocess artifact 불일치다. model·label map hash를 하나의 release manifest로 원자 배포한다.

### 17.2 Python validation은 정상, C# 앱만 특정 카메라에서 실패

앱 decoder가 BGRA를 반환했는데 alpha byte를 제거하는 index가 틀려 channel이 한 byte씩 밀렸다. shape는 `(1,3,64,64)`로 정상이라 단순 shape test가 잡지 못했다. raw color patch와 preprocessed tensor checksum을 golden test에 넣는다.

### 17.3 평균 latency는 정상인데 timeout 증가

평균은 12 ms였지만 batch queue가 과부하 때 길어져 p99가 180 ms가 되었다. inference kernel만 재지 말고 queue를 포함한 end-to-end histogram과 in-flight request 수를 본다.

### 17.4 INT8 뒤 전체 accuracy는 비슷하지만 한 class 붕괴

전체 표본이 많은 class가 평균을 지켰고 어두운 조명의 희소 gesture activation이 calibration range 밖에서 saturation되었다. calibration set slice를 보강하고 class·lighting 교차 slice recall을 release gate로 둔다.

### 17.5 confidence drift가 없는데 실제 품질 하락

모델이 새로운 배경에도 과신했다. confidence는 정확도의 대리값일 뿐이다. 지연 label sampling과 사용자·기기 slice 평가가 없으면 silent failure를 놓친다.

## 18. 배포와 rollback 설계

안전한 승격 순서는 다음과 같다.

1. offline golden·slice·stress test
2. shadow traffic에서 응답 미노출 비교
3. 1% canary와 revision별 metric 분리
4. 10%·50% 단계 승격
5. error budget과 slice guardrail을 만족할 때 100%

rollback 단위는 `model.onnx`만이 아니라 다음 bundle 전체다.

- model과 runtime version
- preprocess·label mapping
- threshold·temperature·reject policy
- golden set과 baseline metric
- schema migration과 cache key

데이터 schema가 비호환으로 바뀌면 이전 binary만 되돌려도 복구되지 않을 수 있다. forward·backward compatible schema 또는 dual-write 기간을 설계한다.

## 23. 연습문제 해답

### 해답 1

원소 수는 $16\cdot32\cdot16\cdot16=131{,}072$다. FP32는 원소당 4 byte이므로 $524{,}288$ byte, FP16은 원소당 2 byte이므로 $262{,}144$ byte다. allocator·workspace overhead는 포함하지 않았다.

### 해답 2

queue wait, preprocess, postprocess를 먼저 분리한다. 특히 dynamic batching과 overload가 queue의 긴 꼬리를 만드는지 확인한다. cold start 또는 runtime fallback도 revision별로 확인한다.

### 해답 3

먼저 같은 raw image를 decode한 pixel을 비교하고, 다음으로 normalization·transpose가 끝난 input tensor를 elementwise 비교한다. 입력이 같을 때만 model graph·operator parity를 조사한다.

### 해답 4

아니다. PSI는 기준 분포와 입력·예측 구성의 변화 신호다. 실제 사용자의 gesture 빈도가 바뀌어도 커진다. slice 성능과 데이터 품질을 조사할 trigger로 사용하되 품질 저하의 증명으로 사용하지 않는다.

### 해답 5

전체 평균은 희소 class 붕괴를 숨길 수 있고, target hardware가 INT8 operator를 실제로 가속하지 않을 수 있으며, confidence calibration과 reject policy가 바뀔 수 있다. slice recall, target latency·memory, calibration을 함께 통과해야 한다.

### 해답 6

head의 feature 수는 고정되지만 preprocess resize·crop, convolution downsampling의 최소 크기, receptive field, runtime dynamic-axis, latency·memory 계약은 남는다. 학습 분포와 다른 aspect ratio·해상도가 품질을 보장하지도 않는다.

## 24. 핵심 요약

1. 이미지 분류 서비스의 artifact는 model 하나가 아니라 preprocess·label·runtime·golden을 포함한 bundle이다.
2. stable ID, raw hash, subject·session group, split manifest가 데이터 계보와 누수 방지의 기반이다.
3. 전처리는 RGB, resize coordinate, scale, normalize, layout 순서를 고정한 ABI다.
4. 평균 latency보다 queue를 포함한 p95·p99와 실제 batch 분포가 운영 경험을 설명한다.
5. mixed precision의 메모리 이득은 optimizer state와 workspace를 포함한 peak 실측으로 판단한다.
6. Python·C++·C#은 같은 golden pixel, tensor, logits를 단계별로 비교해야 한다.
7. ONNX export 성공은 runtime parity, operator coverage, target benchmark를 대신하지 않는다.
8. drift·confidence는 leading indicator이며 지연 label의 slice metric을 대체하지 않는다.
9. quantization은 전체 accuracy뿐 아니라 희소 slice, calibration, target latency를 함께 평가한다.
10. rollback은 model·preprocess·label·threshold·runtime을 하나의 release bundle로 되돌린다.
